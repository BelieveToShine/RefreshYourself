🔥 Python · Basic · Must Know

self is just the instance, passed explicitly — there's no hidden magic

"Instance method vs. class method vs. static method — what's the actual difference, and why does self exist at all?"

Why it matters ▾
  • Almost every Python interview opens OOP with some version of this — it's the fastest way to check the fundamentals actually clicked.
  • Mixing up self, cls, and a plain function is a very common tell that someone memorized the decorators without understanding what they change.
  • Sets up the classmethod-as-alternate-constructor follow-up almost every interviewer asks right after.
🔥 Easy interview recall

self → this instance

cls → the class itself

static → neither one

Think: self isn't magic — it's just a regular parameter that Python fills in with the calling instance for you.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

__init__ is not technically "the constructor." __new__ is what actually creates the instance — __init__ only initializes it afterward; calling __init__ "the constructor" is fine loosely, but know the distinction if an interviewer pushes on it.

🔄 Likely Follow-up

"When would you reach for a classmethod as an alternate constructor?" When you want more than one way to build an instance from different input shapes — e.g. Date.from_string("2026-01-01") alongside the normal Date(year, month, day), each a @classmethod that builds and returns a cls(...) instance.

🎯 Say this in the interview — the exact lines to land

"self is the instance, cls is the class, static gets neither — that's the whole distinction. Instance methods operate on one object's state, classmethods operate on the class itself and are commonly used as alternate constructors, and staticmethods are just regular functions grouped inside the class for organization."

  • self → the specific instance calling the method; always the first parameter of an instance method.
  • cls → the class itself, via @classmethod — commonly used for alternate constructors.
  • @staticmethod → takes neither self nor cls; just a function that happens to live inside the class.
  • Composition over inheritance → reach for "has-a" when you just need to reuse behavior, not commit to a rigid "is-a" hierarchy.
📖 Explanation ▾

Class = a blueprint; object/instance = a concrete thing built from that blueprint. An instance variable is per-object state, set with self.x = ... (usually inside __init__); a class variable is shared across every instance, because it's defined directly in the class body instead. __init__ is the initializer — Python calls it automatically right after a new instance already exists, to set up its starting state.

An instance method takes self — the specific instance calling it — as its first parameter, so it can read and change that one object's state. A classmethod (@classmethod) takes cls — the class itself — instead, most often used as an alternate constructor. A staticmethod (@staticmethod) takes neither; it's really just a regular function that happens to live inside the class for organization.

Composition ("has-a" — a Car has an Engine) is generally preferred over inheritance ("is-a" — a Dog is an Animal) when the real goal is reusing behavior, not committing to a rigid hierarchy. Encapsulation bundles data with the methods that operate on it — Python signals "internal, don't touch" with a leading underscore by convention, not enforced privacy. Polymorphism is different classes responding to the same method call, each in its own way. Abstract classes (a required interface subclasses must implement) and multiple inheritance (a class built from more than one base) go deeper than fundamentals — their own pages cover ABCs, and the MRO/diamond problem.

💻 See the code ▾
Python 
class Widget:
    def foo(self):
        return f"instance: {self}"

    @classmethod
    def bar(cls):
        return f"class: {cls}"

    @staticmethod
    def baz():
        return "no self, no cls"

"Which of these three can you call without an instance?" Widget.bar() and Widget.baz() both work directly on the class — no instance needed. foo needs a real Widget() to call it on. Only bar can still tell you which class it was called on (via cls); baz has no reference to anything at all.

🌍 Real-world example ▾

Most production Python codebases use a @classmethod as an alternate constructor exactly like this: User.from_json(data) parses a JSON payload and returns a fully built User instance, sitting right alongside the normal User(name, email) constructor — same pattern as the Follow-up's Date.from_string(...) example.
