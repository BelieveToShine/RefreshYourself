try / catch / finally — who runs, and when

Why it matters ▾
  • Explains why cleanup code (closing a file, releasing a connection) has to live in finally.
  • Tells you exactly what still runs when an exception is thrown mid-method.
  • The base every follow-up question about custom exceptions builds on.
📖 Explanation ▾

try just marks "watch this code for trouble." If nothing goes wrong, C# skips catch entirely and heads straight for finally.

catch only runs if an exception actually gets thrown inside try — and only if its type matches. You can stack multiple catch blocks for different exception types.

finally is the one guarantee in this whole story: it runs whether or not an exception happened, and even if the exception was never caught at all — which is exactly why cleanup code (closing files, releasing locks) belongs there.

🌍 Real-world example ▾

Cooking on a stove. try is cooking the meal. catch is what you do if it catches fire. finally is turning the stove off — you do that whether dinner turned out great or the kitchen's full of smoke.

🎯 Say this in the interview — the exact lines to land

  • finally always runs — error or not, caught or not.
  • catch only runs when the exception type matches.
  • Put cleanup code in finally — never assume the method reaches its last line.
  • Even an unhandled exception lets finally run before it propagates up.
  • using is built on try/finally — it disposes the object automatically.
