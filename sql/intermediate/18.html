Second highest salary? DENSE_RANK handles the ties for you

"Find the second highest salary / top 3 per department."

Why it matters ▾
🏆 Nth highest
❗ ProblemMAX finds the top salary, but the Nth one — or the top N per department — needs ranking, and ties or too few rows break naive answers.
✅ SolutionRank the rows with DENSE_RANK() (add PARTITION BY for groups) and filter on the rank.
RecallNth highest = rank, then filter on N.
🔥 Easy interview recall

Nth highest = "rank the salaries, then keep rank N."

Think: DENSE_RANK → ties share a rank, no gaps ROW_NUMBER → never ties, picks one arbitrarily RANK → ties share, then skips (1, 2, 2, 4)

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

"The second row of ORDER BY Salary DESC is the second highest salary." With a tie at the top, row 2 is the same salary as row 1 — rank distinct salaries (DENSE_RANK, or SELECT DISTINCT before OFFSET).

🔄 Likely Follow-up

"What should the query return if there is no second highest salary?" Usually NULL. OFFSET/FETCH and a rank filter return no rows at all, so wrap the query in a scalar subquery to get NULL; the MAX(Salary) WHERE Salary < (SELECT MAX(Salary) …) form returns NULL by itself.

🎯 Say this in the interview — the exact lines to land

"I rank the salaries with DENSE_RANK() ordered descending and keep the rows where the rank equals N. Tied salaries get the same rank with no gaps, so N means the Nth distinct salary. For top N per department I add PARTITION BY department."

  • DENSE_RANK → ties share a rank, no gaps — N is the Nth distinct salary.
  • ROW_NUMBER → never ties, so it picks one person among equal salaries.
  • RANK → ties share, then it skips (1, 2, 2, 4) — rank 3 may not exist.
  • OFFSET / FETCH → SELECT DISTINCT Salary … OFFSET N-1 ROWS FETCH NEXT 1 ROWS ONLY.
  • Top N per group → PARTITION BY department, filter rnk <= N in an outer query.
📖 Explanation ▾

A window function can't sit in WHERE, so the pattern is: compute the rank in a CTE or subquery, then filter on it outside. DENSE_RANK() is the usual pick because tied salaries share a rank and no number is skipped. That also means a tie returns every person on that salary, which is normally what "who earns the second highest" should do.

Alternatives exist. OFFSET/FETCH on distinct salaries is short but returns the value, not the people, and it returns no row when N is too big. A correlated subquery — count how many distinct salaries are higher — works everywhere but is clumsier and slower. For top N per group, the ranking approach is the clearest.

💻 See the code ▾
T-SQL 
WITH Ranked AS (
    SELECT Name, Salary,
           DENSE_RANK() OVER (ORDER BY Salary DESC) AS rnk
    FROM Employees
)
SELECT Name, Salary FROM Ranked WHERE rnk = 2;   -- ✅ everyone on the 2nd highest salary

Rank first, filter second — ties both come back.

T-SQL 
WITH Ranked AS (
    SELECT DeptId, Name, Salary,
           DENSE_RANK() OVER (PARTITION BY DeptId ORDER BY Salary DESC) AS rnk
    FROM Employees
)
SELECT DeptId, Name, Salary FROM Ranked WHERE rnk <= 3;   -- ✅ top 3 salaries per department

PARTITION BY restarts the ranking inside each department.

T-SQL 
SELECT (SELECT DISTINCT Salary
        FROM Employees
        ORDER BY Salary DESC
        OFFSET 1 ROWS FETCH NEXT 1 ROWS ONLY) AS SecondHighest;   -- ✅ NULL if there is none

OFFSET 1 skips the highest distinct salary; the outer SELECT turns an empty result into NULL.

🌍 Real-world example ▾

A leaderboard where two players tie for silver: both get silver, and the next player is bronze. Asking for the second-place score returns that one value, and asking who is second returns both names.
