Concat vs. Union vs. Intersect vs. Except — four ways to combine two sequences

"Four different ways to combine two sequences — which ones dedupe, and which ones keep duplicates?"

Why it matters ▾
➕ Concat
❗ ProblemMerging two logs or batches for processing needs every record from both, including ones that happen to repeat — losing a legitimate duplicate record would be a real data-loss bug here.
✅ SolutionConcat lays sequence A then sequence B end-to-end and keeps absolutely everything, duplicates included — the simplest, no-dedupe combine.
RecallConcat = everything, duplicates stay.
🔀 Union
❗ ProblemMerging two tag lists into one display set shouldn't show the same tag twice just because it existed in both source lists.
✅ SolutionUnion is Concat plus a dedupe pass afterward — every distinct value appears exactly once in the combined result.
RecallUnion = Concat, then dedupe.
∩ Intersect
❗ ProblemFinding which products appear in both this month's and last month's bestseller lists needs only the overlap, not either full list.
✅ SolutionIntersect returns only the elements present in both sequences — exactly the overlap, nothing from either side alone.
RecallIntersect = only what's in both.
➖ Except
❗ ProblemFinding which customers from last year never ordered again this year needs last year's list minus this year's, not an overlap and not everything combined.
✅ SolutionExcept returns elements in the first sequence that are not in the second — a one-directional subtraction.
RecallExcept = first sequence, minus whatever's also in the second.
🔥 Easy interview recall

Concat → everything, duplicates stay

Union → Concat + dedupe

Intersect → only in both

Except → in A, not in B

Think: Concat and Union are the same operation, one step apart — Union just adds the dedupe.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Concat is not Union. Concat keeps every duplicate from both sequences; Union runs the exact same combine and then removes duplicates — mixing the two up is the single most commonly confused pair among all four operators.

🔄 Likely Follow-up

"How do these four decide two elements are 'equal' for deduping or matching?" All four default to EqualityComparer<T>.Default (effectively Equals/GetHashCode) unless you pass an explicit IEqualityComparer<T> overload — for a reference type with no overridden Equals, that means reference equality, not "same data."

🎯 Say this in the interview — the exact lines to land

"Concat keeps everything from both sequences, including duplicates. Union is Concat plus a dedupe pass. Intersect returns only elements present in both. Except returns elements in the first sequence that aren't in the second."

  • Concat → no dedupe, order preserved, every element from both.
  • Union → Concat, then distinct, one copy of each value.
  • Intersect → overlap only, in A and in B.
  • Except → one-directional subtraction, in A but not in B.
📖 Explanation ▾

Concat is the simplest of the four: it streams every element of the first sequence, then every element of the second, with no comparison between them at all — if a value exists in both, it shows up twice in the result. Union runs that exact same combine and then removes duplicate values from the combined result, so each distinct value appears exactly once.

Intersect and Except both compare the two sequences against each other rather than just combining them. Intersect keeps only values that exist in both sequences — the overlap. Except keeps only values from the first sequence that do not appear in the second — a one-directional subtraction, so a.Except(b) and b.Except(a) are generally different results.

All four of these are set operators in the sense that their output never contains duplicates of the same value — except Concat, which isn't really a set operation at all, it's a plain sequence-level append. That's the real reason it's grouped with the other three here: not because it behaves like them, but because it's the operator people reach for by mistake when they actually wanted Union.

💻 See the code ▾
C# 
int[] a = { 1, 2, 3 };
int[] b = { 2, 3, 4 };

a.Concat(b);      // ✅ 1, 2, 3, 2, 3, 4 — six items, duplicates kept
a.Union(b);       // ✅ 1, 2, 3, 4 — four items, deduped

Union is literally Concat plus a dedupe pass.

C# 
a.Intersect(b);   // ✅ 2, 3 — present in both a and b
a.Except(b);      // ✅ 1 — in a, not in b
b.Except(a);      // ✅ 4 — in b, not in a (direction matters!)

Except is one-directional — swapping the sequences changes the answer.

🧭 Use Cases — recognize these when they happen to you ▾
1 You're merging two batches of raw log entries for processing

A legitimately repeated log entry (the same error fired twice) is real information, not noise — Concat is correct here precisely because it never removes anything.

RememberDuplicates are meaningful data → Concat, never Union.
2 You're building one combined tag list to display from two source lists

Showing the same tag twice in a UI chip list looks like a bug to the end user even if it's technically "correct data" — Union is what a display list actually needs.

RememberUser-facing display list → Union, not Concat.
3 You need customers that appear on both this quarter's and last quarter's top-spender list

"Consistently high-value" is exactly the overlap between two periods, not either period alone and not a combined list — Intersect is the direct match for this question.

Remember"In both" questions → Intersect.
4 You reach for Concat when the requirement was really "no duplicates"

This is the Common Trap surfacing as a real bug: a dropdown or report shows the same item twice because Concat was used where Union was actually needed — swapping the one method name fixes it completely.

RememberUnexpected duplicate rows → check for a Concat that should be a Union.
🌍 Real-world example ▾

A permissions check needs "roles granted directly, plus roles inherited from group membership," with no role listed twice even if it came from both places. directRoles.Union(groupRoles) is the entire implementation — reaching for Concat here would leave a user with the same role listed twice in the UI, a cosmetic but very visible bug.
