<th> isn't just a bold <td> — and your list tag isn't just visual either

"What's the actual difference between <th> and <td>, and how do you choose between <ol>, <ul>, and <dl>?"

Why it matters ▾
  • Screen readers announce <th> as an actual header — a bold-styled <td> looks the same to sighted users but is invisible as a header to assistive tech.
  • scope is the detail that separates "I know the table tags" from "I know table tags and accessibility" — a common follow-up once someone names <th>.
  • Picking <ol> vs. <ul> vs. <dl> correctly is a quick, easy interview check of whether someone thinks in semantics or just reaches for a <div> and CSS.
🔥 Easy interview recall

<th> → header cell — announced as a header to screen readers

<td> → data cell — plain content, no header role

scope → says which cells a header actually describes

Think: ol → order matters ul → order doesn't dl → term/definition pairs

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

<th> is not just <td> with bold text. The default bold-and-centered look is only a stylesheet default — the actual difference is that <th> carries a header role screen readers rely on, which a bold-styled <td> never gets.

🔄 Likely Follow-up

"So do you need scope on every <th>?" Not on a simple table with one header row — browsers and screen readers can usually work that out on their own. scope earns its spot once a table gets more complex, like headers on both axes or more than one header row, where guessing which header goes with which cell stops being reliable.

🎯 Say this in the interview — the exact lines to land

"A <table> is grouped into <thead>, <tbody>, and <tfoot> for structure. <th> marks a header cell and <td> marks a data cell, and scope="col"/scope="row" tells assistive tech exactly which cells a header describes. For lists, <ol> is for when order matters, <ul> is for when it doesn't, and <dl> pairs terms with their definitions."

  • th vs. td → <th> is a header cell with an implicit accessibility role; <td> is a plain data cell.
  • scope → tells a screen reader which column or row a header cell actually describes.
  • <ol> → use when the order itself is part of the meaning — steps, rankings.
  • <ul> → use when the items are a set with no real order between them.
  • <dl> → use for term/definition pairs — a glossary, a set of key-value details.
📖 Explanation ▾

A table isn't just rows and columns — <thead>, <tbody>, and <tfoot> group those rows by role: the header row(s), the actual data, and a summary row. Inside a row, <th> marks a header cell and <td> marks a data cell. The browser's default bold-and-centered look for <th> is just a stylesheet default, not the reason it exists — the real reason is that <th> carries an implicit header role, so a screen reader announces it as a header and can associate it with the cells it describes.

That association is exactly what scope makes explicit. scope="col" on a header says "everything below me, in this column, is mine"; scope="row" says the same across a row. For a simple table with one header row, browsers and screen readers can usually work that out without it — scope earns its keep once a table gets more complex, like headers on more than one axis, where guessing which header goes with which cell stops being reliable.

💻 See the code ▾
HTML 
<table>
  <thead>
    <tr><th scope="col">Item</th><th scope="col">Price</th></tr> // column headers
  </thead>
  <tbody>
    <tr><th scope="row">Apples</th><td>$3</td></tr> // row header + data cell
  </tbody>
</table>

scope="col" ties "Price" to the price cells below it; scope="row" ties "Apples" to the price cell beside it.

HTML 
<ol><li>Preheat oven</li><li>Mix batter</li></ol> // order matters
<ul><li>Free tier</li><li>Pro tier</li></ul> // order doesn't matter
<dl><dt>API</dt><dd>Application Programming Interface</dd></dl> // term + definition

Same idea, three different shapes: a sequence, a plain set, and a term paired with its meaning.

🌍 Real-world example ▾

Picture a spreadsheet with its header row frozen at the top. Scroll down far enough and you still know which column a number belongs to, because that frozen header stays visible. scope gives a screen reader the same thing without the visuals — it's told, explicitly, which column or row a header describes, even though it can't "see" the frozen row the way a sighted person can.
