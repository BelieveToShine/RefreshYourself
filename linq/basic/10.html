Distinct vs. DistinctBy — dedupe the whole item, or just a key?

"What's the difference between Distinct and DistinctBy, and when did DistinctBy become available?"

Why it matters ▾
🔁 Distinct
❗ ProblemA list of full objects can have exact duplicates you want removed entirely — or near-duplicates that only match on one field, which plain equality won't catch.
✅ SolutionDistinct() removes exact duplicates using the default comparer, or a custom IEqualityComparer<T> you write when "equal" means "same one field."
RecallDistinct = dedupe the whole item.
🎯 DistinctBy
❗ ProblemWriting a whole IEqualityComparer<T> class just to dedupe by one field (like a department or a category) is a lot of ceremony for a one-line idea.
✅ SolutionDistinctBy(keySelector) dedupes by a derived key directly — no comparer class at all.
RecallDistinctBy = dedupe by just a key.
🔥 Easy interview recall

Distinct() → whole item must match

DistinctBy(key) → one key must match

Think: DistinctBy is Distinct with a built-in key selector — no comparer class required. Available from .NET 6 onward.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Reaching for a custom IEqualityComparer<T> class to dedupe by a single field. If you're targeting .NET 6 or later, that entire class is unnecessary — DistinctBy(x => x.Dept) does the exact same job with no comparer at all.

🔄 Likely Follow-up

"Is DistinctBy available in .NET Framework or older .NET Core apps?" No — it ships in System.Linq starting with .NET 6; a project targeting anything earlier has to use Distinct() with a custom IEqualityComparer<T> instead.

🎯 Say this in the interview — the exact lines to land

"Distinct() dedupes by full equality — the default comparer, or one you supply — while DistinctBy(keySelector), available from .NET 6 onward, dedupes by a single derived key with no comparer class needed at all."

  • Distinct() → whole-item equality, needs a comparer class for a partial match.
  • DistinctBy(key) → one key, no comparer class — simplest for the common case.
  • .NET 6+ only — older targets are stuck with Distinct + a custom comparer.
📖 Explanation ▾

Distinct() compares whole elements for equality — by default using Equals/GetHashCode, or a custom IEqualityComparer<T> you pass in when "equal" should mean something narrower, like "same department."

DistinctBy(keySelector) skips the comparer entirely — you just hand it a lambda that picks the key to compare on, and it dedupes by that key alone. It shipped in .NET 6, so it's not available on older target frameworks.

💻 See the code ▾
C# 
class DeptComparer : IEqualityComparer<Person>
{
    public bool Equals(Person a, Person b) => a.Dept == b.Dept;
    public int GetHashCode(Person p) => p.Dept.GetHashCode();
}
var oneA = people.Distinct(new DeptComparer()); // ✅ works, needs the class above

Distinct needs a whole comparer class just to dedupe by one field.

C# 
var oneB = people.DistinctBy(p => p.Dept);  // ✅ same result, no class at all (.NET 6+)

Same outcome, one line — the key selector replaces the entire comparer class.

🧭 Use Cases — recognize these when they happen to you ▾
1 You need one row per customer, department, or category out of a bigger list

Need one representative row per department for a dropdown or a summary list? DistinctBy(x => x.Dept) gets there in one line. This is the #1 scenario you'll actually run into.

RememberOne row per key → DistinctBy, no comparer class.
2 You're targeting an older .NET version without DistinctBy

A legacy codebase still targeting an older framework doesn't have DistinctBy available at all — the custom IEqualityComparer<T> approach is the only option there, not just an alternative.

RememberOlder target framework → Distinct + comparer is the only path.
3 You assume Distinct() alone can dedupe by just one field

Calling plain Distinct() on full Person objects compares every field — two people in the same department with different names still count as different, so nothing gets removed at all.

RememberNo comparer/key → Distinct compares everything, not one field.
🌍 Real-world example ▾

Think of a guest list with duplicate entries. Distinct() removes a guest only if their entire entry — name, email, everything — matches another one exactly. DistinctBy(x => x.Email) removes a guest the moment their email alone repeats, even if the name was typed differently each time.
