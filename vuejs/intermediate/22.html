Vue plugins — one app.use() call, many effects

"What does a Vue plugin's install() function actually get to do?"

Why it matters ▾
🔌 Vue plugins
❗ ProblemShared app-wide setup — a global directive, an API client every component might need, a translation helper — has no obvious place to live if every component has to import and wire it up individually, and nothing stops the same setup running twice by accident.
✅ SolutionA plugin is an object with an install(app, options) function — app.use(plugin, options) calls it exactly once, letting it register global components/directives, provide shared values, or add global helpers in one place.
RecallPlugin = an install(app, options) function app.use() runs exactly once.
🔥 Easy interview recall

Plugin = "an install(app, options) function app.use() runs exactly once."

Think: app.use(plugin) → plugin.install(app) → registers a directive / provides a value / adds a global helper.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Calling a plugin's install logic manually instead of through app.use(). app.use() also guards against installing the exact same plugin twice, which calling install() directly doesn't — a manual call can silently double-register everything.

🔄 Likely Follow-up

"What's a realistic thing a plugin would do in install()?" Register a global directive, provide a shared service (like an API client) app-wide via provide(), or add a global $translate helper via app.config.globalProperties.

📖 Explanation ▾

A plugin is just an object exposing an install(app, options) function (a plain function works too — Vue calls it the same way). Calling app.use(plugin, options) runs that function once, passing it the app instance and whatever options you gave app.use().

What a plugin actually does inside install() is entirely up to it — register a global component or directive with app.component()/app.directive(), make a shared value available app-wide with app.provide(), or attach a global helper method via app.config.globalProperties. Vue Router and Pinia are both ordinary plugins under the hood, installed exactly this way.

app.use() tracks which plugins it has already installed and silently skips a repeat call for the same plugin — calling plugin.install(app) directly bypasses that check entirely.

💻 See the code ▾
Vue 
// i18nPlugin.js
export default {
  install(app, options) {
    app.config.globalProperties.$translate = (key) =>
      options.messages[key] ?? key          // ✅ a global helper
  }
}

Every component can now call this.$translate('hello') — no import needed.

Vue 
import i18nPlugin from './i18nPlugin'

const app = createApp(App)
app.use(i18nPlugin, { messages: { hello: 'Hola' } })   // ✅ install() runs once
app.mount('#app')

A second app.use(i18nPlugin) anywhere else would be silently skipped.

🌍 Real-world example ▾

Vue Router and Pinia both arrive as plugins. app.use(router) and app.use(pinia) are the exact same mechanism as a hand-written plugin — their install() just happens to register a router/store system instead of a single helper method.
