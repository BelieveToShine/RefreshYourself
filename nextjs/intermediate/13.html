Parallel Routes — more than one independently-routable page, one layout

"What are Parallel Routes, and how do they differ from just putting two components side by side?"

Why it matters ▾
🪟 Parallel Routes
❗ ProblemA dashboard that renders an analytics feed and a team feed side by side would otherwise force both into one page's data-fetching and one shared loading/error state — a slow team feed blocks the analytics feed too, even though they have nothing to do with each other.
✅ SolutionNamed slots (@slotName folders) let a layout render more than one independent page simultaneously — each slot streams, loads, and errors on its own, while staying part of the same URL.
Recall@slot = its own independently-routable page, rendered alongside its siblings.
🔥 Easy interview recall

Parallel Routes = "two or more independently-routed pages rendering in the same layout at once."

Think: @analytics and @team — each a real route, each its own loading.js.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

A parallel route is not just "two components side by side in one page.js." The distinguishing feature is that each slot is its own independently-routable segment — its own loading.js/error.js, deep-linkable — not simply a layout arrangement choice.

🔄 Likely Follow-up

"What happens to a slot that has no matching state for the current URL?" You provide a default.js inside that slot's folder as its fallback — without one, Next.js falls back to rendering nothing extra for that slot on a non-matching navigation.

🎯 Say this in the interview — the exact lines to land

"Named slots — @slotName folders — let a layout render more than one independent page at the same time, each with its own loading and error state, each navigable independently — not just two components arranged side by side."

  • @slotName → each slot is its own routable segment, not just layout markup.
  • Independent loading/error state per slot — one slow slot doesn't block the other.
  • default.js → the fallback when a slot has no matching state for the current URL.
  • Deep-linkable — each slot can be driven by its own URL state.
📖 Explanation ▾

A folder named @slotName defines a named slot that a parent layout.js receives as a prop with that same name. Unlike a regular nested route, a slot doesn't add a segment to the URL — instead, it lets the layout render more than one page's worth of content at once, side by side, each slot filled by whatever route currently matches it.

What makes this different from simply importing two components into one page.js is that each slot is a real, independently-routable segment in its own right — it gets its own loading.js and error.js, and its own navigation state. One slot streaming in slowly, or erroring, doesn't affect the other.

Because a slot is matched against the current URL independently, it's possible for a navigation to change one slot's content without a route existing for every slot at every URL — that's exactly the gap default.js exists to fill, as the fallback a slot renders when nothing else matches.

💻 See the code ▾
Next.js 
// folder structure
app/dashboard/
  layout.js            // receives both slots as props
  @analytics/page.js    // its own route + loading.js possible
  @team/page.js          // its own route + loading.js possible

Each slot folder is a sibling route, matched independently against the current URL.

Next.js 
// app/dashboard/layout.js
export default function DashboardLayout({ children, analytics, team }) {
  return (
    <div className="grid">
      {analytics}   // ✅ the @analytics slot's matched page
      {team}         // ✅ the @team slot's matched page
    </div>
  );
}

The slot names become prop names on the layout — Next.js fills each one with its own independently-matched route.

🌍 Real-world example ▾

A dashboard shows a live analytics chart and a team activity feed side by side. The activity feed depends on a slower, less-cacheable query than the analytics chart — with Parallel Routes, the chart can finish and render while the feed's own loading.js is still showing, instead of one shared loading state covering (and being gated by) both.
