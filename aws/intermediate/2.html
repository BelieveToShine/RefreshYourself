Direct Connect is dedicated bandwidth — but it's still one physical link

"VPN vs. Direct Connect — when would you choose each, and what happens if Direct Connect fails?"

Why it matters ▾
🔒 Site-to-Site VPN
❗ ProblemWaiting weeks for a physical circuit to be installed isn't an option when on-prem needs to reach AWS right now.
✅ SolutionA Site-to-Site VPN is an encrypted tunnel over the public internet — no physical circuit needed, so it's the quick option, and it's exactly the path production designs already lean on as the automatic failover when Direct Connect goes down.
RecallVPN → encrypted tunnel over the public internet, quick to stand up, doubles as the failover path.
🔌 Direct Connect
❗ ProblemTraffic sharing the regular internet path means variable bandwidth and latency — not good enough for a workload that needs dedicated, consistent throughput.
✅ SolutionDirect Connect is a dedicated physical line from on-prem to AWS, giving higher bandwidth and more consistent latency — but it's still one physical link, so it needs its own backup: a VPN failover or a second circuit from another location.
RecallDirect Connect → dedicated physical line, higher bandwidth — still needs its own backup.
🔥 Easy interview recall

VPN → encrypted tunnel over the public internet

Direct Connect → a dedicated physical line

Think: VPN is the backup you can turn on today. Direct Connect is the highway you have to build first.

⚠️ Common Trap

"Direct Connect alone is reliable enough." It's still a single physical link (or set of links from one location) that can fail — production DR designs pair it with a VPN failover or run two Direct Connect circuits from different locations.

🔄 Likely Follow-up

"How would you connect multiple on-premises networks to AWS?" Route through a Transit Gateway with a Direct Connect Gateway, so many on-prem sites and VPCs share one connectivity hub instead of each needing its own dedicated link.

🎯 Say this in the interview — the exact lines to land

  • Single-link risk → always pair Direct Connect with a VPN backup or a second circuit.
  • Transit Gateway + Direct Connect Gateway → one hub for many on-prem sites and VPCs.
📖 Explanation ▾

A Site-to-Site VPN is an encrypted tunnel that runs over the public internet between on-prem and AWS. It's the quick option — no physical circuit to install — but bandwidth and latency are variable, since traffic still travels across the regular internet.

A Direct Connect connection is a dedicated physical network link from on-prem to AWS. Bandwidth is higher and latency is more consistent, but it takes longer to provision since a physical circuit has to be set up first. Neither one is "done" on its own for a production design — pair Direct Connect with a VPN as a backup, or use two Direct Connect circuits from different locations.

🧭 Use Cases — recognize these when they happen to you ▾
1 You need on-prem-to-AWS connectivity working today, and there's no time to wait weeks for a physical circuit.

There's no physical circuit to provision, so a Site-to-Site VPN tunnel can be stood up over the public internet right away. Bandwidth and latency then ride the regular internet path — that's the tradeoff for being fast.

RememberNeed it now → VPN, no circuit to wait on.
2 A workload needs steady, high-throughput traffic to AWS with latency that doesn't fluctuate.

That calls for Direct Connect's dedicated physical line — bandwidth is higher and latency stays consistent, because traffic isn't sharing the regular internet path with everyone else. The tradeoff is lead time: a physical circuit has to be provisioned first, so it can't happen overnight.

RememberNeed it steady → Direct Connect, but plan for lead time.
3 You've provisioned Direct Connect and you're calling the design "done."

Direct Connect is still one physical link (or set of links from one location) that can fail on its own — exactly the assumption the Common Trap above calls out. A production design pairs it with a Site-to-Site VPN as automatic failover, or runs a second Direct Connect circuit from a different location.

RememberOne physical link is never the whole design — pair it with a backup.
🌍 Real-world example ▾

A bank's core Direct Connect link to AWS has a Site-to-Site VPN configured as automatic failover, so an ISP fiber cut doesn't sever their AWS connectivity entirely — traffic just shifts onto the VPN path until the physical link is restored.
