Any vs. All vs. Contains — three different existence checks

"What's the difference between Any, All, and Contains, and what do you check with each?"

Why it matters ▾
🔍 Any
❗ ProblemYou need to know if at least one element satisfies a condition, but a hand-rolled loop with an early-exit flag is easy to get wrong.
✅ SolutionAny(predicate) stops at the first match and hands back a plain true/false.
RecallAny = does at least one fit?
⭐ All
❗ ProblemConfirming every element passes a rule usually meant a loop with a boolean flag that flips on the first failure.
✅ SolutionAll(predicate) does exactly that in one call, and still stops the moment one element fails.
RecallAll = does every one fit?
🎯 Contains
❗ ProblemChecking whether one exact value already exists by hand means looping and comparing manually — easy to get subtly wrong for a custom type.
✅ SolutionContains(value) checks for that exact value directly, using the default equality comparer or one you supply.
RecallContains = is this exact value in there?
🔥 Easy interview recall

Any → at least one matches

All → every one matches

Contains → exact value present

Think: Any asks "does one fit?" All asks "do they all fit?" Contains asks "is this one exact thing in there?"

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

An empty sequence fails an All() check. It doesn't — All() on an empty sequence returns true, because there's no element around to violate the condition. This vacuous-truth result trips up a lot of candidates.

🔄 Likely Follow-up

"What does Contains actually use to decide two things are equal?" The default EqualityComparer<T> (falls back to Equals/GetHashCode) unless you pass an explicit IEqualityComparer<T> — for a reference type with no overridden Equals, that means reference equality, not "same data."

🎯 Say this in the interview — the exact lines to land

"Any(predicate) checks whether at least one element matches, All(predicate) checks whether every element matches, and Contains(value) checks whether that exact value is present, using the default equality comparer or one you supply."

  • Any → use it for "does at least one match."
  • All → an empty sequence always returns true — vacuous truth.
  • Contains → equality, not a predicate — needs the exact value, not a condition.
📖 Explanation ▾

Any answers one question: is there at least one element that satisfies the condition? It stops checking the moment it finds a match, so it never walks further than it has to.

All flips that around — every element has to pass the condition. It still short-circuits, but on the first failure instead of the first match. On an empty sequence there's nothing left to fail the check, so it returns true.

Contains isn't a predicate check at all — it's equality. It asks "does this specific value already exist in here?", using Equals (or a supplied IEqualityComparer<T>) to decide what "equal" means.

💻 See the code ▾
C# 
var nums = new List<int> { 2, 4, 6, 7 };
bool anyBig = nums.Any(x => x > 5);   // ✅ true — stops at 6

Any stops at the first match — it never looks at the rest of the list.

C# 
bool allEven = nums.All(x => x % 2 == 0);        // ❌ false — 7 fails it
var empty = new List<int>();
bool allPass = empty.All(x => x > 100);          // ✅ true — nothing to fail

Same All call, opposite outcome on an empty sequence — nothing is around to break the rule.

C# 
bool hasSeven = nums.Contains(7);   // ✅ true — exact value lookup

Contains takes a value, not a condition — there's no lambda here at all.

🧭 Use Cases — recognize these when they happen to you ▾
1 You need a quick yes/no on whether anything in a list qualifies

Is there even one overdue order in this batch? Any(x => x.IsLate) answers that directly — no loop, no counter. This is the #1 scenario you'll actually run into.

Remember"Is there even one?" → Any.
2 You're validating a whole batch before processing it

Before saving an import, you want every row to pass validation — not most of them. rows.All(x => x.IsValid) gives you a single clean gate to check before committing anything.

Remember"Must every single one pass?" → All.
3 You're checking if a specific value is already on a list before adding it

Want to stop a duplicate tag or ID from being added twice? tags.Contains(newTag) checks for that exact value directly — no lambda needed, just the thing you're looking for.

Remember"Is this exact thing already in there?" → Contains.
🌍 Real-world example ▾

Think of a crate of apples. Any asks "is there a single rotten apple in here?" All asks "are every one of these apples ripe?" Contains asks a completely different question: "is this exact apple — the one with tag #42 — in this crate?"
