Modern JS (ES2022–2024) — four old workarounds that now fit on one line

"What recent JS features do you use — .at(), Object.groupBy, Promise.withResolvers?"

Why it matters ▾
✨ Newer built-ins
❗ ProblemInterviewers ask which newer features you actually use, and "ES6 stuff" is a thin answer — while real code still carries old workarounds like arr[arr.length - 1] and hand-written group-by reducers that now have a built-in.
✅ SolutionFour small additions — .at(), findLast, Object.groupBy, Promise.withResolvers — each named beside the workaround it replaces, plus the habit of checking engine support first, shows you keep up without being reckless.
RecallEach new method = one old workaround, shortened.
🔥 Easy interview recall

.at(-1) → the last item, no length math

findLast(fn) → search from the end

Object.groupBy(arr, fn) → bucket items by a key

Promise.withResolvers() → resolve from outside

Think: they are methods, not syntax — older browsers and Node versions simply do not have them.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

arr[-1] is not the last item. Bracket access with -1 looks for a property literally named "-1" and gives undefined — only arr.at(-1) counts from the end.

🔄 Likely Follow-up

"Can I use these in older browsers?" These are new built-in methods (all supported in current major browsers; MDN lists the newest, groupBy and withResolvers, as widely available since March 2024) — but they are methods, not new syntax, so a syntax-only transpiler does not add them; you either skip them or load a polyfill (for example core-js).

🎯 Say this in the interview — the exact lines to land

"These are small built-ins that replace old workarounds: .at(-1) for the last item, findLast to search from the end, Object.groupBy to bucket items by a key, and Promise.withResolvers() to get a promise together with its resolve and reject. They are methods, so I check engine support first."

  • .at(-1) → negative index counts from the end — works on arrays and strings.
  • findLast / findLastIndex → search from the end without reversing a copy.
  • Object.groupBy(items, fn) → an object of arrays, keyed by what fn returns; Map.groupBy returns a Map instead.
  • Promise.withResolvers() → returns { promise, resolve, reject } — settle it from anywhere.
  • Support → all in current browsers — the newest (ES2024) need a recent browser or Node.
📖 Explanation ▾

ECMAScript ships a few small additions every year, and these four each replace a workaround everyone already wrote by hand. .at(-1) reads from the end instead of arr[arr.length - 1], and findLast finds the last match without copying and reversing the array first. Both sit beside the methods in Array Methods.

Object.groupBy(items, fn) calls fn on every item and returns a plain object with no prototype whose keys are those results and whose values are arrays of matching items — the job a reduce used to do. Promise.withResolvers() returns a promise together with its resolve and reject, so you can settle it later from an event handler without leaking variables out of the new Promise executor (see Promises).

Treat these as methods, not syntax: an older engine simply will not have them. All four work in current major browsers (MDN lists .at() since March 2022 and groupBy / withResolvers since March 2024), but check your own support list if you target older ones. For the earlier ES6+ features, see Modern JavaScript / ES6+.

💻 See the code ▾
JavaScript 
const nums = [4, 8, 15, 16];
nums.at(-1);                       // 16  (old: nums[nums.length - 1])
nums.findLast(n => n % 2 === 1);   // 15  (the search starts from the end)

at(-1) and findLast read from the end — no copy, no length math.

JavaScript 
const items = [
  { name: "apple",  type: "fruit" },
  { name: "carrot", type: "veg" },
  { name: "pear",   type: "fruit" }
];
const byType = Object.groupBy(items, item => item.type);
// byType.fruit -> [apple object, pear object]
// byType.veg   -> [carrot object]

One call replaces a reduce that builds the buckets by hand.

JavaScript 
// old way: leak resolve out of the executor
let resolveOld;
const oldWay = new Promise(res => { resolveOld = res; });

// new way
const { promise, resolve, reject } = Promise.withResolvers();
promise.then(value => console.log(value));            // "clicked"
button.addEventListener("click", () => resolve("clicked"));

resolve and reject come out ready to use — no outer variable needed.

🌍 Real-world example ▾

A dashboard needed each sensor's latest reading and a count of alerts per type. .at(-1) and Object.groupBy replaced two small helper functions — but the team checked the compat tables against their own browser list first, and kept the helpers where an older engine still had to be supported.
