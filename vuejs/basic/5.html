v-if vs. v-show — gone from the DOM, or just hidden?

"What's the difference between v-if and v-show?"

Why it matters ▾
🧱 v-if
❗ ProblemA rarely-shown, heavy subtree (a big form, a chart) shouldn't exist in the DOM — or run its own mount logic — when nobody's looking at it.
✅ Solutionv-if truly adds or removes the element from the DOM, triggering real mount/unmount of that subtree each time, including its component lifecycle hooks.
Recallv-if = really there, or really gone.
👁️ v-show
❗ ProblemA tab panel or tooltip that gets toggled on and off constantly shouldn't pay a mount/unmount cost every single time.
✅ Solutionv-show always keeps the element in the DOM and just flips its CSS display — a cheap style change, not a re-render.
Recallv-show = always there, just dressed in display:none.
🔥 Easy interview recall

v-if → removes from the DOM

v-show → toggles display only

Think: v-if = unplug the device. v-show = leave it plugged in, just cover it up.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Using v-show on something that's rarely shown but expensive to initially render. It still pays the full initial render/mount cost regardless of whether it's visible, unlike v-if.

🔄 Likely Follow-up

"So which is cheaper for frequent toggling?" v-show — no repeated mount/unmount cost, just a style flip. v-if is cheaper when the condition rarely changes, since it avoids rendering a subtree that usually isn't needed at all.

🎯 Say this in the interview — the exact lines to land

"v-if truly adds or removes the element from the DOM — real mount and unmount, including lifecycle hooks, every time the condition flips. v-show always keeps the element in the DOM and just toggles display: none — a cheap style change, not a re-render."

  • v-if → use when the condition rarely changes, or the content is expensive to keep mounted.
  • v-show → use for frequent toggling of the same content.
  • v-show still pays the initial render cost, even if it starts hidden.
📖 Explanation ▾

v-if is a real conditional render. When the condition is false, the element (and everything inside it) isn't just invisible — it doesn't exist in the DOM at all, and if it wraps a component, that component actually unmounts, running its cleanup lifecycle hooks. Flipping the condition back to true mounts a fresh instance.

v-show never removes anything. The element is always in the DOM; Vue just sets its inline style="display: none" (or removes it) based on the condition. Because nothing mounts or unmounts, there's no lifecycle cost on every toggle — only the first render pays that cost.

💻 See the code ▾
Vue 
<HeavyChart v-if="tab === 'stats'" />  // ✅ never mounted unless you're on this tab

Rarely-shown, expensive content → v-if avoids paying its mount cost at all.

Vue 
<p v-show="showTooltip">Hover tip</p>  // ✅ flips display:none, no remount on every hover

Frequently toggled content → v-show avoids the repeated mount/unmount cost.

🧭 Use Cases — recognize these when they happen to you ▾
1 A whole settings panel that's only visible to admins

A regular user's session never changes to admin mid-visit, so there's no reason to keep that panel mounted at all. v-if is the right call.

RememberRole-gated content → v-if, condition almost never flips.
2 A tab switcher the user clicks back and forth repeatedly

Switching tabs back and forth many times a session makes v-show the cheaper choice — no repeated mount/unmount, just toggling display.

RememberToggled often → v-show avoids the remount cost.
3 A heavy chart hidden behind v-show "to make it load faster"

Hiding a heavy chart with v-show doesn't skip rendering it — it still mounts and renders fully, just invisibly. If it's rarely needed, v-if is the one that actually avoids the cost.

Rememberv-show="false" ≠ "not rendered" — it still paid full mount cost.
🌍 Real-world example ▾

v-if is unplugging an appliance and putting it back in storage; v-show is leaving it plugged in and just closing a cabinet door over it. One has real setup/teardown cost each time; the other is instant, because the appliance never actually left.
