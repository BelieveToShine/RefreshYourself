Self-attention lets every token look at every other one — expensive by design, saved by the KV cache

"At a high level, what is self-attention, why does it get expensive as context grows, and what problem does the KV cache actually solve?"

Why it matters ▾
🧠 Self-attention
❗ ProblemA model that could only look at nearby tokens would miss meaning that lives far earlier in a passage — like knowing "It" refers back to "cat" several tokens earlier — so context tied to distant tokens would just get lost.
✅ SolutionSelf-attention builds each token's new representation from a weighted mix of every other token in the sequence, pulling context from wherever it actually lives, near or far — the same all-pairs comparison that's also why the cost grows quadratically with sequence length.
RecallSelf-attention = every token mixes in every other token — distance doesn't limit it, but comparing every pair is why it gets expensive.
🔥 Easy interview recall

Self-attention → each token's new view mixes in every other token

Cost → grows quadratically with sequence length

KV cache → reuse past keys/values, don't recompute them

Think: Self-attention is everyone in the room talking to everyone. KV cache is remembering what was already said instead of replaying the whole conversation every time someone speaks.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

"A bigger context window is just a config change." It's not — attention cost grows quadratically with sequence length, so a longer context window is a real compute and cost problem, not a switch to flip.

🔄 Likely Follow-up

"So does the KV cache remove the quadratic cost too?" No — it only avoids recomputing the keys/values for tokens already seen. The new token still has to attend to everything cached before it, so per-step cost still grows with how much context exists; the cache saves recomputation, not the size of the context itself.

🎯 Say this in the interview — the exact lines to land

"Self-attention builds each token's new representation from a weighted mix of every other token, which is what gives a model long-range context — but that all-pairs computation is quadratic in sequence length. The KV cache avoids recomputing the keys and values for every earlier token on each new step, which is what makes generating text one token at a time actually fast."

  • Self-attention → every token can pull context from every other token, near or far.
  • Cost → grows quadratically with sequence length — why longer context windows are expensive, not just "allowed."
  • KV cache → reuses previously computed keys/values instead of recomputing the whole prefix each new token.
  • Without it, generating token N would redo attention over all N-1 prior tokens from scratch every single step.
📖 Explanation ▾

Self-attention gives each token in a sequence a new representation built by mixing in every other token, weighted by how relevant they are to each other. That's the mechanism that lets a model connect a word late in a paragraph back to a word much earlier — nothing about position alone limits which tokens can "talk" to each other.

The catch: because every token compares itself against every other token, the raw amount of attention work grows quadratically as the sequence gets longer — roughly double the tokens, roughly quadruple the attention work. That's a big part of why stretching a model's context window is a real engineering and cost problem, not just a setting someone could flip.

During generation, the model produces one token at a time, and each new token's attention step needs the keys and values computed for every token that came before it. Those earlier keys/values never change, so recomputing them from scratch on every single step would be wasted work — implementations cache them once and reuse them, doing new work only for the token that was just generated. That's the KV cache, and it's why autoregressive generation is fast enough to feel real-time.

💻 See the code ▾
Python (conceptual) 
cache = None
for step in range(max_new_tokens):
    logits, cache = model(next_token, past_key_values=cache)  # ✅ reuse, don't recompute
    next_token = sample(logits)

This is the same shape real libraries use (e.g. Hugging Face's past_key_values) — pass the cache back in, get a bigger one out, never redo the whole prefix.

🧭 Use Cases — recognize these when they happen to you ▾
1 A long conversation and the model still correctly resolves a reference from way earlier

Self-attention doesn't care about position — every token can pull context from any other token in the sequence, however far back it sits, which is exactly why a model can connect a reference many turns earlier without any special handling for distance. This is the #1 scenario you'll actually notice.

RememberSelf-attention → distance doesn't limit which tokens can talk.
2 A long reply streams out token-by-token and each token still appears almost instantly

Each new step reuses the keys/values already computed for every earlier token instead of recomputing the whole prefix again — only the newest token's work is done fresh. That's the KV cache, and it's what makes token-by-token generation feel like a live conversation instead of a slow batch job.

RememberFeels fast → KV cache reuse, not free growth.
3 Someone asks to just bump the context window as a quick config change

Attention cost grows quadratically with sequence length, so widening the context window is a real compute and cost increase, not a switch to flip — and the KV cache doesn't fix this either, since a new token still has to attend to everything already cached before it. A classic interview trap — candidates often treat "increase the context window" as free.

RememberBigger context window → quadratic cost, not a free toggle.
🌍 Real-world example ▾

A waiter who already wrote down everyone's earlier order doesn't re-ask the whole table from scratch for a dessert add-on — they just add one new line to the same ticket. That's the KV cache. It doesn't shrink the ticket, though: a long conversation history still means more prior tokens for every new one to attend to, which is why a chat session with a huge amount of history in context can start to feel slower or pricier the longer it runs.
