{{ }} interpolation — a live wire between data and the DOM

"How does {{ }} interpolation work in a Vue template?"

Why it matters ▾
🔗 {{ }} interpolation
❗ ProblemManually writing el.textContent = value every time a piece of data changes doesn't scale past a few elements, and it's easy to forget one.
✅ Solution{{ expression }} inserts a reactive value directly into the template — Vue tracks the dependency and re-renders that text automatically whenever it changes.
Recall{{ }} = reactive text, no manual DOM updates.
🔥 Easy interview recall

{{ }} = "insert a reactive JS expression's text, auto-updates when it changes."

Think: {{ }} takes an expression, never a statement — no if, no for inside it.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Putting a statement like an if or a for loop inside {{ }}. Only expressions are allowed in there — control flow needs the v-if/v-for directives instead.

🔄 Likely Follow-up

"Is {{ }} safe from XSS?" Yes — it's always rendered as escaped plain text, never parsed as HTML. Only v-html bypasses that escaping, and it carries a real injection risk if the content isn't trusted.

🎯 Say this in the interview — the exact lines to land

"{{ expression }} inserts a reactive value's text content into the DOM. It has to be a JavaScript expression, not a statement, and it's evaluated against the component's reactive state — Vue automatically re-renders it whenever a dependency it reads from changes."

  • Must be an expression, never a statement like if or for.
  • Output is always escaped text — safe from XSS by default.
  • v-html → the one directive that bypasses that escaping, use with care.
📖 Explanation ▾

Anything between {{ }} is evaluated as a JavaScript expression against the component's reactive data — a plain variable, a small calculation, a method call that returns a value. Vue converts the result to a string and inserts it as the element's text content.

Because Vue's reactivity system tracks exactly which reactive values an expression read the last time it ran, it knows precisely when to re-evaluate it — change name, and only the text nodes that actually depend on name update, not the whole page.

The output is always treated as plain text, not markup — a string containing <b> renders literally as the characters <b>, not a bold tag. That's what keeps interpolation safe by default; rendering real HTML requires the separate, explicitly-named v-html directive.

💻 See the code ▾
Vue 
<script setup>
  import { ref } from 'vue';
  const name = ref('Vue');
</script>

<template>
  <h1>{{ name }}</h1>             // ✅ expression — just a variable
  <p>{{ name.toUpperCase() }}</p>  // ✅ expression — a method call
</template>

Both are valid — a plain reference and a small expression are both just expressions.

Vue 
<p>{{ if (loggedIn) { 'Hi' } }}</p>  // ❌ statement — won't compile

Control flow belongs in v-if/v-for, not inside {{ }}.

🧭 Use Cases — recognize these when they happen to you ▾
1 You need to show a plain piece of reactive state

The most common case — drop the variable straight in. This is the #1 scenario you'll actually use interpolation for.

RememberPlain value → just reference it directly inside {{ }}.
2 You need a small formatted or computed display value

A short inline calculation is fine. If the expression starts getting longer than this, it's a signal to move it into a computed property instead (covered a few pages ahead).

RememberShort calc → inline. Anything longer → a computed property.
3 You try to render trusted HTML markup through {{ }}

The browser shows the literal characters <b>Hi</b>, not bold text — {{ }} never parses its output as markup. Real HTML needs v-html, only for content you fully trust.

Remember{{ }} always escapes — it can't render real markup.
🌍 Real-world example ▾

It's like a live scoreboard wired straight to the game's score counter. Nobody walks up and repaints the number by hand — the display is just always showing whatever the counter currently holds.
