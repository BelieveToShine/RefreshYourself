Next.js — built on top of React, never instead of it

"What is Next.js, and what does it add on top of plain React?"

Why it matters ▾
⏭️ Next.js
❗ ProblemPlain React is only a UI library — it has no built-in routing, no server rendering, and no project conventions, so every team ends up hand-wiring its own router, build setup, and optimization story from scratch.
✅ SolutionNext.js is a React framework that adds file-based routing, rendering strategies (SSR/SSG/ISR), and built-in optimizations (images, fonts) on top of plain React — create-next-app scaffolds all of it with sensible defaults in one command.
RecallNext.js = React, plus the routing/rendering/optimization layer around it.
🔥 Easy interview recall

Next.js = "React, plus everything around it — routing, rendering, optimization."

Think: create-react-app gives you React alone. create-next-app gives you React, plus the application layer around it.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Next.js is not a replacement for React. It's a framework built on top of React — every Next.js component is still a plain React component; Next just adds the surrounding application layer.

🔄 Likely Follow-up

"What problems specifically does it solve that plain React — say, via Create React App — doesn't?" File-based routing instead of manual router setup, built-in SSR/SSG where CRA is client-rendered only by default, automatic per-route code-splitting, and image/font optimization out of the box.

🎯 Say this in the interview — the exact lines to land

"Next.js is a React framework — every component is still React, but Next adds file-based routing, built-in SSR/SSG/ISR, and automatic image and font optimization on top of it. create-next-app scaffolds a new project with those defaults already wired up."

  • Plain React → UI library only, no built-in routing or server rendering.
  • Next.js → React plus the routing/rendering/optimization layer.
  • create-next-app → scaffolds the App Router, TypeScript option, ESLint in one command.
📖 Explanation ▾

Plain React gives you components, state, and rendering to the DOM — and stops there. Routing, data fetching conventions, and how the app actually gets built and served are all left for you to assemble yourself.

Next.js is a framework that makes those choices for you: a file-based router, a choice of rendering strategies per route, and automatic image/font optimization, all on top of ordinary React components. Nothing about how a component itself works changes.

Plain React (e.g. via CRA)Next.js
RoutingNone built in — add a library✅ file-based, built in
Server rendering❌ client-rendered only✅ SSR / SSG / ISR
Image/font optimization❌ not included✅ built in
Scaffolding toolcreate-react-appcreate-next-app
💻 See the code ▾
JavaScript 
// app/page.js — still an ordinary React component
export default function HomePage() {
  return <h1>Hello from Next.js</h1>;   // ✅ plain JSX, nothing new
}

The component itself didn't change — Next.js adds the app/ folder, the routing, and the rendering around it.

🧭 Use Cases — recognize these when they happen to you ▾
1 You're starting a brand-new app and deciding between Create React App and Next.js

If the app will need routing, server rendering, or image optimization eventually, Next.js saves you from bolting all of that onto a plain React setup later. This is the #1 scenario you'll actually run into.

RememberNeed routing/SSR eventually → start with Next.js, not plain React.
2 You need server-rendered pages without hand-rolling a Node server

Plain React needs a hand-wired Node/Express server (or a separate framework) to render on the server at all. Next.js ships SSR as a rendering strategy you just opt into per route.

RememberSSR without a hand-rolled server → that's what Next.js's rendering layer is for.
3 You assume adopting Next.js means rewriting your React components

Your existing React knowledge (JSX, hooks, props) carries over directly — Next.js doesn't introduce a new component model. What's new is the folder conventions and rendering options wrapped around those same components.

RememberAdopting Next.js ≠ rewriting components — only the surrounding layer is new.
🌍 Real-world example ▾

A car's engine vs. the whole car. React is the engine — it makes the thing move. Next.js is the car built around that engine: the chassis, the dashboard, the features you'd otherwise have to bolt on yourself. Swap in a different engine and it's still a car; the engine itself hasn't changed by being inside one.
