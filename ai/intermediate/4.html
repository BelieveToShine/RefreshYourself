🔥 AI · Intermediate · Must Know

Retrieval gets you close. Reranking gets you right.

"What is reranking, and why do you need it after retrieval already ran?"

Why it matters ▾
🔍 Retrieval (bi-encoder)
❗ ProblemA query has to be compared against millions of chunks, and a precise query-and-doc-together comparison is too slow to run at that scale.
✅ SolutionA bi-encoder embeds the query and every chunk separately, so ranking is just a quick distance check — cheap enough for the whole corpus, but only approximate.
RecallRetrieval/bi-encoder = fast, approximate, runs over the whole corpus.
🎯 Reranker (cross-encoder)
❗ ProblemThe bi-encoder's approximate ranking can put a topically-close-but-wrong chunk on top — #1 by similarity isn't always #1 by real relevance.
✅ SolutionA cross-encoder scores the query and each shortlisted chunk together, precise enough to flip the order — affordable only because it never runs past the small shortlist retrieval already produced.
RecallReranker/cross-encoder = slow, precise, shortlist only.
🔥 Easy interview recall

Reranking = "re-score the shortlist with a smarter, slower model so the truly best ones float to the top."

Think: Retrieval → fast net, catches anything close Reranker → slow, careful judge, only looks at what the net already caught

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Reranking doesn't replace retrieval. A cross-encoder is too slow and expensive to run against millions of chunks directly — it only works because retrieval already narrowed the field down to a small shortlist first.

🔄 Likely Follow-up

"Why not just use the cross-encoder for the whole search?" It scores the query and one document together, so it can't be pre-computed or indexed like separate embeddings — checking it against millions of chunks per query would be far too slow. Retrieval's job is to make the reranker's precision affordable.

🎯 Say this in the interview — the exact lines to land

"Retrieval uses a fast, approximate similarity check to narrow millions of chunks down to a small shortlist. A reranker — usually a cross-encoder — then looks at the query and each shortlisted chunk together and re-scores them far more precisely, so the truly best few end up on top before they reach the LLM."

  • Bi-encoder → embeds query and docs separately — fast, but only approximate.
  • Cross-encoder → scores query and doc together — precise, but too slow for the whole corpus.
  • Two-stage pattern → fast narrow, then slow-and-precise on the shortlist only — you can't afford one model doing both jobs.
  • Payoff → a cleaner top-k order means less irrelevant content competing for the LLM's attention.
📖 Explanation ▾

Vector or hybrid search is fast because it's cheap: the query and every document are embedded on their own, independently, so comparing them is just a quick distance check. That speed is exactly why it's only approximate — the model never actually looks at the query and a document side by side, so the ranking it produces is a reasonable guess, not a precise judgment.

A reranker fixes that on a small scale. It's commonly a cross-encoder — a model that takes the query and one candidate document together as a single input, so it can weigh how they actually relate to each other, not just how close their separate embeddings happen to land. That's far more accurate, but it's also far more expensive per comparison, which is exactly why it only ever runs against the small shortlist retrieval already produced — never the full corpus.

Retrieval (bi-encoder)Reranker (cross-encoder)
How it scoresquery and doc embedded separatelyquery and doc scored together
Speedfastslow, per pair
Runs overthe whole corpusonly the shortlist
Accuracyapproximatemuch more precise

The result is a top-k list that's meaningfully more relevant than what retrieval alone produced — which matters directly for RAG, since fewer irrelevant chunks competing for the model's attention means a better final answer.

💻 See the code ▾
Pseudocode 
# Stage 1 — retrieval: fast, approximate
query_vec = embed(query)                  # ✅ query embedded on its own
top20 = vector_search(query_vec, k=20)   # nearest chunks by cheap similarity

Fast enough to run over the whole corpus — but only an approximation of true relevance.

Pseudocode 
# Stage 2 — rerank: slow, precise, shortlist only
scored = [(doc, reranker(query, doc)) for doc in top20]  # ✅ query + doc scored TOGETHER
top3 = sorted(scored, reverse=True)[:3]

Only ever runs on the 20 shortlisted candidates — never the full corpus.

🧭 Use Cases — recognize these when they happen to you ▾
1 An interviewer asks why retrieval alone isn't the final answer

This checks whether you know the two-stage split is deliberate, not accidental: retrieval's fast, approximate similarity check narrows millions of chunks down to a small shortlist, then the reranker re-scores just that shortlist far more precisely. One model can't affordably do both jobs at once.

RememberTwo stages exist because one model can't be both fast and precise.
2 Your top-ranked chunk by similarity isn't the one that actually answers the query

This is exactly what the reranker step catches — retrieval's similarity score can rank a topically-close-but-wrong chunk above the one that actually answers the query, because the bi-encoder never looked at the query and the chunk together. The cross-encoder does, and can flip that order before the LLM ever sees the list.

RememberWrong chunk on top by similarity → let the reranker fix the order.
3 You consider running the cross-encoder over the whole corpus instead of a two-stage pipeline

A cross-encoder scores the query and one document together, so it can't be pre-computed or indexed like separate embeddings — checking it against millions of chunks per query would be far too slow. A common trap — candidates sometimes suggest skipping retrieval and relying on the reranker alone, missing why the shortlist step exists in the first place.

RememberCross-encoder never runs on the full corpus — only the shortlist.
🌍 Real-world example ▾

Retrieval is a librarian quickly grabbing 20 books off the shelf whose titles seem related to your question. Reranking is actually reading the opening paragraph of each of those 20 books to see which ones truly answer the question, then handing you just the best 3.
