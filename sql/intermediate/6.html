ROW_NUMBER() vs. RANK() vs. DENSE_RANK() — what happens on a tie

"What's the difference between ROW_NUMBER(), RANK(), and DENSE_RANK() when there are ties?"

Why it matters ▾
🔢 ROW_NUMBER()
❗ ProblemLeaderboards need one unique number per row, even when scores tie.
✅ SolutionHands out unique sequential numbers; a tie is broken arbitrarily.
RecallAlways unique — a tie is split arbitrarily, not meaningfully.
🥈 RANK()
❗ ProblemGiving tied rows different numbers hides that they actually tied.
✅ SolutionGives tied rows the same rank, then skips the next number.
RecallTies share a rank, then a gap follows.
🎯 DENSE_RANK()
❗ ProblemA skipped number after a tie breaks a clean placement list.
✅ SolutionGives tied rows the same rank, then keeps counting — no gap.
RecallTies share a rank, next value never skips.
🔥 Easy interview recall

ROW_NUMBER() → always unique, ties broken arbitrarily

RANK() → ties share a rank, leaves a gap after

DENSE_RANK() → ties share a rank, no gap after

Think: they only diverge exactly at a tie.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

"RANK() and DENSE_RANK() are just two names for the same thing." They diverge exactly at a tie — RANK() leaves a gap (skips a number) right after a tie, DENSE_RANK() doesn't; on data with no ties they'd look identical, which is exactly why people miss the real difference until they hit tied data.

🔄 Likely Follow-up

"Which one would you use to show '1st, 2nd, 3rd place' with no skipped ranks even when there are ties?" DENSE_RANK() — it never leaves a gap, so the visible rank sequence stays consecutive even across ties.

🎯 Say this in the interview — the exact lines to land

"All three number rows using OVER() with an ORDER BY, but they treat ties differently. ROW_NUMBER() always gives unique, sequential numbers — a tie gets split arbitrarily. RANK() gives tied rows the same number, then skips ahead, leaving a gap. DENSE_RANK() also gives tied rows the same number, but keeps counting consecutively right after — no gap."

  • ROW_NUMBER() → always unique; a tie is broken arbitrarily, not meaningfully.
  • RANK() → ties share a rank, then the next value skips a number.
  • DENSE_RANK() → ties share a rank, next value stays consecutive — no gap.
  • No ties in the data → all three look identical, which is exactly what hides the real difference.
📖 Explanation ▾

All three are window functions that number rows using OVER (ORDER BY ...) — same syntax shape, different rule for handling ties. On data with no ties at all, they produce identical output, which is exactly why the real difference goes unnoticed until tied values show up.

ROW_NUMBER() always hands out unique, sequential integers; when two rows tie on the ORDER BY expression, which one gets the smaller number is arbitrary — whichever order the tie happens to land in. RANK() gives every tied row the same rank, then the next distinct value jumps to the number it would have reached if the tie had never happened — skipping the numbers in between. DENSE_RANK() also gives tied rows the same rank, but the next distinct value simply gets the very next integer — nothing is ever skipped.

💻 See the code ▾
SQL 
SELECT Name, Score,
       ROW_NUMBER() OVER (ORDER BY Score DESC) AS RN,
       RANK()       OVER (ORDER BY Score DESC) AS Rnk,
       DENSE_RANK() OVER (ORDER BY Score DESC) AS DRnk
FROM Scores;

-- Name    Score  RN  Rnk  DRnk
-- Alice    95     1    1    1
-- Bob      90     2    2    2   -- tied with Carol
-- Carol    90     3    2    2   -- tied with Bob
-- Dave     80     4    4    3   -- RN keeps counting, Rnk skips 3, DRnk doesn't

Same tie, three different outcomes: RN keeps counting straight through, Rnk skips a number right after the tie, DRnk doesn't.

🧭 Use Cases — recognize these when they happen to you ▾
1 You need exactly one row per duplicate key — dedup or "latest per group"

ROW_NUMBER() numbers every row uniquely, tie or not, so filtering to RN = 1 keeps exactly one row per group — which row "wins" the tie doesn't matter here, only that every row gets a distinct number.

RememberNeed one unique row per group → filter ROW_NUMBER() = 1.
2 Showing standings where a tie should still skip the next placement

RANK() gives Bob and Carol's tie the same number, then the next distinct score jumps ahead — the same rule as two runners tying for 2nd and the next real runner becoming 4th, with "3rd" never handed out.

RememberTie shares a rank, next value skips a number.
3 Showing "1st, 2nd, 3rd" with no placement ever skipped, even on a tie

DENSE_RANK() also gives tied rows the same rank, but the next distinct score gets the very next integer — the visible sequence of places stays consecutive no matter how many rows tied before it.

RememberTie shares a rank, next value never skips.
🌍 Real-world example ▾

Two runners tie for 2nd place in a race. ROW_NUMBER() arbitrarily calls one of them 2nd and the other 3rd — as if the tie never happened. RANK() calls them both 2nd, and the next real runner is 4th — "3rd" is never handed out. DENSE_RANK() also calls them both 2nd, but the next runner is 3rd — no place gets skipped.
