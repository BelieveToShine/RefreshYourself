Why one slows a loop and the other doesn't

"What is the difference between string and StringBuilder, and when would you use each?"

Why it matters ▾
🔤 string
❗ Problemstring is immutable, so a line like s += x doesn't edit it — it throws the old string away and allocates a brand-new one, every single time.
✅ SolutionFor a handful of concatenations that's a non-issue — string stays the simpler, better choice whenever a loop isn't the one doing the concatenating.
Recallstring += → new allocation every time; fine outside a loop.
🧱 StringBuilder
❗ ProblemPut that same allocate-and-discard pattern inside a loop of a thousand iterations, and you've paid for a thousand new strings while throwing 999 of them straight in the garbage.
✅ SolutionStringBuilder keeps one resizable buffer and writes into it directly — .Append() extends that same buffer instead of replacing it, so the loop does far less allocation work overall.
RecallStringBuilder = one buffer, grows in place — built for loops and long chains.
🔥 Easy interview recall

string → immutable, every change is new

StringBuilder → one buffer, grows in place

Think: a loop of += vs. a loop of .Append()

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

String interpolation isn't magic. $"Hello {name}" still builds a brand-new string every time it runs — it's a nicer way to write the formatting, not a way to avoid allocating.

🔄 Likely Follow-up

"Is there a fixed number of concatenations after which StringBuilder wins?" No fixed threshold — use plain string (or interpolation) for a few known pieces, and StringBuilder when appending inside a loop or an unknown number of times.

🎯 Say this in the interview — the exact lines to land

"string is immutable, so every change allocates a new string. StringBuilder keeps one resizable buffer and writes into it directly — that's the whole reason it's faster in a loop."

  • Few concatenations → plain stringLoop / many appends → StringBuilder
  • string is immutable — every change creates a new object.
  • Call .ToString() once at the end to get the final string from a StringBuilder.
  • Interpolation and + are fine for a few known pieces.
📖 Explanation ▾

string is immutable — once created, it never changes. So every += doesn't edit the string, it builds an entirely new one and throws the old one away. Do that once, no problem. Do it a thousand times in a loop, and you've created a thousand throwaway strings.

StringBuilder keeps one resizable buffer and writes into it directly — .Append() extends the same buffer instead of replacing it, so a loop of a thousand appends does far less allocation work overall.

For a handful of concatenations, plain string is simpler and perfectly fine — StringBuilder earns its keep specifically inside loops or long chains.

💻 See the code ▾
C# 
string s = "";
for (int i = 0; i < 1000; i++)
    s += i;   // 1000 new strings created, 999 thrown away

Each += is a brand-new allocation — the loop body pays that cost 1000 times.

C# 
var sb = new StringBuilder();
for (int i = 0; i < 1000; i++)
    sb.Append(i);   // ✅ one growing buffer, no throwaway strings
string result = sb.ToString();

Same 1000 iterations, one allocation instead of a thousand.

🧭 Use Cases — recognize these when they happen to you ▾
1 You're joining a couple of values into one message, just once

A one-off concatenation is exactly what string is for — a few += calls never add up to a real cost, so there's no reason to reach for StringBuilder here.

RememberNo loop, just a few pieces → plain string, keep it simple.
2 You're appending pieces onto a string inside a loop that runs many times

This is the #1 scenario you'll actually run into. A loop means every += allocates and discards a new string on each pass, so swapping in StringBuilder.Append() keeps one buffer and skips almost all of that allocation work.

RememberLoop + many appends → StringBuilder, every time.
3 You reach for string interpolation inside that same loop, assuming it's the fast option

String interpolation isn't magic — $"Hello {name}" still builds a brand-new string every time it runs, so it doesn't avoid the per-iteration allocation that += has inside a loop.

Remember$"..." in a loop = still a new string per pass, so swap in StringBuilder.
🌍 Real-world example ▾

Rewriting a letter vs. a whiteboard. string concatenation is like rewriting the entire letter by hand every time you want to add one more sentence. StringBuilder is a whiteboard — you just keep writing more on the same surface.
