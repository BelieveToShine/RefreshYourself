Margin collapsing — why 20px + 30px leaves 30px, not 50

"Two stacked boxes have 20px and 30px margins — how far apart are they, and why?"

Why it matters ▾
📏 Margin collapsing
❗ ProblemYou add 20px and 30px and expect 50px of space, but the page shows 30px — and a child's margin can even push its parent down instead of pushing the child away from the parent's edge.
✅ SolutionVertical margins that touch don't add up — the browser keeps the larger one. Anything that stops them touching (padding, a border, a new block formatting context, flex or grid) stops the collapse.
RecallTouching vertical margins → the bigger one wins, not the sum.
🔥 Easy interview recall

Margin collapsing = "touching vertical margins merge into one — the bigger wins."

Think: siblings: 20 + 30 → 30 parent + first child, nothing between → the child's margin leaks out padding / border / flow-root / flex / grid → no collapse

🧠 Visual Mental Model — understand it in 5 seconds
🧠 The parent and child case — where it surprises people
⚠️ Common Trap

Margins don't add up. Touching vertical margins merge into the larger one — and a child's top margin with nothing between it and its parent leaks out and moves the parent. Horizontal margins never collapse.

🔄 Likely Follow-up

"My child's margin-top moves the whole parent instead of sitting inside it — why, and how do you stop it?" The parent's top edge touches the child's top margin (no padding, border or content between), so the two merge. Give the parent padding or a border, or set display: flow-root on it.

🎯 Say this in the interview — the exact lines to land

"Adjacent vertical margins collapse — instead of adding, the browser uses the larger one, so 20px and 30px leave 30px. It also happens between a parent and its first or last child, and for an empty block. Padding, a border, a new block formatting context such as display: flow-root, or flex and grid layout all stop it."

  • Siblings → the larger margin wins, not the sum.
  • Parent and first/last child collapse when nothing separates them.
  • Only vertical margins in normal block flow collapse — horizontal never do.
  • Stopped by padding, a border, or flow-root (a new block formatting context).
  • Flex and grid items don't collapse with each other.
📖 Explanation ▾

Margin collapsing is a rule applied in the layout step of the render pipeline (see Browser Rendering): while the browser works out where every box goes, it merges vertical margins that touch. Two siblings with 20px and 30px leave 30px; equal margins leave just one of them. A parent and its first child also collapse if no border, padding or content sits between their top edges — the same goes for the last child's bottom margin when the parent's height is auto. An empty block (no height, padding, border or content) even collapses its own top and bottom margins together.

It does not happen for horizontal margins, for flex or grid items (see Flexbox and CSS Grid), for floated or absolutely positioned boxes, or when the parent creates a new block formatting context — display: flow-root, or overflow set to anything but visible.

Easy habit: use margin in one direction only (say margin-bottom), or space items with gap in flex/grid, so you never depend on collapsing. For how margin fits into the box itself, see the Box Model.

💻 See the code ▾
CSS 
.a { margin-bottom: 20px; }
.b { margin-top: 30px; }   /* gap between a and b = 30px, not 50px */

Two touching vertical margins collapse to the larger one.

CSS 
.parent { }                         /* no padding, no border */
.child  { margin-top: 30px; }       /* leaks out — parent moves down 30px */
.parent { display: flow-root; }      /* ✅ margin stays inside the parent */

flow-root makes the parent its own block formatting context, so its child's margin can't escape.

🌍 Real-world example ▾

Two people each want personal space — one wants 20cm, the other 30cm. Stood side by side they need 30cm between them, not 50, because the two spaces overlap instead of stacking.
