CSS Inheritance — why some styles travel down the tree and others stop cold

"Which CSS properties inherit from a parent element by default, and how do inherit, initial, unset, and revert let you override that?"

Why it matters ▾
🔗 inherit
❗ ProblemSometimes you want a property to copy the parent's current value on purpose — even a box-model property like border that never inherits by default — and the only alternative is retyping the exact same value on every child by hand.
✅ Solutioninherit forces the parent's value down for that one property, whether or not it's naturally one of the inheriting ones.
Recallinherit = copy the parent's value on purpose, even for a property that normally wouldn't.
🧹 initial
❗ ProblemA property's value might really be coming from an inherited ancestor, and there's no plain way to just wipe it back to CSS's own blank-slate starting point.
✅ Solutioninitial resets the property to whatever the CSS spec itself defines as that property's default value, ignoring the parent entirely.
Recallinitial = the spec's own factory default, not the parent's value.
🎚️ unset
❗ ProblemChoosing between inherit and initial for an unfamiliar property first means remembering whether that specific property naturally inherits or not.
✅ Solutionunset makes that choice automatically — inherit on a property that naturally inherits, initial on one that doesn't.
Recallunset = let CSS pick inherit-or-initial for you, based on the property's own default.
🔙 revert
❗ Probleminitial resets a property past the browser's own built-in styling too, which can leave an element looking completely unstyled instead of just back to normal.
✅ Solutionrevert restores whatever the browser's own built-in stylesheet gives that property; revert-layer only rolls back to the previous cascade layer instead.
Recallrevert = back to the browser's own default, not an unstyled blank slate.
🔥 Easy interview recall

Inheritance = "a child element automatically takes an ancestor's value for a property it never set itself."

Think: color, font-family, font-size, line-height, text-align → inherit margin, padding, border, width, background, display → don't inherit

🧠 Visual Mental Model — understand it in 5 seconds
🧠 Don't mix these four — same link, four different outcomes for one property
⚠️ Common Trap

Not every property inherits by default. Typography properties like color and font-family do, but box-model properties like margin, border, and width never inherit on their own — a child always starts from its own default for those, no matter what the parent set.

🔄 Likely Follow-up

"What's the real difference between inherit, initial, unset, and revert?" inherit forces a property to take its parent's value even if it wouldn't normally inherit; initial resets it to the CSS spec's own default; unset picks whichever of those two is natural for that property; revert goes one step further and resets to what the browser's built-in stylesheet would give it.

🎯 Say this in the interview — the exact lines to land

"Typography properties — color, font-family, font-size, line-height, text-align — inherit from a parent by default; box-model properties like margin, padding, border, width, and background don't. inherit, initial, unset, and revert let me override that behavior on purpose instead of guessing why a style showed up somewhere I never set it."

  • Typography inherits — color, font-family, font-size, line-height, text-align, visibility pass down automatically.
  • Box model doesn't — margin, padding, border, width, height, background, display stay exactly where they're set.
  • inherit → forces it even on a property that wouldn't inherit on its own.
  • initial → the spec's own default, ignoring both the parent and the browser's styling.
  • unset → acts like inherit where a property naturally inherits, initial where it doesn't.
  • revert / revert-layer → rolls back to the browser's own styling, or just the previous cascade layer.
📖 Explanation ▾

Inheritance is one specific stage in the CSS cascade pipeline — Styles → Cascade → Specificity → Inheritance → Computed value (see the cascade page for the full pipeline) — it isn't just another name for "the cascade" itself. By default, typography-related properties like color, font-family, font-size, line-height, and text-align pass down from a parent to every descendant that doesn't set its own value for them. Box-model and layout properties — margin, padding, border, width, height, background, and display — don't: each element starts from its own default (usually 0, auto, or none) unless it's told otherwise.

CSS also gives four keywords for overriding that default behavior on purpose:

inheritinitialunsetrevert / revert-layer
What it doesForces the parent's value, even on a property that wouldn't inherit on its ownResets to the value the CSS spec itself defines as the property's starting pointBehaves like inherit if the property naturally inherits, otherwise like initialResets to what the browser's own built-in stylesheet gives it — revert-layer only rolls back to the previous cascade layer, not all the way to the browser

Most "why is this styled weirdly" interview questions trace back here — a stray color or text-align on a wrapper element quietly reaching a component several levels down is inheritance doing exactly what it's supposed to, not a bug in the component itself.

💻 See the code ▾
CSS 
body { color: navy; }
p { }                 /* nothing set here… */
                       /* …p still renders navy — color inherits */

No color rule on p at all — it's still navy because color inherits by default.

CSS 
body { border: 2px solid red; }
p { }                 /* border never inherits… */
                       /* …p has NO border at all */

border is a box-model property — every element starts with border: none unless it sets its own.

CSS 
.card { border: 2px solid #3b82f6; }
.card * { border: inherit; } /* forces it anyway */

inherit overrides the default on purpose — now every child inside .card copies its border.

🧭 Use Cases — recognize these when they happen to you ▾
1 A component's text color, font, or alignment matches its ancestor — and you never wrote a rule for it on the component itself

This is the #1 case you'll actually run into — a typography property like color, font-family, or text-align quietly arrived from somewhere up the tree. It's not a bug in that component; inheritance is doing exactly what it's supposed to.

RememberText style with no matching rule nearby → check an ancestor before assuming a bug.
2 You set a border, margin, or width on a wrapper expecting every child inside to pick it up too — but every child renders with none at all

Box-model properties never inherit by default — every element starts from its own zero/none/auto regardless of what a parent declared. Only typography-related properties inherit automatically; border, margin, padding, width, and background don't.

RememberNo border/margin/width on a child → box-model properties don't inherit, check the child's own rules.
3 You want every element inside one component to deliberately copy a property that wouldn't normally inherit, like matching a border throughout a card

inherit forces that one property to copy the parent's value on purpose, even though border wouldn't inherit on its own — this is a deliberate override, not accidental inheritance.

RememberWant a normally-non-inheriting property to copy the parent anyway → set it to inherit explicitly.
🌍 Real-world example ▾

Think of it like a family surname versus a piece of jewelry. A last name (color, font-family) passes down to every child automatically, without anyone asking for it. A specific piece of jewelry one parent owns (border, margin) belongs to that person alone — it doesn't show up on their kids just because a parent has one.
