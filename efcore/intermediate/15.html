OwnsOne and HasConversion — map a C# shape the database does not have

"How do you map a value object or store an enum as a string?"

Why it matters ▾
🧩 Owned Types & Value Converters
❗ ProblemYour C# model has value objects (an Address, a Money) and enums, but a table only has plain columns. Without help, they become extra tables or unreadable numbers.
✅ SolutionOwnsOne folds a value object into the owner's table, and HasConversion translates a C# type to the type stored in the database and back.
RecallOwnsOne = value object as columns in the owner's table; HasConversion = convert on write, convert back on read.
🔥 Easy interview recall

Owned type = "columns that belong to the owner." Converter = "translate on the way in and out."

Think: OwnsOne → value object stored in the owner's table HasConversion → enum as string, typed id as its raw value Mutable converted value → needs a ValueComparer

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

"A converter on any property just works." For a mutable value such as a List<string> saved as text, change tracking compares references — an in-place edit may not be noticed, and SaveChanges() silently writes nothing. Give it a ValueComparer.

🔄 Likely Follow-up

"Owned type or a separate entity with a one-to-one?" An owned type has no identity of its own, lives and dies with its owner, and is always loaded with it. If other entities need to reference it, or it needs its own lifecycle, make it a real entity.

🎯 Say this in the interview — the exact lines to land

"For a value object like an address I use OwnsOne, so its properties become columns on the owner's table and it has no identity of its own. For an enum I want readable in the database, or a strongly typed id, I use HasConversion. If the converted value is mutable, I also give it a value comparer."

  • OwnsOne → value object in the owner's table, no identity of its own.
  • HasConversion<string>() → enum stored as text.
  • Typed id → convert to and from the raw value (for example a Guid).
  • Mutable converted value → add a ValueComparer or edits may go unnoticed.
📖 Explanation ▾

An owned type is a class with no identity of its own that only makes sense inside its owner — an Address on an Order. With OwnsOne, a reference owned type is stored in the owner's table by default, with column names like ShippingAddress_Street, and it is loaded together with the owner. OwnsMany is for collections and uses a separate table. EF Core 8 also added complex types for value objects that need no identity at all.

A value converter changes a property's type on its way to the database and back. The common uses are storing an enum as a string (HasConversion<string>()) and mapping a strongly typed id such as OrderId to its raw Guid or int. One trade-off: a text enum column is readable, but renaming an enum member later changes what the stored values mean.

The comparer caveat: change tracking has to decide whether a converted value changed. For simple immutable values that works by itself. For a mutable type such as a list, you supply a ValueComparer so EF Core can compare contents and take a safe snapshot.

💻 See the code ▾
C# 
modelBuilder.Entity<Order>()
    .OwnsOne(o => o.ShippingAddress);   // ✅ columns: ShippingAddress_Street, ShippingAddress_City

OwnsOne keeps the address inside the Orders table — no join, no separate key.

C# 
modelBuilder.Entity<Order>()
    .Property(o => o.Status)
    .HasConversion<string>();           // ✅ stored as "Shipped", not 2

modelBuilder.Entity<Order>()
    .Property(o => o.Id)
    .HasConversion(id => id.Value, v => new OrderId(v));   // typed id ↔ raw value

Two common converters: enum to text, and a strongly typed id to its raw value.

C# 
modelBuilder.Entity<Post>()
    .Property(p => p.Tags)
    .HasConversion(
        v => string.Join(",", v),
        v => v.Split(",", StringSplitOptions.RemoveEmptyEntries).ToList(),
        new ValueComparer<List<string>>(
            (a, b) => a!.SequenceEqual(b!),                                  // ✅ compare contents
            v => v.Aggregate(0, (h, s) => HashCode.Combine(h, s.GetHashCode())),
            v => v.ToList()));                                               // snapshot copy

A mutable converted value needs a ValueComparer so in-place edits are noticed.

🌍 Real-world example ▾

An Order has a Money value (amount and currency) and a Status enum. Map Money with OwnsOne so it is just two columns on the same row, and store Status as text so anyone reading the table sees "Shipped" instead of a bare number.
