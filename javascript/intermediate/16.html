Implement curry(fn) — keep collecting until fn.length is met

"Write a curry function so curry(add)(1)(2)(3) and curry(add)(1, 2)(3) both work."

Why it matters ▾
🍛 curry(fn)
❗ Problem"Write a curry function" is a favourite live-coding question, and first attempts usually handle only one argument per call — so curry(add)(1, 2)(3) fails — or call the function too early.
✅ SolutionThe standard answer is a closure that collects arguments across calls and calls the original function only once it holds fn.length of them.
Recallcurry = collect args across calls, call fn once args.length >= fn.length.
🔥 Easy interview recall

Curry = "keep collecting arguments until there are enough, then call the original."

Think: args.length < fn.length → return a function to collect more; enough → call fn.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Curried calls are not always one argument at a time. curry(add)(1, 2)(3) must work too, so compare args.length >= fn.length after every call instead of assuming each call brings exactly one argument.

🔄 Likely Follow-up

"What breaks if fn has default or rest parameters?" fn.length counts only the parameters before the first default value and leaves out a rest parameter, so curry can call the function too early — pass the arity yourself, for example curry(fn, 3).

🎯 Say this in the interview — the exact lines to land

"curry returns a function that collects arguments across calls, using a closure. After each call it checks args.length >= fn.length — if yes, it calls the original function with the collected arguments; if not, it returns another function to collect more."

  • Collect → a closure holds the args so far; each call adds its own.
  • Check → args.length >= fn.length decides: call, or keep collecting.
  • Flexible → any grouping works: (1)(2)(3), (1, 2)(3), (1, 2, 3).
  • Limit → fn.length ignores defaults and rest — so accept an optional explicit arity.
📖 Explanation ▾

Currying turns a function that takes several arguments into a chain of calls. The coding answer is a wrapper: curry(fn) returns a function curried(...args) that remembers the arguments in a closure. Each time it is called it asks one question — do I have fn.length arguments yet? If yes, call fn; if not, return a new function that adds the next batch and asks again.

fn.length is the number of declared parameters, which is why the same code handles (1)(2)(3), (1, 2)(3) and (1, 2, 3) — it never cares how the arguments were grouped. apply(this, …) passes along this so curried methods still work. It is the same "return a wrapper around fn" pattern as debounce and throttle, and the idea itself is covered in Higher-Order & Functional JavaScript.

The weak spot is fn.length: a parameter with a default value, and everything after it, is not counted, and a rest parameter (...nums) is not counted either. For (...nums) => … the length is 0, so the very first call would run the function. The fix is an optional second argument, curry(fn, arity).

💻 See the code ▾
JavaScript 
function curry(fn) {
  return function curried(...args) {
    if (args.length >= fn.length) {
      return fn.apply(this, args);   // enough arguments: call the original
    }
    return (...more) => curried.apply(this, [...args, ...more]);   // not yet: collect more
  };
}

The returned arrow function keeps args alive and feeds the merged list back into curried.

JavaScript 
const add = (a, b, c) => a + b + c;
const curriedAdd = curry(add);
curriedAdd(1)(2)(3);     // 6
curriedAdd(1, 2)(3);     // 6
curriedAdd(1)(2, 3);     // 6
curriedAdd(1, 2, 3);     // 6

Every grouping reaches three collected arguments, so every one gives 6.

JavaScript 
function curry(fn, arity = fn.length) {   // an explicit arity beats fn.length
  return function curried(...args) {
    if (args.length >= arity) return fn.apply(this, args);
    return (...more) => curried.apply(this, [...args, ...more]);
  };
}

const sum = (...nums) => nums.reduce((a, b) => a + b, 0);   // sum.length is 0
curry(sum, 3)(1)(2)(3);   // 6

Without the explicit 3, curry(sum)(1) would run sum straight away.

🌍 Real-world example ▾

A pricing helper applyDiscount(rate, price) was curried once so const tenOff = curriedDiscount(0.1) could be reused as prices.map(price => tenOff(price)) — the same function, with its first argument locked in.
