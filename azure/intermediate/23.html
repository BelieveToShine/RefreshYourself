⭐ Azure · Intermediate · Should Know

If this signal, then that control

"How would you require MFA only for risky sign-ins, and let partner or customer users sign in to your app?"

Why it matters ▾
⚖️ Conditional Access
❗ ProblemRequiring MFA for everyone on every sign-in annoys users, and requiring nothing leaves risky sign-ins unchecked.
✅ SolutionConditional Access policies read signals like user, device, location and sign-in risk, then decide: allow, require MFA, or block.
RecallConditional Access = if signals, then control.
🤝 External identities
❗ ProblemPartners and customers should not need an account created and managed in your company directory just to use your app.
✅ SolutionEntra External ID lets partners sign in as guests with their own identity, and lets customers sign up and sign in to customer-facing apps.
RecallGuests = partners. Customer sign-up = external ID for customers.
🔥 Easy interview recall

Signals in → user, device, location, risk

Controls out → allow, MFA, block

Partner users → B2B guests, own identity

Customers → External ID sign-up

Think: a policy reads the signals after sign-in and picks the control.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

"I turned on MFA, so Conditional Access is done." MFA is only one possible control; a policy only protects the users and apps it targets. A gap in assignments (an app left out, a break-glass account missing, guests forgotten) is the usual failure. Test new policies in report-only mode first so you do not lock everyone out.

🔄 Likely Follow-up

"Does it also apply to guest users?" Yes — policies can target guest and external users too. Also, Conditional Access needs Microsoft Entra ID P1, and risk-based conditions (sign-in risk, user risk) use Entra ID Protection, which is a P2 feature.

🎯 Say this in the interview — the exact lines to land

"I would use a Conditional Access policy: if the sign-in risk is medium or high, require MFA. For partners I would invite them as B2B guests who sign in with their own identity, and for customers I would use Entra External ID for sign-up and sign-in."

  • Conditional Access → if signals, then control, evaluated after first sign-in.
  • Signals → user, device, location, risk, app being accessed.
  • Controls → allow, require MFA, block, or limit the session.
  • Risk-based → needs Entra ID Protection (P2); Conditional Access itself needs P1.
  • Partners → B2B guests with their home identity.
  • Customers → Entra External ID; Azure AD B2C closed to new customers on 1 May 2025.
📖 Explanation ▾

Conditional Access is Entra's policy engine. A policy has assignments — which users, which apps, and which conditions such as location, device platform or sign-in risk — and access controls: block, or grant access if something is satisfied, for example MFA or a compliant device. It is evaluated after the first sign-in step, so it adds to a password rather than replacing it. Roll out new policies in report-only mode first.

MFA asks for a second proof, such as an authenticator app prompt or a security key. Using it as a Conditional Access control, instead of always-on for everyone, is how you ask for MFA only when it matters, such as an unfamiliar location or a risky sign-in. Risk signals come from Entra ID Protection, which is a Microsoft Entra ID P2 feature; Conditional Access itself needs P1.

External users come in two shapes. For partners, B2B collaboration invites them as guest users who sign in with their own work or personal identity, and you control what they can reach. For customers, Entra External ID covers sign-up and sign-in for customer-facing apps. The older Azure AD B2C is no longer available to new customers (since 1 May 2025), so a new project uses External ID with an external tenant, which Microsoft calls its next-generation customer identity solution.

🌍 Real-world example ▾

A company requires MFA for the finance app only when a sign-in looks risky or comes from outside the office, so normal sign-ins stay smooth. Its supplier's staff are invited as guests to see order status, while shoppers on its public app sign up through external identities.
