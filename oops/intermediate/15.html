Shallow vs. deep copy — did you copy the object, or just its pointers?

What's the difference between a shallow copy and a deep copy, and how would you clone an object safely?

Why it matters ▾
🧍 Shallow copy
❗ ProblemYou copy a Person and change copy.Address.City. The original's city changes too — both people point at the same Address object.
✅ SolutionKnow that a shallow copy copies the fields as they are, so reference fields still point to the same objects. Use it only when sharing them is fine.
RecallShallow = new outer object, same inner objects.
🧬 Deep copy
❗ ProblemYou need a truly independent snapshot — for undo, caching, or handing data to another thread — but a plain copy leaves hidden shared objects behind.
✅ SolutionA deep copy also copies the objects the fields point to (and theirs, as deep as needed), so changing one side never touches the other.
RecallDeep = the whole graph is copied, nothing shared.
🔥 Easy interview recall

Shallow → inner objects are shared

Deep → inner objects are copied too

Think: Shallow is photocopying a page that says "see the shared drive". Deep is copying the drive too.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

"A record's with expression gives me an independent copy." It is a shallow copy. A reference-type property in the new record still points at the same object as the original.

🔄 Likely Follow-up

"Why is ICloneable discouraged?" Its Clone() returns object and does not say whether the copy is shallow or deep, so callers cannot trust it. Microsoft's guidance is not to use it in public APIs.

🎯 Say this in the interview — the exact lines to land

"A shallow copy makes a new object but its reference fields still point at the same inner objects. A deep copy copies those inner objects too, so nothing is shared. In C# I write a copy constructor or a clear DeepCopy() method instead of relying on ICloneable."

  • Shallow → copies references, so inner objects are shared (MemberwiseClone).
  • Deep → copies the whole object graph, nothing shared.
  • Records → with is a shallow copy.
  • Cloning → prefer a copy constructor or a named method over ICloneable.
📖 Explanation ▾

Objects hold values and references. A shallow copy copies each field as it is: values are copied, but a reference is copied as a reference, so original and copy point to the same inner object. MemberwiseClone() does exactly this.

A deep copy follows those references and copies the inner objects too. C# has no built-in deep copy for your own classes; you write it yourself, usually as a copy constructor or a method like DeepCopy(). Immutable types (a string, or an immutable record) need no deep copy because nobody can change them.

Value-type fields are copied by value either way, so the problem only shows up with reference-type fields. That is also why record ... with is shallow: it copies the references.

💻 See the code ▾
C# 
public class Address { public string City = ""; }

public class Person
{
    public string Name = "";
    public Address Address = new();

    public Person ShallowCopy() => (Person)MemberwiseClone();   // ❌ Address is shared

    public Person DeepCopy() => new Person
    {
        Name = Name,
        Address = new Address { City = Address.City }   // ✅ own Address
    };
}

MemberwiseClone shares the Address; DeepCopy builds a new one.

C# 
public record Customer(string Name, Address Address);

var b = a with { Name = "Bo" };   // new Customer
// ❌ b.Address and a.Address are the SAME object

with copies the reference, not the Address behind it.

🌍 Real-world example ▾

An "undo" feature copies a document before an edit. With a shallow copy, editing a paragraph object changes the "saved" version too, so undo restores nothing. A deep copy of the paragraphs keeps the snapshot safe.
