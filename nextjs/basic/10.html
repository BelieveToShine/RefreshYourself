Global CSS vs. CSS Modules — who's allowed to see your styles?

"What CSS approaches does Next.js support out of the box, and when would you pick CSS Modules over global CSS?"

Why it matters ▾
🌐 Global CSS
❗ ProblemSome styles (resets, fonts, design tokens) really do need to apply to the entire app, from one place.
✅ SolutionA plain .css file imported once in the root layout applies app-wide — exactly like a normal stylesheet, no extra tooling.
RecallGlobal CSS = one file, the whole app sees it.
🧩 CSS Modules
❗ ProblemTwo components using plain class names like .card can silently collide and override each other's styles as an app grows.
✅ SolutionA file.module.css file gets its class names automatically renamed to be unique — only the component that imports it can ever match them.
RecallCSS Modules = scoped class names, zero naming collisions.
🔥 Easy interview recall

Global CSS → app-wide reach

CSS Modules → scoped to one component

Think: Tailwind and Sass work too — both ship with zero extra config in a default project.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Importing a global .css file from inside a non-root component. Global stylesheets can only be imported from the root layout (app/layout.js, or _app in the Pages Router) — importing one deeper triggers a build error, a deliberate guardrail against accidental global style leakage.

🔄 Likely Follow-up

"Why would you choose CSS Modules over just writing global CSS classes?" Automatic scoping — a CSS Modules class name is guaranteed not to collide with an identically-named class anywhere else in the app, which plain global CSS can't guarantee.

🎯 Say this in the interview — the exact lines to land

"Next.js supports global CSS, CSS Modules, and Tailwind/Sass out of the box with zero extra config. Global CSS, imported once in the root layout, applies app-wide. CSS Modules auto-scope class names per component, so two components can reuse the same class name without ever colliding."

  • Global CSS → one app-wide stylesheet, imported only in the root layout.
  • CSS Modules → class names auto-scoped per component, no naming collisions.
  • Tailwind, Sass → supported with zero extra setup in a default project.
📖 Explanation ▾

Global CSS is a plain stylesheet, imported exactly once — in the root layout — and from then on it behaves like any CSS file dropped into a classic website: every class name in it is visible to every component in the app.

CSS Modules (any file named *.module.css) work differently: at build time, Next.js rewrites each class name into something unique to that file, and the import gives you back an object mapping your original names to the rewritten ones. Two files can both define .card and never conflict, because the names that actually ship are different under the hood.

Tailwind CSS and Sass (.scss) are both supported the same way — install the package, and a default create-next-app project is already wired to compile either one, no extra webpack/PostCSS configuration required.

💻 See the code ▾
JSX 
// app/layout.js
import './globals.css';  // ✅ root layout — the only place a global import is allowed

One global import, right at the top of the app — every page inherits it.

JSX 
// Card.jsx
import styles from './Card.module.css';

export default function Card() {
  return <div className={styles.card}>Hi</div>;  // ✅ scoped to just Card
}

styles.card resolves to a unique generated class name — no other component can accidentally match it.

🧭 Use Cases — recognize these when they happen to you ▾
1 You're setting up app-wide resets, fonts, and color variables

Design tokens, a CSS reset, base typography — these genuinely belong everywhere. One import in the root layout is the right tool. This is the #1 scenario you'll actually run into.

RememberApp-wide basics → global CSS, imported once.
2 You're styling one reusable component other teams also use

A shared Card or Button component is exactly where a naming collision would be most painful to debug later — CSS Modules make that risk disappear by construction, not by convention.

RememberShared/reusable component → CSS Modules.
3 You try to import a global stylesheet from inside a regular component

Next.js deliberately rejects a plain (non-module) CSS import from anywhere but the root layout — it's a guardrail against global styles leaking in from a deeply nested component without anyone noticing.

RememberGlobal CSS outside the root layout → build error, on purpose.
🌍 Real-world example ▾

Global CSS is the building's shared paint job — CSS Modules are each tenant's own apartment. Everyone sees the lobby's color. But "Room 2B" inside one apartment doesn't mean anything to the apartment next door — each component's class names only make sense inside that component.
