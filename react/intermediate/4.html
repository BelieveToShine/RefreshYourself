useMemo & useCallback — caching a value, not guaranteeing a speedup

"What's the difference between useMemo, useCallback, and React.memo, and do they always help?"

Why it matters ▾
🧮 useMemo
❗ ProblemRecomputing an expensive calculation — sorting or filtering a big list — on every single render wastes work when the actual inputs haven't changed at all.
✅ SolutionuseMemo caches the computed result and only reruns the calculation when something in its dependency array actually changes.
RecalluseMemo = cache the VALUE, recompute only when deps change.
🔗 useCallback
❗ ProblemA component creates a brand-new function on every render — same behavior, but a different object in memory — which breaks anything downstream comparing that function by reference, like React.memo's shallow prop check.
✅ SolutionuseCallback caches the function reference itself, so the same function identity is reused across renders when its dependencies haven't changed.
RecalluseCallback = cache the FUNCTION reference, not just its behavior.
🛡️ React.memo
❗ ProblemA component re-renders every time its parent re-renders, even when its own props are exactly the same as last time — wasted render work for output that would look identical either way.
✅ SolutionReact.memo wraps the component and skips its re-render when props are shallowly unchanged since the last render.
RecallReact.memo = skip the RE-RENDER when props haven't changed (shallow).
🔥 Easy interview recall

useMemo → caches a VALUE

useCallback → caches a FUNCTION

React.memo → skips a COMPONENT's re-render

Think: all three only pay off when something downstream is actually comparing references.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Wrapping everything in useMemo/useCallback can only help performance, never hurt it — wrong. Memoization has its own real cost (comparing dependencies on every render, holding cached values in memory) — applying it to a cheap computation or a component that already renders fast can make things slower overall by adding overhead with no matching benefit.

🔄 Likely Follow-up

"Does the React Compiler make useMemo/useCallback obsolete?" Not obsolete, but it's designed to automatically insert this exact category of memoization at build time in many cases — so "do I still need to hand-write these everywhere" is becoming a genuinely live, evolving question rather than a settled "yes, always."

🎯 Say this in the interview — the exact lines to land

"useMemo caches a computed value between renders and only recomputes it when its dependencies change. useCallback caches a function reference so the same function identity is reused instead of a new one every render. React.memo skips re-rendering a whole component when its props haven't changed by reference. None of it is automatically a performance win — it only pays off when something downstream is actually comparing those references."

  • useMemo → caches a VALUE, recomputed only when deps change.
  • useCallback → caches a FUNCTION reference, same identity reused.
  • React.memo → skips a component's re-render when props are unchanged (shallow).
  • Not automatically faster → has its own cost; overusing it on cheap work can be slower.
📖 Explanation ▾

useMemo caches the result of a calculation between renders, recomputing it only when the values in its dependency array change — like keeping a pre-worked answer instead of redoing the same long math problem on every render.

useCallback does the same caching job, but for a function reference instead of a value — without it, a component creates a brand-new function on every render, which looks the same to a human but is a different object in memory. In fact, useCallback(fn, deps) is really just useMemo(() => fn, deps) under the hood — the same caching mechanism, just returning a function instead of a computed result.

React.memo works one level up: it wraps a whole component and skips re-rendering it when its props are shallowly unchanged since the last render. That "shallow" word is exactly why useCallback matters to it — if a parent passes a brand-new function prop every render, React.memo's comparison always sees a "changed" prop and re-renders anyway, even though the function does the same thing. All three tools cost something too (checking dependencies or props every render, holding cached data in memory), so reaching for them on cheap work or a component that already renders fast can add overhead without any real gain — and a newer tool, the React Compiler, can now insert this same category of memoization automatically at build time in many cases.

💻 See the code ▾
JSX 
const sorted = useMemo(() => expensiveSort(items), [items]);  // caches the VALUE

expensiveSort reruns only when items itself changes — every other render just reuses the cached sorted array.

JSX 
const handleClick = useCallback(() => onSelect(id), [id]);  // caches the FUNCTION reference
<MemoChild onClick={handleClick} />  // ✅ same reference every render

MemoChild is wrapped in React.memo — its props check only sees onClick as "unchanged" because handleClick keeps the same reference; without useCallback the memo check would fail every time.

🧭 Use Cases — recognize these when they happen to you ▾
1 You're re-sorting or re-filtering a large list on every render, even when the list itself hasn't changed

This is the classic useMemo case: wrap the calculation with items as its dependency, and the sort only reruns when items itself changes — every other render just reuses the cached result.

RememberExpensive calc + unchanged inputs → useMemo.
2 You wrap a child in React.memo, pass it a callback prop, but it still re-renders every single time anyway

Without useCallback, the parent creates a brand-new function reference every render — React.memo's shallow prop check always sees that as a changed prop, so it re-renders the child anyway even though the function does the exact same thing.

RememberNew function ref every render defeats React.memo — wrap it in useCallback too.
3 A component keeps re-rendering just because its parent re-rendered, even though its own props never changed

Wrapping that component in React.memo lets it skip the re-render entirely when its props are shallowly the same as last time, so a noisy parent doesn't cascade wasted render work down to children that didn't need it.

RememberSame props, noisy parent → React.memo skips the re-render.
🌍 Real-world example ▾

Taping a pre-worked answer to your desk so you don't redo the same long math problem every time someone asks — that's useMemo/useCallback. But taping up the answer to a question that only takes two seconds to redo anyway just adds clutter to your desk without saving any real time.
