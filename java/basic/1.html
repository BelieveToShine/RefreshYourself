JDK vs. JRE vs. JVM — who runs it, who builds it?

"What's the difference between the JDK, the JRE, and the JVM?"

Why it matters ▾
⚙️ JVM
❗ ProblemCompiled bytecode needs something to actually execute it, the same way on Windows, Linux, or a container, without being recompiled for each.
✅ SolutionThe JVM is the runtime engine that loads .class bytecode and executes it — the one piece every Java program genuinely depends on.
RecallJVM = the engine that executes bytecode.
📦 JRE
❗ ProblemThe JVM alone can't run a real program — code calls into String, collections, I/O, and dozens of other standard classes it needs available at runtime.
✅ SolutionThe JRE bundles the JVM with the core class libraries a compiled program needs — enough to run any already-built Java application.
RecallJRE = JVM + the libraries to run a program.
🛠️ JDK
❗ ProblemRunning compiled code is one thing — turning your own .java source into that bytecode, and debugging it, needs tools neither the JVM nor the JRE provide.
✅ SolutionThe JDK adds the development tools — the javac compiler, a debugger, and more — on top of everything the JRE already gives you.
RecallJDK = JRE + the tools to build one.
🔥 Easy interview recall

JVM → runs bytecode

JRE → JVM + libraries to run a program

JDK → JRE + tools to build one

Think: you run Java with a JVM/JRE. You develop Java with a JDK.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Looking for a standalone "JRE download" on a modern Java version. Oracle discontinued separate standalone JRE distributions after Java 8 — today, installing a JDK is also how you get everything you need to run Java.

🔄 Likely Follow-up

"Do you need the JDK to run a compiled .jar file?" No — a JVM (or a JRE on older setups) is enough to run already-compiled bytecode; you only need the JDK to compile source yourself or attach a debugger.

🎯 Say this in the interview — the exact lines to land

"The JVM is the runtime engine that executes bytecode. The JRE is the JVM plus the standard libraries needed to run a compiled program. The JDK is the JRE plus the development tools — the compiler and a debugger — needed to actually build one."

  • JVM → just the execution engine, nothing you install on its own.
  • JRE → enough to run an already-compiled Java program.
  • JDK → everything the JRE has, plus javac and the rest of the dev tools.
📖 Explanation ▾

The JVM is the actual engine — it loads .class bytecode and runs it, the same way regardless of the underlying operating system. It isn't something you download on its own; it comes bundled inside a JRE or a JDK.

The JRE takes that engine and adds the standard class libraries (java.lang, java.util, and the rest) that almost any real program calls into. A JRE is the minimum you need to run a Java application someone already compiled.

The JDK takes the JRE and adds the tools to actually produce that compiled program in the first place — most importantly javac, the compiler, plus a debugger and other developer tooling. If you're writing or building Java code, you need a JDK, not just a JRE.

💻 See the code ▾
Java 
javac HelloWorld.java   // needs the JDK — produces HelloWorld.class
java HelloWorld         // only needs a JVM/JRE — runs the bytecode

Two different tools, two different requirements — javac is a JDK tool, java only needs the runtime.

🧭 Use Cases — recognize these when they happen to you ▾
1 You just need to run someone else's compiled .jar

You only need a JVM (via a modern JDK, or a JRE on an older setup) to run already-compiled bytecode. This is the #1 scenario most end users are actually in.

RememberJust running a .jar → JVM/JRE is enough, no JDK needed.
2 You're setting up a CI server that compiles and tests code

Compiling source and running a debugger both need javac and the other dev tools — that means the full JDK, not just a runtime.

RememberCompiling or debugging source → you need the full JDK.
3 You go looking for a "JRE download" on a modern Java release

Standalone JRE installers were discontinued after Java 8 — on any current release, you install a JDK even if all you plan to do is run programs.

RememberModern Java → install the JDK; a separate JRE isn't offered anymore.
🌍 Real-world example ▾

Think of a car engine, the car, and a full garage. The JVM is just the engine. The JRE is the whole car — engine plus everything you need to actually drive it somewhere. The JDK is the garage — the car, plus every tool needed to build or repair one in the first place.
