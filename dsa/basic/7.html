Heap / Priority Queue — get the min instantly, without ever fully sorting anything

"What is a heap (or priority queue), and how do insert, extract, and peek each work?"

Why it matters ▾
  • The structure behind top-K problems, Dijkstra's algorithm, and merging sorted data.
  • Shows up the moment a problem needs "give me the min/max, fast, repeatedly, as the data changes."
  • A common opener before a harder heap-based follow-up like k-way merge or k-th largest in a stream.
🔥 Easy interview recall

peek → O(1) — always the root

insert → O(log n) — bubble up

extract → O(log n) — bubble down

Think: a heap is just an array shaped like a tree — no pointers, only index math.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

A heap is not a fully sorted structure. It only guarantees the root is the min (or max) — a min-heap's left child can be bigger or smaller than its right sibling, there's no guaranteed order between them.

🔄 Likely Follow-up

"How would you find the k-th largest element in a stream efficiently?" Keep a min-heap of size k — when a new number beats the heap's current minimum (the root), pop the root and push the new number in; the root always holds the k-th largest seen so far, in O(log k) per update instead of re-sorting everything.

🎯 Say this in the interview — the exact lines to land

"A heap is a tree-shaped structure — usually just a plain array, no pointers — that only guarantees the root is the min or max. Peek is O(1), insert bubbles up in O(log n), extracting the root bubbles down in O(log n), and building one from n items is O(n), not O(n log n)."

  • Array, not pointers — parent/children come from index math: parent = (i-1)/2, children = 2i+1, 2i+2.
  • peek → O(1), always the root.
  • insert → O(log n), add at the end, bubble up.
  • extract-min/max → O(log n), swap root with the last element, bubble down.
  • K-way merge → one front element per list in a min-heap, pop + push the next — O(N log k).
📖 Explanation ▾

A heap is a tree-shaped structure that satisfies one property: in a min-heap every parent is ≤ its children, so the smallest value always sits at the root (a max-heap flips this — parent ≥ children, largest at the root). Because a binary heap is always a complete binary tree — every level full except possibly the last, filled left to right — it can be stored as a plain array with no pointers at all. A node's parent and children come from index math alone: for a 0-indexed array, the parent of i is (i-1)/2, and its children are 2i+1 and 2i+2.

Insert adds the new value at the end of the array, then bubbles it up — swapping with its parent — until the heap property holds again; that's O(log n) because a complete tree of n nodes has height O(log n). Extract-min/extract-max (removing the root) swaps the root with the last element, shrinks the array by one, then bubbles that value down through the smaller (or larger) child until it settles — also O(log n). Peek just reads index 0, so it's O(1).

Building a heap from n unsorted items all at once is O(n), not O(n log n) — most nodes sit near the bottom of the tree, so the bubble-down work during construction is tiny for almost all of them. A priority queue is the general idea ("always give me the next highest/lowest priority item"); a binary heap is the standard way to build one, though a sorted list or balanced tree could technically work too, just with worse trade-offs.

💻 See the code ▾
C# 
var pq = new PriorityQueue<string, int>();
pq.Enqueue("low priority", 5);
pq.Enqueue("high priority", 1);   // smaller number = higher priority

pq.Peek();     // ✅ "high priority" — O(1), just reads the root
pq.Dequeue();  // ✅ removes the root, bubbles the new root down — O(log n)

.NET's built-in PriorityQueue<TElement, TPriority> is a binary heap — Peek/Dequeue only ever touch the root.

C# 
var heap = new PriorityQueue<(int val, int list, int idx), int>();
for (int i = 0; i < lists.Count; i++)
    heap.Enqueue((lists[i][0], i, 0), lists[i][0]);

while (heap.Count > 0)
{
    var (val, list, idx) = heap.Dequeue();   // ✅ smallest across all k lists
    result.Add(val);
    if (idx + 1 < lists[list].Count)
        heap.Enqueue((lists[list][idx + 1], list, idx + 1), lists[list][idx + 1]);
}

Each pop pulls the smallest front-of-list value; each push adds that list's next value — O(N log k) total, far better than merging lists two at a time.

🌍 Real-world example ▾

An ER board always has to call the most critical patient next, and new patients keep arriving mid-shift. Re-sorting the whole waiting list on every arrival would be wasteful — a heap gives you "who's next" in O(1) and folds in a new arrival in O(log n), which is exactly why heaps back task schedulers and Dijkstra's shortest-path algorithm too.
