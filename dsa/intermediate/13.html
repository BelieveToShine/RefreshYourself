Kadane's algorithm — at every element, extend or restart?

"Find the contiguous subarray with the largest sum in O(n)."

Why it matters ▾
📈 Kadane's algorithm
❗ ProblemTrying every start and end position costs O(n²), which is far too slow once the array gets large.
✅ SolutionKeep one running sum and, at each element, either extend it or restart from that element — one pass, O(n) time, O(1) space.
RecallBest subarray ending here = extend the last one, or restart.
🔥 Easy interview recall

Kadane = "drop the running sum the moment it goes negative."

Think: cur → best sum of a subarray that ends here best → biggest cur seen so far (the answer)

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

"Start best at 0." That breaks when every number is negative — the answer must be the largest single element (like -1), not an empty 0, so start both cur and best from the first element.

🔄 Likely Follow-up

"Now return the start and end indices, not just the sum." Remember a start index that moves to i every time you restart; whenever cur beats best, save that start and the current i as the best range.

🎯 Say this in the interview — the exact lines to land

"Kadane's algorithm finds the maximum subarray sum in one pass. At each element I keep the best sum of a subarray ending there — either extend the previous one or restart at this element — and track the best value seen overall. That is O(n) time and O(1) space, instead of O(n²) for trying every pair."

  • cur = max(x, cur + x) → extend or restart, nothing else to remember.
  • Restart when the running sum is negative — a negative prefix can only hurt.
  • The answer is the best value seen, not the last running sum.
  • All numbers negative → start from the first element, not 0.
  • Cost → O(n) time, O(1) space.
📖 Explanation ▾

Kadane's algorithm walks the array once and carries one number: the best sum of a subarray that ends at the current element. At each element there are only two choices — extend the previous subarray, or restart with this element alone. If the sum so far is negative, carrying it forward can only make things worse, so restart. A second number, best, remembers the largest value the running sum ever reached.

Each step does constant work, so the whole pass is O(n) time and O(1) space. Written as a formula it is a one-dimensional DP — best ending at i = max(nums[i], best ending at i-1 + nums[i]) — that only ever needs the previous value (see Dynamic Programming). Seen as a rule it is also a greedy choice: throw away a prefix that hurts (see Greedy Algorithms).

Two edge points. If every number is negative, the answer is the largest single element, so start from nums[0] — use 0 only when an empty subarray is allowed. And a sliding window does not fit, because with negative numbers, growing the window can raise or lower the sum. A prefix-sum version also works: track the smallest prefix seen so far and maximize the current prefix minus it.

💻 See the code ▾
C# 
int MaxSubArray(int[] nums)
{
    int cur  = nums[0];     // best sum ending at index 0
    int best = nums[0];     // ✅ first element, not 0 — all-negative safe
    for (int i = 1; i < nums.Length; i++)
    {
        cur  = Math.Max(nums[i], cur + nums[i]);  // restart at nums[i], or extend
        best = Math.Max(best, cur);               // remember the best ever
    }
    return best;
}

On [-2, 1, -3, 4, -1, 2, 1, -5, 4] it returns 6. On [-3, -1, -2] it returns -1, the largest single element.

C# 
(int Sum, int Start, int End) MaxSubArrayRange(int[] nums)
{
    int cur = nums[0], best = nums[0];
    int start = 0, bestStart = 0, bestEnd = 0;
    for (int i = 1; i < nums.Length; i++)
    {
        if (cur < 0) { cur = nums[i]; start = i; }  // restart: new window begins here
        else        { cur += nums[i]; }             // extend

        if (cur > best) { best = cur; bestStart = start; bestEnd = i; }  // ✅ save the range
    }
    return (best, bestStart, bestEnd);
}

Same pass, one extra index. On the example array it returns (6, 3, 6) — the window [4, -1, 2, 1].

🌍 Real-world example ▾

You have a list of daily profit-or-loss figures and want the stretch of consecutive days that earned the most. Kadane answers it in a single pass — it never needs to try every start day and end day.
