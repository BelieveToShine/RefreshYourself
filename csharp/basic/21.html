virtual / override / new — who decides which method runs

"What's the difference between virtual, override and new — and what does sealed do?"

Why it matters ▾
🧬 override vs. new
❗ ProblemWhen a base-typed variable holds a derived object, a method call could run the base version or the derived one — and without clear rules the wrong one runs silently.
✅ Solutionvirtual + override let the real object decide; new only hides, so the variable's type decides; abstract forces an override and sealed stops further ones.
Recalloverride = the object decides · new = the variable decides.
🔥 Easy interview recall

override → the object decides

new → the variable's type decides

abstract → derived class must override

sealed → no more overriding

Think: override follows the object. new follows the variable.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

new and override are not two ways to replace a method. Only override replaces it — new just hides it, so a call through a base-typed variable still runs the base version.

🔄 Likely Follow-up

"Can you override a method that isn't virtual?" No — only a virtual, abstract or already-override method can be overridden; anything else you can only hide with new.

🎯 Say this in the interview — the exact lines to land

"virtual allows a method to be overridden, and override replaces it — the real object's version runs, even through a base-typed variable. new only hides, so the variable's type decides. abstract has no body and forces an override; sealed stops further overriding or inheriting."

  • override → the real object decides at run time — that is polymorphism.
  • new → hides, does not replace — the variable's type decides; leaving it off gives a compiler warning.
  • abstract → no body; every non-abstract derived class must override it.
  • sealed on a class → can't be inherited; on an override → can't be overridden again.
  • Only virtual, abstract or override members can be overridden.
📖 Explanation ▾

A method call through a base-typed variable can go two ways. With virtual + override, the real object picks: an Animal variable holding a Dog runs Dog's method. With new, the derived method is a separate method that hides the base one, so the variable's own type picks — the same variable still runs the base version.

abstract marks a method with no body (inside an abstract class) that every concrete derived class has to override. sealed closes the door: a sealed class can't be a base class (string is one), and a sealed override can't be overridden further.

In practice you almost always want override; new is rare and often a sign the design needs another look. See Polymorphism, Composition over Inheritance and Access Modifiers.

💻 See the code ▾
C# 
public class Animal { public virtual string Speak() => "..."; }
public class Dog : Animal { public override string Speak() => "Woof"; }
public class Cat : Animal { public new string Speak() => "Meow"; }

Dog overrides the virtual method; Cat hides it with new.

C# 
Animal a = new Dog();
Animal b = new Cat();
Console.WriteLine(a.Speak());   // Woof — override: the object decides
Console.WriteLine(b.Speak());   // ... — new: the variable's type decides

Same variable type, same call, different result.

C# 
public abstract class Shape { public abstract double Area(); }

public class Circle : Shape
{
    public double R { get; init; }
    public sealed override double Area() => Math.PI * R * R;   // no further overrides
}

abstract forces Circle to supply Area; sealed stops anyone overriding it again.

🌍 Real-world example ▾

A report base class. Report.Render() is virtual; PdfReport and CsvReport override it, and code holding a Report variable just calls Render() without knowing which one it has.
