Facade — one simple door in front of a messy subsystem

What is the Facade pattern, and how is it different from Adapter?

🧩 Also see the OOP-angle page: Adapter vs. Facade
Why it matters ▾
🚪 Facade
❗ ProblemPlacing an order means calling inventory, payment, shipping, and notifications in the right order. Every caller has to know and repeat that whole recipe.
✅ SolutionA Facade class exposes one simple method that runs the steps in order, so most callers only need to know the facade, not the four subsystems behind it.
RecallFacade = one simple entry point in front of several real subsystem classes.
🔥 Easy interview recall

Facade = "one simple front door over a group of subsystem classes."

Think: OrderFacade.PlaceOrder() → calls inventory, payment, shipping, and notifications for you.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

"Facade and Adapter are basically the same thing." They're not — Adapter exists because of an incompatibility, translating one interface into another; Facade exists purely to simplify, with no incompatibility to fix.

🔄 Likely Follow-up

"Does a Facade hide the subsystem classes completely?" No — it offers a simpler default path for the common case. Callers who need deeper control can still reach the subsystem classes directly.

🎯 Say this in the interview — the exact lines to land

"Facade provides one simple, higher-level interface in front of a set of subsystem classes that have real interdependencies. Callers who only need the common case call the facade's one or two methods instead of coordinating every subsystem themselves, and callers who need more control can still reach the subsystem classes directly."

  • Facade → one simple entry point over several subsystem classes.
  • Doesn't → hide the subsystem — it's a convenience, not a lock.
  • Versus Adapter → no incompatibility required; Facade exists purely to simplify.
  • Structure → Facade class plus several real Subsystem classes.
📖 Explanation ▾

A Facade is one class that exposes a few simple methods in front of a set of Subsystem classes — classes that have real interdependencies and real order-of-operations rules. Placing an order might mean reserving stock, charging a card, scheduling shipping, and sending a notification, each depending on the previous step succeeding. The facade holds that recipe in one place instead of making every caller re-learn it.

It's easy to mix up with Adapter because both sit in front of other classes, but they solve different problems. Adapter exists because of a genuine incompatibility — one interface simply doesn't match another, usually one-to-one. Facade exists purely for simplicity — there's no incompatibility at all, just too many steps for a caller to coordinate.

AdapterFacade
Exists because ofa real interface mismatchtoo many steps, no mismatch
Wrapsusually one classseveral subsystem classes
Hides the wrapped class?yes — callers never see itno — still reachable directly
💻 See the code ▾
C# 
public class OrderFacade
{
    // _inventory, _payment, _shipping, _notifications are injected in the constructor
    public void PlaceOrder(Order o)
    {
        _inventory.Reserve(o);       // step 1
        _payment.Charge(o);          // step 2
        _shipping.Schedule(o);       // step 3
        _notifications.Send(o);      // step 4
    }
}

The facade holds the recipe — four real classes, one order that must be followed.

C# 
// Without the facade — every caller repeats the recipe:
inventory.Reserve(order);
payment.Charge(order);
shipping.Schedule(order);
notifications.Send(order);

// With the facade — one call:
facade.PlaceOrder(order);   // ✅ caller doesn't need to know the steps

Same four calls still happen underneath — the facade just owns the recipe instead of every caller owning a copy of it.

🌍 Real-world example ▾

A car's ignition button. One press hides a complex engine-starting subsystem behind a single simple action. A hotel concierge works the same way — one request to the desk coordinates a restaurant reservation, a taxi, and tickets, instead of you calling all three yourself.
