Arrays & Strings — instant to read, expensive to rearrange

"How is an array laid out in memory, and why is inserting into the middle O(n) even though reading by index is O(1)?"

Why it matters ▾
  • Every later pattern — two pointers, sliding window, prefix sums — assumes you already know how an array behaves. This page is that vocabulary.
  • A near-universal warm-up question before a harder problem is even stated.
  • Confusing "array access is O(1)" with "every array operation is O(1)" is an easy, common mistake to expose in the first two minutes.
🔥 Easy interview recall

arr[i] → O(1) — pure math, no searching

insert/delete at the end → O(1) usually

insert/delete in the middle → O(n) — everyone after it shifts

Think: index math is instant — shifting elements never is.

⚠️ Common Trap

String concatenation in a loop is not free just because it's one line of code. Strings are immutable, so every + copies the whole string built so far — a naive loop is O(n²) overall, which is why languages give you a mutable builder (StringBuilder in C#/Java) for exactly this case.

🔄 Likely Follow-up

"How would you reverse an array in-place?" Swap from both ends toward the middle with two pointers — O(n) time, O(1) extra space. (The full two-pointer technique gets its own page on the Intermediate tier.)

🎯 Say this in the interview — the exact lines to land

"An array is one contiguous block of memory, so arr[i] is just base-address-plus-offset math — O(1). Insert or delete at the end is usually O(1), but doing either in the middle is O(n) because every later element has to shift over. 'In-place' means doing that using the array's own memory — O(1) extra space — instead of copying it."

  • Access is math, not search → base + i × size, same cost for any index.
  • Middle insert/delete is O(n) → every element after the gap shifts by one.
  • In-place → O(1) extra space, modify the array itself instead of copying it.
  • Strings are immutable → every concatenation makes a new string; use a builder in a loop.
📖 Explanation ▾

An array is one contiguous block of memory — every element is the same size, stored back to back with no gaps. That's the whole reason arr[i] is O(1): the runtime doesn't search for index i, it just computes base address + i × element size and jumps straight there.

Insertion and deletion inherit that same layout's downside. Touching the end only affects one slot — O(1), usually. Doing either in the middle means every element after that point has to physically move over by one, to keep the array contiguous — that's O(n).

In-place means doing that move using the array's own memory — O(1) extra space — instead of building a second array to hold the result.

A prefix is a contiguous run from the start of an array or string; a suffix is the same from the end. Palindrome checks and string-matching problems reason about prefixes and suffixes directly — foundational vocabulary the Intermediate tier's own "Prefix Sum & Difference Array" page builds a specific technique on top of.

Strings, in most languages this site covers (C#, Java, Python, JavaScript), are immutable — concatenation, substring, and replace all hand back a brand-new string rather than editing the original. See the Trap above for what that costs inside a loop.

A matrix is usually an array of arrays. matrix[i][j] is still O(1), but a row-major layout means a whole row sits together in memory — looping row-by-row touches memory in order, while looping column-by-column jumps around. That memory-locality difference gets its own page on the Advanced tier ("Time vs. Memory Trade-offs").

💻 See the code ▾
C# 
int[] arr = { 1, 2, 3, 4, 5 };
int i = 0, j = arr.Length - 1;
while (i < j)
{
    (arr[i], arr[j]) = (arr[j], arr[i]);  // ✅ swap in place — no new array
    i++;
    j--;
}

Two pointers close in from both ends — the array itself is mutated. O(n) time, O(1) extra space.

C# 
string report = "";
for (int i = 0; i < 10000; i++)
    report += i;   // ❌ copies the whole string so far, every time

Each += allocates a brand-new string and copies everything built so far — O(n²) total.

C# 
var sb = new StringBuilder();
for (int i = 0; i < 10000; i++)
    sb.Append(i);   // ✅ grows one buffer instead of copying
string report = sb.ToString();

StringBuilder grows one buffer in place — O(n) total for the same loop.

🌍 Real-world example ▾

An array is a row of same-size lockers bolted to a wall, numbered in order. Knowing a locker's number tells you exactly where to walk — no searching. Squeezing a new locker into the middle of the row means physically sliding every locker after it down by one.

The immutable-string trap shows up for real: a report-building loop using += gets visibly slower as row counts grow into the thousands — swapping it for a StringBuilder fixes it without touching any other logic.
