Core Web Vitals — does the page load, react and stay still?

"What are Core Web Vitals and how would you improve each?"

Why it matters ▾
🖼 LCP — loading
❗ ProblemThe page "finishes loading" by the clock, but the user is still staring at a blank or half-empty screen.
✅ SolutionLargest Contentful Paint times when the biggest visible image or text block appears — the moment it feels loaded.
RecallLCP = loads: when the main content shows.
👆 INP — responsiveness
❗ ProblemThe page looks ready, but taps and key presses lag because JavaScript is busy.
✅ SolutionInteraction to Next Paint measures how long the screen takes to respond after the user interacts. It replaced FID as the responsiveness vital in March 2024.
RecallINP = reacts: how fast the screen answers input.
📐 CLS — stability
❗ ProblemContent jumps as images, ads or fonts arrive, so the user taps the wrong thing.
✅ SolutionCumulative Layout Shift adds up unexpected movement. Keep the score small by reserving space before things load.
RecallCLS = jumps: how much the page moves by itself.
🔥 Easy interview recall

LCP → how fast it loads

INP → how fast it reacts

CLS → how much it jumps

Think: LCP → fix the hero image and the server INP → fix long JavaScript tasks CLS → reserve space for everything that arrives late

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

INP replaced FID, and the scores come from real users. INP looks at interactions across the whole visit, not just the first tap. A lab tool like Lighthouse only estimates — the judged numbers are field data from real visitors.

🔄 Likely Follow-up

"Your LCP is slow — what do you check first?" Find what the LCP element actually is. If it's an image: is it lazy-loaded, too big, or discovered late? Then check server response time and render-blocking CSS or JavaScript.

🎯 Say this in the interview — the exact lines to land

"Core Web Vitals are three user-experience metrics: LCP for loading, INP for responsiveness, and CLS for visual stability. The good targets are LCP within 2.5 seconds, INP at 200 milliseconds or less and CLS at 0.1 or less, judged on real visits at the 75th percentile. I improve LCP by optimising and prioritising the main image, INP by breaking up long JavaScript tasks, and CLS by reserving space for images, ads and fonts."

  • LCP → the biggest element painted; good is 2.5 s or less.
  • INP → slow interactions; good is 200 ms or less; it replaced FID.
  • CLS → unexpected movement; good is 0.1 or less.
  • Fix LCP → right-size, prioritise, don't lazy-load the hero.
  • Fix INP → split long tasks so the main thread stays free.
  • Fix CLS → reserve space with width/height or aspect-ratio.
📖 Explanation ▾

Each vital watches a different stage of the render pipeline (see Browser Rendering). LCP is about getting the biggest element painted: a slow server, render-blocking CSS or JavaScript, and an image found late all push it back. CLS is about layout: a box gets moved after the first layout because something arrived with no reserved size. INP is about the main thread: while a long JavaScript task runs, the browser can't handle the tap or paint the next frame.

Thresholds are the published web.dev targets at the 75th percentile of real visits. INP replaced First Input Delay (FID) as a Core Web Vital in March 2024. A lab run such as Lighthouse has no real user input, so it usually uses a stand-in like Total Blocking Time for responsiveness. The fixes build on Lazy Loading & Resource Hints and CSS Performance.

💻 See the code ▾
HTML 
<!-- LCP: hero is not lazy, and gets high priority -->
<img src="hero.jpg" width="1200" height="600" fetchpriority="high" alt="…">

The main image loads first, and its size is known up front.

CSS 
img, video { aspect-ratio: 16 / 9; width: 100%; }  /* space reserved */
.ad-slot { min-height: 250px; }                       /* no jump when the ad arrives */

CLS fix: the box exists before its content does, so nothing shifts.

🌍 Real-world example ▾

Picture a shop: LCP is how soon the main product shows in the window, INP is how quickly the assistant reacts when you ask a question, and CLS is the shelves sliding around while you reach for something.
