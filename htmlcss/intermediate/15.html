float & clearfix — why the parent collapses and how to contain it

"What does float do, why does the parent collapse, and how do you clear it?"

Why it matters ▾
🌊 float
❗ ProblemA floated box leaves normal flow, so its parent forgets it exists and shrinks to zero height — borders and backgrounds wrap nothing, and the next block slides up beside or under the float.
✅ SolutionContain it: display: flow-root on the parent, a clearfix ::after with clear: both, or clear on the element after the float. For page layout, use flexbox or grid instead.
Recallfloat = text wraps around it; the parent doesn't count it in its height.
🔥 Easy interview recall

float = "lift the box out of the flow so text wraps around it — and the parent stops counting it."

Think: parent collapses to 0 → flow-root / clearfix / clear page layout → flex or grid · text around an image → float

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

clear goes on the element after the floats, not on the floats. It means "start below any float on this side". Without it (or flow-root), the parent ignores floated children and collapses to zero height.

🔄 Likely Follow-up

"Would you still use float for a page layout today?" No — flexbox and grid do that job. float is still the right tool for one thing: letting text wrap around an image (and shape-outside for curved wraps).

🎯 Say this in the interview — the exact lines to land

"float takes a box out of normal flow so text wraps around it. Because the parent ignores floated children, its height collapses to zero. I fix that with display: flow-root on the parent, a clearfix using clear: both, or clear on the next element — and for page layouts today I use flexbox or grid instead."

  • float → leaves normal flow; text wraps around it.
  • The parent collapses to zero height — it doesn't count floats.
  • clear: both → start below the floats.
  • Clearfix → an empty ::after that clears inside the parent.
  • display: flow-root → the modern one-line fix.
  • Flex and grid replaced floats for layout; float has no effect on flex or grid items.
📖 Explanation ▾

A floated element is shifted to the left or right edge of its container and removed from the normal flow of boxes, while text and inline content flow around it. In the layout step of the render pipeline (see Browser Rendering) a parent with height: auto only adds up its in-flow children — so if every child is floated, the parent ends up with no height.

There are four ways to make the parent contain its floats:

display: flow-rootclearfix ::afteroverflow: auto/hiddenclear on next element
How it worksparent becomes its own block formatting contextempty pseudo-element with clear: both at the endalso makes a new block formatting contextpushes that element below the floats
Costnone — one linea small extra rulecan clip shadows or add scrollbarsneeds an extra element, and the parent still collapses

Floats built whole page layouts for years; today Flexbox and Modern CSS Layout (grid) do that job better. Floats also stack with margin rules — see Margin Collapsing.

💻 See the code ▾
CSS 
.parent { }                          /* only floated children inside */
.child  { float: left; width: 100px; }
                                      /* ❌ parent height = 0 */

The float leaves the flow, so the parent has nothing to measure.

CSS 
.parent { display: flow-root; }       /* ✅ modern fix */

One line — the parent now grows to contain its floats.

CSS 
.clearfix::after {
  content: "";
  display: block;
  clear: both;                   /* sits below every float */
}

The classic clearfix — still found in older codebases.

🌍 Real-world example ▾

A magazine photo with words wrapping around it: the photo sticks out below the text block because the "frame" around the text was measured from the words alone — until you tell the frame to include the photo.
