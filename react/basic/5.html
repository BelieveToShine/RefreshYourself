React events — one listener, a synthetic wrapper, and no immediate call

"How does React handle events differently from plain DOM event handlers?"

Why it matters ▾
  • Calling the handler instead of passing it is one of the most common early React bugs — it looks harmless until you notice it fires on every render, not on click.
  • Comes up constantly the moment a button, row, or link needs a click handler that takes an argument.
  • A common interview opener, because it quietly tests whether you understand rendering, not just JSX syntax.
🔥 Easy interview recall

Pass the function, don't call it. onClick={fn}, never onClick={fn()}.

Think: handler reference vs. handler result — JSX needs the reference.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Calling the handler directly in JSX, like onClick={handleClick()}, is not just a stylistic choice. It calls the function immediately, during render — not on the actual click — which is a real bug; pass a bare reference (onClick={handleClick}) or wrap it in an inline arrow if it needs arguments.

🔄 Likely Follow-up

"What's the difference between stopPropagation() and preventDefault()?" stopPropagation() stops the event from bubbling up to parent handlers; preventDefault() stops the browser's own default behavior, like a link navigating or a form submitting — calling one does not imply or affect the other.

🎯 Say this in the interview — the exact lines to land

"React wraps native DOM events in its own synthetic event system for cross-browser consistency, attached through camelCase props like onClick. You always pass a reference to the handler, never call it directly in JSX — to pass an argument, wrap the call in an inline arrow function instead."

  • Pass the reference, not the result — onClick={handleClick}, not onClick={handleClick()}.
  • Need an argument? Use onClick={() => handleClick(id)}.
  • stopPropagation() vs. preventDefault() — bubbling vs. the browser's own default action, completely independent.
📖 Explanation ▾

React wraps every native DOM event in its own synthetic event before your handler ever sees it, mainly to smooth over small cross-browser handling differences — that's also why event props are camelCase (onClick) rather than the raw HTML attribute name (onclick).

JSX needs a reference to a function, not the result of calling one. onClick={handleClick} hands React the function itself, to run later on the actual click. onClick={handleClick()} calls it immediately, while the component is still rendering, and hands onClick whatever that call returns instead. Needing an argument doesn't change this — wrap the call in an inline arrow (() => handleClick(id)) so the call itself still only happens on click.

Bubbling still works the normal way, so a click on a nested element also reaches every parent handler above it. stopPropagation() stops that climb; preventDefault() stops a completely separate thing — the browser's own built-in behavior for that event (a link navigating, a form submitting) — which is why calling one never affects the other. The same reference-vs-value idea shows up again in forms: a controlled input's value lives in React state, updated on every onChange; an uncontrolled one lets the DOM hold its own value, read only through a ref when needed.

💻 See the code ▾
JSX 
<button onClick={handleClick()}>
  Save
</button>  // ❌ calls handleClick() now, during render

This runs immediately while the component renders — not when the button is clicked.

JSX 
<button onClick={handleClick}>
  Save
</button>  // ✅ passes the reference — runs only on click

<button onClick={() => handleClick(id)}>
  Delete
</button>  // ✅ inline arrow — still only calls it on click

Both hand React something to call later — a bare reference, or a small inline function that calls it with an argument.

🌍 Real-world example ▾

Handing someone a phone number to call later is passing the function reference — they call it when the time actually comes. Dialing it yourself right now and handing them the already-ringing phone is calling the function immediately. Only the first one is "call this when the time comes."
