Units & Sizing — em multiplies every time it nests, rem never does

"What's the difference between px, %, em, rem, and the viewport units — and when would you reach for min(), max(), or clamp()?"

Why it matters ▾
  • Sizing choices affect real responsiveness and accessibility — a page built entirely in px ignores a user's own font-size preference.
  • A very common early front-end question, often phrased as "walk me through the CSS units you know."
  • Assuming em and rem behave the same is one of the most common everyday CSS mistakes, and interviewers know it.
🔥 Easy interview recall

px → fixed, absolute

% → relative to the parent

rem → relative to the root — never compounds

vw / vh → relative to the viewport

Think: em → multiplies through every level of nesting rem → always the same size, no matter how deep it sits

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

em and rem are not interchangeable. Nested elements each setting font-size: 1.5em multiply on top of every ancestor's own font-size, so three levels can quietly balloon from 16px to 54px — rem always reads off the root's font-size, so it never compounds like that.

🔄 Likely Follow-up

"em vs. rem — when would you use each?" Reach for rem as the default for most sizing (font-size, spacing) since it stays predictable no matter how deeply it's nested; reach for em specifically when you want a value to scale with that one element's own font-size — like button padding that should grow or shrink along with that button's own text.

🎯 Say this in the interview — the exact lines to land

"px is a fixed, absolute unit. Percentages and em scale relative to a parent or the element's own font-size, while rem scales off the root font-size and never compounds. vw/vh scale off the viewport — svh/lvh/dvh exist because mobile browser chrome showing or hiding changes that viewport height. ch sizes text columns off character width, fr is a fractional unit only inside CSS Grid, and min()/max()/clamp() combine any of these into one fluid-sizing expression."

  • rem → safer everyday default for font-size and spacing — doesn't compound through nesting.
  • em → use it when a value should scale with that one element's own font-size, like a button's own padding.
  • svh / lvh / dvh → picked specifically to stop mobile browser chrome from making plain vh jump.
  • clamp(min, preferred, max) → one fluid-sizing expression instead of several media queries.
  • fr → a share of leftover space — only exists inside CSS Grid, not a general-purpose unit.
  • ch → sizes off the current font's "0" character — the standard way to cap a readable line length.
📖 Explanation ▾

px is the one truly absolute unit here — a pixel stays a pixel no matter what's around it. Every other common unit is relative to something else: % reads off a parent's own size, and the two font-based units — em and rem — read off a font-size, just not the same one.

em reads off the current element's own font-size, so if a parent already scaled its font-size with em, a nested child's em multiplies on top of that — three elements nested inside each other, each set to 1.5em, don't add up, they multiply: 1.5 × 1.5 × 1.5. rem always reads off the root <html> font-size instead, so 1.5rem means the same 24px no matter how deep it sits — that predictability is why rem is the safer everyday default.

vw/vh scale off the browser's viewport — but on mobile, the address bar and toolbar showing or hiding actually changes that viewport height mid-scroll, so plain vh can jump. svh/lvh/dvh give a stable choice instead (smallest, largest, or dynamically-tracking viewport height). ch sizes off a font's own "0" character — handy for capping a paragraph at a readable width. fr only exists inside CSS Grid, splitting leftover space into shares. min(), max(), and clamp(MIN, PREFERRED, MAX) combine any of the above into one expression, so a single line of CSS can do what used to take several media queries.

💻 See the code ▾
CSS 
html { font-size: 16px; }
.level1 { font-size: 1.5em; }        // 16 × 1.5 = 24px
.level1 .level2 { font-size: 1.5em; } // 24 × 1.5 = 36px — compounds

Nest one more level the same way and it keeps multiplying — swap every em here for rem and every level stays at 24px.

CSS 
h1 { font-size: clamp(1.5rem, 4vw + 1rem, 3rem); }

Never smaller than 1.5rem, never bigger than 3rem, fluid in between — one line instead of several media queries.

CSS 
.full-screen { height: 100dvh; }  // stays correct as mobile chrome shows/hides
p { max-width: 60ch; }            // readable line length, any font-size

dvh tracks the real, current viewport height on mobile; ch caps a line at roughly 60 characters no matter the font.

🌍 Real-world example ▾

rem is like pricing everything off one shared price list at the front register — no matter which aisle you're standing in, "1.5×" always means 1.5× the price on that one list. em is like each aisle marking its own prices "1.5× the aisle before it" — walk through three aisles and the price has quietly tripled, even though every sign said the exact same "1.5×."
