Content projection — the child owns the frame, the parent fills the slots

How do you build a reusable card/modal component that accepts custom content?

Why it matters ▾
🧩 Content projection
❗ ProblemA card or modal component with its content hard-coded cannot be reused — every screen that needs a different title, body or buttons forces a copy of the component or a long list of inputs.
✅ SolutionThe card keeps the frame (border, padding, layout) and leaves slots with <ng-content>. Each parent writes its own content inside the card's tags and Angular drops it into the right slot.
Recallng-content = a hole the parent fills.
🔥 Easy interview recall

Reusable shell = "the child owns the frame, the parent fills the slots."

Think: ng-content = slot, ng-container = wrapper with no DOM element, ng-template = markup you render later.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Projected content is still created when the slot is hidden. Putting <ng-content> inside an @if only hides it — the parent's content is already built and its code already runs. If it should only be created when shown, pass an ng-template instead and render it with ngTemplateOutlet.

🔄 Likely Follow-up

"When do you use ng-template instead of ng-content?" When the child must decide when and how often to render the content, or pass data back into it — a list that draws one custom row per item is the classic case. ng-content is for fixed, render-once slots.

🎯 Say this in the interview — the exact lines to land

"A reusable card keeps its own frame and exposes slots with ng-content; the parent writes its content between the card's tags and I use select to send each piece to the right slot. When the child needs to render the content many times or pass data into it, I pass an ng-template and render it with ngTemplateOutlet."

  • <ng-content> = a slot where the parent's content appears.
  • select="..." sends matching content to a named slot; the rest goes to the default slot.
  • <ng-container> is a wrapper that adds no DOM element — handy for @if or ngTemplateOutlet.
  • <ng-template> + ngTemplateOutlet renders markup on demand, with data passed in through a context object.
  • Projected content is always created by the parent, even if the slot is not shown.
📖 Explanation ▾

Content projection lets a component accept markup from its parent. In the child you write <ng-content>; whatever the parent puts between the child's tags is shown at that spot. With select (a CSS selector such as [card-title]) you can have several slots, and anything that matches no selector falls into the plain <ng-content> default slot.

<ng-container> is a wrapper that never becomes a real element in the page. Use it when you need to attach @if, a directive or ngTemplateOutlet without adding an extra <div>. <ng-template> is different: it is markup that is not drawn until something renders it. The child can take one as an input (or read it with a content query) and draw it with ngTemplateOutlet, passing a context so the parent's template can use the data — for example one custom row per item.

One thing to remember: projected content belongs to the parent. The parent creates it, its bindings run in the parent's context, and it is created even if the child never shows the slot. That is why a template is the better tool when the child should decide whether and how often to render.

💻 See the code ▾
HTML 
<!-- card.component.html — the frame, with slots -->
<div class="card">
  <header><ng-content select="[card-title]"></ng-content></header>
  <ng-content></ng-content>
  <footer><ng-content select="[card-footer]"></ng-content></footer>
</div>

<!-- parent -->
<app-card>
  <h3 card-title>Order #42</h3>
  <p>Shipped today</p>
  <button card-footer>Track</button>
</app-card>

The title and button land in their named slots; the plain <p> goes to the default slot.

HTML 
<!-- list.component.html — child renders the parent's template once per item -->
@for (item of items(); track item.id) {
  <ng-container
    [ngTemplateOutlet]="rowTpl()"
    [ngTemplateOutletContext]="{ $implicit: item }"></ng-container>
}

<!-- parent -->
<app-list [items]="orders">
  <ng-template #row let-order><b>{{ order.name }}</b></ng-template>
</app-list>

The child owns the loop; the parent owns how one row looks. (The child needs NgTemplateOutlet in its imports and reads rowTpl with a content query such as contentChild.)

🌍 Real-world example ▾

A picture frame shop. The frame (border, size, hanger) is always the same, and each customer slides in their own photo — the frame decides where the photo sits, and never needs to know what the photo is.
