Giving a fixed set of options real names

Why it matters ▾
  • Explains why comparing a status to a "magic number" like 2 is a code smell.
  • Shows up constantly — order status, day of week, log level, HTTP-ish state.
  • Sets up switch statements/expressions used on almost every enum.
📖 Explanation ▾

An enum gives a small, fixed set of options real names instead of raw numbers. Under the hood each name is backed by an integer — starting at 0 and counting up by default — but the whole point is that your code reads Status.Active, never a bare 1 that means nothing on its own.

You can assign the numbers yourself (Closed = 5) when the exact value matters — stored in a database, sent over a wire — but for a purely internal set of options, the default numbering is fine.

A separate, more advanced use — the [Flags] attribute — lets an enum's values be combined with bitwise OR, for "more than one option at once" cases (permissions, days selected). That's the exception, not the everyday case.

💻 See the code ▾ 
enum Status { Pending, Active, Closed }   // 0, 1, 2 by default

Status current = Status.Active;

if (current == Status.Active)              // compare by name, not number
    Console.WriteLine("Still open.");

switch (current)
{
    case Status.Pending: /* ... */ break;
    case Status.Active:  /* ... */ break;
    case Status.Closed:  /* ... */ break;
}
🌍 Real-world example ▾

A traffic light. The light is always exactly one of a fixed, known set — Red, Yellow, Green. You'd never say "the light is state 2" out loud; you say "the light is Green." An enum is that same idea, written into the code.

🎯 Say this in the interview — the exact lines to land

  • An enum is a named set of integer constants — readable instead of magic numbers.
  • Numbering starts at 0 by default — you can override it when the value matters.
  • Compare and switch on the name, never the raw underlying number.
  • [Flags] enums are the exception — for combining multiple options at once.
