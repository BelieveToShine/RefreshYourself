Association, Aggregation & Composition — uses, shares, or owns?

"What's the difference between association, aggregation and composition?"

Why it matters ▾
🔗 Association, aggregation, composition
❗ ProblemIf every object link is just called "has-a", nobody can tell whether deleting a Team should also delete its players, or whether deleting an Order should delete its lines — so lifetimes get decided by accident.
✅ SolutionThe three terms grade the link by strength: association only uses, aggregation holds a part that can live on without it, composition owns a part that goes when it goes.
RecallThree has-a strengths = uses, shares, owns.
🔥 Easy interview recall

Association → uses it

Aggregation → has it, shares it

Composition → has it, owns it

Think: Doctor sees Patient → neither owns the other Team has Players → they outlive the team Order owns OrderLines → they go with the order

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Having a field does not make it composition. A Team with a List<Player> is usually aggregation — the players were created elsewhere and outlive the team. Composition means the whole creates the part and owns its lifetime.

🔄 Likely Follow-up

"How do you tell which one it is in C# code?" Look at who creates the part and who else holds a reference. Created inside the whole and not handed out is typically composition; passed in from outside and used elsewhere is aggregation.

🎯 Say this in the interview — the exact lines to land

"All three are has-a links of increasing strength. Association is one object just using another. Aggregation is a whole–part link where the part can live without the whole. Composition is a whole–part link where the whole owns the part's lifetime, so the part doesn't outlive it."

  • Association → uses or knows about another object; neither owns the other.
  • Aggregation → whole–part, part outlives the whole; hollow diamond in UML.
  • Composition → whole–part, part dies with the whole; filled diamond in UML.
  • Team–Player is aggregation; Order–OrderLine is composition.
  • In C# nothing enforces it — it's a design intent shown by who creates and holds the part.
📖 Explanation ▾

Association is the loosest link: one object knows about or uses another, nothing more. A Doctor sees a Patient; either can exist and be used without the other. In UML it's a plain line.

Aggregation and composition are both whole–part links, and the diamond sits on the whole's side. They differ only by lifetime. A Team aggregates players: disband the team and the players still exist. An Order composes its lines: an order line has no meaning without its order, so it goes when the order goes.

C# has no keyword for any of this. It's a design choice you can read from the code: does the whole create the part and keep it private, or does it receive a part that someone else also holds? Aggregation is the looser link, so it keeps coupling lower than composition does.

💻 See the code ▾
C# 
public class Doctor
{
    public void Treat(Patient patient)   // just uses it for this call
    {
        patient.RecordVisit();
    }
}

Association — Doctor uses a Patient; it keeps no ownership and no long-lived link.

C# 
public class Team
{
    private readonly List<Player> _players = new();

    public void Add(Player player)       // created elsewhere, passed in
        => _players.Add(player);         // players outlive the team
}

Aggregation — the team holds players it did not create, and disbanding it does not end them.

C# 
public class Order
{
    private readonly List<OrderLine> _lines = new();   // created and owned here

    public void AddLine(string sku, int qty)
        => _lines.Add(new OrderLine(sku, qty));        // lines never leave the order
}

Composition — the order creates its lines and keeps them private, so they live and die with it.

🌍 Real-world example ▾

A building and what's in it. Demolish the building and its rooms are gone with it — composition. Close a library and its books still exist and can move to another library — aggregation. A doctor and a patient just meet; neither belongs to the other — association.
