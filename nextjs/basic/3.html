A folder isn't a route — until page.js says so

"How does a folder become a URL in the App Router?"

Why it matters ▾
📁 File-Based Routing
❗ ProblemWithout some automatic rule, every URL path would need to be manually registered somewhere — a separate router config file to keep in sync with the actual pages.
✅ SolutionIn the App Router, a folder's path under app/ becomes a URL segment automatically, and a page.js file inside that folder is what actually makes the route renderable — no separate router config needed.
RecallFolder path = the URL. page.js = what actually renders there.
🔥 Easy interview recall

File-based routing = "the folder is the URL, page.js is what renders there."

Think: app/blog/post/ is the URL /blog/post — but it only renders if page.js actually lives inside it.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Adding a folder under app/ doesn't automatically make it a visible route. Without a page.js inside it, the folder contributes to the URL structure of its children but renders nothing itself at that level.

🔄 Likely Follow-up

"What other special filenames exist inside a route folder?" layout.js (shared UI wrapper), loading.js (loading UI), error.js (error UI), and route.js (an API endpoint instead of a page) — each plays its own specific, reserved role.

🎯 Say this in the interview — the exact lines to land

"In the App Router, a folder's path under app/ becomes a URL segment, but only a page.js file inside that folder actually makes it a renderable route — a folder with no page.js just organizes the path for its children without rendering anything itself."

  • Folder path → URL segment, automatic.
  • page.js → makes it render; without it, nothing shows.
  • layout.js / loading.js / error.js / route.js → other reserved roles inside a route folder.
📖 Explanation ▾

Every folder under app/ contributes its name as a URL segment — app/blog/post/ always corresponds to the path /blog/post, whether or not anything actually renders there.

What makes that path visible is a specific file inside it: page.js. A folder with no page.js is still a real part of the URL structure — just not a route on its own. It's useful exactly for this: grouping related routes together, or holding a shared layout.js, without that grouping folder itself being a page.

FileRole inside a route folder
page.jsmakes the folder a renderable route
layout.jsshared UI wrapper, persists across child navigation
loading.jsshown while the route's content is loading
error.jsshown if the route throws an error
route.jsan API endpoint at this path instead of a page
💻 See the code ▾
JavaScript 
// app/blog/post/page.js → URL: /blog/post
export default function PostPage() {
  return <h1>One blog post</h1>;   // ✅ this file is what makes it render
}

Remove this file and /blog/post stops being a route — the folder alone was never enough.

🧭 Use Cases — recognize these when they happen to you ▾
1 You add a page.js inside a new folder and expect it to just work

This is the #1 scenario you'll actually run into: create a folder, drop a page.js in it, and the route exists — no router file to edit anywhere else.

RememberFolder + page.js → the route exists, nothing else to register.
2 You group related routes under a folder that holds no page.js of its own

app/account/ can hold a shared layout.js for /account/settings and /account/billing without itself being a page — the grouping folder organizes the path without rendering anything at /account directly.

RememberA folder can organize/share layout without being its own route.
3 You create the folder but forget to add page.js, then wonder why the route 404s

An empty folder (or one with only other files, no page.js) reserves the URL segment but renders nothing — visiting it directly is a 404, which surprises anyone expecting the folder alone to be enough.

RememberNo page.js in the folder → that exact URL 404s.
🌍 Real-world example ▾

A labeled drawer vs. what's actually inside it. A drawer labeled "Blog" exists as soon as you name it — but it's empty until you actually put something in it. The folder name is the label (the URL); page.js is the thing you actually put inside that makes opening that drawer show you something.
