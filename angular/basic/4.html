🔥 Must Know

Directive — the thing a component secretly already is

What's the actual difference between a component and a directive, and between the two kinds of directive?

Why it matters ▾
👓 Attribute directive
❗ ProblemAn element already in the DOM sometimes just needs its look or behavior tweaked — tearing it out and rebuilding it for a simple class toggle or hover highlight would be overkill and would wipe out its state.
✅ SolutionAn attribute directive attaches behavior to that same element without a template of its own — it just edits a property, so the element never leaves the DOM (NgClass, NgStyle, a custom highlight directive).
RecallAttribute directive = same element, only its look/behavior changes.
🏗️ Structural directive
❗ ProblemElements need to be conditionally added, removed, or repeated based on data — and mistaking this for a simple CSS hide is the classic follow-up trap right after any *ngIf/*ngFor question.
✅ SolutionA structural directive changes the DOM itself: *ngIf/@if adds or removes the element (destroying and rebuilding it), *ngFor/@for creates one instance per item in an iterable.
RecallStructural directive = adds/removes the element itself, not a CSS hide.
👤 Component
❗ ProblemSometimes a piece of UI needs its own markup, not just a behavior tweak applied to an element that already exists — neither an attribute nor a structural directive carries a template.
✅ SolutionA component is technically a directive too — the one kind that also brings its own view/template, so it renders a whole new subtree rather than modifying an existing element.
RecallComponent = a directive + its own template.
🔥 Easy interview recall

Attribute directive → changes look/behavior, same element

Structural directive → adds/removes the element itself

Component → a directive + its own template

Think: *ngIf and @if don't hide anything — they destroy and rebuild.

⚠️ Common Trap

*ngIf/@if is not "hiding" an element like display:none. It actually destroys and recreates that element (and everything inside it) every time the condition flips — re-running its lifecycle hooks and wiping any local state it held.

🔄 Likely Follow-up

"Why does @for require track but *ngFor didn't strictly require trackBy?" Angular made track mandatory specifically because an easy-to-forget implicit default (object identity) was a common source of "state got wiped after a reorder" bugs under *ngFor — forcing the decision up front prevents that whole bug class.

🎯 Say this in the interview — the exact lines to land

"A directive attaches behavior to an existing element without a template of its own. An attribute directive changes how that element looks or behaves; a structural directive changes the DOM itself, adding or removing elements. A component is technically a directive too — just one that also carries its own template."

  • Attribute directive → use for a reusable look/behavior tweak on an existing element, e.g. highlight-on-hover.
  • Structural directive → use when elements need to be conditionally added, removed, or repeated.
  • @for requires track → no implicit default, so you always state how Angular should identify "the same item."
📖 Explanation ▾

A directive is a class that attaches behavior to an existing DOM element or component, without necessarily changing what's rendered structurally. The real hierarchy: directives split into attribute directives and structural directives — and a component is technically a third case, a directive that also carries its own view/template.

Attribute directives (NgClass, NgStyle, a custom highlight directive) change appearance or behavior on the same element — no new DOM appears. Structural directives (*ngIf, *ngFor, *ngSwitch) change the DOM itself. *ngIf doesn't hide its element with CSS — it actually adds or removes it (and everything inside it) from the DOM based on the expression's truthiness; the * is sugar Angular expands into an <ng-template>. *ngFor creates one DOM instance per item in an iterable, tracked (by default, by object identity) so Angular knows what actually changed between renders.

Modern Angular adds native control-flow syntax — @if/@else, @for (... ; track ...), @switch — built directly into the template compiler rather than imported as directives, generally faster, and the modern default going forward; existing *ngIf/*ngFor code still runs, and both are supported. @for requires an explicit track expression, with no implicit fallback. A custom directive is just a class decorated with @Directive({ selector: '[appHighlight]' }), usually reading/reacting to the host element with @HostBinding/@HostListener (or the newer host metadata object) and inject(ElementRef) for direct DOM access.

🧭 Use Cases — recognize these when they happen to you ▾
1 You need to show, hide, or repeat a whole element based on a condition or a list

This is the #1 scenario you'll actually build — reach for a structural directive (*ngIf/@if, *ngFor/@for). It doesn't just hide the element with CSS; it adds or removes it from the DOM, destroying and rebuilding it (and its state) each time the condition flips.

RememberShow/hide/repeat a whole element → structural directive, not a style tweak.
2 You need to change an existing element's classes or inline styles based on some state

Reach for an attribute directive (NgClass, NgStyle, or a custom one) — it edits a property on the element that's already there. No new DOM appears and nothing gets destroyed; only the look/behavior changes.

RememberChanging look/behavior on the same element → attribute directive, no DOM impact.
3 You start writing a custom directive that also needs to render its own markup

Attribute and structural directives never carry a template of their own — that's what the table above already shows. Candidates sometimes try to force new markup into a directive; the fix is to reach for a component instead, since a component is the one kind of directive that actually brings a view.

RememberNeed new markup, not just behavior → component, not a directive.
🌍 Real-world example ▾

Glasses, a doorway, and a new person. An attribute directive is like handing someone glasses — it changes how they see or behave, same person underneath. A structural directive is like deciding whether that person is even in the room at all — adding or removing them entirely. A component is a whole new person walking in, with their own face (template) and personality (logic).
