TaskGroup — when one task fails, its siblings are cancelled, not left running

"How do you run concurrent tasks safely in asyncio and cancel them on failure or timeout?"

Why it matters ▾
🧵 Structured concurrency
❗ ProblemWith a bare create_task or gather, other tasks can keep running after a sibling fails or the caller gives up — orphaned work, lost errors, nothing stopping a hang.
✅ SolutionTaskGroup ties every task to one async with block: it waits for all of them, cancels the rest if one fails, and asyncio.timeout() puts a deadline on the whole block.
RecallTaskGroup = one scope owns its tasks — fail one, cancel the rest.
🔥 Easy interview recall

TaskGroup = "one scope owns its tasks — fail one, cancel the rest."

Think: TaskGroup → one task fails, siblings are cancelled timeout() → block too slow, cancelled, TimeoutError gather → one fails, the others keep running

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

asyncio.gather does not cancel the other tasks when one fails. The first error reaches you straight away, but the rest keep running in the background unless you cancel them yourself.

🔄 Likely Follow-up

"What if two tasks in the group fail?" The group raises one ExceptionGroup holding both errors, and you handle them by type with except*.

🎯 Say this in the interview — the exact lines to land

"In asyncio, a TaskGroup runs tasks as one unit: if any task fails, the rest are cancelled and the errors come out together as an ExceptionGroup. asyncio.timeout() puts a deadline on a whole block. Both need Python 3.11 or newer."

  • TaskGroup → one failure should stop the whole batch — no task is left running.
  • gather → collect all results — add return_exceptions=True if partial failure is fine.
  • asyncio.timeout(n) → one deadline for a block; raises TimeoutError.
  • wait_for(aw, n) → deadline for a single awaitable.
  • Group errors → handle with except*.
  • Cancellation lands at a task's next await — code that never awaits can't be cancelled.
📖 Explanation ▾

A TaskGroup (Python 3.11+) is a scope that owns its tasks. Write async with asyncio.TaskGroup() as tg:, then tg.create_task(...) for each job. The block does not finish until every task in it has finished, so nothing is left running by accident. If a task raises an error, the group cancels the other tasks and, once everything has stopped, raises an ExceptionGroup holding the errors.

asyncio.timeout(seconds) (3.11+) is the matching tool for deadlines. Wrap a block in async with asyncio.timeout(2): and if it takes longer, the work inside is cancelled and TimeoutError is raised. Put it around a TaskGroup and one deadline covers the whole group.

gather is the older way: it returns results in order, but when one awaitable fails the error reaches you at once while the others keep running unless you cancel them. Cancellation is delivered as CancelledError at a task's next await. On Python older than 3.11, use gather and wait_for instead.

💻 See the code ▾
Python 
import asyncio

async def ok():
    await asyncio.sleep(1)
    print("ok finished")      # never printed: cancelled first

async def boom():
    await asyncio.sleep(0.1)
    raise ValueError("boom")

async def main():
    try:
        async with asyncio.TaskGroup() as tg:
            tg.create_task(ok())
            tg.create_task(boom())
    except* ValueError as eg:   # ✅ catches errors inside the group
        print("caught", len(eg.exceptions), eg.exceptions[0])

asyncio.run(main())

Prints only caught 1 boom. When boom() fails after 0.1 seconds, the group cancels ok() while it is still sleeping, so "ok finished" never appears.

Python 
async def slow():
    await asyncio.sleep(10)

async def main():
    try:
        async with asyncio.timeout(0.5):
            await slow()
    except TimeoutError:
        print("too slow, cancelled")

asyncio.run(main())

Prints too slow, cancelled. After 0.5 seconds the work inside the block is cancelled and TimeoutError is raised at the async with.

🌍 Real-world example ▾

A page needs the user, their orders and some recommendations, fetched in parallel. If the user lookup fails there is no point waiting for the rest, so a TaskGroup cancels them — and an asyncio.timeout(2) around the whole thing means the request can never hang.
