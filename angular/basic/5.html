Pipes — pure by default, and why that's the whole performance story

What's the difference between a pure and an impure pipe, and why does it matter?

Why it matters ▾
  • Explains a common invisible bug — a list that silently stops updating on screen is very often a pure pipe fed a mutated-in-place array.
  • A direct performance question — impure pipes are one of the first things flagged in a change-detection performance review.
  • A near-guaranteed follow-up to "what is a pipe," since it tests whether you understand change detection, not just the | syntax.
🔥 Easy interview recall

pure: true → reference changed only

pure: false → every change-detection cycle

Think: pure is memoized and cheap. impure has no shortcut — it runs every tick.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

.push() on the array a pure pipe reads from will make it re-render. It won't — the array's reference never changed, so Angular's pure-pipe check sees "same reference, skip" even though the contents actually did.

🔄 Likely Follow-up

Is the built-in async pipe pure or impure, and why does that answer matter here? Impure, deliberately — it has to check on every change-detection cycle whether the Observable/Promise it's subscribed to has produced a new value, since the template expression itself (someObservable$) keeps the same reference the whole time, so a pure check could never key off it.

🎯 Say this in the interview — the exact lines to land

"A pipe transforms a value for display without touching the underlying data. Pure is the default — it only reruns when the input's reference changes — while an impure pipe reruns on every change-detection cycle, which is why pure is the safer default for performance."

  • pure: true (default) → reruns only on a reference change — cheap, memoized.
  • pure: false → reruns every CD cycle — expensive if the transform does real work.
  • AsyncPipe → impure on purpose — it has to watch a stream, with no reference change to key off.
  • Mutating in place (.push()) → a pure pipe won't notice — use a new array reference instead.
  • Pipe vs. a template method call → the pipe gets caching, the method call reruns unconditionally every cycle.
📖 Explanation ▾

A pipe is a class decorated with @Pipe that transforms a value for display in a template, applied with the | syntax — {{ value | myPipe }}. It never touches the underlying data; it just returns a new, transformed value for the view to show.

Pure is the default, whether you write pure: true or leave the flag off entirely. Angular only reruns a pure pipe when the bound expression's reference changes — a new array/object, or a changed primitive. Impure (pure: false) reruns on every single change-detection cycle, no matter what. That's the entire performance story: a pure pipe only does work when there's a real reason to, an impure one does work constantly.

This is also exactly why the built-in async pipe is impure on purpose — an Observable's own variable reference never changes, so a pure check could never notice a new value arriving from the stream. Impure is the deliberate exception for a real case a reference check can't cover, not a shortcut to reach for casually.

💻 See the code ▾
TypeScript 
@Pipe({ name: 'truncate' })  // no pure: false — pure by default
export class TruncatePipe implements PipeTransform {
  transform(value: string, limit = 20) {
    return value.length > limit ? value.slice(0, limit) + '…' : value;
  }
}

No pure: false flag needed — Angular's default is pure, so this only reruns when value or limit actually changes.

TypeScript 
items.push(x);            // ❌ pipe won't rerun — same array reference
items = [...items, x];   // ✅ new reference — pipe reruns

Same data change, two different outcomes — only the second one gives the pure pipe a reason to notice.

🌍 Real-world example ▾

A pure pipe is a photo you only reprint when someone hands you a genuinely different photo. An impure pipe is reprinting a fresh copy every single minute just in case something in the original changed — whether or not it actually did.
