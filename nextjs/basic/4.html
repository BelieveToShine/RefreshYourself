layout.js — the UI that survives navigation

"Why doesn't a layout re-fetch its data every time you navigate between its child pages?"

Why it matters ▾
🧱 layout.js
❗ ProblemIf a shared nav or sidebar re-rendered — and refetched its own data — on every single page navigation, every click would feel like a fresh reload: flashing UI, repeated requests for data that never changed.
✅ Solutionlayout.js wraps page.js (and any nested routes below it) in shared UI that persists across navigation between its own child routes — React keeps the layout mounted and only swaps the inner page content.
Recalllayout.js wraps the page and stays mounted — only the inner page content swaps.
🔥 Easy interview recall

Layout = "the frame that stays, while the picture inside it changes."

Think: layout.js wraps page.js — navigate A → B, the layout never remounts, only the inner slot does.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Expecting a layout to re-run its own data-fetching or state setup on every child-page navigation. It deliberately doesn't — that's the performance benefit; reach for template.js instead if a fresh instance per navigation is actually the goal.

🔄 Likely Follow-up

"Does every route need a layout.js?" No — a nested route with no layout.js of its own just uses whichever ancestor layout.js is in scope. A ROOT layout.js, at the top of app/, is the only one that's mandatory.

🎯 Say this in the interview — the exact lines to land

"layout.js wraps page.js, and any nested routes below it, in shared UI that persists across navigation — React keeps it mounted and only swaps the inner page content, which is exactly why it doesn't re-fetch or re-run its own setup on every navigation. template.js is the rare alternative that does remount every time, for when a fresh instance per navigation is actually the goal."

  • layout.js → stays mounted across navigation between its child routes.
  • template.js → remounts every time — use only when fresh state per navigation is the goal.
  • Only a root layout.js is mandatory; nested routes fall back to the nearest ancestor layout.
📖 Explanation ▾

layout.js renders once around a route and all of its nested children. Navigating between those children only swaps what's inside the layout's own slot — the layout component itself is never torn down and rebuilt, so its state (open dropdowns, scroll position, anything it fetched) survives the navigation.

template.js looks almost identical in shape but behaves the opposite way — React treats it as a brand-new instance on every navigation, which is useful specifically when you want a fresh mount each time (a per-page enter animation, for example), at the cost of losing whatever a persistent layout would have kept.

💻 See the code ▾
JavaScript 
// app/dashboard/layout.js
export default function DashboardLayout({ children }) {
  return (
    <>
      <Sidebar />             // ✅ mounted once, stays put
      {children}              // the matching page.js renders here
    </>
  );
}

children is the slot — only what's passed there changes between navigations.

JavaScript 
// app/dashboard/template.js — same shape, different behavior
export default function DashboardTemplate({ children }) {
  return <div className="fade-in">{children}</div>;  // ⚠️ remounts every navigation
}

A fresh instance every time is the point here — a persistent layout wouldn't replay this animation on every page.

🧭 Use Cases — recognize these when they happen to you ▾
1 A sidebar's scroll position or open/closed state should survive page clicks

This is the #1 scenario you'll actually run into: put the sidebar in layout.js and its open/closed state and scroll position just keep working as the user clicks between pages — nothing to manually preserve.

RememberShared, stateful nav/sidebar → belongs in layout.js.
2 Dashboard tabs that swap content without a visible reload

Because the shared chrome around the tabs lives in a layout, switching tabs feels instant — only the inner content region updates, not the whole screen.

RememberNo remount → tab switches feel instant, not like a reload.
3 You want a fresh enter animation on every single page, but used layout.js

An enter animation placed in layout.js only plays once, on first mount — it won't replay on later navigations because the layout never remounts. template.js is the one built specifically to remount every time.

RememberNeed it to replay every navigation → template.js, not layout.js.
🌍 Real-world example ▾

A picture frame on a wall. You swap the photo inside it all the time, but the frame itself stays screwed to the wall — you don't take it down and rehang it for every new photo. layout.js is the frame; the page content is the photo.
