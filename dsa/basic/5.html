Hash Table — the one trick that turns O(n²) into O(n)

"What is a hash table / hash map, and how does it give average O(1) lookup?"

Why it matters ▾
  • Turns a brute-force nested-loop check into a single pass — the highest-leverage rewrite in the whole interview.
  • Almost every "count occurrences," "find a duplicate," or "does a pair sum to X" question reduces to one hash map.
  • A common opener: expect the interviewer to ask you to improve a nested-loop solution using exactly this structure.
🔥 Easy interview recall

Hash table = "run the key through a function to know exactly which slot to check — no scanning."

Think: is target - x already in the map? → O(n) two-sum instead of checking every pair.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Hash map operations are not always O(1). That's the average case with a decent hash function and a healthy load factor — a poor hash function, or enough collisions piling into one bucket, degrades every operation toward O(n).

🔄 Likely Follow-up

"What makes a hash function good?" It spreads keys evenly across buckets so nothing clusters, and it's cheap to compute — a poor one funnels many keys into the same few buckets and drags performance toward O(n).

🎯 Say this in the interview — the exact lines to land

"A hash table hashes the key to compute a bucket index directly, giving average O(1) insert, lookup, and delete. Collisions — two keys landing in the same bucket — are normal and handled with chaining or open addressing, and the table resizes once the load factor gets too high to keep that average O(1)."

  • Collision → expected, not a bug — handled by chaining (a list per bucket) or open addressing (probe another slot).
  • Load factor rises → more collisions, O(1) slips toward O(n) — that's why the table resizes and rehashes.
  • Frequency counting → one pass with a map turns "how many times does X appear" into O(n).
  • Two-sum pattern → check if target − x was already seen before adding x — O(n), not O(n²).
📖 Explanation ▾

A hash table maps a key to a value by running the key through a hash function, producing a number, then using that number (usually the key's hash modulo the table's current size) as the index into an array of "buckets." That's the whole trick: instead of scanning entries one by one the way a linked list would (O(n)), the table computes exactly where to look, giving average-case O(1) insert, lookup, and delete.

Collisions — two different keys hashing to the same bucket — are unavoidable once there are more possible keys than buckets (the pigeonhole principle), and every hash table has to plan for them. Chaining keeps a small list of every entry that landed in that bucket. Open addressing instead probes a different bucket, following a fixed rule, until it finds one that's free.

ChainingOpen addressing
Where a collision goessame bucket keeps a small listprobes a different bucket
Extra memorya list per bucketnone — stays inside one array
Gets tricky when…one bucket's list grows longthe array fills up — probing gets long

Load factor is entries divided by buckets. As it climbs, collisions get more frequent and that average O(1) starts sliding toward O(n) — which is why a hash table automatically grows its bucket array and rehashes everything once load factor crosses a threshold (commonly around 0.75), the same amortized-cost trade-off a dynamic array makes when it resizes.

💻 See the code ▾
Pseudocode 
count = {}
for x in arr:
    count[x] = count.get(x, 0) + 1   // one map, one pass

Frequency counting: one pass with a map turns "how many times does X appear" into O(n) instead of comparing every pair.

Pseudocode 
seen = {}
for x in arr:
    if (target - x) in seen:
        return (x, target - x)   // ✅ found — O(n)
    seen[x] = true              // remember x for later

Two-sum: check if the partner you need is already in the map before adding the current value — one pass, O(n), instead of checking every pair.

🌍 Real-world example ▾

A parking garage with numbered spots is a hash table. Your ticket number tells you exactly which spot to check — you don't drive past every level scanning for your car. Two cars occasionally getting assigned the same numbered spot by mistake is the collision; the garage's fix (a second spot right next to it) is chaining.
