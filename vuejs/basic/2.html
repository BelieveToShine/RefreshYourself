createApp() + .mount() — turning a plain <div> into a live app

"How do you create and mount a Vue application?"

Why it matters ▾
🚀 createApp + mount
❗ ProblemA component tree described in code doesn't do anything on its own — the browser's actual DOM has no idea it exists yet.
✅ SolutioncreateApp() builds the app instance, and .mount() attaches it to a real DOM element, replacing that element's contents with the live, rendered component tree.
RecallcreateApp = build it. mount = attach it to a real element.
🔥 Easy interview recall

Mounting = "createApp builds the app; .mount() attaches it to a real DOM element."

Think: createApp(App).mount('#app') — the element has to already exist in the HTML when that line runs.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Running the mounting script before the target element exists in the HTML. If the <script> executes before #app is parsed, mounting fails silently or throws — the element has to already be there.

🔄 Likely Follow-up

"Can you mount more than one Vue app on one page?" Yes — createApp() instances are fully independent; each manages its own subtree and state, and they don't share reactivity or plugins unless you explicitly wire that up.

🎯 Say this in the interview — the exact lines to land

"createApp(RootComponent) creates an app instance, and calling .mount('#app') on it renders that component tree into a real DOM element — replacing whatever was already inside that element."

  • The target element must already exist in the DOM when .mount() runs.
  • Multiple createApp() calls → fully independent apps, no shared state by default.
  • .mount() replaces the element's existing content, it doesn't append to it.
📖 Explanation ▾

createApp() is the entry point — it takes a root component and returns an app instance, a separate object you can still configure (register plugins, global components, directives) before anything actually appears on screen.

Calling .mount() on that instance is the step that actually touches the DOM. It takes a CSS selector (or a real DOM element) and renders the root component's template into it — overwriting whatever static markup was already sitting inside that element. The element itself keeps its identity; only its contents change.

Because mounting is a real DOM operation, the target element has to exist at the moment .mount() runs. A <script> tag placed in the document <head>, executing before the body has parsed, is a common way to hit this — the fix is either placing the script after the target element, or deferring it.

💻 See the code ▾
Vue 
import { createApp } from 'vue';
import App from './App.vue';

createApp(App).mount('#app');  // ✅ #app must already exist in index.html

The usual entry file (main.js) in a Vite-scaffolded project — two steps, build then attach.

Vue 
// Two independent apps on one page
createApp(HeaderWidget).mount('#header');
createApp(ChatWidget).mount('#chat');   // ✅ separate state, separate lifecycle

Each createApp() call is its own, fully independent app instance.

🧭 Use Cases — recognize these when they happen to you ▾
1 You're mounting onto a standard Vite-built index.html

The scaffold already places the mount script tag right before </body> — by the time it runs, #app is already in the DOM. This is the setup you'll hit in almost every real project.

RememberScript after the element → mount just works.
2 You're embedding two separate widgets on one legacy page

Two independent app instances, each mounted to its own element. They don't share reactive state unless you deliberately pass something between them.

RememberTwo widgets → two independent createApp() calls.
3 The mount script runs before the target element is parsed

A plain <script> in <head> runs before the body is parsed, so document.querySelector('#app') finds nothing. Mount either after the element, or inside a DOMContentLoaded handler.

RememberScript runs too early → mount target doesn't exist yet.
🌍 Real-world example ▾

It's like a stage crew building a set backstage, then rolling it out onto a marked spot on an already-built stage. The spot on the stage (the DOM element) has to exist before the crew can roll the set (the app) into it.
