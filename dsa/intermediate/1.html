Two pointers & sliding window — turning O(n²) into O(n)

"How would you avoid a nested loop when scanning an array or string — say, finding the longest substring without repeating characters?"

Why it matters ▾
  • The highest-leverage rewrite in coding interviews — turns a nested-loop O(n²) scan into one pass, and shows up across arrays, strings, and linked lists.
  • Interviewers use "can you avoid the nested loop" as a filter question before moving on to harder DP or graph problems.
  • Spotting which variant applies — sorted input, a fixed-size window, or a grow/shrink condition — is usually the actual hard part, not the code itself.
🔥 Easy interview recall

Two pointers → ends move inward (sorted array)

Fixed window → a same-size box slides

Variable window → the box grows & shrinks

Think: right only moves forward. left only moves forward. Neither ever backs up — that's the whole O(n) guarantee.

⚠️ Common Trap

Moving pointers inward always finds the pair. That only works because the classic two-sum example uses a sorted array — moving left or right predictably raises or lowers the running sum; on unsorted data the same code still runs, it just silently returns the wrong answer instead of erroring.

🔄 Likely Follow-up

"Isn't this the same as just using a hash map?" A hash map also solves two-sum in O(n) time, but at O(n) extra space. The sorted two-pointer version gets the same O(n) time with O(1) extra space (not counting the sort itself, if the input wasn't already sorted) — a genuine space/time tradeoff, not one technique beating the other.

🎯 Say this in the interview — the exact lines to land

"Two index variables replace a nested loop: two pointers move toward each other on a sorted array, a fixed window slides one step at a time and updates in O(1), and a variable window grows on the right and shrinks on the left whenever a condition is violated — all three do a single pass instead of two nested ones."

  • Two pointers → only works because the array is sorted — that's what makes moving a pointer predictable.
  • Fixed window → add the new element, drop the old one, never recompute the whole window from scratch.
  • Variable window → expand right, shrink left on violation — still O(n) because left never moves backward.
  • Fast/slow → slow marks the last good value written, fast scans ahead — same idea as linked-list cycle detection, just on an array.
  • vs. a hash map → O(1) extra space instead of O(n), but only once the input is sorted.
📖 Explanation ▾

Two pointers means using two index variables to walk a collection instead of nesting a second loop inside the first. The classic case is "does a sorted array contain two numbers that sum to a target?" — one pointer starts at the front, one at the back. If the current sum is too small, the left pointer moves right to grow it; if too large, the right pointer moves left to shrink it. That only works because the array is sorted — a sorted order is what makes "move this pointer" a predictable, one-directional change instead of a guess.

A sliding window is a two-pointer pair that always defines a contiguous range. A fixed window keeps the range exactly k wide and slides it one step at a time, updating the running value in O(1) instead of resumming the whole window. A variable window lets the range grow and shrink: the right pointer always expands it, and the left pointer only advances when the window breaks some rule (too many distinct characters, sum too large, …). It's still one O(n) pass overall — across the whole scan, left only ever moves forward, so its total movement can never exceed the length of the collection, even though it moves in short bursts rather than every step.

Fast/slow pointers move through the same collection at different speeds. This is the same mechanic already used for linked-list cycle detection and finding the middle node — here it shows up on a plain array instead: removing duplicates from a sorted array in place, where a slow pointer marks the last unique value written and a fast pointer scans ahead for the next one.

💻 See the code ▾
C# 
static bool HasPairWithSum(int[] sorted, int target)
{
    int left = 0, right = sorted.Length - 1;
    while (left < right)
    {
        int sum = sorted[left] + sorted[right];
        if (sum == target) return true;   // ✅ found it
        if (sum < target) left++;         // too small → grow the sum
        else right--;                     // too big → shrink the sum
    }
    return false;
}

left only ever moves right, right only ever moves left — O(n) time, O(1) extra space, and only correct because sorted is sorted.

C# 
static int MaxSumOfK(int[] nums, int k)
{
    int windowSum = 0;
    for (int i = 0; i < k; i++) windowSum += nums[i];  // build the first window
    int best = windowSum;

    for (int i = k; i < nums.Length; i++)
    {
        windowSum += nums[i] - nums[i - k];   // add new, drop old — O(1) per slide
        best = Math.Max(best, windowSum);
    }
    return best;
}

No recompute from scratch each slide — only the two boundary elements change, not the whole window.

C# 
static int LongestUniqueSubstring(string s)
{
    var lastSeen = new Dictionary<char, int>();
    int left = 0, best = 0;

    for (int right = 0; right < s.Length; right++)
    {
        char c = s[right];
        if (lastSeen.TryGetValue(c, out int idx) && idx >= left)
            left = idx + 1;              // ❗ repeat found — jump left forward

        lastSeen[c] = right;
        best = Math.Max(best, right - left + 1);
    }
    return best;
}

right expands every step; left only jumps forward when a repeat forces it — neither pointer ever moves backward.

C# 
static int RemoveDuplicates(int[] sorted)
{
    if (sorted.Length == 0) return 0;
    int slow = 0;                     // last unique value written

    for (int fast = 1; fast < sorted.Length; fast++)
    {
        if (sorted[fast] != sorted[slow])
        {
            slow++;
            sorted[slow] = sorted[fast];  // write the new unique value
        }
    }
    return slow + 1;                  // count of unique values
}

Same fast/slow idea as the linked-list cycle check — here fast scans ahead, slow marks where the next unique value goes.

🌍 Real-world example ▾

Your API rate-limits by "no more than N requests in the last 60 seconds." That's a variable sliding window over a timestamp list — expand the window to include the new request, then shrink it from the old end until only requests inside the last 60 seconds remain. Same shape as "longest substring without repeats," just applied to timestamps instead of characters.
