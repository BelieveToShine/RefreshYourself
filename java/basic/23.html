enum — more than a named integer, a real, type-safe class

"What is an enum in Java, and how is it more than just a named integer constant?"

Why it matters ▾
🔢 enum
❗ ProblemA plain int constant (STATUS_PENDING = 0) compiles with any integer value at all, carries no behavior of its own, and prints as a meaningless number in logs.
✅ Solutionenum defines a fixed, type-safe set of named constant instances of a real class — invalid values can't even compile, and each constant can hold its own fields, constructor, and method body.
Recallenum = a closed set of real objects, not just labeled numbers.
🔥 Easy interview recall

enum = "a fixed set of named, type-safe constants — each one a real object."

Think: Status.ACTIVE isn't the number 1 wearing a costume — it's an actual object that can carry its own data and behavior.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Relying on ordinal() for logic or persistence is not the same as relying on the constant's name. Insert a new constant in the middle, or reorder them, and every previously stored ordinal() value now silently points at the wrong constant.

🔄 Likely Follow-up

"Can an enum have a method each constant implements differently?" Yes — declaring a method abstract inside the enum body forces every constant to supply its own implementation, which is effectively a per-constant anonymous subclass under the hood.

🎯 Say this in the interview — the exact lines to land

"enum defines a fixed, type-safe set of named constant instances of a real class — not bare labels. Each constant can hold its own fields, use a constructor, and even override a method with its own implementation."

  • enum constant → a real object, can carry fields and a constructor.
  • Invalid value → doesn't even compile, unlike a plain int constant.
  • Per-constant method body → each constant is its own subclass under the hood.
📖 Explanation ▾

An enum is a class with a fixed, closed list of instances — the compiler guarantees nothing else of that type can ever exist. Each constant can take constructor arguments, store its own fields, and expose its own methods, exactly like any other object.

Compare that to a plain int constant: a method expecting a status code has no way to reject a nonsense value like 99 — it compiles fine either way. An enum parameter can only ever be one of the real, named constants that actually exist.

💻 See the code ▾
☕ Java 
public enum Status {
    PENDING("Pending"), ACTIVE("Active"), CLOSED("Closed");

    private final String label;
    Status(String label) { this.label = label; }
    public String describe() { return "currently " + label.toLowerCase(); }
}

Every constant gets its own label — a real constructor call, once per constant, at class-loading time.

☕ Java 
public enum Operation {
    PLUS  { public int apply(int a, int b) { return a + b; } },
    MINUS { public int apply(int a, int b) { return a - b; } };

    public abstract int apply(int a, int b);
}

Each constant supplies its own method body — under the hood, that's a per-constant anonymous subclass of Operation.

☕ Java 
int code = status.ordinal();     // ❌ fragile — breaks if constants get reordered
String code2 = status.name();  // ✅ stable — the name never silently shifts

Persist the name() (or a dedicated explicit code field) — never the ordinal().

🧭 Use Cases — recognize these when they happen to you ▾
1 You replace a set of int status codes with an enum

A bare int field happily accepts 99 with no matching status at all. An enum parameter simply has no way to be anything other than one of its real, named constants.

RememberNonsense status codes compile with int, never with enum.
2 You call a constant's own method instead of writing a switch elsewhere

No giant switch statement scattered across the codebase to keep in sync — the behavior for each constant lives right next to that constant's own definition.

RememberPer-constant method → one less switch statement to maintain.
3 You persist or compare a constant using its ordinal()

A constant's ordinal() is just its position in the declaration — insert a new constant above it later and every value saved before that change now points at the wrong one.

RememberPersist the name, never the position.
🌍 Real-world example ▾

A panel of real, labeled buttons vs. unmarked holes. PENDING, ACTIVE, and CLOSED are actual labeled buttons — you can only press one that genuinely exists. A plain int status code is an unmarked panel with numbered holes; nothing stops someone from poking in a number that was never wired to anything.
