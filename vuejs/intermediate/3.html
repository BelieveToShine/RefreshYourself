Nested Routes — a layout that keeps its own inner slot

"How do nested routes work in Vue Router?"

Why it matters ▾
🪆 Nested routes
❗ ProblemA settings page with "Profile," "Billing," and "Security" tabs all share the same sidebar and page shell — rebuilding that shell as three separate flat routes would duplicate the layout three times.
✅ SolutionA route's children array declares sub-routes that render inside a second, nested <router-view> living inside the parent's own component — the shell mounts once, only the inner content swaps.
Recallchildren = routes that render inside the parent's OWN router-view, not the top-level one.
🔥 Easy interview recall

Nested route = "a route-view inside a route-view."

Think: parent keeps its shell mounted, only the inner slot swaps between children.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Giving a route children is not enough on its own. The parent component needs its OWN <router-view> in its template — a route with children but no nested <router-view> inside the parent's markup never renders the child anywhere.

🔄 Likely Follow-up

"How does this differ from two flat sibling routes?" Nested routes automatically share the parent's rendered layout — flat siblings each render fully independently, with no shared wrapper unless you build one by hand.

🎯 Say this in the interview — the exact lines to land

"A route's children array defines nested routes that render inside a second <router-view> living inside the parent route's own component — so a shared layout mounts once and only the inner content swaps as the child route changes."

  • children: [] → defines the sub-routes under a parent path.
  • Nested <router-view> → must exist in the parent's own template, or children render nowhere.
  • Shared layout → mounts once, doesn't remount per child.
  • Vs. flat siblings → no shared wrapper unless built manually.
📖 Explanation ▾

A nested route is declared with a children array on the parent route's config — each child still gets its own path and component, just scoped underneath the parent's path.

The part that's easy to miss: the parent route's own component needs a <router-view> somewhere in ITS template too. The top-level <router-view> in App.vue renders the parent; the parent's own inner <router-view> is what renders whichever child matched — think of it as router-views nesting exactly as deep as your route config nests.

This is what makes a dashboard-style layout cheap: the sidebar, header, and page frame live once in the parent, and switching between "Profile" and "Billing" only re-renders the small inner slot, not the whole page.

💻 See the code ▾
Vue 
{
  path: '/dashboard',
  component: DashboardLayout,
  children: [                        // nested routes
    { path: 'profile', component: ProfilePage },
    { path: 'billing', component: BillingPage }
  ]
}

Child paths are relative — profile, not /profile.

Vue 
<!-- DashboardLayout.vue -->
<Sidebar />
<router-view />    <!-- ✅ required — this is where children render -->

Skip this inner <router-view> and the child never shows up, even though the route matched.

🧭 Use Cases — recognize these when they happen to you ▾
1 A settings page with multiple tabs (Profile, Billing, Security)

Each tab is a child route. The settings shell (sidebar, page title) mounts once; only its nested <router-view> swaps between tabs.

RememberShared shell + swapping content → nested routes, not flat ones.
2 The URL matches but nothing new renders on screen

The router matched the child route correctly, but the parent's template never added its own <router-view> — there's simply no slot for the child to render into.

RememberNothing renders despite a match → check the parent has its own <router-view>.
🌍 Real-world example ▾

An admin panel with a persistent sidebar and a changing content pane. The sidebar and header are the parent's own markup; "Users," "Orders," and "Reports" are child routes that only ever swap the inner pane — nesting is what makes that layout reusable without copy-pasting the sidebar into three separate pages.
