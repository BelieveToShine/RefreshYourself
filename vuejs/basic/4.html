v- directives — five words that make a template reactive

"What are Vue directives, and what do v-bind, v-on, v-if, v-show, and v-for each do?"

Why it matters ▾
🧩 Directives
❗ ProblemA template can't just write plain JS to set attributes, bind events, or loop — HTML attributes are only ever strings.
✅ SolutionDirectives are special v--prefixed attributes the compiler recognizes and turns into real reactive behavior — binding, listening, conditional rendering, looping — right inside the markup.
RecallDirective = a v- attribute that attaches reactive behavior to an element.
🔥 Easy interview recall

v-bind → attribute (shorthand :)

v-on → event (shorthand @)

v-if / v-show → conditional

v-for → loop

Think: : = bind, @ = on. Modifiers like .prevent / .stop / .once refine the behavior.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

v-if and v-show are not interchangeable. They look like they do the same thing (hide an element), but how they do it is very different — covered in full on the next page.

🔄 Likely Follow-up

"What's the shorthand syntax for v-bind and v-on?" : for v-bind (e.g. :href="url"), and @ for v-on (e.g. @click="handler").

🎯 Say this in the interview — the exact lines to land

"Directives are special v--prefixed template attributes that attach reactive behavior to an element — v-bind binds an attribute, v-on binds an event listener, v-if/v-show control whether or how an element renders, and v-for renders a list. Most have a shorthand: : for bind, @ for on."

  • v-bind / : → binds an attribute to a reactive value.
  • v-on / @ → binds an event listener.
  • Modifiers like .prevent, .stop, .once → refine behavior without extra JS.
📖 Explanation ▾

A directive is a v--prefixed attribute the Vue compiler recognizes and turns into real reactive wiring, instead of a plain static attribute. v-bind (shorthand :) ties an attribute's value to reactive state — :class and :style specifically also accept objects or arrays, so a class or style can turn on and off based on data. v-on (shorthand @) attaches an event listener.

v-if/v-else conditionally render an element — added to or removed from the DOM entirely — while v-show toggles its CSS display instead (full comparison next page). v-for renders one element per item in a list.

v-bind / :v-on / @v-ifv-for

💻 See the code ▾
Vue 
<a v-bind:href="profileUrl">Profile</a>   // long form
<a :href="profileUrl">Profile</a>           // ✅ shorthand, same thing

: is just shorthand for v-bind: — identical behavior.

Vue 
<form @submit.prevent="save">  // ✅ .prevent calls preventDefault() for you
  <button @click.once="ack">OK</button>  // ✅ fires only the first click
</form>

Modifiers chain onto the event name — no manual event.preventDefault() needed.

🧭 Use Cases — recognize these when they happen to you ▾
1 An attribute's value needs to change with your data

A disabled state, a dynamic image source, a conditional class — any attribute driven by data reaches for v-bind/:.

RememberAttribute depends on data → v-bind / :.
2 You need to react to a user action, like a click or a keypress

Any DOM event — click, submit, keyup — wires up through v-on/@, with a matching method or inline expression.

RememberReact to an event → v-on / @.
3 You reach for v-show when you meant v-if (or vice versa)

Both hide an element visually, but only v-if actually removes it from the DOM. Picking the wrong one can mean paying an unnecessary mount cost, or losing component state you expected to keep — full detail on the next page.

RememberSame visual result, different DOM cost — never assume they're swappable.
🌍 Real-world example ▾

Directives are like labeled dials on the same machine. One dial wires in a power source (v-bind), one wires in a button press (v-on), one decides if the machine is even plugged in (v-if) — same machine, different job per dial.
