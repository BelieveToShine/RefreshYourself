Vite or Next.js — do you need the server to do any work?

"Create React App is deprecated — what do you start a project with, and when Next.js?"

Why it matters ▾
⚡ Vite
❗ ProblemBrowser-only React still needs something to bundle your code and give you a fast dev server.
✅ SolutionVite is a build tool for a client-rendered app; you add routing and your own backend.
RecallVite = fast tooling for a client-side SPA.
🧩 Next.js
❗ ProblemA client-only app ships a nearly empty HTML page, and you wire up routing, data loading, and server rendering yourself.
✅ SolutionNext.js is a framework with file-based routing, server rendering, Server Components, and data loading built in.
RecallNext.js = a framework with the server included.
🔥 Easy interview recall

Vite → fast tooling for a client-side SPA

Next.js → a framework with the server included

Think: need server features (SEO, SSR, data)? → framework. Otherwise → Vite.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Treating Vite and Next.js as two versions of the same thing. Vite is a build tool; Next.js is a framework that brings its own build tooling, routing, and server features. "Which is faster?" misses the real question: do you need server features at all?

🔄 Likely Follow-up

"So what happens to existing Create React App projects?" The React team deprecated CRA on February 14, 2025. It still works in maintenance mode, but it is not a starting point for new work. Teams move to a framework or to Vite when it is worth the effort, and react.dev links migration guides for both.

🎯 Say this in the interview — the exact lines to land

"Create React App was deprecated in February 2025. If I just need a client-rendered single-page app — an internal tool or dashboard with no SEO needs — I would use Vite. If I need server rendering, SEO, built-in routing, or Server Components, I would start with a framework like Next.js. The deciding question is whether I need server features."

  • Vite → fast dev server and bundler for a client-side app.
  • Next.js → a framework: routing, server rendering, data loading.
  • Decide by need for server features, not popularity.
  • Vite alone → you add routing yourself.
  • Create React App → deprecated Feb 2025, maintenance mode only.
📖 Explanation ▾

Create React App (CRA) was deprecated on February 14, 2025. It still works in maintenance mode, but react.dev now points new apps to a framework (such as Next.js, React Router or Expo), or to a build tool such as Vite, Parcel or Rsbuild if a framework does not fit.

Vite is a build tool: a fast dev server and a production bundle. A Vite React app is a client-rendered single-page app — the browser downloads the JavaScript and builds the page. Vite alone gives you no routing and no server rendering; you add a router yourself and talk to your own backend. It suits dashboards, internal tools, and apps behind a login where SEO does not matter. Routing basics are in Routing.

Next.js is a framework: file-based routing, server rendering, Server Components, and data loading in one project. It earns its extra concepts when you need server-rendered HTML for SEO or first load, or want the server to do work close to the data (see SSR & Hydration and Server Components). It is the best-known option, but other React frameworks exist.

💻 See the code ▾
Shell 
# Vite: a client-rendered React app
npm create vite@latest my-app -- --template react

# Next.js: a framework with routing and server rendering
npx create-next-app@latest

Two different starting points. The prompts these commands show can change between versions.

JSX 
import { createRoot } from 'react-dom/client';
import App from './App';

createRoot(document.getElementById('root')).render(<App />);  // ✅ the browser renders everything

A Vite app boots like this: the browser runs the JavaScript and builds the page.

JSX 
// app/page.jsx — a Server Component in the Next.js App Router
export default async function Page() {
  const res = await fetch('https://api.example.com/items');  // ✅ runs on the server
  const items = await res.json();
  return <ul>{items.map((i) => <li key={i.id}>{i.name}</li>)}</ul>;
}

In a framework, the page can fetch on the server and send ready HTML. In the App Router, a component is a Server Component by default.

🌍 Real-world example ▾

A food stall vs. a restaurant. A stall (Vite) is quick to set up and perfect if customers just walk up; a restaurant (Next.js) comes with a kitchen, a menu system, and staff — worth it only when you actually need to serve people that way.
