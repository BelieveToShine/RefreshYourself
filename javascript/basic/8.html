... — one symbol, two completely opposite jobs

"What's the difference between destructuring, spread, and rest — and how can spread and rest both use the exact same ... syntax?"

Why it matters ▾
📤 Spread
❗ ProblemPassing every array item as its own argument to something like Math.max, or copying an object/array to change just one field, would mean writing out each element or property by hand.
✅ SolutionSpread (...) used inside a call or a literal expands one array/object into its individual elements or properties — Math.max(...nums), { ...user, age: 31 } — a brand-new array/object, nothing mutated.
RecallSpread = expands one thing into many, inside a call or literal.
📥 Rest
❗ ProblemA function like sum(...values) needs to accept any number of arguments, and a destructuring pattern sometimes needs to grab "everything else" left over — with no way to know how many values that'll be ahead of time.
✅ SolutionRest (...) used in a binding position — a parameter list or destructuring pattern — collects every remaining value into one new array, and must be the last item since everything left has to go there.
RecallRest = collects many things into one, inside a binding position — always last.
🔥 Easy interview recall

... in a call or literal → spread — expands one into many

... in a binding or parameter → rest — collects many into one

Think: spread blows one thing apart. rest sweeps everything left into one pile. Same dots, opposite direction.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

... is not always "spread." The exact same three dots is rest when it sits in a binding position (a destructuring pattern or a function parameter) instead of a call or a literal — the syntax looks identical, only the position tells you which one it is.

🔄 Likely Follow-up

"Can you spread a Map or a Set the same way you spread an array?" Yes — spread works on any iterable (arrays, strings, Map, Set, NodeLists), not just arrays; for a plain object it works too, but that's a separate, non-iterable-based spread that copies own enumerable properties instead.

🎯 Say this in the interview — the exact lines to land

"Destructuring pulls values out of an array or object into named variables. Spread and rest both use ..., but in opposite directions — spread expands one array/object into many values inside a call or a literal, while rest collects many values into one array/object inside a binding position like a parameter list or a destructuring pattern."

  • Array destructuring → position matters: const [a, b] = arr takes items in order.
  • Object destructuring → name matters, not order: const { x, y } = obj matches by key.
  • Default values → only kick in on undefined, e.g. const { x = 5 } = obj.
  • Spread → in a call or literal: [...arr], { ...obj }, fn(...args).
  • Rest → in a binding position: const [first, ...rest] = arr, function f(a, ...rest).
  • Same token, opposite job — position in the code, not the dots themselves, decides which one it is.
📖 Explanation ▾

Destructuring is just unpacking — pulling values out of an array or object into their own named variables in one line, instead of reaching in with arr[0] or obj.name one at a time. Array destructuring matches by position (const [a, b] = [1, 2]); object destructuring matches by property name (const { name, age } = user), and can rename on the way out (const { name: userName } = user). Either kind can nest — const { address: { city } } = user reaches straight into a nested shape — and either kind can give a fallback with =, which only fires when the value is actually undefined, not for any other falsy value like 0 or "".

Spread and rest are where the confusion starts, because they share the exact same ... token. The trick is to stop reading the dots and read the position instead:

SpreadRest
Directionexpands one → manycollects many → one
Where it appearsa function call, an array/object literala destructuring pattern, a function's parameter list
ExampleMath.max(...arr)function f(a, ...rest)
Count allowed per formas many as you likeexactly one, and it must be last

That last row is the one people forget: a rest parameter or a rest destructuring target has to be the final item — function f(...rest, a) is a syntax error, because everything remaining has to go into rest, so there's nothing meaningful left to put after it.

💻 See the code ▾
⚡ JavaScript 
// Array & object destructuring, with a default and a nested pull
const [first, second] = [10, 20];       // first = 10, second = 20
const { name, age = 18 } = { name: "Sam" }; // age falls back to 18
const { address: { city } } = user;              // reach straight into a nested object

Array destructuring matches by position; object destructuring matches by name — a default only fills in for undefined.

⚡ JavaScript 
// SPREAD — inside a call and a literal, expands one thing into many
const nums = [4, 9, 2];
Math.max(...nums);                    // ✅ same as Math.max(4, 9, 2)
const combined = [...nums, 100];      // ✅ [4, 9, 2, 100] — a new array
const copy = { ...user, age: 31 };   // ✅ new object, one field overridden

Spread only shows up where JavaScript expects a list of things — a call's arguments, or the inside of []/{}.

⚡ JavaScript 
// REST — inside a binding position, collects many things into one
const [head, ...tail] = [1, 2, 3, 4]; // head = 1, tail = [2, 3, 4]

function sum(...values) {           // values = [] if called with nothing
  return values.reduce((a, b) => a + b, 0);
}
sum(1, 2, 3);                        // ✅ 6

Rest always sits at the end of a parameter list or destructuring pattern — it grabs "everything still left," so nothing can come after it.

🧭 Use Cases — recognize these when they happen to you ▾
1 You need a copy of an object or array to change one field, without touching the original

Spreading inside a {} or [] literal copies every existing property or element into a brand-new array/object, so { ...user, age: 31 } gives you a new object with one field overridden while user itself is never mutated.

RememberCopy without mutating → spread inside a literal.
2 A function needs to accept any number of arguments, not a fixed list

A rest parameter collects every argument the caller actually passed into one array inside the function body, so function sum(...values) works the same whether it's called with one number or ten — no fixed parameter count to plan for.

RememberUnknown number of arguments → rest parameter.
3 You see the three dots inside a destructuring pattern and call it "spread" out loud

The exact same three dots sit in a binding position here — a destructuring pattern, not a call or a literal — so const [head, ...tail] = arr is rest collecting everything left into tail, not spread expanding anything. A common trap — the syntax looks identical to the spread you just saw in a function call, but position decides which one it is.

Remember... in a binding position → always rest, never spread.
🌍 Real-world example ▾

Think of a delivery box. Spread is opening the box and laying every item out on the table separately — you now have many things instead of one box. Rest is the opposite: sweeping every item still on the table into one new box you didn't have before. Same "gather the items" motion, opposite direction.
