static — one shared copy, owned by the class, not any object

"What does static actually mean for a field or method, and when does a static initializer block run?"

Why it matters ▾
🏛️ static
❗ ProblemSome state (a shared counter, a cached config, a connection pool) belongs to the whole class, not to any one object — giving every instance its own copy would waste memory and let copies drift out of sync.
✅ Solutionstatic members belong to the class itself — one shared copy every instance reads and writes, set up once by a static initializer block when the class is first loaded, before any instance exists.
Recallstatic = the class's own copy, shared by every instance.
🔥 Easy interview recall

static = "one copy, owned by the class, not any instance."

Think: instance.field → every object's own. ClassName.field → everyone shares the same one.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Assuming a static initializer block only runs because the class is mentioned somewhere in the source. It runs on first "active use" — the first instantiation, static method/field access, or a subclass being initialized — not merely because the class name appears in an import or an unused reference.

🔄 Likely Follow-up

"What if a class has several static initializer blocks and several static field initializers?" They all run in the exact order they're declared in the source, interleaved together — a static field initializer and a static block aren't two separate passes, they execute top-to-bottom as one sequence.

🎯 Say this in the interview — the exact lines to land

"A static member belongs to the class itself, not to any one instance — there's exactly one shared copy, and every instance reads and writes that same copy. A static initializer block runs once, when the class is first loaded, before any instance is created, and static blocks/field initializers run in source-declaration order."

  • Static field → one shared copy, accessed via the class name.
  • Static initializer → runs once on first active use, before any instance exists.
  • Declaration order → blocks and field initializers run top-to-bottom, interleaved.
📖 Explanation ▾

A static field or method is attached to the class object itself, not to any particular instance — call it with ClassName.member (calling it through an instance reference also compiles, but it's the same one shared copy either way, which is exactly why doing so is misleading style).

A static initializer block (static { ... }) runs exactly once, the first time the class is actively used — the first instantiation, the first access to a static field/method, or a subclass being initialized. It always finishes before the very first instance's constructor runs.

When a class has multiple static field initializers and static blocks, they execute in the exact order they appear in the source, top to bottom, as a single interleaved sequence — not field initializers first and then blocks, or vice versa.

💻 See the code ▾
Java 
class Counter {
    static int total = 0;   // ✅ one copy, shared by every Counter
    int id;                        // each instance gets its own

    Counter() { total++; id = total; }
}

total is shared — every new Counter() bumps the exact same field.

Java 
class Config {
    static String MODE = "dev";     // 1st — field initializer
    static { System.out.println(MODE); }   // 2nd — block, runs after the field above it
    static int VERSION = 3;         // 3rd — declared after the block
}

All three run once, in this exact top-to-bottom order, the first time Config is actively used.

🧭 Use Cases — recognize these when they happen to you ▾
1 Counting how many instances of a class have been created

A running total across every created object needs one shared place to live — a static field is exactly that. This is the #1 reason most people first reach for static.

RememberTotal across all instances → a static field.
2 A utility method that doesn't need any instance state

A pure calculation that doesn't touch any object's own state has no reason to require an instance — static lets callers invoke it directly off the class.

RememberNo instance state involved → a static method is the natural fit.
3 You assume a static field resets per test or per request

A static field lives for the whole life of the class in that JVM — it doesn't reset between test methods or requests just because a new object was created. A shared mutable static is a common source of flaky tests and cross-request leaks.

RememberStatic state outlives any one instance, test, or request.
🌍 Real-world example ▾

A static field is the building's shared lobby sign, not each tenant's own mailbox. Every tenant (instance) reads and can update that one sign — change it from apartment 3 and apartment 7 sees the change too, because there's only ever one sign, not one per tenant.
