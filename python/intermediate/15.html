@cache and @lru_cache — free memoization, until the cache never forgets

"How do you memoize a function in Python, and what are the limits of lru_cache?"

Why it matters ▾
🧠 Memoization
❗ ProblemCalling a slow, predictable function again and again with the same arguments repeats the same work every single time.
✅ Solution@cache and @lru_cache store each result against its arguments, so a repeat call returns the stored answer instead of running the function again.
RecallMemoize = remember the answer for these exact arguments.
🔥 Easy interview recall

@lru_cache = "remember the answer for these exact arguments."

Think: @cache → no limit — keeps every result @lru_cache(maxsize=N) → keeps N, drops the least recently used

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

@cache is not free. It never evicts, so every new argument combination stays in memory — and on a method, self is part of the key, so the cache keeps every instance alive as long as the cache itself lives.

🔄 Likely Follow-up

"Can you cache a function that takes a list?" No — the arguments become dictionary keys, so they must be hashable and a list raises TypeError. Pass a tuple instead.

🎯 Say this in the interview — the exact lines to land

"functools.cache and lru_cache memoize a function — they store the result for each set of arguments and return it on repeat calls. The arguments must be hashable, and you should only cache pure functions."

  • @cache → unbounded, simplest — fine for a small, fixed set of inputs, like a recursive Fibonacci.
  • @lru_cache(maxsize=N) → bounded — use when inputs vary and memory matters; it drops the least recently used entry.
  • Arguments must be hashable — a list raises TypeError, so pass a tuple.
  • Only pure functions — same input must always give the same output, or you serve stale answers.
  • cache_info() → hits and misses; cache_clear() empties the cache.
  • cached_property → once per instance — computed on first access, then stored.
📖 Explanation ▾

Memoization means: remember a function's result for each set of arguments, and return the stored answer when the same arguments come back. functools.lru_cache does this as a decorator, using a dictionary keyed by the arguments. @cache (Python 3.9+) is the same idea with no size limit. @lru_cache(maxsize=N) keeps at most N entries and drops the least recently used one when it is full; plain @lru_cache defaults to maxsize=128.

Because the arguments become dictionary keys, they must be hashable — lists, dicts and sets are not, so they raise TypeError. Only cache pure functions (same input, same output, no side effects), or the cache will hand back stale answers; cache_clear() empties it and cache_info() shows hits, misses and current size. On a method, self is one of the arguments, so the cache holds a reference to every instance it has seen.

For a value that depends only on one object and is needed once, use functools.cached_property (3.8+): it runs on first access, stores the result on the instance, and never calls the function again for that object.

💻 See the code ▾
Python 
from functools import lru_cache

@lru_cache(maxsize=2)
def square(n):
    print("computing", n)
    return n * n

print(square(2))   # miss: computes
print(square(2))   # hit: no "computing" line
print(square(3))   # miss
print(square(4))   # miss: cache full, evicts 2
print(square(2))   # miss again: 2 was evicted
print(square.cache_info())

Prints computing 2, 4, 4, computing 3, 9, computing 4, 16, computing 2, 4, then CacheInfo(hits=1, misses=4, maxsize=2, currsize=2). Only the second call was a hit; the fifth missed because maxsize=2 had already evicted 2.

Python 
from functools import cache

@cache
def total(nums):
    return sum(nums)

total([1, 2])   # ❌ TypeError: unhashable type: 'list'
total((1, 2))   # ✅ 3 — a tuple is hashable

The list can't become a dictionary key, so the call fails before the function even runs. A tuple works.

🧭 Use Cases — recognize these when they happen to you ▾
1 You call the same function with the same arguments again and again

The decorator keeps a dictionary of results keyed by the arguments. On a repeat call it returns the stored answer and skips the work. Use it only on pure functions.

RememberCache = remember per exact arguments.
2 Your inputs keep changing and memory could grow

@cache has no limit, so every new argument combination stays in memory. @lru_cache(maxsize=N) keeps only N entries and drops the least recently used one.

RememberVarying inputs → use a bounded cache.
3 You put @cache on a method

A common trap — self is part of the cache key, so the cache keeps a reference to every instance it has seen, for as long as the cache lives.

RememberOn a method, self is in the key.
🌍 Real-world example ▾

A web service calls get_tax_rate(country) thousands of times a minute, but there are only a handful of distinct countries. One @lru_cache turns almost every call into a dictionary lookup — and a cache_clear() when the rates change keeps it honest.
