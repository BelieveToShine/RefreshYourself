Same 3 promises, four different verdicts — .all vs .allSettled vs .race vs .any

"If the exact same three promises settle in the same order — one rejects first, then two fulfill after it — what does each of Promise.all, Promise.allSettled, Promise.race, and Promise.any actually resolve or reject with?"

Why it matters ▾
🅰️ Promise.all
❗ ProblemSeveral operations need to run at once and ALL of them must succeed before you can move on — but nothing says what should happen the moment just one of them fails.
✅ SolutionPromise.all fulfills only once every promise fulfills, and rejects the instant any one rejects — discarding every other promise's result, even ones that hadn't failed.
Recallall = all-or-nothing; one rejection loses everyone else's result too.
🅱️ Promise.allSettled
❗ ProblemPromise.all's own downside is real: one failure throws away every other promise's outcome, so you can't tell which of the rest actually succeeded.
✅ SolutionPromise.allSettled waits for every promise no matter what, and its own returned promise never rejects — you get every status back, nothing lost.
RecallallSettled = always fulfills, one entry per promise, nothing lost.
🏁 Promise.race
❗ ProblemSometimes you only care about whichever operation finishes first — but "finishes first" is ambiguous about whether a fast failure should count as the winner.
✅ SolutionPromise.race settles the instant the very first promise settles, fulfilled or rejected — a fast rejection wins the race and rejects the whole thing.
Recallrace = first SETTLEMENT wins, win or lose.
🏆 Promise.any
❗ ProblemA race that lets a fast failure win is the wrong tool when a fast decline must never beat a slower approval among several redundant attempts.
✅ SolutionPromise.any skips over rejections and only settles on the first fulfillment, rejecting itself only once every single promise has already rejected.
Recallany = first SUCCESS wins; ignores rejections until all reject.
🔥 Easy interview recall

"all needs EVERYONE to fulfill. allSettled waits for EVERYONE no matter what. race and any both take the FIRST — but race takes the first SETTLEMENT, any takes the first SUCCESS."

Think: all = AND, everyone → allSettled = wait for all, ALWAYS fulfills → race = first to settle, win or lose → any = first to actually WIN.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Promise.race is not "whoever wins first." It settles with whichever promise settles FIRST, full stop — if that first one happens to reject, race rejects too, even if a slower promise in the same group would have fulfilled.

🔄 Likely Follow-up

"So what's actually different between race and any then?" race settles the instant ANY promise settles, fulfilled or rejected. any ignores rejections and only settles on the first FULFILLMENT — it only rejects once every single promise in the group has rejected.

🎯 Say this in the interview — the exact lines to land

"Promise.all needs every promise to fulfill and rejects the moment any one fails. Promise.allSettled always waits for every promise and its own returned promise never rejects. Promise.race settles the instant the first promise settles, whether that's a win or a loss. Promise.any settles on the first FULFILLMENT specifically, and only rejects if every promise rejects."

  • Promise.all → need everything to succeed TOGETHER — one failure sinks the whole group.
  • Promise.allSettled → need every result no matter what — nothing is lost to a partial failure.
  • Promise.race → need whichever finishes first, win or lose — a timeout race, or redundant sources you don't fully trust.
  • Promise.any → need the first SUCCESS specifically, tolerating some failures along the way.
  • allSettled is the direct fix for all's biggest risk — losing every OTHER promise's result just because one failed.
📖 Explanation ▾

All four combinators take an array of promises and hand back ONE new promise — but each one decides that new promise's fate by a different rule. The table below is the whole comparison in one look:

Resolves whenRejects when
Promise.allAll fulfillAny one rejects
Promise.allSettledAll settle (always)Never — it never rejects because of a member's rejection
Promise.raceFirst one settles (fulfilled OR rejected)First one settles, if that first settlement was a rejection
Promise.anyFirst one fulfillsOnly if ALL reject

The real risk lives in Promise.all: it rejects the instant the FIRST promise fails, and every other promise's result — even ones that would have succeeded a moment later — is simply thrown away. Promise.allSettled exists specifically to fix that: it waits for every promise no matter what and hands back a full array of {status, value or reason} entries, so nothing about the group's outcome is ever lost.

Promise.race and Promise.any narrow the same idea down to just the FIRST result. race stops caring about the other two the moment anything settles, win or lose. any keeps listening past rejections and only stops at the first success — it only rejects itself once every promise in the group has already rejected.

💻 See the code ▾
JS 
const requests = [fetchUser(), fetchOrders(), fetchInventory()];
// fetchOrders() rejects; the other two fulfill a moment later
try {
  await Promise.all(requests);
} catch (err) {
  // ❌ rejects immediately with fetchOrders' error
  // fetchUser()/fetchInventory()'s results are gone — never even awaited
}

The moment one promise rejects, Promise.all throws away every other promise's result — even the ones that hadn't failed.

JS 
const outcomes = await Promise.allSettled(requests);
// ✅ always fulfills — one entry per promise, same order as the input
// [{status:'fulfilled', value:...}, {status:'rejected', reason:...}, {status:'fulfilled', value:...}]

allSettled's OWN returned promise never rejects — the failure just becomes one entry inside the array you get back.

JS 
const group = [rejectsFirst(), fulfillsSecond(), fulfillsThird()];
await Promise.race(group);   // ❌ rejects — the FIRST settlement is a rejection
await Promise.any(group);    // ✅ fulfills — skips it, waits for the first WIN

Same three promises, same settle order — race takes the first SETTLEMENT (a rejection), any skips it and takes the first FULFILLMENT.

🧭 Use Cases — recognize these when they happen to you ▾
1 A page needs the user, their orders, and inventory together — none of it makes sense with only some of them

If fetchOrders rejects, Promise.all rejects immediately and throws away fetchUser's and fetchInventory's results too — even though they hadn't failed. That's the right tool only when every piece is truly required together.

RememberAll required together → Promise.all, but one failure loses the rest too.
2 A dashboard renders several independent widgets, and one widget's data failing shouldn't blank out the others

Promise.allSettled waits for every widget's request no matter what, and its own returned promise never rejects — you get back one status entry per widget, so a single failed widget never wipes out the ones that succeeded.

RememberIndependent, best-effort results → allSettled, nothing lost.
3 Checkout fires three redundant payment authorizers at once, and only an actual approval should ever win

A fast decline settles before the slower approval, so Promise.race would reject the whole checkout on that decline alone. Promise.any is the fix here — it skips rejections and only settles on the first actual success.

RememberNeed the first SUCCESS, not the first settlement → Promise.any, not race.
🌍 Real-world example ▾

Your checkout page calls three redundant payment authorizers at once to cut latency, and only a successful authorization should ever win — a fast decline must not beat a slightly slower approval. Promise.race would let the fast decline win just because it settled first. Promise.any is the right call here: it skips rejections and only settles on the first actual approval.
