Stored procedure vs. function — EXEC it or use it inside a query

What is the difference between a stored procedure and a user-defined function?

Why it matters ▾
🧰 Procedure vs. function
❗ ProblemTreating them as the same thing leads to the wrong tool: you cannot SELECT from a procedure, and you cannot make a function change your tables.
✅ SolutionA procedure is an action you EXEC — it can change data, use transactions and return several result sets; a function is a value or table you use inside a query, under write restrictions.
RecallProcedure = does something. Function = gives back something you can query.
🔥 Easy interview recall

Procedure → an action you EXEC

Function → a value you use inside a query

Think: a procedure does. A function returns — and stays out of your tables.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

"A function is just a procedure that returns a value." A function cannot make persistent changes to tables, and a procedure cannot be used inside a SELECT, WHERE or JOIN the way a function can.

🔄 Likely Follow-up

"Scalar function or inline table-valued function — which is safer in a big query?" An inline table-valued function is expanded into the calling query like a parameterized view, so the optimizer sees through it; a scalar function can be run once per row and slow things down (SQL Server 2019 and later can inline some of them).

🎯 Say this in the interview — the exact lines to land

"A stored procedure is an action you run with EXEC — it can change data, manage transactions and return several result sets. A function returns a value or a table and is used inside a query, but it cannot change permanent tables."

  • Procedure → EXEC an action: updates, transactions, several result sets, output parameters.
  • Function → used inside a query — SELECT, WHERE, JOIN, APPLY.
  • Functions cannot change permanent tables; procedures can.
  • Inline table-valued function → behaves like a parameterized view, optimised with the query around it.
  • Scalar function in a large query → watch performance; it can run once per row.
📖 Explanation ▾

A stored procedure is a saved batch of T-SQL you run with EXEC. It can insert, update and delete, control transactions, use TRY/CATCH, return an int status code, fill OUTPUT parameters and send back one or more result sets. It stands on its own — you cannot put it inside a SELECT. (Basics are on Stored Procedures.)

A user-defined function exists to be used inside a query. A scalar function returns one value, so it can sit in a select list or WHERE. A table-valued function returns a table, so it goes in FROM or CROSS APPLY. The inline form is a single RETURN (SELECT ...) — think "view that takes parameters". In exchange for that reach, a function is not allowed side effects on permanent tables.

Rule of thumb: need to do something (change data, run a workflow, return several results) → procedure. Need a reusable piece of a query → function, preferably the inline table-valued kind. One cousin worth contrasting: a trigger also runs code, but fires automatically instead of being called.

💻 See the code ▾
T-SQL 
CREATE PROCEDURE dbo.usp_ShipOrder @OrderId INT
AS
BEGIN
    SET NOCOUNT ON;
    UPDATE dbo.Orders SET Status = 'Shipped' WHERE OrderId = @OrderId;   -- ✅ procedures may change data
    SELECT OrderId, Status FROM dbo.Orders WHERE OrderId = @OrderId;
END;
-- run it on its own:
EXEC dbo.usp_ShipOrder @OrderId = 42;

A procedure is called by itself with EXEC — it cannot appear inside another query.

T-SQL 
CREATE FUNCTION dbo.fn_OrdersFor (@CustomerId INT)
RETURNS TABLE
AS
RETURN (SELECT OrderId, Total FROM dbo.Orders WHERE CustomerId = @CustomerId);
-- use it inside a query:
SELECT c.Name, o.Total
FROM dbo.Customers AS c
CROSS APPLY dbo.fn_OrdersFor(c.CustomerId) AS o;   -- ✅ function used in FROM

An inline table-valued function: a parameterized query you can join to. (Each snippet is its own batch; GO separates batches in client tools.)

🌍 Real-world example ▾

Scenario: the "Ship order" button calls a stored procedure, because shipping updates several tables and returns a confirmation; the "orders for this customer" query that five reports share is an inline table-valued function, because reports need to join to it.
