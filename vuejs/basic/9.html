computed vs. watch — a value, or an action?

"When would you use watch instead of a computed property?"

Why it matters ▾
🧮 computed
❗ ProblemA derived value needs to exist in the template, read directly, kept automatically in sync with the state it's built from.
✅ Solutioncomputed synchronously derives and returns a new value from other reactive state — it IS a value, used directly in the template.
Recallcomputed = a value you read.
👀 watch
❗ ProblemSomething needs to actually happen — an API call, a save to storage — in reaction to a value changing, not just a new value to display.
✅ Solutionwatch runs a side-effect callback in reaction to a value changing — it doesn't return anything into the template; it DOES something.
Recallwatch = an action you trigger.
🔥 Easy interview recall

computed → a value, used in the template

watch → an action, a side effect

Think: if you're about to return something for the template, it's computed. If you're about to do something (fetch, save, log), it's watch.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Using a watcher to compute a derived value that's then manually stored into a separate ref. That's exactly what computed exists for, and it avoids the double-reactivity-trigger and staleness risk of manually keeping two refs in sync yourself.

🔄 Likely Follow-up

"When would you actually need watch over computed?" Any time the reaction is an action, not a value — fetching new data when an ID prop changes, persisting a value to localStorage, or triggering an animation in response to a state change.

🎯 Say this in the interview — the exact lines to land

"computed synchronously derives and returns a new value from other reactive state — it's a value, used directly in the template. watch runs a side-effect callback in reaction to a value changing — it doesn't return anything into the template, it does something, like an API call or a log."

  • computed → produces a value the template reads.
  • watch → triggers an action — fetch, save, log.
  • Deriving a value inside a watcher → a sign you wanted computed instead.
📖 Explanation ▾

computed is for anything that's genuinely still "a value" — it just happens to be calculated from other reactive state instead of being set directly. It has to return something, and it's meant to stay pure: no API calls, no manual DOM work, no storage writes inside the getter.

watch is for reacting to a change with an action instead of a value — it receives the new (and old) value and runs a callback, but that callback's return value is thrown away. If what you're building is "when X changes, go do Y," that's a watcher, not a computed property wearing a disguise.

💻 See the code ▾
Vue 
const fullName = computed(() => `${first.value} ${last.value}`);  // ✅ a value
<!-- <p>{{ fullName }}</p> -->

fullName is read directly in the template — it IS the value.

Vue 
watch(userId, async (newId) => {
  profile.value = await fetchProfile(newId);  // ✅ an action, not a returned value
});

watch's callback does something (fetches data) — it doesn't hand a value to the template.

🧭 Use Cases — recognize these when they happen to you ▾
1 You need a formatted or combined value for the template

The template needs to display something built from other state. This is the #1 scenario computed exists for.

RememberNeed to show a derived value → computed.
2 A prop changing should trigger a fresh data fetch

An API call is a side effect, not a value — it has to live in a watch callback, never inside a computed getter.

RememberReact to a change with an API call → watch.
3 You watch a value just to copy it into a second ref

Manually copying one reactive value into another ref via watch is exactly the job computed already does, more simply and without the risk of the two refs briefly going out of sync.

Rememberwatch just copying a value into another ref → should be computed.
🌍 Real-world example ▾

computed is a thermometer's current reading; watch is the thermostat that kicks the heater on when that reading drops. One just reports a value; the other reacts to it by doing something in the real world.
