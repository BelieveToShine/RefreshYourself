HttpClient — why every call comes back as an Observable, not a Promise

"Why does HttpClient return an Observable instead of a Promise, and what does that actually let you do?"

Why it matters ▾
  • HttpClient is the very first thing most apps touch to load real data — almost every app talks to a backend somewhere.
  • "Observable vs. Promise" here is a filter question — it separates people who know the actual capability difference from people who just know Angular "uses RxJS."
  • Forgetting to subscribe is a genuinely common real bug, not a trick question — it looks like a silent failure but nothing was ever sent.
🔥 Easy interview recall

HttpClient → returns an Observable, not a Promise

Observable → cold until subscribed, cancellable after

Think: .subscribe() is the "go" button — nothing fires before it, and unsubscribing can stop it mid-flight.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Calling this.http.get(url) without subscribing does not send a broken request — it sends no request at all. HttpClient returns a cold Observable, so nothing happens until something subscribes to it, directly or through the async pipe.

🔄 Likely Follow-up

"If unsubscribing cancels the request, do you always need to manually unsubscribe from every HTTP call?" Not quite — HttpClient's Observables complete on their own after the one response, so a simple one-off request won't leak even if you forget; manual cancellation matters specifically when you want to abort an in-flight request early, like the user navigating away or typing a new search before the last one finished.

🎯 Say this in the interview — the exact lines to land

"HttpClient methods return an Observable, not a Promise, because a Promise represents one eventual value and can't be cancelled once it starts. An Observable can be unsubscribed to actually abort the request, and it composes with RxJS operators like retry, catchError, and switchMap."

  • HttpClient → returns an Observable from every method (get/post/put/delete).
  • Nothing is sent until something subscribes — directly, or implicitly through the async pipe.
  • Unsubscribing before it completes actually cancels the underlying request — a genuine capability a Promise doesn't have.
  • Errors surface as an HttpErrorResponse, handled with catchError in the pipe or an error callback in .subscribe().
  • Repeating headers on every call is the exact repetitive problem interceptors exist to solve.
📖 Explanation ▾

HttpClient is Angular's built-in service for making HTTP requests, injected like any other service — provided app-wide with provideHttpClient() in a modern standalone app, or HttpClientModule in the older NgModule style. Every method (get, post, put, delete, …) returns an Observable, and nothing is actually sent until something subscribes to it — a direct .subscribe() call, or implicitly through the async pipe in a template.

A Promise represents exactly one eventual value and can't be cancelled once it starts. An Observable is cancellable — unsubscribing aborts the underlying request — and composable with RxJS operators: retry(n) automatically re-issues a failed request up to n times before giving up, switchMap can cancel one in-flight request and start a new one, and streams can be combined. That's the concrete reason HttpClient returns an Observable instead of a Promise — not just "Angular likes RxJS."

Errors surface as an HttpErrorResponse carrying the status code and response body, handled with the catchError operator in the request's pipe, or an error callback passed to .subscribe({ error: ... }). Headers go through the request's options parameter — but repeating that on every single call is exactly the repetitive problem HTTP interceptors exist to solve, including attaching an auth token automatically; interceptors get their own dedicated page later in this track.

💻 See the code ▾
TypeScript 
this.http.get<User[]>('/api/users')
  .pipe(
    catchError(err => {           // ❌ request failed
      console.error(err);
      return of([]);               // ✅ fallback so the stream still completes
    })
  )
  .subscribe(users => this.users = users);  // ✅ this is what actually fires it

catchError inside the pipe turns a failed request into a safe fallback value — the stream still completes instead of throwing unhandled.

TypeScript 
this.http.get(url);               // ❌ nothing happens — cold Observable, never subscribed
this.http.get(url).subscribe();   // ✅ actually fires the request

HttpClient's Observable is cold — writing the call alone only builds a description of the request, it doesn't send it.

🌍 Real-world example ▾

A Promise-based call is like placing a phone order you can't cancel once you've hung up — it's happening the moment you place it. An Observable-based call is like ordering through a food delivery app: you can cancel right up until it's actually delivered. And if you never tap "place order" — never subscribe — nothing gets cooked at all, no matter how carefully you filled out the order screen.
