🔥 AI · Basic · Must Know

Same prompt, different answer every time — until you touch one knob

"Explain temperature vs. top-p. When would you set temperature to 0?"

Why it matters ▾
  • Every single API call to an LLM carries these settings — this is baseline literacy before RAG, agents, or anything else in the track makes sense.
  • Directly explains why the same prompt can come back with a different answer twice, which is usually the first thing a skeptical stakeholder asks about.
  • A near-universal opening question in AI/GenAI interviews, right after "what is a token" and before anything about architecture comes up.
🔥 Easy interview recall

Token → the actual billed unit, often a piece of a word

Context window → max tokens the model can see in one call

Temperature ≈ 0 → greedy — same pick almost every time

Higher temperature → flatter odds, more varied picks

Think: temperature never changes which token is most likely — only how flat the curve looks right before one gets picked.

⚠️ Common Trap

"Temperature 0 guarantees word-for-word identical output every time." It makes the model greedily pick the single most likely token almost every call — but most providers still don't promise bit-for-bit identical results across every call. Treat it as "near-deterministic," not an absolute guarantee.

🔄 Likely Follow-up

"What happens if my prompt plus the expected completion goes over the context window?" The call gets truncated or rejected with an error — the model can't attend to tokens beyond that window, so a long conversation needs older turns trimmed or summarized before the next call.

🎯 Say this in the interview — the exact lines to land

"Temperature reshapes how flat the next-token probability curve is — near 0 greedily picks the single most likely token every time, higher values spread real odds across more candidates. Top-p instead trims which tokens are even in the running by cumulative probability, so for classification, extraction, or code generation I'd set temperature to 0, not touch top-p."

  • Temperature → controls how flat the probability curve is, not "creativity" itself.
  • Set it to 0 → for classification, extraction, code generation — same input, same output.
  • Raise it → for brainstorming and creative writing, where variety is the actual goal.
  • Top-p → keeps tokens until their combined probability crosses p — an adaptive cutoff.
  • Top-k → keeps only the k most likely tokens — a fixed-size cutoff either way.
📖 Explanation ▾

A token is the actual unit of text a model reads and is billed on — often a piece of a word rather than a whole word, and exactly how a word splits depends on the tokenizer that particular model uses. The context window is the maximum number of tokens the model can attend to in one call, prompt and completion combined — go over it and the call gets truncated or rejected outright, not silently handled.

Temperature controls next-token sampling by reshaping how flat that probability curve is. Near 0 makes the model pick the single most likely token almost every time — a greedy pick. Pushing it up spreads real odds across more candidates, so the same prompt can land on a different, still-plausible token on each call. Top-p and top-k act one step earlier: they decide which tokens are even allowed into that sampling step before temperature reshapes their odds. Top-p keeps the smallest set of candidates whose combined probability crosses a threshold; top-k keeps a fixed number of the highest-probability candidates, regardless of how likely or unlikely the cut-off tail actually is.

Max tokens caps how long the completion is allowed to run before it gets cut off. Stop sequences end generation the moment a chosen string appears, which is useful for stopping right after a delimiter instead of waiting for the model to decide it's done on its own. None of these knobs make a model "smarter" — they only control how much text comes back and how much variety is allowed while picking it.

💻 See the code ▾
Python 
response = client.chat.completions.create(
    model="your-chat-model",        # whichever model you're calling
    messages=[{"role": "user", "content": "Classify: refund request"}],
    temperature=0                    # ✅ same input → same output
)

Good for classification and extraction — you want the same label picked every time, not a different one on retry.

Python 
response = client.chat.completions.create(
    model="your-chat-model",
    messages=[{"role": "user", "content": "Give me a tagline for a coffee shop"}],
    temperature=0.9                  # 🎲 varied wording on every call
)

Good for brainstorming — you want a different, creative option each call, not the same tagline twice.

🌍 Real-world example ▾

Temperature 0 is like asking the same barista to make your usual order exactly the same way, every single time — reliable, no surprises. Higher temperature is like telling them "surprise me" — you'll still get something in the same general category, but the specific recipe changes each round.

Scenario: a classification service returns a different label for the exact same input on two separate calls. First thing to check: the temperature setting — anything above 0 means the greedy, near-deterministic pick isn't guaranteed, and setting it to 0 (or very low) is the fix for any task that needs the same input to reliably produce the same output.
