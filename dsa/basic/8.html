BFS vs DFS — why only one of them promises the shortest path

"What is a graph, and what's the actual difference between BFS and DFS traversal?"

Why it matters ▾
  • Every later graph page — patterns, shortest path/MST, topological sort — assumes you already know BFS and DFS cold.
  • Forgetting the visited set is the single most common bug in a live graph-coding round — it causes an infinite loop the moment a cycle exists.
  • A frequent warm-up question before an interviewer moves on to a harder graph problem.
🔥 Easy interview recall

BFS → queue, level by level, finds shortest path

DFS → stack (or recursion), goes deep first

Think: BFS spreads out like ripples in a pond. DFS commits to one path until it's forced to backtrack.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

A graph is not a tree — it can loop back on itself. Skip the visited set and BFS/DFS on a graph that has a cycle will revisit the same nodes forever instead of finishing.

🔄 Likely Follow-up

"When would you choose BFS over DFS, or vice versa?" Reach for BFS when you need the shortest path in an unweighted graph, or the question is phrased as "minimum number of steps." Reach for DFS when you just need to know if a path exists, need to explore every possibility (backtracking), or the graph is very wide — DFS's memory use tracks depth, not breadth.

🎯 Say this in the interview — the exact lines to land

"BFS uses a queue and explores level by level, so it's the one that guarantees the shortest path in an unweighted graph. DFS uses a stack or recursion and goes as deep as possible before backtracking — simpler to write, but no shortest-path guarantee. Both run in O(V + E)."

  • Adjacency list → the default choice for sparse graphs; a matrix only pays off when you need O(1) edge lookups on a dense graph.
  • BFS → reach for it when the question says "shortest" or "minimum steps."
  • DFS → reach for it for path existence, cycle detection, or backtracking-style exploration.
  • Always track a visited set — a graph can have cycles, unlike a tree.
  • Connected components → count how many times you start a fresh BFS/DFS from an unvisited node.
📖 Explanation ▾

A graph is just nodes (vertices) connected by edges — no more mysterious than that. An edge can be one-way (directed, like "follows" on social media) or two-way (undirected, like "friends with"), and it can carry a cost (weighted) or just mark a plain connection (unweighted). Two representations show up constantly — an adjacency list and an adjacency matrix:

Adjacency listAdjacency matrix
SpaceO(V + E)O(V²), always
"Is there an edge u→v?"scan a list — O(degree)direct lookup — O(1)
Best forsparse graphs (few edges)dense graphs (many edges)
Typical interview default✅ yes, almost alwaysonly when O(1) edge lookup matters

BFS and DFS both visit every node and edge exactly once — O(V + E) either way — but they get there completely differently:

BFSDFS
Data structurequeue (FIFO)stack, or recursion (call stack)
Explore orderlevel by leveldeep down one path first
Shortest path (unweighted)?✅ guaranteed❌ no guarantee
Typical use"minimum steps," level-order problemspath existence, cycle detection, backtracking

A connected component is just every node reachable from every other node in a cluster. Finding all of them is one loop: run BFS or DFS from any node you haven't visited yet, mark everything it reaches as one component, then move to the next unvisited node — still O(V + E) in total, because each node and edge is only ever touched once across the whole loop.

💻 See the code ▾
🐍 Python 
from collections import deque

def bfs(graph, start):
    visited = {start}              # ✅ mark visited right away
    queue = deque([start])
    order = []
    while queue:
        node = queue.popleft()     # FIFO — oldest node first
        order.append(node)
        for neighbor in graph[node]:
            if neighbor not in visited:
                visited.add(neighbor)   # ✅ mark before enqueueing
                queue.append(neighbor)
    return order

BFS visits neighbors level by level — the first time it reaches a node is always via the shortest path (fewest edges).

🐍 Python 
def dfs(graph, start, visited=None, order=None):
    if visited is None:
        visited, order = set(), []
    visited.add(start)             # ✅ mark visited before recursing
    order.append(start)
    for neighbor in graph[start]:
        if neighbor not in visited:
            dfs(graph, neighbor, visited, order)  # go deep before backtracking
    return order

DFS commits to one neighbor and goes all the way down before trying the next — the call stack remembers where to backtrack to.

🐍 Python 
def count_components(graph, nodes):
    visited = set()
    components = 0
    for node in nodes:
        if node not in visited:
            components += 1            # a fresh, unvisited node = a new component
            visited |= set(bfs(graph, node))  # mark the whole component
    return components

Reuses the same bfs() from above — each call marks one whole component, so counting how many times you start a fresh call from an unvisited node is the number of components.

🌍 Real-world example ▾

Think of a city's road map. Each intersection is a node, each street is an edge — a one-way street is a directed edge, a tollbooth is a weighted edge. Finding the fewest turns to get somewhere is exactly what BFS is doing; wandering down one street until you hit a dead end before backtracking is what DFS is doing.
