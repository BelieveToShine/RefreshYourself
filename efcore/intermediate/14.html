TPH, TPT, TPC — one table, or a join, or repeated columns?

"How does EF Core map a class hierarchy to tables?"

Why it matters ▾
🧬 Inheritance Mapping
❗ ProblemYour C# classes inherit from each other, but a database has no inheritance. EF Core has to pick a table layout, and each layout trades speed against tidy columns.
✅ SolutionKnow the three layouts: TPH (one table, the default), TPT (one table per type, joined) and TPC (one table per concrete type, no joins).
RecallTPH = one table + discriminator; TPT = table per type + joins; TPC = table per concrete type, columns repeated.
🔥 Easy interview recall

Inheritance mapping = "one table, joined tables, or copied columns."

Think: TPH → one table, a Discriminator column, nullable derived columns TPT → a table per type, joined on the key TPC → a table per concrete type, base columns repeated

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

"TPT is the cleanest layout, so it must be the best one." It is the most normalized, but reading a type needs joins. TPH is the default, and EF Core's own guidance generally leans toward it for performance — choose TPT or TPC for a reason, not by taste.

🔄 Likely Follow-up

"Why is TPH the default, and what is its downside?" Everything lives in one table, so queries need no joins. The cost is that columns that belong only to a derived type must be nullable, and the table gets wider as the hierarchy grows.

🎯 Say this in the interview — the exact lines to land

"EF Core can map a hierarchy three ways. TPH, the default, puts everything in one table with a discriminator column. TPT gives each type its own table and joins them. TPC, added in EF Core 7, gives each concrete type its own full table. I start with TPH and only switch when the nullable columns or the shape of the data say otherwise."

  • TPH → default, one table with a discriminator; derived columns are nullable.
  • TPT → table per type; reads need joins (EF Core 5+).
  • TPC → table per concrete type; no joins, base columns repeated (EF Core 7+).
  • Switch away from TPH only for a reason — a very wide, mostly-NULL table, or strict per-type tables.
📖 Explanation ▾

A database table has no "is-a" relationship, so EF Core has to flatten the hierarchy. With TPH (table-per-hierarchy, the default) every type in the hierarchy shares one table, and a Discriminator column says which type each row is. There are no joins, but columns that exist only on a derived type must allow NULL.

TPT (table-per-type, EF Core 5+) gives each type its own table holding only that type's columns. The derived table's key is also a foreign key to the base table, so loading a Dog joins the two. TPC (table-per-concrete-type, EF Core 7+) gives each concrete type a table with all its columns, base ones included — no joins when you query one concrete type, but the base columns are repeated, and an abstract base gets no table.

💻 See the code ▾
C# 
public abstract class Animal { public int Id { get; set; } public string Name { get; set; } }
public class Dog : Animal { public string Breed { get; set; } }
public class Cat : Animal { public int Lives { get; set; } }

public DbSet<Animal> Animals { get; set; }   // ✅ TPH by default — nothing else to configure
public DbSet<Dog> Dogs { get; set; }
public DbSet<Cat> Cats { get; set; }

With no extra configuration, EF Core uses TPH: one Animals table plus a discriminator column.

C# 
modelBuilder.Entity<Animal>().UseTptMappingStrategy();   // EF Core 7+: table per type
// or
modelBuilder.Entity<Animal>().UseTpcMappingStrategy();   // EF Core 7+: table per concrete type

Opt in to TPT or TPC on the root type of the hierarchy.

C# 
var dogs = await db.Animals.OfType<Dog>().ToListAsync();   // TPH: filters on the discriminator

OfType<T>() reads one subtype — under TPH that is just a filter on the discriminator column.

🌍 Real-world example ▾

A Payment hierarchy with CardPayment, BankTransfer and WalletPayment that each add a couple of columns fits TPH well. If each subtype adds a dozen of its own, one wide, mostly-NULL table gets awkward — that is the moment to measure and consider TPT or TPC.
