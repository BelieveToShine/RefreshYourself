params, optional & named — three ways to make a call easier to write

"What's the difference between params, optional, and named parameters?"

Why it matters ▾
  • Avoids overload explosion — instead of five overloads to cover every combination of arguments, one method with defaults covers all of them.
  • Comes up the moment you're calling a method with more parameters than you actually care about — framework APIs lean on this constantly.
  • A common early stumble: reaching for the wrong one of the three, because they solve different problems, not the same one.
🔥 Easy interview recall

params → many args, one array

optional → default if omitted

named → match by name, any order

Think: all three exist so a caller can write less at the call site — a variable count, a skipped argument, or a clearer order.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Named arguments can be written in any order — but you can't put a positional argument after a named one. Once an argument in the call is named, every argument after it must also be named, or the compiler rejects the call.

🔄 Likely Follow-up

"What happens to old callers when a library changes an optional parameter's default value?" Nothing, until they recompile — the default is baked into the caller's compiled code at compile time, so an old caller keeps using the old default until it's rebuilt against the new version.

🎯 Say this in the interview — the exact lines to land

"params lets a caller pass a variable number of arguments as one array parameter. Optional parameters have a compile-time default used when the caller omits them. Named parameters let a caller specify arguments out of order by name."

  • params → use for a genuinely open-ended argument list — logging tags, a list of ids, format arguments.
  • optional → use for a setting most callers accept as-is, so they don't have to pass it every time.
  • named → use to skip a middle optional argument, or to make a call with several arguments self-documenting.
  • Optional defaults are fixed at compile time, not looked up at runtime — a library update doesn't change them for already-compiled callers.
📖 Explanation ▾

params turns a whole tail of arguments into a single array parameter — the caller can pass zero, one, or a hundred values, and the method sees them as one array. It has to be the last parameter in the signature, and a method can only declare one.

Optional parameters give a parameter a default value the caller can skip. That default isn't looked up when the method runs — it's a compile-time constant, copied straight into the caller's own compiled code the moment the caller was built.

Named parameters aren't about the method's signature at all — they're a call-site choice to specify an argument by its parameter name instead of its position, so the order written in the call no longer has to match the order in the declaration.

💻 See the code ▾
C# 
void SendEmail(string to, params string[] cc)
{
    // cc is just an array here
}

SendEmail("a@x.com");                       // cc.Length == 0
SendEmail("a@x.com", "b@x.com", "c@x.com");  // ✅ cc = ["b@x.com","c@x.com"]

params must be the last parameter, and packs any number of extra arguments — including none — into one array.

C# 
void SendEmail(string to, string subject = "Hi")
{
    // ...
}

SendEmail("a@x.com");              // ✅ subject == "Hi" — the default
SendEmail("a@x.com", "Reminder");  // subject == "Reminder"

The default only applies when the caller omits the argument — it's a compile-time value, not something re-checked at runtime.

C# 
SendEmail(subject: "Reminder", to: "a@x.com");  // ✅ order doesn't matter
SendEmail("a@x.com", subject: "Reminder");      // ✅ positional, then named
SendEmail(to: "a@x.com", "Reminder");            // ❌ named, then positional — won't compile

Named arguments can appear in any order — but once you name one, everything after it must be named too.

🌍 Real-world example ▾

Ordering a sandwich. params is "add as many toppings as you like" — the shop doesn't care if that's zero or ten. Optional is the shop's default bread — say nothing and you get white, every time, because that default was decided when the menu was printed. Named is calling out "no onions" without listing every other ingredient in the order they appear on the menu.
