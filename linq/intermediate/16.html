let, into and Grouping in Query Syntax — the query-syntax-only keywords

"What do let and into actually do in query syntax, and what do they look like translated to method syntax?"

Why it matters ▾
🔤 let
❗ ProblemA query needs an expensive or repeated sub-expression — a string split, a computed total — more than once per element; repeating it inline recomputes it every time it's written and clutters the query.
✅ Solutionlet introduces a named intermediate value computed once per element, which the rest of the query can reference by name — it translates to a Select projecting an anonymous type carrying both the original item and the computed value.
Recalllet = compute once, name it, reuse it.
🔁 into
❗ ProblemAfter a group by, the query needs to keep filtering or ordering the groups themselves — but group by ends the current range variable's scope, leaving nothing left to query against.
✅ Solutioninto re-binds the query's result (most commonly right after group by) as a brand-new range variable, so the query expression can continue with further where/orderby clauses over that new sequence.
Recallinto = continue querying what you just produced.
🔥 Easy interview recall

let → compute once, name it

into → re-bind and keep querying

Think: let saves a value mid-row. into restarts the query on the row's output.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

let doesn't declare a reusable C# local variable. It compiles down to a Select that projects an anonymous type carrying the original item plus the new value — the "variable" only exists inside the query expression, not as a real local afterward.

🔄 Likely Follow-up

"Can into only follow group by?" Technically it can also follow a select clause to continue querying a projected result, but after group by is by far the dominant real use — continuing to filter or order groups is the construct's main job.

🎯 Say this in the interview — the exact lines to land

"let names an intermediate value inside a query so an expensive expression isn't recomputed per reference — it compiles down to a Select producing an anonymous type. into re-binds a query's result, most commonly right after group by, as a new range variable so the query can keep filtering or ordering, which group by alone wouldn't allow since it ends the original range variable's scope."

  • let → compute once, avoid recomputation, becomes a Select under the hood.
  • into → rebind as a new range variable, continue querying.
  • Most common into use → filtering/ordering groups right after group by.
  • Both are query-syntax-only — no matching keyword exists in method syntax.
📖 Explanation ▾

let exists purely for query syntax — there's no separate "let" method. Under the covers, the compiler turns every let into a Select that projects an anonymous type holding the original range variable alongside the new named value, so every clause after it (where, another let, select) can reference the computed value without recomputing it.

into is the query-syntax way of saying "treat what I just produced as the new starting point." A group by ... into g is the classic shape: group by alone produces the groups and ends the query, but writing into g immediately after captures that grouped result as a fresh range variable g, so where/orderby/select can keep going against the groups themselves — filtering out small groups, ordering by group total, and so on.

Neither keyword has a one-to-one method-syntax equivalent — they're restructured instead: let becomes an extra Select in the chain, and into becomes nothing more than continuing to chain more LINQ methods onto the result of GroupBy.

Query-syntax keywordWhat it doesMethod-syntax equivalent
letnames an intermediate value per elementan extra Select projecting new { item, value }
into (after group by)rebinds groups as a new range variablejust continuing to chain methods on GroupBy(...)'s result
💻 See the code ▾
C# 
var result = from p in products
              let tax = p.Price * 0.1   // computed once per p
              where tax > 5              // reuses tax, doesn't recompute
              select new { p.Name, tax };

tax is computed once and reused by both where and select.

C# 
var result = products
    .Select(p => new { p, tax = p.Price * 0.1 })   // let → Select
    .Where(x => x.tax > 5)
    .Select(x => new { x.p.Name, x.tax });

This is exactly what the let version above compiles down to.

C# 
var busyCustomers = from o in orders
                   group o by o.CustomerId into g   // g = the groups
                   where g.Count() > 2               // filters the groups themselves
                   orderby g.Count() descending
                   select g;

into g is what lets where/orderby run on the groups, not the original orders.

🧭 Use Cases — recognize these when they happen to you ▾
1 An expensive calculation is referenced more than once in a query

A discount calculation (or a string parse) referenced in both where and select is the textbook reason to reach for let — name it once, every later clause reuses the same computed value.

RememberUsed more than once in the query → let, not a repeated inline expression.
2 Reporting: only months above a threshold, sorted by total

A report that groups orders by month, then keeps only months with more than 10 orders and sorts by total, needs into g right after group by — without it there's no way to filter or sort the groups themselves in query syntax.

RememberFiltering/ordering groups after group by → always needs into.
3 Expecting a let value to exist outside the query

tax from a let clause only exists inside that query expression's projection — it isn't a C# local variable you can reference after the query ends, because it really lives inside the anonymous type the compiler generated.

Rememberlet's name is scoped to the query, not the surrounding method.
🌍 Real-world example ▾

A reporting query groups orders by month, then needs only months with more than 10 orders, sorted by total descending. group by o.Month into g where g.Count() > 10 orderby g.Sum(o => o.Total) descending select g is the idiomatic query-syntax shape — into g is exactly what makes filtering and ordering the groups possible after the group by.
