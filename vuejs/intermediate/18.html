<KeepAlive> — freezing a component instead of killing it

"What does <KeepAlive> cache, and what hooks fire instead of mount/unmount?"

Why it matters ▾
🧊 <KeepAlive>
❗ ProblemSwitching away from a tab/component and back destroys the old instance and creates a brand-new one — a half-filled form, a scroll position, or a fetched list the user already loaded is gone the moment they come back.
✅ Solution<KeepAlive> wraps a dynamic/conditionally-rendered component and caches its instance instead of destroying it, so switching back restores the exact same state.
Recall<KeepAlive> = pause the component, don't kill it.
🔥 Easy interview recall

<KeepAlive> = "freezes a component instead of destroying it."

Think: switch away → deactivated (frozen, not unmounted); switch back → activated (same instance, same data).

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

<KeepAlive> doesn't persist state forever across unrelated navigation. It only caches instances it's directly wrapping — unmounting the <KeepAlive> itself clears its whole cache, so a cached component is only safe inside its own <component :is>/<router-view>.

🔄 Likely Follow-up

"How do you limit how much it caches?" The max prop caps the number of cached instances — once exceeded, the least-recently-used one is evicted and will remount fresh next time.

🎯 Say this in the interview — the exact lines to land

"<KeepAlive> caches a dynamically-switched component's instance instead of destroying it, so switching back restores the exact previous state. activated/deactivated fire instead of mounted/unmounted on a cache hit, and the max prop caps how many instances it keeps."

  • <KeepAlive> → caches the instance, data survives the switch.
  • activated / deactivated → fire instead of mounted / unmounted.
  • Only caches what it directly wraps — unrelated unmounts elsewhere aren't affected.
  • max prop → LRU eviction once the cache is full.
📖 Explanation ▾

<KeepAlive> wraps a dynamic component (typically <component :is="..."> or a <router-view>) and, instead of destroying the component being switched away from, moves it into an in-memory cache. Its DOM is detached, but the component instance — its reactive data, computed values, watchers — stays alive exactly as it was.

Because the instance never actually unmounts, Vue fires activated when it's shown again and deactivated when it's hidden, instead of the usual mounted/unmounted pair. Any hook that should re-run every time a tab becomes visible (like refetching data) belongs in activated, not mounted — mounted only fires once, the first time.

The cache isn't unlimited by default. The max prop caps it to a fixed number of instances; once a new one would exceed that, the least-recently-used cached instance is evicted and destroyed for real, so it remounts fresh the next time it's shown.

💻 See the code ▾
Vue 
<KeepAlive max="3">             <!-- caps the cache at 3 instances -->
  <component :is="activeTab" />
</KeepAlive>

The 4th tab opened evicts the least-recently-used cached one.

Vue 
import { onActivated, onDeactivated } from 'vue'

onActivated(() => {
  refreshList()                 // ✅ runs every time this tab is shown again
})
onDeactivated(() => {
  pausePolling()                // instance is frozen, not destroyed
})

onMounted would only fire once — these fire on every cache hit.

🌍 Real-world example ▾

A settings page with "Profile," "Billing," and "Notifications" tabs. Wrapping the tab's dynamic component in <KeepAlive> means a half-filled "Billing" form is still there, untouched, after a user clicks over to "Notifications" and back.
