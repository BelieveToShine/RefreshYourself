sort() — why [10, 9, 1] comes back as [1, 10, 9]

"Why does [10, 9, 1].sort() give [1, 10, 9], and does sort return a new array?"

Why it matters ▾
🔀 sort()
❗ ProblemCalling sort() on numbers with no comparator quietly gives the wrong order, and const sorted = arr.sort() looks like a copy but changes the original — both are silent bugs, no error is thrown.
✅ SolutionThe default sort compares items as text, so numbers need a comparator like (a, b) => a - b; and sort() rearranges the same array in place — copy first ([...arr] or toSorted()) when the original must stay.
Recallsort() = text order by default, and it changes the original array.
🔥 Easy interview recall

sort() → compares as text

sort((a, b) => a - b) → compares as numbers

sort() → changes the original array

toSorted() → returns a copy

Think: [10, 9, 1].sort() → "1" < "10" < "9" as text → [1, 10, 9].

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

sort() does not return a new array. It sorts the original in place and hands back that same array, so const b = a.sort() makes a and b one and the same array — copy first, or use toSorted().

🔄 Likely Follow-up

"How do you sort numbers without touching the original?" Copy first with [...arr].sort((a, b) => a - b), or call arr.toSorted((a, b) => a - b) — toSorted is ES2023 and works in all current major browsers (older ones need the spread copy). The spread copy is shallow: objects inside are still shared.

🎯 Say this in the interview — the exact lines to land

"By default sort() turns items into strings and compares them as text, so [10, 9, 1] becomes [1, 10, 9]. For numbers I pass a comparator like (a, b) => a - b. And sort() changes the original array and returns that same array — toSorted() is the version that returns a copy."

  • Default → compares as text, so "10" comes before "9".
  • Comparator → return a number, not true/false: negative means a first, positive means b first.
  • Return value → the same array, not a copy — it is changed in place.
  • Equal items → keep their original order (sort is stable since ES2019).
  • ES2023 twins → toSorted, toReversed, toSpliced, with return copies — all ES2023, supported in current browsers.
📖 Explanation ▾

With no comparator, sort() converts every item to a string and compares them by their character codes, like dictionary order for characters. That is why 10 sorts before 9 — the character "1" comes before "9". It is the same "everything becomes text" surprise you meet in type coercion. Items that are undefined are always moved to the end.

A comparator is a function (a, b) that returns a number: negative puts a first, positive puts b first, zero means "equal". So a - b sorts numbers ascending and b - a descending. Returning a boolean such as a > b never says "a goes first", so don't. For words, use a.localeCompare(b).

sort(), reverse() and splice() all change the array they are called on, and sort() returns that same array. ES2023 added copying twins — toSorted(), toReversed(), toSpliced() and with(index, value) — which leave the original alone. MDN lists them as widely available since 2023; on an older browser, copy first with [...arr] (a shallow copy — see Arrays & Objects and Array Methods).

💻 See the code ▾
JavaScript 
const nums = [10, 9, 1];
nums.sort();                  // [1, 10, 9]  (compared as text)
nums.sort((a, b) => a - b);   // [1, 9, 10]  (numbers, ascending)
nums.sort((a, b) => b - a);   // [10, 9, 1]  (numbers, descending)

Each call re-sorts the same nums array in place.

JavaScript 
const original = [3, 1, 2];
const result = original.sort();
console.log(result === original);   // true: same array, not a copy
console.log(original);              // [1, 2, 3]  (the original changed)

Assigning the result of sort() does not make a copy.

JavaScript 
const scores = [3, 1, 2];
const sorted = scores.toSorted((a, b) => a - b);  // [1, 2, 3], a new array (ES2023)
console.log(scores);                              // [3, 1, 2]  unchanged
const older = [...scores].sort((a, b) => a - b);  // copy first, then sort

Both give a sorted copy; the spread version works where toSorted is not available yet.

🌍 Real-world example ▾

A price list showed 100 above 25. The code used plain sort(), so prices were compared as text — adding (a, b) => a - b fixed the order, and copying the array first stopped another widget sharing the same array from being reordered behind its back.
