const, readonly, static — locked when? Shared how many times?

Why it matters ▾
  • Explains why some "constants" can change per-object and others truly can't.
  • Tells you which one to reach for: a fixed rule, a per-object setting, or a shared counter.
  • A quick way to show you understand compile-time vs. runtime.
🔥 Easy interview recall

const → locked before it runs

readonly → locked once, per object

static → one shared copy

Think: static readonly → computed once, shared forever

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Changing a const doesn't update old callers. The value is baked into their compiled code at compile time — they stay stale until they're rebuilt.

🎯 Say this in the interview — the exact lines to land

"const is fixed at compile time and always shared. readonly is fixed once per object, at construction. static is a sharing rule, not a locking rule — one copy for every instance."

  • static readonly combines both: computed once, shared forever.
  • readonly can differ per object — const never can.
📖 Explanation ▾

const is baked into the compiled code itself — the value has to be known at compile time (a literal, or another const), and it's always implicitly shared, never per-object.

readonly is more flexible: it can be assigned in the constructor, so different objects can end up with different, still-unchangeable values — useful when the "constant" depends on something only known at runtime.

static is a completely different axis — it's not about whether a value can change, it's about whether there's one copy shared by every instance, or one copy per instance. You can combine it with readonly (static readonly) for a value computed once at startup and shared forever.

💻 See the code ▾
C# 
public const int MaxRetries = 3;   // compile-time, shared
MaxRetries = 5;   // ❌ compile error — const can never be reassigned

const is locked before the program even runs — there's no legal way to change it, ever.

C# 
public readonly string Id;
public Config(string id) => Id = id;   // ✅ allowed — inside the constructor
Id = "new";   // ❌ compile error — outside the constructor

Two different Config objects can end up with two different Id values — each locked after its own constructor runs.

C# 
public static int InstanceCount;
// every Config instance reads and writes the SAME InstanceCount

static isn't about locking at all — it's one copy shared by every instance.

🌍 Real-world example ▾

A printed rulebook vs. a signed contract vs. a shared office clock. const is the rulebook — printed once, identical for everyone, never reprinted. readonly is a signed contract — fixed once signed, but each person's contract can say something different. static is the office wall clock — there's exactly one, and everyone in the room reads the same time off it.
