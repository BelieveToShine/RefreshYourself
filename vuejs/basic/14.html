<style scoped> — one level of isolation, not a sealed box

"What does <style scoped> actually do inside a Single File Component?"

Why it matters ▾
📄 Scoped Styles
❗ ProblemPlain CSS is global — a rule like .title { color: red } written for one component can silently restyle a same-named class in a completely different component.
✅ Solution<style scoped> auto-generates a unique data attribute Vue applies to that component's own elements, so its CSS rules only match inside that component.
RecallScoped = Vue tags every element with a unique attribute, then rewrites your selectors to require it.
🔥 Easy interview recall

Scoped CSS = "your selector, plus an invisible unique attribute Vue adds for you."

Think: .title becomes .title[data-v-xxxx] at build time — same class name, now component-specific.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Assuming scoped styles fully isolate a child component too. A scoped rule targeting a child's root element still applies (one level, by design) — it's not true Shadow-DOM-level isolation.

🔄 Likely Follow-up

"How would you intentionally style a child from a scoped parent?" The :deep() pseudo-class — :deep(.child-class) { … } — explicitly escapes the scoping boundary for that one selector.

🎯 Say this in the interview — the exact lines to land

"A .vue file bundles template, script, and style for one component in a single file. <style scoped> makes Vue auto-generate a unique data attribute for that component's elements and rewrite its CSS selectors to require that attribute, so its rules only match inside that component."

  • Scoping works by attribute selectors, not a build-time rename of class names.
  • A scoped rule aimed at a child's root element still applies — one level, by design.
  • :deep(.selector) deliberately escapes scoping to style a child from the parent.
  • Without scoped, a rule is plain global CSS — no isolation at all.
📖 Explanation ▾

A Single File Component bundles everything one component needs — markup, logic, and style — into one .vue file with <template>, <script>, and <style> sections. Without scoped, that style block is just ordinary global CSS — it can affect any matching element anywhere in the app.

<style scoped> changes that: at build time, Vue adds a unique data attribute (like data-v-f3a1) to every element this component renders, and rewrites every selector in that style block to also require that attribute. .title effectively becomes .title[data-v-f3a1] — same class name elsewhere, different attribute, no collision.

That attribute only gets added to elements this component itself renders directly — a selector that happens to target a child component's own root element still matches it, because Vue also stamps the parent's scope attribute onto a child's outermost tag. This is the one deliberate leak in otherwise one-way scoping, and it's exactly why :deep() exists as the explicit, intentional version of reaching further in.

💻 See the code ▾
Vue 
<!-- Card.vue -->
<template>
  <h3 class="title">Hello</h3>
</template>

<style scoped>
.title { color: red; }   // only this component's .title
</style>

Compiles to roughly .title[data-v-f3a1] { color: red; } — a .title in another component is untouched.

Vue 
<style scoped>
:deep(.child-title) { color: blue; }   // explicitly reaches into a child
</style>

:deep() is the deliberate escape hatch — everything else in the block stays scoped as normal.

🧭 Use Cases — recognize these when they happen to you ▾
1 You're styling a component without worrying about name collisions

Reusing simple class names like .title or .wrapper across many components is completely normal with scoped — each one's attribute keeps its own rules local. This is the #1 scenario you'll actually run into.

Rememberscoped → reuse simple class names freely, no global collision.
2 You need to override a child component's root-level styling from its parent

A layout component that needs to adjust how a child it renders looks — spacing, a border — reaches for :deep() rather than removing scoped entirely, keeping the rest of its styles isolated.

RememberNeed to style a child → :deep(), not dropping scoped.
3 You assume a child's internal elements are untouchable from the parent

A parent's scoped rule that happens to target a child's own root element still matches it — Vue stamps the parent's scope attribute onto that outer tag too. Scoped styles are one level of protection, not a sealed Shadow DOM boundary.

RememberScoped rule on a child's root element → still applies, by design.
🌍 Real-world example ▾

Think of a name tag with a hidden barcode. Two people can both be called "Alex," but each name tag's barcode makes it scannable as exactly one specific person. Scoped CSS works the same way — the class name can repeat everywhere, but the hidden attribute Vue adds keeps each component's rules pointed at only its own elements.
