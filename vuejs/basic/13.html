Slots — a picture frame the parent fills in

"What's a slot, and how do named slots differ from the default slot?"

Why it matters ▾
🖼️ Slots
❗ ProblemProps can hand a child plain data, but not arbitrary markup — a reusable Card component can't know in advance exactly what HTML a caller will want inside it.
✅ SolutionA slot is a placeholder in the child's own template — <slot></slot> — that the parent fills with its own markup, letting the child control the layout while the parent controls the content.
RecallSlot = a hole in the child's template; the parent's markup drops into it.
🔥 Easy interview recall

<slot> → one unnamed hole

<slot name="x"> → named hole

<template #x> → fills that named hole

Think: A picture frame (child) with a photo (parent's content) dropped inside it.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Assuming slot content runs in the child's own data scope. By default, slot content is compiled in the parent's scope — only a scoped slot deliberately exposes child data back to the parent's slot content.

🔄 Likely Follow-up

"What's a scoped slot for?" Letting the child pass data out to the slot content the parent writes — e.g. a list component that owns the data but lets the parent decide how each row renders.

🎯 Say this in the interview — the exact lines to land

"A slot is a placeholder in a child component's template that the parent fills with its own markup — <slot></slot> for the default slot, or <slot name="header"> paired with <template #header> in the parent for a named one."

  • Default slot → one unnamed hole, fills with whatever plain markup the parent puts inside the tag.
  • Named slot (<slot name="x">) → a specific labeled hole, matched by <template #x>.
  • Slot content compiles in the parent's own scope by default — not the child's.
  • A scoped slot passes child data out to the parent's slot content — the reverse direction of a normal prop.
📖 Explanation ▾

A slot is written as <slot></slot> inside a child component's own template — it marks a spot where whatever the parent puts between the child's opening and closing tags gets rendered instead. This is the default slot: one unnamed hole, used when a component has just one natural place for custom content.

A component can declare several holes by naming them — <slot name="header"></slot> and <slot name="footer"></slot> — and the parent targets each one with <template #header> / <template #footer> (# is shorthand for v-slot:). Content with no matching <template> tag falls into the default slot automatically.

Slot content is written by the parent, so by default it's compiled in the parent's own data scope, not the child's — it can see the parent's data, not the child's internals. A scoped slot is the deliberate exception: the child passes data out through the slot (<slot :item="row">), and the parent's <template #default="{ item }"> reads it back.

💻 See the code ▾
Vue 
<!-- Card.vue (child) -->
<template>
  <div class="card"><slot></slot></div>   // the hole
</template>

The child owns the <div class="card"> wrapper styling — not what's inside it.

Vue 
<!-- Parent.vue -->
<Card>
  <p>Hello, world</p>   // ✅ fills the default slot
</Card>

Whatever the parent writes between the tags lands exactly where <slot> was.

Vue 
<slot name="header"></slot>      // named hole in the child
<Card>
  <template #header><h3>Title</h3></template>   // targets it by name
</Card>

A component can have several named slots alongside one default — each targeted independently.

🧭 Use Cases — recognize these when they happen to you ▾
1 You're building a generic wrapper — a card, a modal, a panel

A Modal handles the overlay, close button, and positioning, but has no idea what content any given caller wants inside it — a slot lets every usage put in different markup. This is the #1 scenario you'll actually run into.

RememberGeneric wrapper → the slot is what makes it reusable.
2 A component has multiple distinct regions (header, body, footer)

A layout component with a header, body, and footer gives each region its own named slot, so a caller can fill only the regions it actually needs and leave the rest with the component's own default content.

RememberSeveral distinct regions → one named slot per region.
3 You try to use the child's own data inside the slot content

Slot content written by the parent can only see the parent's own data by default — a variable that only exists inside the child's setup() simply isn't reachable there. A scoped slot is the only way the child can hand its own data out.

RememberSlot content → parent scope by default, not the child's.
🌍 Real-world example ▾

A picture frame and a photo. The frame (the child component) decides the border, the stand, how it hangs on the wall — but the photo inside it (the parent's content) is whatever you choose to put in. Swap the photo and the frame doesn't change at all.
