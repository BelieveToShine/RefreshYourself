Lazy loading & resource hints — load what's in view first, never delay the hero

"How do you stop below-the-fold images from slowing the page?"

Why it matters ▾
🖼 Lazy loading
❗ ProblemA page with 40 images downloads all 40 up front — even ones far below the fold that the user may never scroll to — and they fight the images that matter for bandwidth.
✅ Solutionloading="lazy" makes the browser fetch an image only when it gets near the viewport; width/height reserve its space so nothing jumps; fetchpriority and preload speed up the one image that must be fast.
RecallLazy for below the fold. Eager (plus priority) for the hero.
🔥 Easy interview recall

Lazy loading = "don't fetch what the user can't see yet — but never delay the hero."

Think: below the fold → loading="lazy" the hero image → no lazy, fetchpriority="high" every image → width + height

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Don't lazy-load the hero image. loading="lazy" on the biggest above-the-fold image makes it load later — it hurts the Largest Contentful Paint instead of helping. Lazy is for what's below the fold.

🔄 Likely Follow-up

"The lazy images pop in and the page jumps — why?" Without width and height (or aspect-ratio) the browser doesn't know an image's size until it arrives, so it reserves no space and everything below shifts. Give every image its dimensions.

🎯 Say this in the interview — the exact lines to land

"I add loading="lazy" to below-the-fold images so the browser fetches them only when the user scrolls near. I give every image width and height so the space is reserved and nothing shifts. The hero image is never lazy — I give it fetchpriority="high", and preload it if the browser would find it late."

  • loading="lazy" → below the fold only; the default is eager.
  • width + height → reserve the space, so no layout shift.
  • Never lazy-load the LCP image — the main above-the-fold one.
  • fetchpriority="high" → a hint to fetch the key image sooner.
  • rel="preload" → fetch early what the browser would find late.
  • rel="preconnect" → open the connection early to another origin.
📖 Explanation ▾

When the parser meets an <img> it normally starts the download straight away (loading="eager", the default). With loading="lazy" the browser holds the request until the image is close to the viewport. The same attribute works on <iframe>. Pair it with width and height: the browser uses them to work out the image's shape before it downloads, so the layout step (see Browser Rendering) reserves the box and nothing jumps when the picture arrives. img { max-width: 100%; height: auto } still keeps it responsive.

Resource hints help the important things load sooner. They are hints, so use them sparingly — too many compete with each other.

💻 See the code ▾
HTML 
<!-- hero: eager (default) + high priority -->
<img src="hero.jpg" width="1200" height="600" fetchpriority="high" alt="…">

<!-- below the fold: lazy + reserved space -->
<img src="photo.jpg" width="800" height="400" loading="lazy" alt="…">

Hero fetches first; the photo waits — and both keep their space.

HTML 
<!-- a CSS background image is found late — fetch it early -->
<link rel="preload" as="image" href="hero-bg.jpg">

<!-- open the connection to the CDN early -->
<link rel="preconnect" href="https://cdn.example.com">

Hints for what the browser would otherwise discover late.

🌍 Real-world example ▾

Think of a pop-up bookshelf that only pulls out the books near where you're standing, while the empty slots stay marked so the shelf never resizes when a book arrives.
