Anonymous types — a shape with no name, built just for this query

"What is an anonymous type, and why does Select(x => new { ... }) need one?"

Why it matters ▾
🧩 Anonymous types
❗ ProblemA query often only needs two or three fields out of a much wider entity — writing a brand-new named DTO class every single time, just to hold "Name and Total," is ceremony nobody wants for a one-off shape.
✅ SolutionSelect(x => new { Name = x.Name, Total = x.Total }) has the compiler generate an unnamed, read-only class on the spot — inferred entirely from the object-initializer syntax, with no class declaration written anywhere.
RecallAnonymous type = a one-off shape the compiler names, so you don't have to.
🔥 Easy interview recall

Anonymous type = "a shape with no name, good for exactly one method."

Think: new { Name = x.Name, Total = x.Total } → a real class exists, you just never get to write or see its name.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Trying to return an anonymous type from a public method, or store it in a field typed by name. It has no name to declare as a return type or field type — var only works because the compiler already knows the type in the same method where it was created.

🔄 Likely Follow-up

"So how would you actually get that shape out of a method?" Use a named DTO class or a record if the shape needs to leave the method, dynamic if you're willing to give up compile-time type safety, or a tuple ((string Name, decimal Total)) for something quick and still statically typed.

🎯 Say this in the interview — the exact lines to land

"An anonymous type is a compiler-generated, unnamed class with read-only properties, inferred from an object initializer like new { Name = x.Name, Total = x.Total } — it's for a one-off projection shape that doesn't earn a named DTO class."

  • Stays in one method → var is all you need, the compiler already knows the real type.
  • Needs to leave the method → it can't — switch to a named DTO class, a record, a tuple, or dynamic.
  • Every anonymous-type property is read-only, set once at construction — there's no way to assign into it afterward.
📖 Explanation ▾

Writing new { Name = x.Name, Total = x.Total } doesn't skip creating a class — the compiler still generates a real one, with real read-only properties, behind the scenes. What it skips is the name: that generated class gets a name only the compiler ever uses, never one you can write in your own source code.

That's exactly why var is the natural partner for it: var doesn't need to know the type's name either, it just captures whatever type the right-hand side actually produced — compiler-to-compiler, with no name required on either side. The moment that value needs to cross a method boundary (as a parameter, a return value, a field typed by name), something needs to write down the type, and an anonymous type has nothing to write.

WorkaroundStays statically typed?When to reach for it

💻 See the code ▾
C# 
var summaries = customers.Select(c => new { c.Name, c.Total });

foreach (var s in summaries)
    Console.WriteLine($"{s.Name}: {s.Total}");   // ✅ works — still inside the same method

var + the same method = no name ever needed.

C# 
public var GetSummary(Customer c) => new { c.Name, c.Total };
// ❌ doesn't compile — "var" isn't a legal return type, and the real type has no name to write

There's no legal way to name the return type — use a record instead.

C# 
public record CustomerSummary(string Name, decimal Total);

public CustomerSummary GetSummary(Customer c) =>
    new CustomerSummary(c.Name, c.Total);   // ✅ a real, named type — safe to return

A record is a name you can write down, so it can leave the method.

🧭 Use Cases — recognize these when they happen to you ▾
1 You only need 2-3 fields for a view, within the same method

Rendering a quick list or a console report where the shape never leaves this method? An anonymous type via var is the simplest, lowest- ceremony option. This is the #1 scenario you'll actually run into.

RememberOne-off shape, same method → anonymous type + var.
2 The shaped result needs to be returned from a method or stored in a field

A service method handing a shaped result back to a controller, or an API response model, needs a name the caller's code can reference — swap the anonymous type for a record or a plain DTO class before it crosses that boundary.

RememberCrosses a method boundary → named DTO/record, not anonymous.
3 You try to declare a field or method signature with the anonymous type's "name"

There's no syntax for "the type that new { Name, Total } just produced" — it genuinely has no spellable name, so public SomeType Get() { ... } can never name it as the return type, full stop.

RememberNo spellable name → can never appear in a signature.
🌍 Real-world example ▾

It's a sticky note, not a filing-cabinet label. A sticky note is perfect for jotting something down and using it right where you wrote it — but you'd never hand it to someone in another building and expect them to find it by name. An anonymous type is that sticky note; a named DTO class is the properly labelled file.
