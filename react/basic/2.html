JSX — HTML-shaped syntax for calling a function

"What is JSX, and how does it actually become JavaScript?"

Why it matters ▾
  • Explains why a component can only return one thing — and why you reach for a Fragment instead of an extra <div>.
  • Clears up a common first-week confusion: JSX looks like HTML, but nothing ever parses it as HTML.
  • One of the most common opening questions in a React interview.
🔥 Easy interview recall

JSX = "sugar for React.createElement() calls, compiled before your code ever runs."

Think: <h1>Hi</h1> compiles to React.createElement('h1', null, 'Hi').

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

JSX is not HTML that React parses at runtime. It's compiled — by Babel or another build tool — into plain JavaScript function calls before your code ever runs, so there's no runtime HTML-parsing step anywhere in the process.

🔄 Likely Follow-up

"Why must a component return a single root element?" Because a JavaScript function can only return one value — a Fragment (<>...</>) solves this without adding an extra, unwanted real DOM node the way wrapping everything in an extra <div> would.

🎯 Say this in the interview — the exact lines to land

"JSX isn't HTML — it's syntax that a build tool like Babel compiles into React.createElement() calls before the browser ever runs the code. A component is just a function that returns one of those calls, and it has to return a single root, which is why a Fragment exists."

  • createElement() / jsx() → compiled output, never something the browser parses as HTML.
  • Functional components → preferred today over classes — less verbose, no this-binding, and logic shares through custom Hooks.
  • One root only → use a Fragment, not a wrapper <div>, to avoid an extra DOM node.
  • A component can return null — that's valid, it just renders nothing.
📖 Explanation ▾

A component is just a reusable function that returns UI. Modern React almost always uses functional components — plain functions that use Hooks — instead of class components. They're less verbose, avoid the classic this-binding confusion classes create, and let you share logic through a custom Hook instead of inheritance or a higher-order component.

A browser's JavaScript engine has no idea what to do with a tag like <h1>. That's exactly why the compile step exists: Babel (or another build tool) turns it into React.createElement() calls — or, in newer React versions, the automatic jsx() runtime calls — so what actually reaches the browser is ordinary JavaScript, never markup.

Because a JavaScript function can only return one value, a component must return a single root. A Fragment (<>...</>) satisfies that rule without adding a real, extra DOM node the way an unnecessary wrapper <div> would. A component is also allowed to return null — that's valid, and it simply renders nothing.

💻 See the code ▾
JSX 
const el = <h1 className="title">Hello</h1>;  // what you actually write — looks like HTML

This is the JSX exactly as typed — a tag, one attribute, one piece of text.

JSX 
const el = React.createElement('h1', { className: 'title' }, 'Hello');  // what card 1 compiles to

Same three pieces, now function arguments: 'h1' → the tag name, { className: 'title' } → the attributes, 'Hello' → the child content.

🌍 Real-world example ▾

JSX is a recipe card written in a friendly shorthand. The kitchen — the JavaScript engine — never reads that shorthand directly. Someone, the compiler, translates it into precise, step-by-step instructions first.
