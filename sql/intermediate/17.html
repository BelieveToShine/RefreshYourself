Self, FULL and CROSS — three joins, three row-count surprises

"Explain a self join, a FULL OUTER JOIN and a CROSS JOIN."

Why it matters ▾
🪞 Self join
❗ ProblemA table that points at itself (employee → manager) can't be read with an ordinary join.
✅ SolutionJoin the table to itself under two aliases.
RecallSelf join = the same table, twice.
↔️ FULL JOIN
❗ ProblemReconciling two lists needs rows from both sides, matched or not.
✅ SolutionFULL OUTER JOIN keeps unmatched rows from both sides, filling NULLs.
RecallFULL = everything from both sides.
✖️ CROSS JOIN
❗ ProblemSometimes you want every combination, like sizes with colours.
✅ SolutionCROSS JOIN pairs every row with every row, with no condition.
RecallCROSS = every pair, m × n rows.
🔥 Easy interview recall

Self → a table joined to itself

FULL → everything from both sides

CROSS → every pair, m × n rows

Think: Self → same table, two aliases FULL → unmatched rows kept on both sides CROSS → no ON, rows multiply

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

"A WHERE filter on a FULL JOIN just narrows the result." A filter on one table's column also drops the NULL-filled rows from the other side, quietly turning the FULL join into a one-sided join.

🔄 Likely Follow-up

"When would you use a CROSS JOIN on purpose?" To build every combination — dates by stores, sizes by colours — or to make a complete grid so a report can show zero for a missing combination.

🎯 Say this in the interview — the exact lines to land

"A self join joins a table to itself under two aliases, typically employee to manager. A FULL OUTER JOIN keeps unmatched rows from both sides, with NULL filling the gaps. A CROSS JOIN pairs every row with every row, so m rows by n rows gives m × n."

  • Self join → same table, two aliases; use LEFT so the top boss (no manager) stays.
  • FULL OUTER JOIN → matched rows plus unmatched rows from both sides.
  • CROSS JOIN → no ON; the row count is m × n.
  • Find mismatches → FULL JOIN then WHERE a.Id IS NULL OR b.Id IS NULL.
  • Accidental Cartesian → FROM A, B with no WHERE returns m × n rows.
📖 Explanation ▾

A self join is an ordinary join where both sides are the same table, so you must give each side its own alias. The classic case is an Employees table with a ManagerId column that points back at Employees.Id. Use LEFT JOIN if the person at the top has no manager and should still appear.

A FULL OUTER JOIN returns the matches, plus the rows only in the left table, plus the rows only in the right, with NULL in the missing side. It is the tool for comparing two tables. A CROSS JOIN has no join condition at all: every left row meets every right row. That is useful for calendars and combinations, but the same result appears by accident with the old comma syntax and a forgotten WHERE.

💻 See the code ▾
T-SQL 
SELECT e.Name AS Employee, m.Name AS Manager
FROM Employees AS e
LEFT JOIN Employees AS m ON e.ManagerId = m.Id;   -- ✅ top boss stays, Manager = NULL

A self join: the same table appears twice, once as the employee and once as the manager.

T-SQL 
SELECT a.Id AS LeftId, b.Id AS RightId
FROM TableA AS a
FULL OUTER JOIN TableB AS b ON a.Id = b.Id
WHERE a.Id IS NULL OR b.Id IS NULL;   -- ✅ only rows missing on one side

A FULL OUTER JOIN used to find what does not match between two tables.

T-SQL 
SELECT s.Size, c.Color
FROM Sizes AS s
CROSS JOIN Colors AS c;   -- 3 sizes × 2 colours = 6 rows

CROSS JOIN lists every size with every colour.

🌍 Real-world example ▾

A self join is looking each person's boss up in the same staff list. A FULL join is merging two guest lists and keeping everyone on either one. A CROSS join is pairing every starter on a menu with every main.
