🔥 DSA · Basic · Must Know

Follow the chain, or jump straight there?

"What is a linked list, and how is it different from an array?"

Why it matters ▾
  • Almost every DSA interview opens with "what is a linked list" before moving into harder problems built on top of it.
  • Reversal and cycle detection are two of the most common "write it on the whiteboard" questions in the entire DSA track.
  • Explains why real systems (browser back/forward history, an LRU cache's entry list) reach for a linked list instead of an array.
🔥 Easy interview recall

Linked List = "a chain of nodes connected by pointers, not sitting together in memory."

Think: Array → jump anywhere, shift to insert. Linked List → walk to get there, repoint to insert.

🧠 Visual Mental Model — watch the arrow flip mid-walk
⚠️ Common Trap

Overwriting curr.next before saving it. Once you write curr.next = prev, the only way forward is gone unless you grabbed next = curr.next first — the single most common bug in a live-coded reversal.

🔄 Likely Follow-up

"How would you find the middle of a linked list in one pass?" The same slow/fast two-pointer idea — fast moves two nodes for every one of slow's; when fast reaches the end, slow is standing at the middle.

🎯 Say this in the interview — the exact lines to land

"A linked list is a chain of nodes where each node points to the next — nodes aren't stored contiguously, so you trade an array's O(1) random access for O(1) insertion and deletion at a known node. Cycle detection and reversal both come down to walking the list with more than one pointer at a time."

  • Singly → each node points only forward. Doubly → nodes also point backward.
  • Cycle detection → Floyd's tortoise/hare, two pointers at different speeds, O(n) time, O(1) space.
  • Reversal → one pass, flipping each node's next pointer to point at the previous node.
  • Finding the middle → the same slow/fast pattern as cycle detection, not a new trick.
📖 Explanation ▾

A linked list stores each value inside its own node object, and every node holds a pointer to the next one. Nothing requires those nodes to sit next to each other in memory — they can live anywhere at all, as long as each one still points to the next.

That's exactly why the trade-off flips compared to an array. To reach the 5th node you have to walk from the head one pointer at a time — there's no formula that jumps straight there the way array indexing does. But once you're already standing at a node, adding or removing it is just repointing one or two pointers — no shifting every element after it, the way an array insert or delete requires.

Doubly linked adds a prev pointer on every node, so you can walk backward just as easily. Circular linked closes the loop — the last node's next points back to the head instead of stopping at null — useful for round-robin scheduling, or for noticing you've gone all the way around once.

💻 See the code ▾
C# 
Node prev = null, curr = head;
while (curr != null) {
    Node next = curr.Next;   // save BEFORE overwriting
    curr.Next = prev;         // ✅ flip the pointer
    prev = curr;
    curr = next;
}
head = prev;                  // prev is the new head

Save next before overwriting curr.Next — that's the one line the whole trap is about.

C# 
Node slow = head, fast = head;
while (fast != null && fast.Next != null) {
    slow = slow.Next;
    fast = fast.Next.Next;
    if (slow == fast) return true;   // ✅ cycle found
}
return false;                         // fast hit the end — no cycle

The same slow/fast idea finds the middle too — stop when fast reaches the end, and slow is standing right at the middle.

🌍 Real-world example ▾

A linked list is a treasure hunt. Each clue only tells you where the next clue is — you can't skip straight to clue 10, you have to follow the chain from the start. An array is a row of numbered lockers: walk straight to locker 10, no clues needed.
