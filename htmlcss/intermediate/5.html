CSS Grid — rows AND columns, lined up together on purpose

What is CSS Grid, how do fr, repeat(), and minmax() work, and how is Grid actually different from Flexbox?

Why it matters ▾
🧩 Grid-level properties
❗ ProblemSetting the same alignment on every single child one at a time is repetitive, and it's easy to leave one item's rule out and get an inconsistent layout.
✅ Solutionjustify-items/align-items and justify-content/align-content set one default alignment for the whole container at once — every cell, or the whole set of tracks, follows it without a per-item rule.
RecallGrid-level = one default alignment, applied to the whole container.
🎯 Item-level properties
❗ ProblemA single container-wide default has no way to make just one item sit differently — changing it to fit that one item would knock every other item out of line too.
✅ Solutionjustify-self/align-self override the container's default for just one item, so a single child can sit differently without touching anything else's alignment.
RecallItem-level = justify-self/align-self, overrides one item only.
🔥 Easy interview recall

Flexbox → one dimension at a time

Grid → two dimensions, together

Think: Flexbox lines items up. Grid maps them onto real rows and columns at once.

🧠 Visual Mental Model — named areas, mapped onto real cells
⚠️ Common Trap

auto-fill and auto-fit don't do the same thing. auto-fill keeps every track it could fit, even the empty ones — they still take up space; auto-fit collapses those empty tracks so the real items stretch to fill the space instead.

🔄 Likely Follow-up

"So which one should I actually use?" auto-fit almost always, for a responsive row of cards — you want the existing items to stretch and fill the row rather than leave reserved gaps; reach for auto-fill only when you deliberately want equal-sized empty tracks to stay reserved, e.g. lining up against another fixed grid.

🎯 Say this in the interview — the exact lines to land

"CSS Grid lays out a container in rows and columns together with display: grid — the fr unit splits whatever space is left into fractions, repeat() and minmax() build flexible track lists, and grid-template-areas names regions so the layout reads like a map. It's a genuinely two-dimensional tool, where Flexbox only ever aligns one row or one column at a time."

  • fr → splits whatever space is left after fixed-size tracks are placed, not the whole container.
  • repeat() → shorthand for writing the same track size over and over.
  • minmax() → a track that never shrinks below or grows past the two bounds given.
  • auto-fill vs. auto-fit → auto-fill reserves empty tracks, auto-fit collapses them so items stretch.
  • grid-template-areas → names regions once, then every item just says which named area it belongs to.
  • Grid vs. Flexbox → two dimensions at once, vs. one — reach for Grid whenever rows and columns both need to line up together.
📖 Explanation ▾

display: grid turns an element into a grid container, and every direct child becomes a grid item. Rows and columns are called tracks, sized with grid-template-rows and grid-template-columns. The fr unit is a fractional free-space unit — 1fr means "one share of whatever space is left" after any fixed-size tracks are placed, so grid-template-columns: 200px 1fr 1fr gives one fixed 200px column and splits the rest evenly between the other two. repeat(3, 1fr) is shorthand for writing 1fr three times, and minmax(150px, 1fr) defines a track that never shrinks below 150px or grows past its 1fr share.

auto-fill and auto-fit both let the browser decide how many tracks fit — the difference is what happens to the ones nothing gets placed into. auto-fill keeps every track it could physically fit, even the empty ones, so they still take up real space. auto-fit collapses those same empty tracks down to nothing, letting the actual items stretch to fill the space instead. grid-template-areas takes naming further: write the whole layout as a small grid of names in one string, then give each item a matching grid-area — no juggling row/column numbers by hand.

Grid also has its own alignment properties, separate from the per-item ones — see the table below. And the fastest way to keep Grid straight from Flexbox: Flexbox is fundamentally a one-dimensional layout tool — one row, or one column, at a time; wrapping onto multiple lines still doesn't give true alignment across both axes together. Grid is a genuinely two-dimensional layout tool — rows and columns aligned together, on purpose. That's the whole reason a full-page layout (header/sidebar/main/footer) reaches for Grid, while a single toolbar or nav row reaches for Flexbox.

💻 See the code ▾
CSS 
.layout {
  display: grid;
  grid-template-columns: repeat(3, 1fr);            /* 3 equal columns */
  grid-template-rows: 80px minmax(200px, 1fr);  /* fixed row, flexible row */
  gap: 16px;
}

repeat(3, 1fr) writes three equal columns without typing 1fr three times; minmax(200px, 1fr) keeps the second row at least 200px tall no matter how little content it has.

CSS 
.cards {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(150px, 1fr));  /* 2 items: 1 real track + 1 stays empty */
}

.cards {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(150px, 1fr));   /* 2 items: empty track collapses, both stretch */
}

Same 2 items, same container width — auto-fill leaves the extra track reserved and empty; auto-fit removes it so the 2 real items split all the space between them.

CSS 
.page {
  display: grid;
  grid-template-columns: 160px 1fr;
  grid-template-areas:
    "header header"
    "sidebar main"
    "footer footer";
}

.header  { grid-area: header; }
.sidebar { grid-area: sidebar; }
.main    { grid-area: main; }
.footer  { grid-area: footer; }

Each child just names which area it belongs to — the shape of the grid-template-areas string is already close to what actually renders, which is why it reads faster than four separate row/column numbers.

🧭 Use Cases — recognize these when they happen to you ▾
1 You're laying out a whole page — header, sidebar, main content, footer

Write the layout as a small grid of names in one grid-template-areas string, then give each child a matching grid-area — no juggling row/column numbers by hand. This is exactly the shape that reaches for Grid over Flexbox: rows and columns need to line up together, not just one row or column at a time.

RememberWhole-page shape → grid-template-areas, not Flexbox.
2 You're building a responsive row of cards, and the number of cards keeps changing

repeat(auto-fill/auto-fit, minmax(...)) lets the browser decide how many tracks fit instead of hard-coding a column count. auto-fill still reserves a track for every one that could physically fit, even the empty ones; auto-fit collapses those empty tracks so the real cards stretch to fill the row instead.

RememberCard count varies → auto-fit so real cards stretch, not empty reserved tracks.
3 Every item aligns the same way, except one that needs to sit differently

justify-items/align-items (or justify-content/align-content) set one default alignment for the whole container. justify-self/align-self then override that default for just one item, so a single child sits differently without touching the alignment of everything else.

RememberOne item needs its own alignment → justify-self/align-self, not a new container default.
🌍 Real-world example ▾

A page layout with a header, sidebar, main content, and footer is the textbook Grid use case — one grid-template-areas string reads almost exactly like the page it produces, which is why Grid, not Flexbox, is the natural fit for "lay out the whole page" instead of "line up one row of things."
