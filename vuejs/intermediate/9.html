reactive() destructure — where did the reactivity go?

"What happens if you destructure a reactive() object — and how do you avoid it?"

Why it matters ▾
🔌 Reactivity link
❗ ProblemDestructuring a property off a reactive() object (const {x} = state) copies out a plain value — if that variable is handed to a watch or used in a computed, it quietly stops reacting with no error and no warning, so a "broken" feature looks like a mystery bug instead of an obvious mistake.
✅ SolutiontoRefs(state) converts every property of a reactive object into its own ref that stays linked back to the source — destructure the result of toRefs() instead of the reactive object itself, and the connection survives.
RecallDestructure reactive() directly → plain copy, disconnected. Destructure toRefs() → live refs.
🔥 Easy interview recall

naive destructure → plain value, disconnected

toRefs() destructure → live ref, still connected

Think: reactive hands you a copy when you pull a property out. toRefs hands you a pointer.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Not every value pulled off a reactive object stays "live." Only a ref and the reactive object itself stay connected — a plain property destructured straight off reactive() is a disconnected copy from the moment it's assigned.

🔄 Likely Follow-up

"Does this affect ref() the same way?" No — a ref is already a boxed object with a .value property, so passing the ref itself around (not its .value) keeps the reactive connection intact even across function boundaries.

🎯 Say this in the interview — the exact lines to land

"Destructuring a property off a reactive() object copies out a plain value, so it's no longer connected to the source. toRefs(state) converts every property into a ref first, so destructuring the result stays safely linked."

  • const {x} = state → plain copy, disconnected the moment it's assigned.
  • toRefs(state) → every property becomes a ref, safe to destructure.
  • A watcher on a destructured variable → silently never fires — it was never reactive to begin with.
  • ref() itself → unaffected, since passing a ref around always keeps its link.
📖 Explanation ▾

reactive() wraps an object in a Proxy — reading or writing a property on that proxy is what triggers Vue's reactivity tracking. The moment you write const {x} = state, JavaScript's own destructuring syntax reads state.x once, copies that primitive value into a brand-new local variable, and the proxy is never touched again after that — x is just a number from then on, like photocopying a page instead of keeping a link to the live document.

toRefs(state) sidesteps this by building a plain object where every property is replaced with its own ref — a small boxed object with a getter/setter .value that reads and writes straight through to the original reactive() source. Destructuring that object copies out the refs, not the raw values, so the link survives.

💻 See the code ▾
Vue 
const state = reactive({ x: 1 })
const { x } = state          // ❌ plain number, copied out

watch(() => x, () => {
  console.log('x changed')  // never logs
})

state.x = 2                  // x is still 1, watcher never fires

The destructured x is just a number from the instant it's assigned — nothing watches it.

Vue 
const state = reactive({ x: 1 })
const { x } = toRefs(state)  // ✅ x is a ref, still linked

watch(x, () => {
  console.log('x changed')  // logs "x changed"
})

state.x = 2                  // x.value is now 2

toRefs() hands back live refs — watch(x, …) works directly on them.

🧭 Use Cases — recognize these when they happen to you ▾
1 A watch set up on a destructured variable silently never fires

The watcher isn't broken — x was never reactive to begin with, because it was destructured straight off state. The component just looks "frozen" with no error anywhere to point at the real cause.

RememberSilent watcher → check whether the watched value came from a plain destructure.
2 Fixing it with toRefs() or a getter function

Either watch toRefs(state).x directly, or skip destructuring entirely and watch a getter — watch(() => state.x, …) — which always reads straight from the live source.

RememberWatch the ref, or watch a getter function — never a destructured plain value.
🌍 Real-world example ▾

A form's validation stops updating after a refactor that destructured a composable's state for "cleaner" code. The validation logic was watching a value that had already been copied out of its reactive source — switching the composable to return toRefs() (or just not destructuring) fixes it without touching the validation logic at all.
