EAFP means Python's idiom is to try first and handle failure — not check permission up front

"What does 'Pythonic' mean? EAFP vs. LBYL — and why has pathlib become the modern default over os.path?"

Why it matters ▾
  • Checks whether you write idiomatic Python instead of porting a pattern straight from another language.
  • EAFP vs. LBYL comes up constantly around file access, dict lookups, and "what could go wrong here" questions.
  • A natural opener before a deeper question about why pathlib replaced os.path as the modern default.
🔥 Easy interview recall

EAFP → try first, catch the failure

LBYL → check first, then act

Think: LBYL leaves a gap between check and act — EAFP closes it. Same idea makes pathlib beat os.path.

⚠️ Common Trap

Pythonic does not mean "as compressed as possible." A deeply nested one-liner comprehension or a long chained-method call written just to look clever is worse than a few plain, named lines — if it needs a comment to explain itself, it has traded too much clarity for cleverness.

🔄 Likely Follow-up

"Give a concrete example where EAFP beats LBYL." Opening a file: if os.path.exists(path): open(path) (LBYL) leaves a gap where the file could be deleted between the check and the open; try: open(path) except FileNotFoundError: (EAFP) has no such gap.

🎯 Say this in the interview — the exact lines to land

"EAFP — try the operation and catch the exception — is Python's own idiom, and it avoids the check-then-act race window that LBYL can introduce."

  • EAFP → try first, handle failure — the idiomatic Python style; no gap between checking and acting.
  • LBYL → check first, then act — common in other languages, but the check can go stale before the act runs.
  • pathlib.Path → the modern default over os.path — an actual object with operator overloading, not a bag of string functions.
  • enumerate() / zip() / any() / all() → idiomatic building blocks — reach for these before manually tracking an index or hand-writing the loop.
  • Readability → beats brevity — a comprehension that needs a comment to explain itself has traded too much clarity for cleverness.
📖 Explanation ▾

Pythonic code uses the language's own idioms instead of porting a pattern straight from another language — a list comprehension instead of building a list with .append() in a C-style loop, enumerate() instead of manually tracking an index, zip() to pair up multiple iterables element-wise, any()/all() to short-circuit over a sequence of booleans.

EAFP ("Easier to Ask Forgiveness than Permission") tries the operation first and catches the exception if it fails — the idiomatic Python style. LBYL ("Look Before You Leap") checks a condition first, then acts — more common in other languages, and in Python it can leave a gap between the check and the act where the condition quietly stops being true.

os.path works with plain strings through a collection of separate functions (os.path.join, os.path.exists, …). pathlib.Path is an actual object representing a path, with methods and operator overloading (path / "subdir" / "file.txt"), so path manipulation reads more naturally and stays cross-platform correct by default.

💻 See the code ▾
Python 
# os.path — strings + separate functions
import os.path
full = os.path.join(base, "subdir", "file.txt")

# pathlib — one object, / operator overload
from pathlib import Path
full = Path(base) / "subdir" / "file.txt"

Path reads like the folder structure itself — no nested function calls, and it produces the correct separator on every OS.

Python 
# LBYL — check first, then act
if os.path.exists(path):
    f = open(path)  # ❌ file can vanish right here

# EAFP — try first, handle failure
try:
    f = open(path)
except FileNotFoundError:
    ...  # ✅ no gap between check and act

Both handle a missing file — EAFP just has no window where the answer can change between the check and the action.

🌍 Real-world example ▾

A batch job checked if os.path.exists(path): before opening a temp file, but a separate cleanup process occasionally deleted that exact file in the split second between the check and the open() call — an intermittent, hard-to-reproduce crash. Swapping the check for try: open(path) except FileNotFoundError: removed the gap entirely: there was no longer a moment where the answer could change between deciding and acting.
