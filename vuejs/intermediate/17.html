<Transition> vs. <TransitionGroup> — animating one thing, or a whole list

"How does <Transition> know when to apply which CSS class?"

Why it matters ▾
🎭 <Transition>
❗ ProblemA single element toggling in or out with v-if/v-show just snaps between states — no fade, no slide — unless something tells the browser exactly when to start and stop a CSS transition.
✅ Solution<Transition> adds and removes a fixed set of CSS classes at each stage of entering/leaving, so you only have to write the CSS for those class names.
Recall<Transition> = Vue toggles the classes, you write the CSS.
📋 <TransitionGroup>
❗ ProblemA v-for list has many elements entering, leaving, and reordering at once — wrapping each one in its own <Transition> doesn't explain how the *surviving* items should slide into their new positions.
✅ Solution<TransitionGroup> animates the whole list's enter/leave the same way, plus a MOVE animation for items that simply changed position.
Recall<TransitionGroup> = <Transition> for a list, plus reorder animation.
🔥 Easy interview recall

<Transition> → one element, 6 stage classes

<TransitionGroup> → a list, plus a move animation

Think: Vue adds/removes the class names — you only ever write the CSS for them.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Wrapping an always-visible element in <Transition> and expecting it to animate. The element must actually be conditionally rendered (v-if/v-show, or a dynamic component) — <Transition> has nothing to animate without a real enter/leave to attach to.

🔄 Likely Follow-up

"How does <TransitionGroup> animate reordering specifically, not just enter/leave?" It uses the FLIP technique internally (via a v-move class) — measuring each item's position before and after the DOM change, then animating the difference.

🎯 Say this in the interview — the exact lines to land

"<Transition> wraps a single toggling element and applies CSS classes like v-enter-active/v-leave-active at each stage, so I just write the CSS for those class names. <TransitionGroup> does the same for a v-for list, plus a FLIP-based move animation when items reorder."

  • <Transition> → one toggling element, 6 class names across enter/leave.
  • <TransitionGroup> → a whole list, same classes plus v-move.
  • Needs a real conditional render — a permanently-visible element never animates.
  • Reordering uses FLIP — measure before, measure after, animate the difference.
📖 Explanation ▾

<Transition> wraps a single element or component that toggles in or out, and applies a fixed set of CSS classes at each moment of that toggle — v-enter-from, v-enter-active, v-enter-to, and the three leave equivalents. Vue adds and removes them at the right time; all you write is the CSS transition/animation rule that reacts to them.

<TransitionGroup> applies that same class behavior to every item in a v-for list, and adds one more thing neither plain <Transition> nor a list of them individually could do: a MOVE animation for items that stayed in the list but changed position, using the FLIP technique under a v-move class.

<Transition><TransitionGroup>
Wrapsone element/componenta whole v-for list
Enter/leave classes✅ same 6 class names✅ same 6 class names
Reorder (MOVE) animation❌ not applicable✅ v-move, via FLIP
Renders a wrapper element?❌ no (unless <transition> needs one)✅ yes by default (<span>, override with tag)
💻 See the code ▾
Vue 
<Transition>
  <p v-if="show">Hello</p>    <!-- ✅ real conditional render -->
</Transition>

/* only the class names matter */
.v-enter-active, .v-leave-active { transition: opacity 0.3s; }
.v-enter-from, .v-leave-to { opacity: 0; }

Vue toggles these four class names for you — you only write the CSS rule.

Vue 
<TransitionGroup tag="ul" name="list">
  <li v-for="item in items" :key="item.id">{{ item.text }}</li>
</TransitionGroup>

.list-move { transition: transform 0.4s; }   // ✅ animates reorder

The :key is what lets Vue tell "same item, new spot" apart from "new item entering."

🌍 Real-world example ▾

A modal dialog and a sortable to-do list on the same page. The modal's open/close is one <Transition> fading a single element; the to-do list's reordering after a drag-and-drop is <TransitionGroup> sliding every surviving row into its new spot — same class-driven CSS underneath both.
