A route is more than a path — it carries data, and decides where you land

"How do you attach custom data to a route, and control scroll position on navigation?"

Why it matters ▾
🧭 Route meta, lazy routes, scroll behavior
❗ ProblemA real app needs more from routing than "show this component": some routes need an auth check, every route's component shouldn't ship in one giant bundle, and swapping pages with no scroll handling leaves the user stuck wherever the last page happened to scroll to.
✅ Solutionmeta attaches arbitrary data to a route definition that a guard can read, component: () => import(...) loads that route's code as its own chunk only when visited, and scrollBehavior decides where the page lands after each navigation.
RecallThree independent knobs on the same route table: data, loading, and scroll.
🔥 Easy interview recall

meta → data a guard can read

lazy component → its own chunk, loaded on visit

scrollBehavior → where the page lands next

Think: the route table isn't just "path → component" anymore — it's path → component → data, loading strategy, and scroll rule, all in one place.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Auth checks don't belong inside every route component. Reading a meta flag from one centralized beforeEach guard covers every route automatically — repeating the check inside each component is scattered logic that's easy to forget on a newly added route.

🔄 Likely Follow-up

"What does savedPosition actually capture?" The scroll position Vue Router recorded just before leaving that route via the browser's back/forward buttons — letting scrollBehavior restore it precisely instead of always resetting to the top.

🎯 Say this in the interview — the exact lines to land

"route.meta attaches arbitrary data to a route definition that a guard can read — like {requiresAuth: true}. A lazy route (component: () => import(...)) loads its own chunk only when visited, and scrollBehavior controls where the page scrolls to after navigation, including restoring the saved position on back/forward."

  • meta → data attached to the route, read by guards and components.
  • Lazy component → its own chunk, not bundled with every other route.
  • scrollBehavior → decides landing position — top, saved, or an anchor.
  • Auth checks scattered per-component → the trap — one centralized guard reading meta is the fix.
📖 Explanation ▾

route.meta is just a plain object on the route definition — Vue Router never reads it itself, which is exactly the point: it's a blank slot for whatever data your own guards or components need, with no built-in meaning attached to any key name.

Lazy-loaded routes use a dynamic import() instead of a static import for the route's component. The build tool splits that component into its own file, so visiting /settings for the first time is the moment its code actually downloads — not page load, and not every other route's code either.

scrollBehavior is a function you hand to createRouter() that runs after every navigation and returns where to scroll to: a fixed position ({top: 0}), an element anchor, or the savedPosition Vue Router already recorded for a back/forward navigation.

💻 See the code ▾
Vue 
const routes = [
  {
    path: '/dashboard',
    component: Dashboard,
    meta: { requiresAuth: true }   // just data — router doesn't act on it
  }
]

router.beforeEach((to, from) => {
  if (to.meta.requiresAuth && !isLoggedIn()) {
    return '/login'        // ✅ one guard covers every route
  }
})

Add meta: {requiresAuth: true} to a new route and it's protected automatically — no per-component code to remember.

Vue 
{
  path: '/reports',
  component: () => import('./Reports.vue') // own chunk, loaded on first visit
}

Nobody downloads Reports.vue's code until they actually navigate to /reports.

Vue 
createRouter({
  routes,
  scrollBehavior(to, from, savedPosition) {
    if (savedPosition) return savedPosition // back/forward: restore exact spot
    return { top: 0 }              // ✅ a fresh navigation starts at top
  }
})

Without this, every navigation keeps whatever scroll position the previous page happened to leave behind.

🧭 Use Cases — recognize these when they happen to you ▾
1 Protecting a whole section of routes behind login

Every route under /admin gets the same meta.requiresAuth flag. The single global guard protects all of them — adding a new admin route never means writing a new auth check.

RememberOne flag per route, one guard for all of them.
2 A rarely-visited settings page is bloating the main bundle

Switching that one route's component to a dynamic import() moves it out of the main bundle entirely — most visitors who never open settings never download its code at all.

RememberRarely-visited route → lazy-load it, shrink the main bundle.
3 A user hits the browser's back button on a long list page

Without scrollBehavior returning savedPosition, going back would drop the user at the top of a long list instead of back where they were reading.

RemembersavedPosition → the exact spot the user left, on back/forward only.
🌍 Real-world example ▾

An admin dashboard with 30 routes, half of them admin-only. Every admin route carries meta: {requiresAuth: true, role: 'admin'}, one global guard checks both fields, every admin-only screen is lazy-loaded since most visitors never see them, and scrollBehavior resets to the top on a fresh navigation but restores the exact scroll position when a user backs out of a long audit log.
