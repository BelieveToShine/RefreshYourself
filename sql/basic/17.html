CASE WHEN — if / else inside a query

"How do you do if/else logic inside a SELECT?"

Why it matters ▾
🔀 CASE WHEN
❗ ProblemA query has no if statement, so labelling rows, custom sorting or counting by category would otherwise need several queries or application code.
✅ SolutionCASE returns a different value per row based on conditions, anywhere an expression is allowed.
RecallCASE = if / else-if / else that returns a value.
🔥 Easy interview recall

CASE = "an if / else-if / else that returns a value for every row."

Think: the first true WHEN wins. No match and no ELSE gives NULL.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

"No ELSE means the row keeps its original value." It does not — a row that matches no WHEN gets NULL, so add an ELSE whenever NULL is not what you want.

🔄 Likely Follow-up

"How do you count orders per status as separate columns, without PIVOT?" Conditional aggregation: SUM(CASE WHEN Status = 'Paid' THEN 1 ELSE 0 END) per column — one pass over the table, one column per category.

🎯 Say this in the interview — the exact lines to land

"CASE WHEN is SQL's if/else for expressions. It checks the conditions top to bottom, returns the THEN of the first true one, and falls to ELSE — or NULL if there is no ELSE."

  • Searched CASE → CASE WHEN condition THEN … — any condition, ranges, AND/OR.
  • Simple CASE → CASE col WHEN value THEN … — equality only, shorter to write.
  • First match wins → put the most specific WHEN first.
  • Anywhere an expression goes → SELECT, ORDER BY, even inside aggregates.
  • Conditional aggregation → SUM(CASE … THEN 1 ELSE 0 END) gives pivot-style counts.
📖 Explanation ▾

There are two forms. The searched form puts a full condition after each WHEN. The simple form compares one column to values, like CASE Status WHEN 'Paid' THEN …. Both stop at the first match and return its THEN value; if nothing matches they return the ELSE value, or NULL when there is none.

Because CASE is an expression, it works wherever a value is allowed — a SELECT list, ORDER BY, and inside SUM or COUNT. The simple form uses equality, so WHEN NULL never matches; test nulls with WHEN col IS NULL in the searched form. All THEN values should be of compatible types.

💻 See the code ▾
T-SQL 
SELECT Name, Score,
       CASE WHEN Score >= 80 THEN 'A'
            WHEN Score >= 50 THEN 'B'
            ELSE 'Fail'           -- ✅ without this, other rows get NULL
       END AS Grade
FROM Students;

A searched CASE turns a number into a label; the first true WHEN decides.

T-SQL 
SELECT COUNT(*) AS Total,
       SUM(CASE WHEN Status = 'Paid' THEN 1 ELSE 0 END) AS PaidCount,
       SUM(CASE WHEN Status = 'Open' THEN 1 ELSE 0 END) AS OpenCount
FROM Orders;

Conditional aggregation: each SUM adds 1 only for rows that match, giving one column per category.

T-SQL 
SELECT Name, Status
FROM Orders
ORDER BY CASE WHEN Status = 'Urgent' THEN 0 ELSE 1 END, Name;   -- ✅ urgent first

CASE in ORDER BY gives a custom sort order.

🌍 Real-world example ▾

A parcel sorter follows a rule list: over 5 kg goes to the red bin, else over 1 kg to the yellow bin, else green. The first rule that fits decides, and that is exactly how CASE reads its WHEN lines.
