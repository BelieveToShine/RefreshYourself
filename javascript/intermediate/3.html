[[Prototype]] vs. .prototype — two different things wearing the same name

"What's the difference between an object's [[Prototype]] and a function's prototype property, and how does JavaScript resolve a property that isn't on the object itself?"

Why it matters ▾
  • Mixing up .prototype and [[Prototype]] out loud is one of the most common slips candidates make on this exact question — and one of the easiest to catch.
  • This is the real mechanism behind class, extends, and every "how does inheritance work in JS" question — no engine magic beyond this.
  • Comes up any time instanceof, method lookup, or "why does this object have a method I never wrote on it" gets asked.
🔥 Easy interview recall

[[Prototype]] → the real internal link every object has

.prototype → a property that exists only on functions

lookup → walks up the chain until it hits null

Think: .prototype is the blueprint a function hands off; [[Prototype]] is the link the resulting object actually ends up carrying.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

.prototype and [[Prototype]] are not the same thing. .prototype is a property that exists only on functions — the blueprint new hands to objects it builds; [[Prototype]] is the actual internal link every object carries to its own parent.

🔄 Likely Follow-up

"So is class doing something totally different under the hood?" No — class is syntax sitting on top of this exact same prototype system; a class's methods still live on its .prototype, and extends just wires up the [[Prototype]] chain automatically. (Full depth on that lives on its own Classes & Inheritance page, later in this track.)

🎯 Say this in the interview — the exact lines to land

"Every object has an internal [[Prototype]] link; functions additionally have a .prototype property that becomes the [[Prototype]] of objects built with new. Reading a property walks up that chain — the object itself, then its prototype, then that prototype's prototype — until it's found or the chain hits null."

  • [[Prototype]] the real internal link — every object has one, all the way up to Object.prototype.
  • .prototype only exists on functions — the blueprint new hands to whatever it builds.
  • Lookup walks up, never down — checks the object itself, then each prototype in turn, until null.
  • Object.create(proto) sets [[Prototype]] directly — no function or new required.
  • instanceof walks that same chain — asking "does X.prototype show up anywhere above this object?"
📖 Explanation ▾

[[Prototype]] is an internal slot every object carries — a hidden link to another object it can borrow properties and methods from. .prototype is a completely ordinary, visible property, but it only exists on functions: it's the object a function hands off as the [[Prototype]] of whatever gets built by calling that function with new. They're related — one configures the other — but they are not the same slot, and confusing them is exactly the trap above.

Reading a property on an object never checks a copy of anything — it walks live links. JavaScript first looks at the object's own properties; if it's not there, it moves to Object.getPrototypeOf(obj) (the object's [[Prototype]]), then that object's own [[Prototype]], and so on, until either something matches or the chain reaches null — the fixed end point every chain eventually hits. instanceof uses this exact same chain: x instanceof Y asks "does Y.prototype appear anywhere while walking up x's [[Prototype]] chain?" — not "was x literally built by Y."

Object.create(proto) and a constructor function called with new are two doors into that same mechanism: Object.create sets [[Prototype]] directly, no function involved; new Dog() gets there indirectly, by copying whatever object currently sits in Dog.prototype into the new object's [[Prototype]]. Because [[Prototype]] is a shared link, not a copy, mutating a prototype that many objects share changes what every one of them sees. Reach far enough up almost any chain and you hit Object.prototype — the ancestor nearly every plain object shares — so writing to it directly (Object.prototype.isAdmin = true) makes isAdmin quietly show up on every plain object in the program, including ones that never asked for it. That's prototype pollution: not a syntax error, just a shared mutation with a much bigger blast radius than it looks like. (The security angle — how this actually gets exploited — gets its own deeper page later in this track.)

💻 See the code ▾
JavaScript 
function Animal(name) { this.name = name; }
Animal.prototype.eat = function () { return `${this.name} eats`; };

const rex = new Animal('Rex');
console.log(rex.eat());                    // "Rex eats" — found on Animal.prototype, not on rex
console.log(rex.hasOwnProperty('eat')); // false — it's inherited, not own
console.log(rex instanceof Animal);        // true — Animal.prototype IS in rex's chain

eat isn't on rex at all — the lookup walks up to Animal.prototype and finds it there; hasOwnProperty proves it's inherited.

JavaScript 
const animalProto = { eat() { return 'eating'; } };
const rex = Object.create(animalProto); // rex.[[Prototype]] === animalProto, directly
rex.name = 'Rex';

console.log(rex.eat());                          // "eating" — inherited, no function or new involved
console.log(Object.getPrototypeOf(rex) === animalProto); // true

No constructor, no new — Object.create() wires up [[Prototype]] in one line.

JavaScript 
const config = {};
console.log(config.isAdmin);      // undefined — normal, unrelated object

Object.prototype.isAdmin = true;  // ❌ mutating the shared prototype
console.log(config.isAdmin);      // true — every plain object now "has" it

config never touched isAdmin — but because Object.prototype is shared by every plain object, one bad line changes what all of them return. Here's exactly why you never mutate a shared prototype.

🌍 Real-world example ▾

Think of a company's reporting line. If you don't know the answer to something, you ask your manager; if they don't know either, they ask theirs, all the way up to the CEO — nobody photocopies every company rule down to each employee ahead of time, they just know who to ask next. [[Prototype]] is that "who do I ask next" link, and the lookup chain is exactly this escalation, one level at a time.
