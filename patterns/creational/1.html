Singleton — a class that builds itself, exactly once

"What is the Singleton pattern's structure, and how do you implement it thread-safely in C#?"

🧩 Also see the OOP-angle page: DI and the anti-pattern debate
Why it matters ▾
🔒 Singleton
❗ ProblemLetting every part of the app create its own new AppConfig() (or cache, or connection pool) wastes memory and risks different pieces of code reading inconsistent state.
✅ SolutionSingleton restricts the class to exactly one instance, created once, and handed out through one static access point every caller shares.
RecallOne private constructor, one static field, one access point.
🔥 Easy interview recall

Singleton = "a class that only ever builds one of itself."

Think: Private constructor → blocks new from outside Static field → holds the one instance Lazy<T> → makes the creation thread-safe

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

A bare if (_instance == null) _instance = new Foo(); is not thread-safe. Two threads can both pass the null check before either one assigns the field, so each creates its own instance — use Lazy<T> or a static field initializer instead.

🔄 Likely Follow-up

"Isn't a static class basically the same thing?" No — a static class in C# can't implement an interface and has no instance at all, so it can never be substituted for one. A Singleton is a real object with exactly one instance, which is exactly what lets it implement an interface and still be passed around like any other dependency.

🎯 Say this in the interview — the exact lines to land

"Singleton restricts a class to exactly one instance, with one global access point to it. In C# I make creation thread-safe with Lazy<T> or a static field initializer, never an unguarded null check — and the private constructor is what actually stops anyone else from calling new."

  • Structure → one class, a private constructor, a static field, a static accessor.
  • Thread-safe creation → Lazy<T> or a static initializer, never a bare null check.
  • Not a static class → it's a real object: it can implement an interface and be passed around.
  • The anti-pattern debate and the DI-container alternative → covered in depth on OOP's own Singleton page.
📖 Explanation ▾

Singleton's intent is narrow: ensure a class has only one instance, and give the whole program one global point to reach it from. The structure that delivers that is three small pieces on one class — a private (or protected) constructor so nothing outside the class can call new, a static field that holds the sole instance, and a static accessor that hands it out.

In C#, the static field's creation has to be thread-safe — Lazy<T> is the idiomatic way, since it's thread-safe by default and only builds the instance the first time something actually asks for it. A plain static field initializer (private static readonly Foo _instance = new Foo();) is also thread-safe, because the runtime guarantees it runs exactly once, before the type is first used — it just can't defer the work the way Lazy<T> can.

This page is deliberately about the shape, not the debate — the question of whether reaching for a global accessor is a good idea at all, and the DI-container alternative, is a real and worthwhile discussion that OOP: Singleton Pattern already covers in depth. Here, the one thing worth being precise about: a Singleton is not the same as a C# static class — a static class has no instance, can't implement an interface, and can't be handed to anything expecting a constructor parameter, while a Singleton is a perfectly ordinary object that happens to be limited to one instance.

💻 See the code ▾
C# 
public sealed class ConfigurationManager
{
    private static readonly Lazy<ConfigurationManager> _lazy =
        new(() => new ConfigurationManager());   // thread-safe, built on first use

    public static ConfigurationManager Instance => _lazy.Value;  // the one access point

    private ConfigurationManager() { }                                 // nobody else can call new
}

The three structural pieces in one class: a private constructor, a static field, a static accessor.

C# 
// ❌ Not thread-safe
public static ConfigurationManager Instance
{
    get
    {
        if (_instance == null)
            _instance = new ConfigurationManager();   // two threads can both pass this check
        return _instance;
    }
}

Two threads can both see _instance == null before either one finishes assigning it — each ends up building its own object.

🌍 Real-world example ▾

A national ID registry. There is exactly one registry for a country — every agency that needs to register or look up an ID talks to that same one system, not a private copy it builds for itself. That's the whole point of Singleton: some things genuinely exist once, by design, not by accident.
