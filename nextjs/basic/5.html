[slug] vs. [...slug] vs. [[...slug]] — how many segments, and is one even required?

"What's the difference between [slug], [...slug], and [[...slug]]?"

Why it matters ▾
🔹 [slug]
❗ ProblemA blog needs one route per post, but writing a separate file for every possible post isn't realistic.
✅ Solution[slug] captures one single dynamic URL segment — app/blog/[slug]/page.js matches /blog/anything.
Recall[slug] = exactly one dynamic segment.
🔹🔹 [...slug]
❗ ProblemSome routes — docs, nested categories — need to match a variable, multi-level path, and a single [slug] can only ever capture one segment.
✅ Solution[...slug] is a catch-all that captures one or more segments as an array — /docs/a, /docs/a/b, and deeper all match the same route.
Recall[...slug] = catch-all, needs at least one segment, gives an array.
🔹🔹? [[...slug]]
❗ ProblemThe same route should sometimes also match with zero extra segments — e.g. a docs home page — but a plain catch-all can't match its own bare parent route at all.
✅ Solution[[...slug]] is an optional catch-all — the same array capture as [...slug], but it also matches when there are zero extra segments.
Recall[[...slug]] = optional catch-all, matches zero or more.
🔥 Easy interview recall

[slug] → one segment

[...slug] → 1+ segments, array

[[...slug]] → 0+ segments, array

Think: double brackets = optional. The more dots/brackets, the more it can swallow.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

[...slug] is not the same as [[...slug]]. [...slug] requires at least one segment; [[...slug]] is the optional version that also matches the bare parent route with zero extra segments.

🔄 Likely Follow-up

"How does the component read the dynamic segment's value?" Via the params prop Next.js passes into page.js (e.g. { params: { slug } }) — in Next.js 15+ this prop is a Promise that must be awaited, covered in Advanced.

🎯 Say this in the interview — the exact lines to land

"[slug] captures exactly one dynamic segment. [...slug] is a catch-all that captures one or more segments as an array. [[...slug]] is an optional catch-all — the same array capture, but it also matches when there are zero extra segments."

  • [slug] → one segment, no array.
  • [...slug] → catch-all, needs at least one segment, gives an array.
  • [[...slug]] → optional catch-all, also matches zero segments.
📖 Explanation ▾

All three are folder names in square brackets — the brackets are what mark a segment as dynamic instead of a literal path piece. The difference is how much of the URL each one is willing to swallow.

[slug] takes exactly one piece. [...slug] takes the rest of the path, however many pieces that is — as long as there's at least one. [[...slug]] does the same, but the extra outer brackets mean "or none at all," so it also matches the folder's own bare route.

[slug][...slug][[...slug]]
Segments captured11 or more0 or more
Matches bare parent route?n/a❌ no✅ yes
params valuea stringan array of stringsan array, or undefined
💻 See the code ▾
JavaScript 
// app/blog/[slug]/page.js → /blog/hello
export default function Post({ params }) {
  return <h1>{params.slug}</h1>;   // ✅ "hello" — a plain string
}

One folder, one captured piece — params.slug is just a string.

JavaScript 
// app/docs/[...slug]/page.js → /docs/a/b/c
export default function Docs({ params }) {
  return <p>{params.slug.join("/")}</p>;  // ✅ ["a","b","c"] — an array
}

A catch-all always hands back an array, even when the path only has one extra piece.

JavaScript 
// app/docs/[[...slug]]/page.js → matches /docs too
export default function Docs({ params }) {
  const parts = params.slug ?? [];  // ✅ undefined at the bare /docs route
  return <p>{parts.join("/") || "home"}</p>;
}

At the bare /docs route, params.slug is undefined — the plain catch-all would have 404'd here instead.

🧭 Use Cases — recognize these when they happen to you ▾
1 A product page keyed by a single ID in the URL

This is the #1 scenario you'll actually run into: one product, one ID, one segment — a plain [id] (the same pattern as [slug]) is all that's needed.

RememberOne value in the URL → a plain [param], not a catch-all.
2 A documentation site mirroring an arbitrarily deep folder path

Docs sites don't know their folder depth up front — one [...slug] route handles every depth of nesting without a separate file per level.

RememberUnknown depth → one [...slug] route instead of one file per level.
3 You used [...slug] for docs and the bare /docs home page now 404s

A plain [...slug] never matches its own bare parent route — only switching the folder name to [[...slug]] makes /docs itself resolve too.

RememberBare route 404s under a catch-all → that's the sign to make it optional.
🌍 Real-world example ▾

A mail slot vs. a mailbox vs. an empty-allowed mailbox. [slug] accepts exactly one envelope. [...slug] accepts a whole stack, as long as there's at least one. [[...slug]] accepts a stack too — but it's also fine if the box is checked and found empty.
