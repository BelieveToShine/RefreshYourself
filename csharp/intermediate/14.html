yield return — a method that pauses instead of returning

"What does yield return actually do to the method it's written in?"

Why it matters ▾
  • Turns a normal-looking method into a compiler-generated state machine — nobody writes that class by hand.
  • It's the mechanism behind how foreach and LINQ produce values one at a time instead of loading everything into memory first.
  • A common interview opener for "explain what IEnumerable<T> actually does under the hood."
🔥 Easy interview recall

yield return = "pause here, hand back one value, resume from this exact line next time."

Think: calling the method does nothing — only MoveNext() (driven by foreach) actually runs any code, one yield return at a time.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Calling Numbers() does not run any of its code. It only hands back an iterator object — the body starts executing, up to the first yield return, only once something actually enumerates it, like a foreach loop.

🔄 Likely Follow-up

"If you foreach over the same iterator method twice, does the second run pick up where the first left off?" No — every call to the method returns a brand-new iterator with its own state; enumerating it again reruns the whole method from the top. The "paused" state belongs to one specific enumeration, not to the method itself.

🎯 Say this in the interview — the exact lines to land

"yield return makes the compiler rewrite the method into a hidden state machine implementing IEnumerator<T>. Calling the method runs none of its code — only when foreach calls MoveNext() does it execute, running until the next yield return and pausing there until the next call."

  • Calling the method → returns an iterator instantly, no code has run yet.
  • Each MoveNext() → resumes exactly where it paused, not from the top.
  • yield return → the compiler generates the state machine, not you.
  • A fresh enumeration → starts a brand-new, independent state every time.
📖 Explanation ▾

Behind the scenes, the compiler turns a method that contains yield return into a full generated state machine class implementing IEnumerator<T> — fields to remember local variables, plus a marker for exactly which yield return to resume from. None of that class exists in your source; it's produced entirely by the compiler the moment it sees the keyword.

That's why the method's own code doesn't run when you call it — calling it only constructs the state-machine object. The real work only happens when something drives it forward, one MoveNext() at a time, which is exactly what a foreach loop does underneath.

This is also why yield return is the standard way to write a lazy sequence over something large — a file read line by line, or an endless sequence — since only one item ever has to exist in memory at a time, instead of building a whole List<T> up front.

💻 See the code ▾
C# 
static IEnumerable<int> Numbers()
{
    Console.WriteLine("start");              // doesn't run yet
    yield return 1;
    Console.WriteLine("middle");             // runs on 2nd MoveNext()
    yield return 2;
    Console.WriteLine("end");                // runs on 3rd MoveNext()
}

var seq = Numbers();
Console.WriteLine("called Numbers()");        // ✅ prints first — nothing above ran

Numbers() itself makes nothing print — the body only starts running once something enumerates the sequence.

C# 
foreach (var n in seq)
{
    Console.WriteLine($"got {n}");
}
// output: start, got 1, middle, got 2, end

Each MoveNext() call runs only up to the next yield return, then pauses there — the interleaved output proves it.

C# 
foreach (var n in Numbers())   // a brand-new call
{
    // "start", "middle", "end" all print again, from the top
}

A fresh call to Numbers() creates a brand-new iterator with its own state — nothing is shared with the enumeration that already finished.

🌍 Real-world example ▾

Think of reading a long book aloud, one page at a time, only when someone says "next." You don't read the whole book into memory before starting — you keep your place, read a page, stop, and wait. A yield return method works the same way over a sequence, which is exactly why file-reading helpers and endless-sequence generators are written with it: a method streaming a multi-gigabyte log file one line at a time never needs the whole file in memory, because each line is only produced the instant something actually asks for it.
