static vs. instance — one shared copy or one per object, and what sealed shuts off

"When would you use a static class or member instead of an instance one, and what does sealed do?"

Why it matters ▾
🏷️ static, instance, sealed
❗ ProblemPutting everything in static helpers feels easy, but the state becomes global — any caller can change it, and a test cannot swap it for a fake. Leaving every class open for inheritance invites subclasses it was never designed for.
✅ SolutionUse static for stateless helpers and constants, instance members for per-object state you may want to replace, and sealed to say a class is not built to be a base.
Recallstatic = shared by the type. instance = one per object. sealed = no subclasses.
🔥 Easy interview recall

static → one copy, on the type

instance → one per object

sealed → no subclasses

Think: static belongs to the type. instance belongs to the object. sealed is the end of the chain.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

static is not just "a method with no object." It is one shared copy for the whole app, so mutable static state is global state any caller can change, and callers cannot swap a static class for a fake in a test.

🔄 Likely Follow-up

"Why would you seal a class?" Inheritance has to be designed for. Sealing says "not built to be a base", so nobody can override behaviour you never planned for, and you can remove sealed later without breaking anyone.

🎯 Say this in the interview — the exact lines to land

"A static member belongs to the type, so there is one shared copy; an instance member belongs to each object. I use static for stateless helpers and constants, and instance members for state and anything I want to inject or fake in tests. Mutable static state is hidden global state. sealed stops a class being inherited, which is a deliberate choice when it isn't designed as a base."

  • static → one copy, shared by every caller of the type.
  • instance → each object has its own state, and it can be injected or replaced.
  • Good static → stateless helpers and constants, like Math.Max.
  • Static class → can't be instantiated, inherited, or implement an interface, so it can't be injected as one.
  • Mutable static state → hidden global state; tests leak into each other.
  • sealed → no subclasses; use it when a class isn't designed as a base.
📖 Explanation ▾

A static member belongs to the type: there is one shared slot, reached through the type name. An instance member belongs to each object: every new makes a fresh slot. So per-object data like an Id must be instance, and a shared counter or constant can be static.

Static is right for stateless helpers (Math.Max) and constants. It gets risky when it holds changing state: that is global state, any code can touch it, and tests can leak into each other. A static class also can't be instantiated or inherited and can't implement an interface, so you can't hand one to a constructor as an abstraction. That is why logic you want to swap or fake usually belongs in an instance behind an interface (see Dependency Inversion).

sealed shuts the door on inheritance. It is a design statement: this class isn't built to be a base, so nobody can override behaviour it never planned for. string is sealed. You can also write sealed override on one member to stop further overrides of just that member. Removing sealed later doesn't break existing callers. For the static, const and readonly mechanics, see C# Basic 5.

💻 See the code ▾
C# 
public class Counter
{
    public static int Total;        // one shared slot for the type
    public int Id;                  // one slot per object

    public Counter() { Total++; Id = Total; }
}

var a = new Counter();              // Counter.Total == 1, a.Id == 1
var b = new Counter();              // Counter.Total == 2, b.Id == 2

Total is shared through the type; each object keeps its own Id.

C# 
public sealed class Money { }

public class Fake : Money { }       // ❌ compile error: cannot derive from a sealed type

sealed closes the chain — nothing can inherit from Money.

🌍 Real-world example ▾

One company phone line vs. desk phones. The company has one main number that everyone shares (static); each employee also has their own desk phone with their own settings (instance). And a "sealed" job title is one that no one is allowed to split into sub-roles.
