div p vs. div > p — one space and everything you match changes

"What are the different types of CSS selectors, and what's the actual difference between div p, div > p, h2 + p, and h2 ~ p?"

Why it matters ▾
  • Picking the wrong combinator is one of the most common real CSS bugs — a style lands on every nested item instead of just the direct one, or the other way around.
  • Interviewers like to sketch a small HTML tree on a whiteboard and ask what a selector actually matches — that's a "can you read the tree," not "can you recite syntax," check.
  • :is() and :where() come up as a near-automatic follow-up any time the answer needs to shorten a repeated selector list.
🔥 Easy interview recall

div p → any depth (descendant)

div > p → one level down only (child)

h2 + p → the very next sibling (adjacent)

h2 ~ p → any sibling after it (general)

Think: space → descendant, any depth > → child, exactly one level + → immediately next sibling ~ → any sibling that comes later

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

div > p is not "any p inside the div." The > only matches a direct child — a <p> nested one level deeper inside something else (like inside an <article>) is skipped entirely; that's what the plain space, div p, is for.

🔄 Likely Follow-up

"If :is() and :where() both group selectors, why would you ever pick one over the other?" :is() takes on the specificity of whichever argument inside it is most specific, so it can end up outranking rules you didn't expect. :where() always contributes zero specificity, so it's the safer default when you just want to shorten a selector list without changing which rule wins.

🎯 Say this in the interview — the exact lines to land

"Basic selectors — element, class, ID, attribute — pick elements by what they are. Combinators — descendant, child, adjacent sibling, general sibling — pick by where they sit relative to another element in the tree. Pseudo-classes target a state or position, pseudo-elements target a sub-part of an element, and :is(), :where(), and :not() let me group or exclude selectors without repeating them — with :where() always adding zero specificity and :is() taking on its most specific argument's weight."

  • Basic selectors pick by what an element is — p (element), .card (class), #header (ID), [type="text"] (attribute).
  • div p → any depth (descendant) div > p → one level down only (child)
  • h2 + p → immediately next sibling only (adjacent) h2 ~ p → any sibling after it (general)
  • Pseudo-classes (one colon, :hover, :first-child) target a state or position; pseudo-elements (two colons, ::before, ::first-line) target a sub-part that isn't its own real element.
  • :is() and :where() both group selectors, but only :is() carries specificity — :where() always counts as zero; :not() excludes a match instead of grouping one in.
📖 Explanation ▾

The four basic selectors pick an element by what it is, not where it sits:

SelectorExampleMatches
Elementpevery <p> on the page
Class.cardevery element with class="card" — a class can repeat on many elements
ID#headerthe one element with id="header" — an ID is meant to be unique per page
Attribute[type="text"]every element whose type attribute is exactly "text"

A combinator doesn't change what you're looking for — it changes where in the tree you're allowed to look, relative to another selector. div p (a plain space) looks at every descendant, no matter how deep. div > p looks exactly one level down. h2 + p looks only at the sibling immediately after h2. h2 ~ p looks at any sibling after h2, however many sit in between. The diagram above shows the same four combinators against one shared tree, so the difference is an actual result, not just a definition.

Pseudo-classes (one colon — :hover, :first-child, :nth-child()) target an element in a particular state or position, without needing an extra class in the markup. Pseudo-elements (two colons — ::before, ::after, ::first-line) target a specific part of an element that isn't a separate node in the DOM at all. That's the definitional split this page keeps to — the full walkthrough with more examples of each lives on its own page: Pseudo-classes & Pseudo-elements.

:is(), :where(), and :not() are selector functions — each takes one or more selectors as arguments instead of matching directly:

:is():where():not()
What it doesMatches if any listed selector matchesMatches if any listed selector matchesMatches only if the listed selector does not match
Specificity it addsThe specificity of its most specific argumentAlways zero — contributes nothingThe specificity of its own argument
Typical useShorten a selector list where winning the cascade is fineShorten a selector list without risking it outranking other rulesExclude one case from an otherwise broad selector
💻 See the code ▾
HTML 
<div>
  <h2>Title</h2>
  <p>A</p>             // direct child, right after h2
  <article>
    <p>B</p>           // nested one level deeper
  </article>
  <p>C</p>             // direct child, further down
</div>

This is the exact markup the diagram above is drawn from — same three <p> elements labelled A, B, C.

CSS 
div p     { color: teal; }   // A, B, C — every depth
div > p   { color: teal; }   // A, C — B is skipped, it's nested
h2 + p    { color: teal; }   // A only — the very next sibling
h2 ~ p    { color: teal; }   // A, C — any later sibling

Same markup, same color rule — only the combinator changes which <p> actually turns teal.

CSS 
:is(.card, .panel) h3 { }     // specificity = h3 + whichever of .card/.panel is highest
:where(.card, .panel) h3 { }  // specificity = h3 only — grouping adds zero

Same elements matched either way — but :where() never changes which rule wins the cascade; :is() can.

🌍 Real-world example ▾

Think of the tree as a building. div p is "search the whole building for a room" — any floor, any hallway. div > p is "only the rooms opening directly off the lobby" — one floor down, nothing further. h2 + p is "only the room whose door is right next to the sign" — the very next one, no exceptions. h2 ~ p is "any room further down the same hallway past the sign" — could be next door, could be five doors down.
