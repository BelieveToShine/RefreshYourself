^, &(n-1), &1 — the bit tricks that skip the hash map, the modulo, and the loop

"Given an array where every number appears exactly twice except one, find that one number — without using extra memory."

Why it matters ▾
🔧 Bit manipulation
❗ ProblemSome problems — finding the odd one out, checking odd/even, testing a flag — can feel like they need extra memory or loops.
✅ SolutionWorking directly on the bits with &, |, ^ and shifts solves them with a single cheap operation.
Recalla ^ a = 0, and n & (n-1) clears the lowest set bit.
🔥 Easy interview recall

a ^ a → 0 (cancels itself)

a ^ 0 → a (unchanged)

n & (n-1) → clears the lowest set bit

n & 1 → odd if 1, even if 0

Think: XOR cancels every pair → whatever's left over is the answer &(n-1) peels off one bit at a time → count bits, or test power-of-two

⚠️ Common Trap

>> doesn't always fill with 0 on the left. Right-shifting a negative number can be arithmetic (sign-preserving) or logical (always 0-fill) depending on the language — never assume the same behavior across C#, Java, Python, and JavaScript without checking that language's actual rule.

🔄 Likely Follow-up

"How would you count the number of 1 bits in a 32-bit integer, faster than checking all 32 bits?" Repeatedly apply n = n & (n-1) and count the iterations until n hits 0 — Brian Kernighan's trick, which only loops once per set bit, not once per bit position.

🎯 Say this in the interview — the exact lines to land

"XOR-ing a value with itself gives 0, and XOR-ing with 0 leaves it unchanged — so XOR-ing a whole array finds the one number without a pair, in O(n) time and O(1) space. n & (n-1) clears the lowest set bit, which is how you check for a power of two or count set bits with Brian Kernighan's trick. n & 1 checks odd vs. even, and bitmasking uses each bit of an integer as its own flag."

  • ^ XOR → finds the single non-duplicate with no hash map — every pair cancels to 0.
  • n & (n-1) → clears the lowest set bit — the base of the power-of-two check and Brian Kernighan's bit count.
  • n & 1 → tests odd vs. even in one step, no % 2 needed.
  • Bitmasking (mask | (1 << i)) → represents a small set of flags in a single integer — the same idea behind bitmask DP later.
  • Right shift (>>) → sign behavior isn't guaranteed the same across languages — check before relying on it.
📖 Explanation ▾

The five bitwise operators are the raw material: AND (&) gives 1 only where both bits are 1, OR (|) gives 1 where either bit is 1, XOR (^) gives 1 only where the bits differ, and NOT (~) flips every bit. Left shift (<<) moves bits left and fills with 0 — the same as multiplying by 2 per shift. Right shift (>>) moves bits right, the same as dividing by 2 per shift for a positive value — see the Trap above for why negative values need care.

OperatorRule
&1 only if both bits are 1
|1 if either bit is 1
^1 only if the bits differ
~flips every bit
<<shift left, fills with 0 (×2 per shift)
>>shift right (÷2 per shift for positive values)

The XOR trick works because ^ is commutative and associative — the order of the array never matters — combined with two identities: a value XOR-ed with itself is 0, and a value XOR-ed with 0 is unchanged. Every pair cancels itself out, and the one value with no partner is the only thing left standing at the end.

n & (n-1) clears the lowest set bit because subtracting 1 flips every trailing 0 to 1 and the lowest 1 to 0, and ANDing with the original then wipes that lowest 1 out. A power of two has exactly one bit set, so n & (n-1) == 0 (with n != 0) confirms it in one step. Applying the same clear repeatedly and counting the steps (Brian Kernighan's trick) counts set bits faster than checking all 32 positions when few bits are actually set. n & 1 isolates that same lowest bit in miniature — every bit above it represents a multiple of 2, so only the lowest one decides odd versus even. Bitmasking just puts this to work as storage: mask | (1 << i) sets bit i, mask & (1 << i) checks it, and mask & ~(1 << i) clears it — the technique the Dynamic Programming Intermediate page's bitmask/state-machine DP is built on.

💻 See the code ▾
Python 
def single_number(nums):
    result = 0
    for n in nums:
        result ^= n            # every pair cancels to 0
    return result

single_number([4, 1, 2, 1, 2])  # ✅ 4 — O(n) time, O(1) space

No hash map, no sorting — one pass, one running result variable.

Python 
def is_power_of_two(n):
    return n > 0 and (n & (n - 1)) == 0

def count_set_bits(n):        # Brian Kernighan's trick
    count = 0
    while n:
        n &= (n - 1)      # clears the lowest set bit
        count += 1
    return count

count_set_bits loops once per set bit, not once per bit position — fast when few bits are set.

Python 
mask = 0
mask |= (1 << 2)          # set bit 2 → flag "2" is on
is_on = mask & (1 << 2)   # ✅ non-zero → flag "2" is on
mask &= ~(1 << 2)         # clear bit 2 → flag "2" is off again

One integer, one bit per flag — set / check / clear, no separate boolean array needed.

🧭 Use Cases — recognize these when they happen to you ▾
1 Every number appears twice except one, and you can use no extra memory

A value XOR-ed with itself is 0, and with 0 it is unchanged, and order does not matter. So every pair cancels out and only the unpaired number is left. No hash map needed.

RememberPairs cancel under XOR.
2 You need to test for a power of two, or count the 1 bits

n & (n-1) wipes out the lowest set bit. A power of two has exactly one bit set, so for n > 0 the result is 0. Repeating it and counting the steps counts set bits, one loop per set bit.

RememberClear lowest bit, check for zero.
3 You store several on/off settings, like permissions, in one integer

Give each flag its own bit. Set it with |, test it with &, and clear it with & ~, all on one integer instead of separate fields.

RememberOne integer, one bit per flag.
4 You right-shift a negative number and assume it fills with 0

A common trap — right shift can be arithmetic (keeps the sign) or logical (fills with 0), and the rule differs between languages. Check the rule for your language before relying on it.

RememberDo not assume >> behaves the same everywhere.
🌍 Real-world example ▾

Folding laundry: every sock that has a matching partner gets paired up and set aside — what's left on the floor at the end is the one odd sock with no match. That's exactly what XOR-ing an array does with numbers instead of socks.

Scenario: a permissions or feature-flag system stores several boolean settings in one integer instead of several separate columns — bit 0 = "can edit," bit 1 = "can delete," bit 2 = "can invite," and so on. Checking, granting, or revoking one permission is a single &, |, or & ~ against that one integer, instead of reading and writing several separate fields.
