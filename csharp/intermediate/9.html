Pattern matching — a type check and a cast, in one step

"What is pattern matching (is patterns, switch expressions)?"

Why it matters ▾
🧩 Pattern Matching
❗ ProblemTesting a value's real type the old way takes a separate check plus a separate cast, and stacking that across several types into an if/else-if chain repeats the check by hand while a forgotten case just does nothing, with no warning.
✅ SolutionAn is pattern tests and binds in one line, and a switch expression runs that same test across every case as one exhaustive expression — the compiler forces every case to be handled instead of trusting you remembered.
RecallPattern matching = a type check and a cast fused into one step; a switch expression makes that check exhaustive.
🔥 Easy interview recall

is pattern → test and bind, one line

switch expression → same test, but exhaustive, returns a value

Think: pattern matching = an is check and a cast, fused into one step.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

A switch expression is not "the same switch, just shorter." It returns a value directly, must be exhaustive (or end in a _ discard), and has no fall-through — a different construct, not a syntax shortcut for the statement form.

🔄 Likely Follow-up

"What happens if a switch expression genuinely doesn't cover every case?" The compiler warns (CS8509) at compile time, and if that gap is ever actually hit at runtime, C# throws a SwitchExpressionException instead of silently doing nothing.

🎯 Say this in the interview — the exact lines to land

"Pattern matching lets you test a value's type or shape and use the result in one step — an is pattern tests and binds a variable in one line, and a switch expression runs that same test across several cases, but must be exhaustive and returns a value directly."

  • is Type t tests and binds — no separate cast needed.
  • switch statement executes code, no value, no fall-through between arms.
  • switch expression returns a value and must be exhaustive.
  • Forgetting a case in an expression is a compile-time warning, not a silent skip.
📖 Explanation ▾

An is pattern (shape is Circle c) is the smallest unit of pattern matching — it tests the value's runtime type and, on success, hands you c already typed as Circle. No separate cast, no separate check.

Stack several of these into an if / else-if chain and you get working code, but every branch repeats the check by hand, and an untested case just does nothing. A switch expression matches the same patterns, but as one expression that must produce a value for every possible input — the compiler checks that for you instead of trusting you remembered.

That's the real difference from a plain switch statement: a statement runs code and can leave a case unhandled with no consequence; an expression must return something, so an unhandled case becomes a warning today and a SwitchExpressionException if it's ever actually hit.

💻 See the code ▾
C# 
if (shape is Circle c)
    Console.WriteLine(c.Radius);   // c is already a Circle — no cast needed

The is pattern tests and binds in one line — c is ready to use.

C# 
double area = shape switch
{
    Circle c => Math.PI * c.Radius * c.Radius,
    Square s => s.Side * s.Side,
    _ => throw new ArgumentException("unknown shape")  // required
};

The expression returns area directly — the compiler forces full coverage (or a _ arm) before it will even compile.

C# 
double area = shape switch
{
    Circle c => Math.PI * c.Radius * c.Radius
    // Square case missing — CS8509 warning at compile time
};

Miss a case here and the compiler warns immediately — the if/else if version would just silently skip it at runtime.

🧭 Use Cases — recognize these when they happen to you ▾
1 You're filtering a mixed collection down to one type

This is the #1 scenario you'll actually run into: looping over a mixed list and testing each item's real type. The is pattern hands you an already-typed variable the moment the test succeeds — no separate cast line needed.

Rememberis Type t = test and bind, one line.
2 You're computing a value that's different per case

A switch expression matches each shape and hands back its area directly — the compiler requires every case to produce a value (or an explicit _), so a shape added later can't silently fall through unhandled.

Rememberswitch expression = same test, but exhaustive, returns a value.
3 You port an old switch statement to a switch expression, assuming it's just shorter syntax

A switch expression isn't "the same switch, just shorter" — it must return a value, so it must be exhaustive. A statement can leave a case silently unhandled with zero warning; an expression flags the same gap as a compile-time warning and throws if that gap is ever actually hit, which is exactly why porting old code and expecting identical behavior is a trap.

RememberMissing case: a statement stays silent, an expression warns at compile time and throws if hit.
🌍 Real-world example ▾

You're processing a mixed batch of shapes to compute area. Checking each one with a chain of is tests works, but it's easy to add a new shape later and forget to add its branch. A switch expression turns that same batch into one expression the compiler refuses to compile until every shape is actually handled.
