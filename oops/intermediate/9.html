Multiple inheritance — why C# allows one base class but many interfaces

"Why doesn't C# support multiple inheritance, and how do interfaces solve the diamond problem?"

Why it matters ▾
💎 The diamond problem
❗ ProblemIf a class could inherit from two classes that both override the same method of a shared base, a call on the child has two possible answers, and the compiler or the reader has to guess which one wins.
✅ SolutionC# allows only one base class, so there is never a second path to follow, and lets a class implement many interfaces, where a clash is settled explicitly.
RecallOne base class, many interfaces.
🔥 Easy interview recall

class → one base only

interface → as many as you like

diamond → two paths, which one wins?

Think: Two parents, same method → ambiguous call One parent + interfaces → no ambiguity, or you name the winner

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

"C# has no multiple inheritance" is not quite right. A class can't have two base classes, but it can implement many interfaces — that is multiple inheritance of a contract, not of fields and implementation.

🔄 Likely Follow-up

"What if two interfaces declare the same method?" One public method can satisfy both, or you implement each explicitly (void IPrinter.Start()) so the caller picks the behaviour by the interface type it holds.

🎯 Say this in the interview — the exact lines to land

"C# allows one base class because two base classes with the same member create the diamond problem: which inherited version does the child get? Interfaces avoid it. A class can implement many, they carry contracts and no instance fields, and if two clash I settle it with an explicit implementation. And if I need behaviour from two sources, I'd compose."

  • class → exactly one base class, so only one inheritance path.
  • interface → implement as many as you need; they hold no instance fields.
  • Diamond → two paths to one base member; which one wins?
  • Same member in two interfaces → explicit implementation, void IA.M(); the caller picks by interface type.
  • Default interface members (C# 8+) → still no instance fields; if two defaults clash, the class must resolve it.
  • Need behaviour from two sources → compose instead of inheriting both.
📖 Explanation ▾

The diamond problem shows up when a class inherits from two parents that both come from the same base. If both parents override Start(), then copier.Start() has two candidate answers, and there are also questions about the shared base's state. Some languages allow it and add rules to resolve it. C# chose the simple route: one base class, so there is only ever one path up.

You still get the useful part, many interfaces. An interface is a contract, so there is no inherited state to duplicate. If two interfaces declare the same member, one public method can satisfy both, or you implement each explicitly and the caller chooses by the interface type it holds. Since C# 8, interfaces can carry default method bodies on runtimes that support it; they still have no instance fields, and if two defaults clash the class must say which one wins.

If you want behaviour from two places, don't reach for two parents. Hold the pieces as fields and delegate to them, as in Inheritance vs. Composition.

💻 See the code ▾
C# 
public class Copier : Printer, Scanner   // ❌ compile error: a class can have only one base class
{
}

Two base classes are not allowed — this is where C# draws the line.

C# 
public interface IPrinter { void Start(); }
public interface IScanner { void Start(); }

public class Copier : IPrinter, IScanner   // ✅ many interfaces are fine
{
    void IPrinter.Start() => Console.WriteLine("Printing");   // only via IPrinter
    void IScanner.Start() => Console.WriteLine("Scanning");   // only via IScanner
}

Same method name on both interfaces, each implemented explicitly — no ambiguity.

C# 
var c = new Copier();
// c.Start();                    // ❌ not a member of Copier itself
((IPrinter)c).Start();           // ✅ prints "Printing"
IScanner s = c;
s.Start();                       // ✅ prints "Scanning"

The caller picks the behaviour by the interface type it holds.

🌍 Real-world example ▾

One manager, many badges. An employee has one direct manager (the base class), because two managers giving conflicting orders is the diamond. But they can hold many certifications (interfaces), and each one is a clear, separate promise.
