Where vs. OfType — filter, or filter-and-cast?

"list.Where(x => x is Cat).Cast<Cat>() vs. list.OfType<Cat>() — same filter, so why does OfType exist?"

Why it matters ▾
🔍 Where + Cast
❗ ProblemYou only want the Cats out of a mixed list, but Where(x => x is Cat) still hands you a sequence typed as the original base type — you can't call Cat-only members on it yet.
✅ SolutionChaining .Cast<Cat>() afterward turns that filtered sequence into a real IEnumerable<Cat> — a second, explicit step.
RecallWhere + Cast = filter, then cast — two calls.
🎯 OfType
❗ ProblemWriting the filter-then-cast pattern correctly, every single time, is two method calls to remember and keep in the right order.
✅ SolutionOfType<Cat>() fuses the type-check and the cast into one call, and skips null and mismatched elements automatically along the way.
RecallOfType = filter + cast, fused into one call.
🔥 Easy interview recall

Where(x => x is Cat).Cast<Cat>() → two calls

OfType<Cat>() → one call, already typed as Cat

Think: Where filters but leaves you typed as the base type. OfType filters and casts, for free.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Where(x => x is Cat) does not give you Cat-typed items. The filtered sequence is still declared as the original base type — you still need .Cast<Cat>() (or a Select) before calling anything Cat-only, where OfType<Cat>() hands you an IEnumerable<Cat> directly.

🔄 Likely Follow-up

"Does OfType<T>() use something special under the hood, or is it just is again?" It's the same is type-check per element, just fused with the cast — OfType doesn't need a new mechanism, it just saves you from writing the check and the cast as two separate calls.

🎯 Say this in the interview — the exact lines to land

"list.Where(x => x is Cat).Cast<Cat>() and list.OfType<Cat>() end up with the same Cats, but OfType does the filtering and casting in one call, where Where alone leaves the sequence typed as the original base type until you cast it yourself."

  • OfType<T>() → filter + cast, fused into one call.
  • Where(x => x is Cat) → result is still typed as the base type until you cast it.
  • Same final answer either way — OfType just needs no is-check written by hand.
📖 Explanation ▾

Where(x => x is Cat) filters down to the actual Cat instances, but the sequence it hands back is still declared as the original element type — you need a second call, .Cast<Cat>(), before you can touch anything Cat-specific.

OfType<Cat>() does both jobs in a single call: it checks each element's type and casts the ones that match, in one pass, giving you an IEnumerable<Cat> directly. Along the way it quietly skips null and anything that isn't a Cat — the same outcome Where's is check already produced, just without writing that check by hand.

💻 See the code ▾
C# 
List<Animal> animals = new() { new Cat(), new Dog(), null, new Cat() };
var catsA = animals.Where(x => x is Cat).Cast<Cat>();  // ✅ still 2 steps

Where alone leaves you with Animal, not Cat — the Cast is what fixes the type.

C# 
var catsB = animals.OfType<Cat>();  // ✅ same Cats, 1 step — null & Dog skipped

One call, already typed as Cat — no separate cast anywhere.

🧭 Use Cases — recognize these when they happen to you ▾
1 You're pulling one type out of a mixed collection and need its members right away

You need just the circles, already typed as Circle, to read .Radius right away. OfType<Circle>() gets you there in one call. This is the #1 scenario you'll actually run into.

RememberNeed the typed members immediately → OfType<T>().
2 You need the filtered-but-not-yet-cast sequence for something else first

Sometimes you want the filtered sequence on its own terms first — e.g. logging how many matched — before deciding whether to cast it at all. Where as its own step still earns its place here.

RememberNeed the filter step on its own → plain Where first.
3 You call a Cat-only member right after Where, with no cast

The sequence from Where is still IEnumerable<Animal> — calling a Cat-only method on its elements without a cast in between simply won't compile, even though every element really is a Cat at runtime.

RememberWhere alone never changes the declared type.
🌍 Real-world example ▾

A box of mixed shapes. Pulling out just the circles and immediately measuring each one's radius is one motion with OfType<Circle>(). Checking "is this a circle?" and then casting it afterward is the same job, just split into two separate motions.
