COUNT, SUM, AVG — what happens when NULL shows up

"What do COUNT, SUM, AVG, MIN, and MAX do, and how do they each handle NULL?"

Why it matters ▾
🧮 NULL rows in an aggregate
❗ ProblemIt's easy to assume COUNT(*) and COUNT(column) always return the same number over the same table.
✅ SolutionCOUNT(*) counts every row, NULLs included, because it's counting rows rather than a column's value — every other aggregate (COUNT(column), SUM, AVG, MIN, MAX) silently skips any row where that column is NULL.
RecallCOUNT(*) counts NULLs too — every other aggregate quietly skips them.
🔥 Easy interview recall

Aggregates = "skip every NULL — except COUNT(*), which counts the row anyway."

Think: COUNT(column) can be smaller than COUNT(*) if that column has NULLs.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

COUNT(column) and COUNT(*) always give the same number. COUNT(column) skips any row where that specific column is NULL, so it can return a smaller number than COUNT(*), which counts every row regardless of NULLs.

🔄 Likely Follow-up

"Does AVG treat NULLs as 0?" No — AVG ignores NULL rows entirely, removing them from both the sum and the divisor count; treating a NULL as 0 would silently produce a different, wrong average, since a NULL isn't a known zero value.

🎯 Say this in the interview — the exact lines to land

"COUNT, SUM, AVG, MIN, and MAX all ignore NULL values in the column they're aggregating — they just skip those rows. The one exception is COUNT(*), which counts every row no matter what, because it's counting rows, not evaluating a column."

  • COUNT(*) → counts every row, NULLs included — it's counting rows, not a column's value.
  • COUNT(column) → skips any row where that column is NULL, so it can be smaller than COUNT(*).
  • SUM, AVG, MIN, MAX → all ignore NULL rows in that column automatically.
  • AVG specifically → divides by the count of non-NULL rows, never treats a NULL as 0.
📖 Explanation ▾

COUNT, SUM, AVG, MIN, and MAX all operate on a single column, and every one of them quietly drops any row where that column is NULL before doing its calculation. COUNT(Price) only counts the rows where Price actually has a value — not every row in the table.

COUNT(*) is the one exception, because it isn't looking at a column at all — it's counting rows, full stop. A row with a NULL price is still a row, so COUNT(*) counts it; COUNT(Price) does not.

AVG deserves its own note: it's effectively SUM(column) / COUNT(column), using the same NULL-filtered set for both halves — the NULL rows are removed from the total and the divisor, never treated as a zero value.

FunctionWhat happens to a NULL Price row
COUNT(*)✅ counted — it's still a row
COUNT(Price)❌ skipped
SUM(Price)❌ skipped
AVG(Price)❌ skipped from both the total and the divisor
MIN(Price) / MAX(Price)❌ skipped
💻 See the code ▾
SQL 
-- Products: 5 rows, one NULL Price (Id 3, Gizmo)
SELECT
    COUNT(*)      AS TotalRows,     -- ✅ 5 — every row counts
    COUNT(Price)  AS RowsWithPrice, -- ❌ 4 — NULL row skipped
    AVG(Price)    AS AvgPrice        -- divides by 4, not 5
FROM Products;

COUNT(*) returns 5, COUNT(Price) returns 4 — and AVG only divides by those same 4 rows, not all 5.

SQL 
-- Same table, same NULL row
SELECT
    SUM(Price)  AS TotalPrice,   -- 90.00 — NULL row excluded
    MIN(Price)  AS LowestPrice,  -- 10.00 — NULL never considered
    MAX(Price)  AS HighestPrice  -- 40.00 — NULL never considered
FROM Products;

SUM, MIN, and MAX all just leave the NULL row out, the same way COUNT(Price) and AVG did.

🧭 Use Cases — recognize these when they happen to you ▾
1 You need the total number of rows in the table, no matter what

A row with a NULL price is still a row. COUNT(*) isn't looking at any column at all, so it counts that row exactly like every other one. This is the #1 aggregate call you'll actually see in a report or dashboard.

RememberCOUNT(*) counts rows — NULLs don't exclude a row from existing.
2 You need to know how many rows actually have a value in one specific column

COUNT(Price) evaluates the Price column on every row, so the one row where Price is NULL never gets counted — the result can genuinely be smaller than COUNT(*) over the exact same table.

RememberCOUNT(column) can be smaller than COUNT(*) — NULLs in that column drop out.
3 You're averaging or summing a column where some rows have no value at all

AVG(Price) is really SUM(Price) / COUNT(Price) over the same NULL-filtered rows — the NULL row is removed from both the total and the divisor, never treated as a zero value. A common interview trap — candidates often assume a missing value drags the average down toward zero, when it's actually excluded from the calculation entirely.

RememberA NULL row is removed from the math, not counted as 0.
🌍 Real-world example ▾

Averaging test scores in a class where a few students haven't taken the test yet. Those missing scores are NULL, not zero — so AVG() only averages the students who actually have a score. Counting the missing students as zero would drag the average down and unfairly make the whole class look like it's doing worse than it is.
