Fiber — why React can pause in the middle of rendering

"What is Fiber, and why was it introduced?"

Why it matters ▾
  • Explains why React can support features like transitions and Suspense at all — Fiber is the re-architecture that made them possible, not a separate add-on bolted on top.
  • Interviewers use this question to separate "knows the term" from "understands what actually changed inside React."
  • A common opener before diving into concurrent rendering, since concurrency only makes sense once interruptible rendering is understood first.
🔥 Easy interview recall

Fiber = "broke rendering into small, interruptible units of work — a re-architecture, not just a faster diff."

Think: the old reconciler ran synchronously to completion once started; Fiber can pause partway through.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Fiber is not just a faster diffing algorithm. It's a full rewrite of React's internal rendering architecture into an interruptible unit-of-work structure — the old (stack) reconciler ran synchronously to completion once started and couldn't pause; Fiber's re-architecture is specifically what makes concurrent features possible at all, not just a speed optimization on top of the same approach.

🔄 Likely Follow-up

"What can be interrupted during rendering, and what can't?" The render phase — pure, side-effect-free, computing what should be on screen — can be paused, abandoned, or restarted; the commit phase — actually applying changes to the real DOM and running effects — is synchronous and cannot be interrupted once it begins, which is also exactly why render logic must stay pure.

🎯 Say this in the interview — the exact lines to land

"Fiber is React's internal rendering architecture, introduced in React 16 — it broke rendering into small units of work so the work can be paused, prioritized, and resumed instead of running to completion synchronously like the old reconciler. That's not a performance tweak; it's what makes concurrent features possible at all."

  • Reconciliation → compares the new element tree to the previous one to find the minimal real DOM changes.
  • Keys → let React match elements by identity across renders, not just by position in the tree.
  • Fiber → a re-architecture into interruptible units of work, not a faster diff algorithm.
  • Render phase → pure and side-effect-free, so it can be paused or thrown away safely.
  • Commit phase → synchronous, can't be interrupted once it starts.
📖 Explanation ▾

Reconciliation is how React figures out what changed. Every render produces a new element tree; React compares it against the previous tree and computes the smallest set of real DOM updates needed — keys are what let it match elements by identity across that comparison instead of just by their position, so a reordered list updates the right items instead of every item.

Fiber is the internal data structure and algorithm React has used to do this work since React 16. Before Fiber, the reconciler ran as a single recursive call stack — once it started walking the tree, it couldn't stop until the whole thing was done. Fiber reorganizes that same work into a linked structure of small units, so React can pause between units, hand control back to the browser for something more urgent, and resume later — or throw the work away entirely and start over.

That's only safe because the render phase — the part that decides what should be on screen — is pure and has no side effects. React may call it more than once, or abandon a half-finished pass, before anything real happens. The commit phase — writing to the actual DOM and running effects — is synchronous and runs straight through once started, which is exactly why side effects don't belong in render logic: they'd fire unpredictably, possibly more than once, on work that might never even be kept.

💻 See the code ▾
JSX 
// Conceptually, each of these can become its own "unit of work" Fiber pauses between —
// not literal internal React source, just the shape of the idea.
function App() {
  return (
    <>
      <Header />   // one unit
      <Sidebar />  // another unit — React can pause between these
      <Content />  // and another
    </>
  );
}

There's no public API to "see" a unit of work directly — this just illustrates the shape of the idea: one component tree, broken into pieces small enough to pause between.

🌍 Real-world example ▾

Fiber is a chef who can pause chopping vegetables halfway through if a more urgent order comes in, then pick up again exactly where they left off. The old reconciler is a chef who, once they start a recipe, must finish that exact recipe start to finish before touching anything else — even if another table's order is burning.
