C# · Basic · Normal

Three ways to skip naming the type — only one is risky

Why it matters ▾
  • Clears up a common myth — var is not "untyped."
  • Explains why dynamic typos only show up when the code actually runs.
  • A quick way to show you know the difference between compile-time and runtime.
📖 Explanation ▾

var doesn't turn off type checking — it just asks the compiler to figure out the type from the right-hand side, once, at compile time. var name = "Sam"; is exactly as strict as string name = "Sam";; it just saves typing the type twice.

object is the base type everything in C# ultimately is — useful when you genuinely don't know (or don't care about) the specific type, but you pay for it: a value type stored as object gets boxed, and you have to cast back to the real type before using its specific members.

dynamic turns type checking off until the program is actually running. Call a method that doesn't exist on a dynamic variable and the code compiles fine — it only blows up, at runtime, the moment that line executes.

💻 See the code ▾ 
var name = "Sam";              // compiler knows this is a string

object anything = 42;           // boxed — an int stored as object
int back = (int)anything;       // must cast to use it as an int

dynamic thing = "Sam";
thing = 42;                      // legal — dynamic can switch types
thing.Quack();                   // compiles fine, throws at runtime
🌍 Real-world example ▾

A labelled box vs. an unlabelled box vs. a mystery box. var is a box with the label filled in for you automatically — still clearly labelled. object is a plain box — anything fits, but you have to open it and check before using what's inside. dynamic is a box you don't even check — you just reach in and hope.

🎯 Say this in the interview — the exact lines to land

  • var is still strongly typed — resolved once, at compile time.
  • object → box value types, cast to use them.
  • dynamic → checked at runtime, not compile time.
  • A typo on a dynamic call compiles fine, throws later.
  • var never means "no type" — it means "infer the type for me."
