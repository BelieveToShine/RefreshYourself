try / catch / finally — who runs, and when

Why it matters ▾
👀 try
❗ ProblemCode that might throw partway through needs to run without an exception instantly crashing the whole method before anything can react.
✅ Solutiontry just marks that block as "watched" — it always runs first, and if nothing goes wrong C# skips catch entirely and heads straight for finally.
Recalltry = watch for trouble, always runs first.
🧯 catch
❗ ProblemNot every exception should be handled the same way — you need to react to one specific error type without blindly swallowing every other kind.
✅ Solutioncatch only runs when the thrown exception's type matches — you can stack several for different types, and it's skipped entirely when nothing was thrown.
Recallcatch = only fires on a matching type; skipped if no error.
🧹 finally
❗ ProblemCleanup code — closing a file, releasing a connection — has to run no matter which path the method took, even if the exception was never caught at all, or resources leak.
✅ Solutionfinally always runs — error or not, caught or not. It's the one guarantee in the whole story, which is exactly why using is built on top of it.
Recallfinally = the block that always runs, no matter what.
🔥 Easy interview recall

finally = "the block that always runs, no matter what."

Think: try → watch catch → handle finally → cleanup, always

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

An uncaught exception does NOT skip finally. It still runs before the exception propagates up — cleanup happens either way.

🎯 Say this in the interview — the exact lines to land

"try watches for trouble, catch handles a matching exception, and finally always runs — whether there was an error, and whether it was caught or not."

  • catch only runs when the exception type matches.
  • using is built on try/finally — it disposes the object automatically.
📖 Explanation ▾

try just marks "watch this code for trouble." If nothing goes wrong, C# skips catch entirely and heads straight for finally.

catch only runs if an exception actually gets thrown inside try — and only if its type matches. You can stack multiple catch blocks for different exception types.

finally is the one guarantee in this whole story: it runs whether or not an exception happened, and even if the exception was never caught at all — which is exactly why cleanup code (closing files, releasing locks) belongs there.

💻 See the code ▾
C# 
try
{
    int result = 10 / int.Parse(input);   // might throw
}
catch (DivideByZeroException ex)
{
    Console.WriteLine("Can't divide by zero.");  // only if it threw
}
finally
{
    Console.WriteLine("Always runs.");   // ✅ error or not
}

The matching catch only fires on a divide-by-zero — a different exception type would skip it entirely.

C# 
try
{
    throw new InvalidOperationException();   // no matching catch
}
finally
{
    Console.WriteLine("Cleanup still runs.");   // ✅ runs anyway
}
// exception still propagates up to the caller after this

No catch at all — finally still runs before the exception continues upward.

🧭 Use Cases — recognize these when they happen to you ▾
1 Your code runs cleanly and nothing ever throws

This is the #1 scenario you'll actually run into — nothing goes wrong, so C# skips catch entirely and heads straight for finally.

RememberNo error → catch skipped, finally still runs.
2 An exception is thrown that matches one of your catch blocks

Like the divide-by-zero example above — the thrown exception's type matches a catch block, so that block runs to handle it, and finally still runs afterward to clean up.

RememberMatching exception type → catch handles it, finally still follows.
3 An exception is thrown that nothing catches

Wrong type, or no catch at all — like the second code example above. Candidates often assume an uncaught exception skips cleanup; it doesn't. finally still runs before the exception keeps propagating up to the caller.

RememberUncaught exception → finally still runs, then it keeps propagating.
🌍 Real-world example ▾

Cooking on a stove. try is cooking the meal. catch is what you do if it catches fire. finally is turning the stove off — you do that whether dinner turned out great or the kitchen's full of smoke.
