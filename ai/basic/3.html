🔥 AI · Basic · Must Know

A pretrained model can finish your sentence — it takes two more stages to make it actually helpful

"What's the difference between pretraining, instruction-tuning (SFT), and RLHF or DPO — and why does a model need all three stages?"

Why it matters ▾
  • Checks whether you understand what "training an LLM" actually means, not just that it "read a lot of text."
  • Explains why a raw base checkpoint downloaded from a model hub behaves so differently from a chat/instruct model of the same size.
  • A common opener whenever RLHF, SFT, DPO, "base model," or "aligned model" comes up — this one pipeline explains all of those terms at once.
🔥 Easy interview recall

Pretraining → predicts the next word, from raw text

Instruction-tuning (SFT) → follows instructions, from example answers

RLHF / DPO → matches human preference, from ranked responses

Think: Pretrain → raw ability SFT → follows instructions RLHF/DPO → matches human preference

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Skipping straight from pretraining to RLHF/DPO doesn't work. The base model was never taught to follow instructions or hold a chat format, so there's no reliable instruction-following behavior yet for RLHF/DPO to align — instruction-tuning has to come first.

🔄 Likely Follow-up

"So what's actually different about DPO vs. classic RLHF?" DPO optimizes directly on chosen-vs-rejected response pairs — no separate reward model, no reinforcement learning loop. RLHF trains a reward model on human preference judgments first, then runs reinforcement learning (commonly PPO) to optimize the LLM against that reward signal. Both target the same kind of preference alignment; DPO is generally simpler and cheaper to run.

🎯 Say this in the interview — the exact lines to land

"An LLM goes through three stages: pretraining learns language and knowledge from raw text, instruction-tuning teaches it to actually follow instructions, and RLHF or DPO aligns its answers to what people prefer — each stage builds on the one before it."

  • Pretraining → self-supervised next-token prediction over massive raw text; produces a base model.
  • Instruction-tuning (SFT) → trains on curated (instruction, ideal response) pairs; teaches it to actually follow instructions.
  • RLHF → trains a separate reward model on human preference judgments, then uses reinforcement learning to optimize against it.
  • DPO → optimizes directly on chosen-vs-rejected pairs — no reward model, no RL loop, generally cheaper than RLHF.
  • Order matters → pretrain → instruction-tune → RLHF/DPO, always in that sequence.
📖 Explanation ▾

Pretraining is self-supervised: the model just predicts the next token over huge amounts of raw text (books, web pages, code), with no human labeling involved. That produces a base model — genuinely good at completing text in the style it was trained on, but with no built-in habit of answering a question or following an instruction, because nothing in that raw text specifically taught it to do that.

Instruction-tuning (also called supervised fine-tuning, or SFT) fixes that: the base model is trained further on a curated set of (instruction, ideal response) pairs, so it learns the actual shape of a helpful, chat-formatted answer. RLHF and DPO both push a step further, aligning the model's answers toward what people actually prefer, not just "a plausible response." RLHF does this indirectly — train a reward model on human preference judgments, then run reinforcement learning (commonly PPO) to optimize the model against that reward signal. DPO skips the middleman: it optimizes directly on pairs of chosen-vs-rejected responses, with no separate reward model and no RL loop, which is generally simpler and cheaper to run.

The order is fixed for a reason: each stage assumes the previous one already happened. Jumping straight from a raw base model to RLHF/DPO doesn't work well, because there's no reliable instruction-following behavior yet for that alignment step to sharpen.

💻 See the code ▾
Python 
from transformers import AutoModelForCausalLM

base = AutoModelForCausalLM.from_pretrained("acme-model-8b")          # 📚 pretraining only — completes text
chat = AutoModelForCausalLM.from_pretrained("acme-model-8b-instruct")  # 🧑‍🏫 same base, instruction-tuned + aligned

Same size model, two different checkpoints — base is the raw pretrained output; instruct already went through instruction-tuning (and usually RLHF/DPO) on top of it.

JSON 
{
  "prompt": "Explain recursion simply.",
  "chosen": "Recursion is a function that calls itself with a smaller input until it reaches a base case.",
  "rejected": "Recursion is when code repeats a lot."
}

✅ chosen is the response a human rater preferred; ❌ rejected is the one they preferred less — this pair, not a single "correct" answer, is what RLHF's reward model and DPO both train on.

🌍 Real-world example ▾

This is exactly why a downloaded "base" checkpoint from a model hub often ignores an instruction or just rambles on instead of answering it — it was never instruction-tuned. The moment a provider ships a "-chat" or "-instruct" version of the same model, that's the same underlying weights after instruction-tuning and, usually, RLHF or DPO on top.
