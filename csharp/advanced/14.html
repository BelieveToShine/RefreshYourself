Dictionary — hash it, find the bucket, check the chain

"How does Dictionary<TKey,TValue> work internally, and how does it differ from SortedDictionary and HashSet?"

Why it matters ▾
🗂️ Hash tables
❗ ProblemSearching a list for a key means checking items one by one — the more items, the slower every lookup gets. And a sorted structure still needs several comparisons per lookup.
✅ SolutionDictionary turns the key into a number with GetHashCode(), uses it to jump straight to a bucket, and only compares the few entries that landed there. That makes lookups, adds and removes O(1) on average.
RecallDictionary = hash → bucket → short chain; O(1) average, O(n) worst case.
🔥 Easy interview recall

Dictionary = "hash the key, jump to a bucket, check the little chain."

Think: Hashed (Dictionary, HashSet) = fast, no order. Sorted (SortedDictionary) = ordered, but O(log n). HashSet = keys only.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Don't change a key's hashed fields after you add it. The entry was filed under the old hash, so the dictionary looks in the wrong bucket and reports the key as missing — even though it is still in there. Use immutable keys.

🔄 Likely Follow-up

"Is Dictionary thread-safe?" No — concurrent writes can corrupt it. Use ConcurrentDictionary or a lock (see Concurrent Collections). A related follow-up is why a bad GetHashCode hurts: see Equals & GetHashCode.

🎯 Say this in the interview — the exact lines to land

"Dictionary hashes the key with GetHashCode to pick a bucket, then compares entries in that bucket with Equals — O(1) on average, O(n) if everything collides. When it fills up it grows and re-buckets every entry. SortedDictionary is a tree: ordered, O(log n). HashSet is the same hashing with keys only."

  • Lookup → hash → bucket → compare with Equals; O(1) on average.
  • Collisions → entries share a bucket; many collisions push it toward O(n).
  • Growth → resize and rehash — an occasional expensive add; set a capacity if you know the size.
  • SortedDictionary → a balanced tree: sorted by key, O(log n).
  • HashSet<T> → the same hashing, keys only; its Add tells you whether the item was new.
📖 Explanation ▾

When you add or look up a key, Dictionary calls GetHashCode() on it and maps the result to one of its internal buckets. Each bucket leads to a small chain of entries. The dictionary walks that chain and uses Equals to find the exact key. With a good hash the chains are very short, which is why the average cost is O(1). With a bad hash — say, every key returns the same number — one chain gets long and every operation approaches O(n).

When the internal arrays fill up, the dictionary grows to a larger size and re-buckets all existing entries. Most adds are cheap; the occasional one that triggers a resize is not. Passing an initial capacity avoids this when you know roughly how many items are coming. Iteration order is an implementation detail — don't rely on it.

SortedDictionary<TKey,TValue> doesn't hash at all: it keeps keys in a balanced tree, so it stays sorted and costs O(log n), and it needs the keys to be comparable. HashSet<T> uses the same hashing idea as Dictionary but stores only items, so it is the tool for "have I seen this before?".

💻 See the code ▾
C# 
var ages = new Dictionary<string, int>();
ages["ann"] = 31;                              // hash -> bucket -> entry
if (ages.TryGetValue("ann", out var age)) { }  // O(1) on average

var seen = new HashSet<string>();
bool isNew = seen.Add("ann");                  // true the first time, false after

var sorted = new SortedDictionary<string, int>(ages);  // ordered by key, O(log n)

Same lookup idea in Dictionary and HashSet; the tree-based one trades speed for order.

C# 
class Key { public int Id; public override int GetHashCode() => Id; /* + Equals */ }

var k = new Key { Id = 1 };
var map = new Dictionary<Key, string> { [k] = "x" };
k.Id = 2;                                      // ❌ key changed after adding
bool found = map.ContainsKey(k);               // false — wrong bucket

A mutated key is lost. Prefer immutable keys such as strings, ints or records.

🌍 Real-world scenario ▾

A loop that checks list.Contains(id) for 100,000 ids is crawling. Loading the ids into a HashSet<int> once turns each check from a scan into a hash lookup, and the job drops from minutes to a blink.
