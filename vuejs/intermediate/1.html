Vue Router — who decides what's on screen

"How does basic routing work in Vue Router?"

Why it matters ▾
🧭 Vue Router
❗ ProblemA single-page app has no real pages to load — without something tracking the URL, every "page" a user visits would need to be faked with manual show/hide logic and the browser's back/forward buttons would do nothing useful.
✅ SolutionVue Router maps each URL path to a component, swaps it into <router-view> on navigation, and keeps the browser's history/back-forward working — all without a real page reload.
RecallRouter = URL → component lookup table, rendered into one placeholder slot.
🔥 Easy interview recall

Vue Router = "a lookup table from URL path to component."

Think: URL changes → router looks it up → <router-view> swaps the component in, no reload.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

A plain <a href="/about"> is not the same as <router-link to="/about">. The plain anchor tells the browser to do a full page reload, which throws away all of the app's in-memory state — <router-link> updates the URL via the History API and lets Vue Router swap the component instead.

🔄 Likely Follow-up

"Hash history vs. HTML5 history mode?" Hash mode (#/path) needs no server configuration since the server only ever sees /. HTML5 mode gives clean URLs but needs the server configured to serve index.html for every route.

🎯 Say this in the interview — the exact lines to land

"Vue Router keeps a route table mapping URL paths to components. <router-view> is the placeholder where the currently matched component renders, and <router-link> navigates between routes client-side, without a full page reload."

  • createRouter() → builds the route table from a routes array of {path, component}.
  • <router-view> → the placeholder that renders whichever component matched.
  • <router-link> → client-side navigation, no reload, no state lost.
  • Plain <a href> for in-app links → forces a full reload, the classic mistake.
📖 Explanation ▾

Vue Router is a separate library, installed and wired up with createRouter({history, routes}). The routes array is just a list of {path, component} pairs — the router's whole job is matching the current URL against that list and knowing which component is "the one for this path."

<router-view> is the actual spot in your template where the matched component gets rendered — think of it as a named slot that the router fills in and swaps out as navigation happens. Everything around <router-view> (a nav bar, a footer) stays mounted; only the slot's contents change.

<router-link> renders an actual <a> tag under the hood (so right-click/open-in-new-tab still works), but intercepts the click and updates the URL via the browser's History API instead of letting the browser request a new page — that's the whole difference from a plain anchor.

💻 See the code ▾
Vue 
import { createRouter, createWebHistory } from 'vue-router'

const router = createRouter({
  history: createWebHistory(),
  routes: [                         // the route table
    { path: '/', component: HomePage },
    { path: '/about', component: AboutPage }
  ]
})

The router's only job is matching a path to a component — nothing more.

Vue 
<!-- App.vue -->
<nav>
  <router-link to="/">Home</router-link>      <!-- ✅ client-side nav -->
  <router-link to="/about">About</router-link>
</nav>

<router-view />                     <!-- matched component renders here -->

Swap <router-link> for <a href> here and in-app navigation would reload the whole page.

🧭 Use Cases — recognize these when they happen to you ▾
1 Building the main nav bar for a multi-page SPA

Every top-level nav item is a <router-link>. Clicking one only ever updates the route table's match and re-renders <router-view> — the header and footer around it never remount.

RememberNav bar → always router-link, never a plain anchor.
2 Deploying behind a static host / CDN

A user typing /about directly asks the server for that path. In HTML5 history mode, the server must be configured to serve index.html for every route so Vue Router (running client-side) can take over and match it.

RememberHTML5 mode needs a server rewrite rule, or deep links 404.
🌍 Real-world example ▾

A dashboard app with "Home," "Reports," and "Settings" tabs. Each tab is a <router-link> pointing at its own path; the shared sidebar stays mounted and only the content area inside <router-view> swaps — exactly the feel of a native app, built with plain URL routing.
