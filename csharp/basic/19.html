Delegates & Func / Action / Predicate — a variable that holds a method

"What is a delegate in C#, and how do Func, Action and Predicate relate to it?"

Why it matters ▾
🧩 Delegates
❗ ProblemCode that has to run "some method the caller picks" — a sort rule, a filter, a callback — can't take a method as an argument, so you end up writing a separate hard-coded version for every behaviour.
✅ SolutionA delegate is a type-safe reference to a method: you pass the method around like a value, and the compiler checks that its parameters and return type match.
RecallDelegate = a type-safe variable that holds a method.
🔥 Easy interview recall

Func → returns a value

Action → returns nothing (void)

Predicate → returns bool

Think: Func gives back an answer Action just does something Predicate says yes or no

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Func, Action and Predicate are not a different thing from delegates. They are delegates — ready-made generic ones — so you rarely need to declare your own delegate type.

🔄 Likely Follow-up

"Is Predicate<T> the same as Func<T, bool>?" Same shape, but they are different delegate types, so one can't be assigned to the other directly — wrap it in a lambda. List<T>.FindAll takes a Predicate; LINQ's Where takes a Func.

🎯 Say this in the interview — the exact lines to land

"A delegate is a type-safe reference to a method — it fixes the parameter and return types. Func returns a value, Action returns void and Predicate<T> returns bool; they're all ready-made delegates, and a delegate can hold several methods with +=."

  • A delegate is a type-safe method reference — the compiler checks the signature.
  • Func returns a value (the last type argument is the result); Action returns void.
  • Predicate<T> is a bool-returning delegate — what FindAll and RemoveAll take.
  • += makes it multicast: the methods run in the order added, and with a return value you only get the last one's.
  • Lambdas are the usual way to create one — LINQ's Where and Select take a Func.
📖 Explanation ▾

A delegate is a type that describes a method's shape — its parameters and its return type. A variable of that type can hold any method that fits, and calling the variable calls the method. The compiler checks the match, which is why it is called type-safe.

You almost never write your own delegate type. Func, Action and Predicate<T> are ready-made generic ones: Func<int, int> takes an int and returns an int (the last type is always the result), Action<string> takes a string and returns nothing, and Predicate<int> takes an int and returns bool. You usually hand them a lambda like x => x * x — this is how LINQ's Where and Select work.

A delegate can hold more than one method: += adds one, -= removes one, and calling it runs them in order (multicast). That is the idea underneath events, and a lambda that uses outside variables is a closure. A lambda can also be turned into data instead of code — see expression trees.

💻 See the code ▾
C# 
Func<int, int> square = x => x * x;               // returns int
Action<string> log = s => Console.WriteLine(s);    // returns void
Predicate<int> isEven = n => n % 2 == 0;          // returns bool

Console.WriteLine(square(5));   // 25
log("hi");
Console.WriteLine(isEven(4));   // True

One variable per shape — each holds a method and is called like one.

C# 
static int Apply(Func<int, int> f, int x) => f(x);

Console.WriteLine(Apply(x => x + 1, 6));   // 7 — the caller picks the behaviour
var evens = new List<int> { 1, 2, 3, 4 }.FindAll(n => n % 2 == 0);   // FindAll takes a Predicate<int>

Passing a method in as an argument is the main reason delegates exist.

C# 
Action<string> log = s => Console.WriteLine(s);
log += s => Console.WriteLine("also: " + s);   // multicast
log("hi");   // prints "hi", then "also: hi"

+= chains another method; calling the delegate runs them in order.

🌍 Real-world example ▾

Sorting and filtering. list.FindAll(n => n % 2 == 0) hands the "which items?" rule in as a Predicate, and list.Sort((a, b) => a.CompareTo(b)) hands in the ordering rule — the list's own code stays the same while you swap the behaviour.
