Closed API vs. open-weight — who ends up owning the servers?

"When would you choose a closed API model like GPT, Claude, or Gemini over an open-weight model like Llama or Mistral — and what are you actually trading off?"

Why it matters ▾
  • Comes up any time a team has to pick a model provider — it shows you think about cost and control, not just "which model is smartest."
  • Explains real production setups: some products call a hosted API for everything, others self-host an open-weight model for high-volume traffic.
  • A common way interviewers probe build-vs-buy thinking on top of pure model knowledge.
🔥 Easy interview recall

Closed / API (GPT, Claude, Gemini) → hosted, no weights, pay per token

Open-weight (Llama, Mistral) → weights downloadable, you host, you own the ops cost

Think: closed buys you capability + simplicity, open-weight buys you control + cost at scale.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

"Open-weight always means cheaper." Self-hosting swaps a per-token bill for a GPU and engineering bill — at low volume, the ongoing API cost from a closed provider is often actually cheaper than running your own servers.

🔄 Likely Follow-up

"So is a closed model always going to give the better answer?" Not necessarily — a smaller open-weight model fine-tuned tightly on one narrow task can match or beat a general-purpose closed model at that specific task, even though the closed model is stronger in general.

🎯 Say this in the interview — the exact lines to land

"Closed/API models like GPT, Claude, and Gemini are hosted — you call an API, never see the weights, and pay per token. Open-weight models like Llama and Mistral hand you the weights themselves, so you self-host and own the infrastructure cost, but you also get full control over customization and where your data lives."

  • Closed / API → reach for it when you want the strongest available capability with the least operational effort.
  • Open-weight → reach for it when control, cost at scale, or data residency matter more than having the single best model.
  • Closed → never hands you the weights Open-weight → weights are yours to download
  • Closed → the provider runs the servers Open-weight → you (or your cloud) run them
  • Many real systems mix both — a closed model for the hardest reasoning, a self-hosted open model for high-volume, cost-sensitive work.
📖 Explanation ▾

Closed/API models — the OpenAI GPT family, Anthropic's Claude family, Google's Gemini family — are called over a hosted API. You never get the model weights; the provider handles serving, scaling, and much of the safety tuning behind the scenes. In exchange, you typically get the strongest general-purpose capability available at any given time, for an ongoing per-token cost, and your data-residency and control options are limited to whatever the provider's own policies allow.

Open-weight models — Meta's Llama family, Mistral's models, and others — publish their weights for download. You can self-host on your own infrastructure or rented cloud GPUs, which gives you full control over customization, fine-tuning, and exactly where your data lives. The tradeoff: you own the serving, operations, and GPU cost yourself, and usually need more engineering effort to get anywhere near the quality bar the top closed models already hit out of the box.

💻 See the code ▾
HTTP 
POST https://api.<provider>.com/v1/chat/completions
Authorization: Bearer <api-key>                 -- you never receive the weights

The request leaves your infrastructure entirely — the provider's servers run the model and hand back only the output.

Python 
from transformers import AutoModelForCausalLM

model = AutoModelForCausalLM.from_pretrained("meta-llama/Llama-3-70B")
model.to("cuda")   # ✅ runs on YOUR GPU — you own this cost

The weights are downloaded onto hardware you provision — nothing leaves your own infrastructure.

🌍 Real-world example ▾

A product might send its hardest reasoning calls to a closed API model for quality, while routing high-volume, simpler classification or extraction calls to a self-hosted open-weight model — keeping the per-token bill low on the bulk of the traffic and reserving the closed model's extra capability for the calls where it actually pays off.
