LTS vs. STS — support length picks the release, and .NET Standard is now mostly legacy

"What's the difference between LTS and STS releases, and what is .NET Standard — do you still use it?"

Why it matters ▾
📅 LTS vs. STS
❗ ProblemUpgrading the runtime every year is costly for a production system, but a runtime that is out of support gets no more patches.
✅ SolutionEach release is labelled LTS (longer support) or STS (shorter); pick LTS for apps you cannot upgrade often, STS if you move quickly.
RecallLTS = stay put. STS = keep moving.
🧩 .NET Standard
❗ ProblemBefore .NET 5, .NET Framework and .NET Core were separate stacks, so a library built for one could not simply be used by the other.
✅ Solution.NET Standard was a shared API contract: one library targeting it ran on every runtime that supported that version. Modern .NET now covers most of that need directly.
RecallA contract, not a runtime — now mostly legacy.
🔥 Easy interview recall

LTS → longer support, even versions (6, 8, 10)

STS → shorter support, odd versions (7, 9)

.NET Standard → an API contract, not a runtime

Think: LTS is for apps you leave alone; STS for teams that upgrade often. New libraries target modern .NET; netstandard is only for old consumers.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Treating STS as a preview or "less production-ready." An STS release is a normal, supported release; it just has a shorter support window, so you have to upgrade sooner.

🔄 Likely Follow-up

"Should a new class library target netstandard2.0?" Only if .NET Framework (or another older consumer) must use it. Otherwise target a current .NET version, or multi-target both with <TargetFrameworks>.

🎯 Say this in the interview — the exact lines to land

"Each .NET release is either LTS or STS. LTS gets a longer support window and STS a shorter one; since .NET 5 a new version arrives each November, and the even-numbered ones are LTS. LTS is supported for three years and STS for two, and I check Microsoft's support policy for exact end dates. .NET Standard was a shared API contract so one library could run on both Framework and .NET Core; today I target modern .NET directly, and use netstandard2.0 or multi-targeting only when .NET Framework consumers still matter."

  • LTS → longer support — the safer default for a production app you cannot upgrade every year.
  • STS → shorter support — fully supported, just with a sooner end date.
  • Support length → LTS 3 years, STS 2 years — the STS window has changed before, so read exact end dates from the policy page.
  • .NET Standard → an API contract — new code targets modern .NET; keep netstandard2.0 only for .NET Framework reach.
📖 Explanation ▾

LTS and STS are support labels on a release. A new major version ships once a year in November. Since .NET 5 the pattern has been: odd-numbered (7, 9) are STS, even-numbered (6, 8, 10) are LTS. Today Microsoft's policy gives LTS three years of support and STS two years. STS used to be shorter, so read the policy page for exact end dates before you plan an upgrade.

.NET Standard was a specification: a named set of APIs (the last version is 2.1). A library that targeted a version could run on any runtime that implemented it. netstandard2.0 was the version widely used to reach .NET Framework; netstandard2.1 was never supported by .NET Framework. It is a contract, so there is nothing to install.

Since .NET 5 there is one modern .NET to target, which is why Microsoft steers new libraries to a current net version instead. If you still need Framework consumers, multi-target. Related background: .NET vs. .NET Framework and SDK vs. Runtime, .csproj & NuGet.

💻 See the code ▾
.csproj 
<!-- an app: pick one release (look up its support window) -->
<TargetFramework>net8.0</TargetFramework>

<!-- a library that must also reach .NET Framework: multi-target -->
<TargetFrameworks>net8.0;netstandard2.0</TargetFrameworks>

Multi-targeting builds the library once per target; consumers pick the best match.

🌍 Real-world example ▾

Car leases and plug adapters. LTS is the long lease you renew rarely and STS the short lease you swap often; .NET Standard was a travel adapter for plugs from different countries — handy then, but now most sockets are the same shape.
