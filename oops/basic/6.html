DRY, KISS & YAGNI — three small rules, and when DRY goes too far

"What do DRY, KISS and YAGNI mean — and can DRY ever be taken too far?"

Why it matters ▾
🧰 DRY, KISS & YAGNI
❗ ProblemWithout a few shared rules of thumb, code grows the same rule copied in five places, clever layers nobody can follow, and features built for a future that never came.
✅ SolutionDRY keeps each piece of knowledge in one place, KISS picks the simplest design that works, and YAGNI says to build a thing only when it is actually needed.
RecallFewer repeats, less cleverness, no guesses.
🔥 Easy interview recall

DRY → one place for each rule

KISS → the simplest thing that works

YAGNI → don't build it until needed

Think: DRY removes repeats KISS removes cleverness YAGNI removes guesses

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

DRY does not mean "never write similar-looking code twice." It is about repeating the same knowledge; merging code that only looks alike, but changes for different reasons, couples two things together and is often worse than the duplication.

🔄 Likely Follow-up

"So when is it fine to duplicate?" When two pieces look alike today but change for different reasons. A common rule of thumb is to wait until the same change really hits several copies, often around the third, before pulling out a shared helper.

🎯 Say this in the interview — the exact lines to land

"DRY says each piece of knowledge should live in one place, KISS says choose the simplest design that works, and YAGNI says don't build something until you actually need it. DRY can be overdone: merging code that only looks similar creates the wrong abstraction and couples things that change for different reasons."

  • DRY → one source of truth for each rule, so a change is made once.
  • KISS → the simplest design that solves today's problem; clever is a cost.
  • YAGNI → don't build for an imagined future; build it when it is needed.
  • DRY too far → premature abstraction: one shared helper full of flags.
  • Test before merging: do the copies change for the same reason? Same → merge. Different → leave them.
📖 Explanation ▾

DRY means every piece of knowledge, like a tax rule or a validation limit, has one clear home. If the rule changes, you edit one place instead of hunting for copies and missing one. KISS asks for the plainest design that does the job; a reader should follow it without a map. YAGNI asks you to leave out features and extension points nobody has asked for yet.

The three agree on one thing: less code to read, change and get wrong. They pull apart in one place. DRY pushes you to merge, and merging code that only looks alike forces a shared helper to grow flags and special cases for each caller. That is a premature abstraction, and now every caller is tied to every other. Ask whether the copies change for the same reason (the idea behind SRP) before you merge.

These are rules of thumb, not laws. YAGNI does not mean ignoring needs you already know about, and KISS does not mean skipping a design the problem really needs. They are tools for judgment, not replacements for it.

💻 See the code ▾
C# 
public static class Pricing
{
    public const decimal VatRate = 0.20m;      // the rule lives here, once

    public static decimal WithVat(decimal net)
        => net * (1 + VatRate);                // cart and invoice both call this
}

DRY done right — one rule, one home. Changing the rate is a single edit.

C# 
// ❌ DRY taken too far: two different things forced into one helper
public string Render(Doc doc, bool isInvoice, bool isEmail, bool shortForm)
{
    if (isInvoice) { /* invoice layout */ }
    else if (isEmail) { /* email layout */ }
    // ... every new caller adds another flag
    return "";
}

DRY gone wrong — invoice and email only looked alike. Two small methods would change independently; this one changes for everyone.

🌍 Real-world example ▾

A recipe book. One master recipe for the sauce that every dish points to (DRY). Recipes short enough to follow while cooking (KISS). And no pasta machine until you actually start making pasta (YAGNI).
