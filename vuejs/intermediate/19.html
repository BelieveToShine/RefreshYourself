ref in the template, v-model on a component — one word, two very different jobs

"How do you support v-model on your own custom component?"

Why it matters ▾
🎯 Template refs
❗ ProblemSome things — calling focus() on an input, measuring an element's size, reading a child component's exposed method — can't be done through reactive data at all; they need the real DOM node or instance.
✅ SolutionA template ref (<input ref="el"> + const el = ref(null)) gives direct access to the real element or child instance once it exists in the DOM.
RecallTemplate ref = a handle to the real DOM, not reactive data about it.
🔁 Custom v-model
❗ ProblemTwo-way binding is built-in for <input>, but your own custom component (a styled text box, a rating picker) has no default way to say "this prop is the one v-model should read and write."
✅ Solutionv-model on a component is sugar for a modelValue prop plus an update:modelValue emit — implement both and v-model works on your component too.
RecallCustom v-model = modelValue prop + update:modelValue emit, nothing magic.
🔥 Easy interview recall

Template ref → real DOM, only after mount

Component v-model → modelValue prop + emit

Think: a ref is null until the DOM exists; v-model is just a prop and an emit wearing a shortcut.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Reading a template ref's value before onMounted fires. It's still null during setup()'s synchronous execution, since the real DOM element doesn't exist yet at that point.

🔄 Likely Follow-up

"Can a component support multiple v-models?" Yes — v-model:propName syntax lets a component expose several independently-named two-way-bound props/emit pairs on the same instance.

🎯 Say this in the interview — the exact lines to land

"A template ref gives direct access to the real DOM element or child instance, but only after onMounted — it's null before that. v-model on a custom component is sugar for a modelValue prop plus an update:modelValue emit, and a component implements both to support it."

  • Template ref → null until mounted, then the real DOM/instance.
  • Custom v-model → modelValue prop + update:modelValue emit, no magic.
  • Multiple v-models → v-model:propName per independently-bound prop.
  • Reading a ref too early → always null, the classic mistake.
📖 Explanation ▾

A template ref is declared by giving an element (or child component) a ref="name" attribute in the template, then creating a matching const name = ref(null) in <script setup>. Vue fills that ref in with the real DOM element — or the child component's public instance — once it actually exists, which is after mount, not during setup()'s own synchronous run.

v-model on a custom component isn't a special feature the component has to "support" through some separate API — it's plain prop-and-emit syntax in disguise. v-model="text" is shorthand for binding a prop named modelValue to text and listening for an update:modelValue event to write back to it. A component that defines a modelValue prop and emits update:modelValue already works with v-model, with no extra configuration.

💻 See the code ▾
Vue 
<input ref="inputEl" />

<script setup>
import { ref, onMounted } from 'vue'

const inputEl = ref(null)
console.log(inputEl.value)      // ❌ null — setup() runs before mount

onMounted(() => {
  inputEl.value.focus()         // ✅ real <input> element now
})
</script>

Same ref, two different moments — only after mount does it point at anything real.

Vue 
<!-- MyInput.vue -->
<script setup>
defineProps(['modelValue'])
defineEmits(['update:modelValue'])
</script>

<template>
  <input
    :value="modelValue"
    @input="$emit('update:modelValue', $event.target.value)"
  />
</template>

This is the whole implementation — v-model="text" on this component now just works.

🌍 Real-world example ▾

A search box that auto-focuses on page load, built as its own component. A template ref on the inner <input> calls .focus() in onMounted, while the component's own modelValue/ update:modelValue pair lets the parent bind it with a plain v-model="searchText", same as a native input.
