Python has no formal interface keyword — ABC and Protocol are the two different ways it fakes one

"How does Python achieve interface-like behavior without a formal interface keyword? Duck typing vs. explicit abstraction — when do you reach for Protocol over inheritance?"

Why it matters ▾
  • Checks whether you know Python's two real answers to "how do I define a contract" — people coming from Java/C# often assume there's one, formal interface.
  • Comes up any time the conversation turns to plugin systems, typing third-party code, or "how would you enforce this method exists" in a code review.
  • Sets up the trap of assuming inheritance is the only way to get interface-like safety.
🔥 Easy interview recall

ABC → inheritance, enforced when instantiated

Protocol → no inheritance, checked by a type checker only

Think: ABC locks the door at runtime. Protocol just checks the shape on paper.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

"You always need inheritance to get interface-like safety." Protocol gives you static-type-checked duck typing on third-party objects you don't control and can't make inherit from your own ABC.

🔄 Likely Follow-up

"When would you reach for an ABC instead of a Protocol?" When you control the whole class hierarchy and actually want a contract enforced at runtime — instantiation itself fails if a method is missing — plus the ability to share real implementation through inheritance. Protocol adds no runtime enforcement of its own; it's purely a static-typing tool.

🎯 Say this in the interview — the exact lines to land

"ABC is inheritance-based and runtime-enforced; Protocol is structural and static-check-only — I'd pick Protocol when I don't own the class."

  • Duck typing is the informal version of both — call the method you need and trust it exists, no contract checked anywhere.
  • ABC → own the hierarchy — use it when you want the contract enforced at instantiation and want to share real implementation.
  • Protocol → don't own the class — use it to type-check objects (third-party, stdlib) you can't make inherit from anything.
  • No inheritance required for Protocol — an object satisfies it just by having the right method shape.
📖 Explanation ▾

ABC (from abc, short for abstract base class) plus @abstractmethod defines a base class that can't be instantiated until every abstract method is overridden by a concrete subclass — Python checks this the moment you try to build the object, not when you call a method later. Python has no separate interface keyword the way Java or C# does; an ABC that only declares abstract methods, with no implementation of its own, is Python's version of a pure interface — it's the same tool used more strictly.

Protocol (from typing) is a middle ground between that and plain duck typing. A static type checker matches an object against a Protocol purely by shape — its method names and signatures — with no inheritance required at all. An object satisfies a Protocol even if it never imports or hears about that Protocol class; the checker just confirms the methods it needs are there.

💻 See the code ▾
Python 
from abc import ABC, abstractmethod

class Storage(ABC):
    # no implementation here — just the required shape
    @abstractmethod
    def save(self, data: str) -> None: ...

Storage()  # ❌ TypeError: Can't instantiate abstract class

Storage can't be built until a subclass actually implements save — the check happens the moment you try to instantiate it, not later.

Python 
from typing import Protocol

class Storable(Protocol):
    def save(self, data: str) -> None: ...

class S3Bucket:              # never heard of Storable
    def save(self, data: str) -> None:
        ...

def persist(target: Storable) -> None: ...
persist(S3Bucket())  # ✅ type-checks — shape matches, no inheritance

S3Bucket satisfies Storable purely by having a matching save method — it never imports or inherits from Storable.

🌍 Real-world example ▾

You're writing a function that has to accept file-like objects from a few different third-party libraries — you can't edit those libraries to make their classes inherit from your own ABC. A Protocol with a single .read() method lets a type checker confirm any of them fit, purely by shape, with zero changes to the third-party code.
