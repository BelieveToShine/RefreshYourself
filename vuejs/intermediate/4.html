Navigation Guards — who gets to stop a route change

"What are navigation guards, and how do router.push() and router.replace() differ?"

Why it matters ▾
🛂 Navigation guards
❗ ProblemAn unauthenticated user could type /admin directly into the address bar and land on a protected page — a component-level check alone never runs for direct URL entry.
✅ SolutionA guard like router.beforeEach runs for every navigation attempt, including direct URL entry, and can redirect or cancel it before the target component ever mounts.
RecallGuard = a checkpoint that runs before a route change is allowed to finish.
🔥 Easy interview recall

router.push() → adds a history entry

router.replace() → swaps the current one

Think: push leaves a back-button trail. replace leaves none.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Forgetting to resolve the guard's decision is not a harmless no-op. A guard that never calls its callback (or never resolves/returns in the Promise-based form) leaves the navigation hanging indefinitely — it neither proceeds nor fails, it just stalls.

🔄 Likely Follow-up

"Where would an auth check actually go?" A global router.beforeEach guard checking a store's auth state — it runs for every navigation attempt, including direct URL entry, which a component-level check alone would never catch.

🎯 Say this in the interview — the exact lines to land

"Navigation guards run at different scopes — beforeEach globally, beforeEnter per route, and component-level guards — and each can allow, redirect, or cancel a navigation. router.push() adds a new history entry; router.replace() swaps the current one, leaving no back-button trail."

  • beforeEach → runs on every navigation, the right place for an auth check.
  • beforeEnter → scoped to one route in its own config.
  • router.push() → adds a history entry, back button works.
  • router.replace() → no history entry added, back skips it entirely.
📖 Explanation ▾

Navigation guards are functions the router calls at specific points in a route change: router.beforeEach for every single navigation, beforeEnter on just the routes that declare it, and component-level guards (like onBeforeRouteLeave) scoped to one component. Each one can call next() (or just return, in modern versions) to allow the navigation, return a path/route object to redirect, or return false to cancel it.

router.push(path) is what a normal link click does under the hood — it adds a new entry to the browser's history stack, so the back button returns to where you came from. router.replace(path) does the same navigation but overwrites the current history entry instead of adding a new one — useful after a redirect you don't want the user to "go back" into (like a login page redirecting to the dashboard).

💻 See the code ▾
Vue 
router.beforeEach((to, from) => {
  const auth = useAuthStore()
  if (to.meta.requiresAuth && !auth.loggedIn) {
    return { name: 'login' }   // ✅ redirect, runs for direct URL entry too
  }
})

This runs even if the user types /admin directly into the address bar.

Vue 
router.push('/dashboard')      // ✅ adds a history entry
router.replace('/dashboard')   // ❌ no entry — back skips this navigation

Use replace after login so "back" doesn't return to the login form.

🧭 Use Cases — recognize these when they happen to you ▾
1 Protecting an admin section from unauthenticated users

One beforeEach guard, written once, covers every path in the app — including ones typed directly into the address bar, which a component-only check would miss entirely.

RememberApp-wide auth → beforeEach, not a per-component check.
2 Redirecting right after a successful login

After a successful login, replacing the current history entry means pressing "back" doesn't land the user right back on the login form they just submitted.

RememberPost-login redirect → replace(), not push().
🌍 Real-world example ▾

Your service rejects a payment form submit because a session token just expired mid-edit. A global beforeEach guard catches the next navigation attempt, sees the expired session, and redirects to the login page with router.replace() — the broken form state never ends up reachable again via the back button.
