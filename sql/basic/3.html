INNER JOIN vs. LEFT JOIN — what happens to the rows with no match

"What's the difference between an INNER JOIN and a LEFT JOIN?"

Why it matters ▾
🔗 INNER JOIN
❗ ProblemKeeping every row even when there's no real match on the other table would report a relationship that doesn't actually exist — a customer paired with an order that was never placed.
✅ SolutionINNER JOIN keeps a row only when the join condition finds a match on both tables — anything unmatched on either side is left out of the result entirely.
RecallINNER JOIN → only rows that match on both sides.
📋 LEFT JOIN
❗ ProblemAn INNER JOIN quietly drops any left-table row with zero related rows on the right — a report that reads as missing data, not a query bug, unless someone already suspects the join.
✅ SolutionLEFT JOIN keeps every row from the left table no matter what, filling the right side's columns with NULL wherever there's no match.
RecallLEFT JOIN → every left row kept, NULLs when there's no match.
🔥 Easy interview recall

INNER JOIN → only rows that match on both sides

LEFT JOIN → every left row, NULLs when there's no match

Think: LEFT JOIN never drops a left-table row; INNER JOIN can drop rows from both sides.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

A LEFT JOIN with a filter on the right table's column in WHERE still behaves like a LEFT JOIN. It doesn't — a WHERE filter runs after the join, and NULL never satisfies a WHERE condition, so it silently discards the unmatched rows too, quietly turning the LEFT JOIN back into something that behaves like an INNER JOIN.

🔄 Likely Follow-up

"What about RIGHT JOIN and FULL JOIN?" RIGHT JOIN is the mirror of LEFT JOIN — it keeps all rows from the right table instead; FULL JOIN keeps the unmatched rows from both sides at once.

🎯 Say this in the interview — the exact lines to land

"An INNER JOIN only returns rows that have a match on both sides — no match, no row. A LEFT JOIN keeps every row from the left table regardless, and fills the right side's columns with NULL wherever there's no match."

  • INNER JOIN → use when a match is required — you only want rows that genuinely exist on both sides.
  • LEFT JOIN → use when the left table must stay complete — e.g. every customer, even ones with zero orders.
  • A WHERE filter on the right table's column silently turns a LEFT JOIN back into an INNER JOIN — filter in the ON clause instead.
  • RIGHT JOIN and FULL JOIN extend the same idea — mirror the left table, or keep both sides' unmatched rows.
📖 Explanation ▾

INNER JOIN compares both tables and keeps a row only when the join condition finds a match on each side — anything left unmatched on either table simply doesn't appear in the result. LEFT JOIN starts from the left table and keeps every one of its rows no matter what; when a row has no match on the right, the right table's columns just come back as NULL instead of the row being dropped.

The practical difference shows up the moment you need "everyone," not just "everyone who qualifies." A report built on INNER JOIN quietly drops any left-table row that has zero related rows on the right — which reads as missing data, not a query bug, unless whoever's looking already knows to suspect the join.

💻 See the code ▾
SQL 
SELECT c.Name, o.OrderId
FROM Customers c
INNER JOIN Orders o ON o.CustomerId = c.Id;

A customer with zero orders is simply absent from this result — INNER JOIN never mentions them.

SQL 
SELECT c.Name, o.OrderId
FROM Customers c
LEFT JOIN Orders o ON o.CustomerId = c.Id;

That same customer now appears once, with o.OrderId = NULL, instead of vanishing.

🧭 Use Cases — recognize these when they happen to you ▾
1 You need only the pairs that truly exist on both sides

A report like "customers who actually placed an order" only makes sense when a real match exists on both sides. INNER JOIN is exactly right here — it keeps a row only when both a customer and a matching order exist.

RememberReal match required on both sides → INNER JOIN.
2 You need "everyone" — even rows with nothing on the other side

A roster of every customer must include the ones with zero orders. LEFT JOIN keeps that customer row and just fills the order columns with NULL, instead of dropping the row the way INNER JOIN would. This is the #1 scenario you'll actually run into.

RememberLeft table must stay complete → LEFT JOIN.
3 A LEFT JOIN with a WHERE filter on the right table's column

A WHERE filter runs after the join, and NULL never satisfies a WHERE condition — filtering on the right table's column in WHERE quietly discards the unmatched rows again, turning the LEFT JOIN back into something that behaves like an INNER JOIN. A great interview trap — candidates often assume the JOIN keyword alone decides the result, forgetting WHERE runs afterward.

RememberFilter the right table in ON, not WHERE — or you lose the LEFT JOIN's whole point.
🌍 Real-world example ▾

Think of a school roster and locker assignments. A LEFT JOIN lists every student on the roster, even the ones with no locker — their locker column just comes back blank. An INNER JOIN only lists students who actually have a locker assigned — anyone without one doesn't show up on the list at all.
