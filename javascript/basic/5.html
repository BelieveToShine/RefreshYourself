function declarations vs. expressions — one hoists, one doesn't

"What's the difference between a function declaration, a function expression, and an arrow function — and why can you call one of them before it's even defined?"

Why it matters ▾
  • Mixing up which form is hoisted causes real "cannot access before initialization" and "is not a function" bugs the moment code gets reordered or split into modules.
  • Interviewers use this to check you know functions are values, not just a keyword — the idea every later topic (closures, callbacks, this) builds on.
  • A common opener before "explain closures" or "how does this work" — shaky basics here make the interviewer doubt the deeper answers.
🔥 Easy interview recall

A function is "just a value with a job" — name it, store it in a variable, pass it into another function, or hand it work to do later.

Think: function foo(){} = built before any code runs (hoisted). const foo = () => {} = built only when that line runs (not hoisted).

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Function expressions aren't hoisted the way declarations are. Calling const greet = () => {} (or = function(){}) before that line throws — only a function greet(){} declaration can be called before its own line in the file.

🔄 Likely Follow-up

"Is a named function expression the same as a declaration?" No — const greet = function named(){} is still an expression: the outer binding greet isn't hoisted, only the inner name named is visible inside the function's own body (handy for recursion or a clearer stack trace).

🎯 Say this in the interview — the exact lines to land

"A function declaration is hoisted, so it can be called from anywhere in its scope. A function expression or arrow function is just a value assigned to a variable — it only exists once that line runs. Either way, functions are first-class values in JavaScript: they can be stored, passed as arguments, returned from other functions, and even carry their own properties."

  • function foo(){} → declaration, hoisted — safe to call from anywhere in its scope.
  • const foo = function(){} → expression, not hoisted — must be defined before it's called.
  • const foo = () => {} → arrow function — shorter syntax, same not-hoisted rule as any expression.
  • Higher-order function → takes and/or returns a function — e.g. arr.map(callback).
  • Functions are values → store them, pass them, return them, just like a number or a string.
📖 Explanation ▾

A function declaration (function greet(){}) is hoisted — the engine builds the whole function before running any code in that scope, so it can be called from the top of the scope, even above the line it's written on. A function expression (const greet = function(){}) is just a normal variable assignment: the value happens to be a function, but like any const/let, it doesn't exist until that line executes.

Arrow functions are a shorter way to write a function expression — (n) => n * 2 skips the function keyword and, for a single expression body, the { } and return too. They follow the same not-hoisted rule as any expression, and they're always anonymous unless assigned to a name.

A first-class function just means a function is a regular value — assign it to a variable, store it in an array, pass it into another function, or return it from one. A higher-order function is one that takes a function as an argument or returns one; the function it's handed is often called a callback because it gets "called back" later. Every function returns a value — explicitly via return, or undefined automatically if it never hits one.

Default parameters (function f(x = 1)) fill in a value only when that argument is missing. Rest parameters (function f(...args)) collect every remaining argument into one real array. And because a function is really just a callable object, it can carry its own properties too — greet.language = "en" is legal, and typeof greet still reports "function".

💻 See the code ▾
JavaScript 
greet();                  // ✅ works — declarations are hoisted

function greet() {
  console.log("Hi!");
}

A declaration is fully hoisted — the whole function exists before this line even runs.

JavaScript 
greet();                  // ❌ ReferenceError: Cannot access 'greet' before initialization

const greet = function () {
  console.log("Hi!");
};

An expression is just a variable assignment — it doesn't exist until this line runs. (With var instead of const, the error would be "greet is not a function" instead.)

JavaScript 
const double = (n) => n * 2;   // implicit return — no { } or return needed
double(4);                     // 8

Arrow functions skip function and return for a single expression body — otherwise they follow the exact same not-hoisted rule as any expression.

JavaScript 
function order(item, qty = 1, ...extras) {
  console.log(item, qty, extras);
}
order("book");                 // "book" 1 []
order("book", 2, "gift-wrap"); // "book" 2 ["gift-wrap"]

qty = 1 is a default parameter — used only when that argument is missing. ...extras is a rest parameter — it collects every remaining argument into one array.

JavaScript 
function announce(name, callback) {   // callback — a function passed in
  callback(`Welcome, ${name}!`);
}
announce("Sam", (msg) => console.log(msg)); // higher-order call

announce.usedBy = "onboarding flow";   // functions can hold properties too

announce is a higher-order function — it takes another function as an argument (a callback). The last line works because a function is really just a callable object.

🌍 Real-world example ▾

A function declaration is a recipe printed in the restaurant's cookbook before service starts — any cook can look it up the moment the kitchen opens. A function expression is a recipe scribbled on a sticky note mid-shift — it only exists once someone actually writes it down, so asking for it before that moment finds nothing.
