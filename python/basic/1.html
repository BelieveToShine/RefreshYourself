🔥 Python · Basic · Must Know

Python compiles to bytecode first, then interprets that — "interpreted" isn't the whole story

"Is Python interpreted or compiled? Is it dynamically typed? What is duck typing?"

Why it matters ▾
  • Almost always one of the first questions in a Python interview — it checks whether you actually understand how the language runs, not just its syntax.
  • Duck typing quietly explains a lot of "why does this code even work" moments later on, whenever an object is passed somewhere without inheriting from anything.
  • Dynamic typing is the root cause behind most "why did this only fail at runtime" bugs Python developers get asked to explain.
🔥 Easy interview recall

Compiled or interpreted? → both — bytecode first, then interpreted

Dynamically typed → type decided at runtime

Duck typing → behavior matters, not declared type

Think: Python only compiles ahead of time down to bytecode — everything else (type, behavior) gets decided while it runs.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

"Interpreted" means there's no compiling at all. CPython actually compiles your source to bytecode first — it just never compiles that bytecode down to native machine code ahead of time the way C does.

🔄 Likely Follow-up

"What actually happens when Python executes a .py file?" The source gets parsed and compiled into bytecode (cached as .pyc files inside __pycache__), then the CPython VM's interpreter loop executes that bytecode.

🎯 Say this in the interview — the exact lines to land

"Python compiles to bytecode first, then interprets that — it's not 'no compilation at all,' just not compiled ahead of time to native machine code like C."

  • CPython → compiles source to bytecode (.pyc, cached in __pycache__), then the VM's interpreter loop runs it.
  • Dynamically typed → type is decided at runtime, not declared; a name can be rebound to any type.
  • Duck typing → cares about behavior, not declared type — if an object has the right methods, it works.
  • PEP 8 → the official style guide; indentation itself is significant, it's how Python defines a block.
📖 Explanation ▾

CPython (the standard implementation almost everyone runs) parses your source and compiles it into bytecode — a lower-level set of instructions, saved as .pyc files inside a __pycache__ folder so the same file doesn't need recompiling next time. The CPython virtual machine then interprets that bytecode. So "interpreted" doesn't mean zero compilation — it means the compiled form is bytecode, not native machine code, and something still has to run a loop over it, unlike C's compiled machine code, which the CPU executes directly.

Dynamically typed means a variable's type isn't declared or checked until the program actually runs — the same name can be rebound from an int to a string to a list, and Python won't complain until code actually tries an operation the current value can't support. Duck typing goes further: code that calls obj.read() doesn't care what class obj is, only that it has a .read() method — "if it walks like a duck and quacks like a duck, treat it like a duck."

PEP 8 is the language's official style guide, and indentation is significant on top of that — it's how Python marks a block instead of braces. Two newer syntax pieces worth knowing by name: the := walrus operator (3.8+) assigns and returns a value in the same expression, and match/case structural pattern matching (3.10+) can destructure tuples and class patterns with guards — genuinely more than sugar over a chained if/elif, since it expresses structural matches a chain of if/elif can't cleanly.

💻 See the code ▾
Python 
while (chunk := file.read(8192)):  # ✅ assign + check in one line
    process(chunk)

Without :=, you'd assign chunk = file.read(8192) once above the loop, then repeat that same line again inside it just to re-check the condition — the walrus does both in one expression.

🌍 Real-world example ▾

Any object with a .read() method can be passed to code expecting a "file-like object" — a real file, an in-memory io.StringIO, a network socket wrapper. Python never checks for a formal interface or base class, only that the method it's about to call actually exists.
