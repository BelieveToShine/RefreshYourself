Task.WhenAll — start them together, wait for all

"How do you run several async calls concurrently and wait for all of them — and what happens if two of them fail?"

Why it matters ▾
⏱️ WhenAll / WhenAny
❗ ProblemAwaiting three independent calls one after another runs them one at a time — the total wait is the sum of all three, even though nothing forced them to wait on each other.
✅ SolutionStart all the calls first, then await Task.WhenAll(...) — the total wait is about the slowest one. Use WhenAny when you only need the first to finish, such as a timeout.
RecallWhenAll = wait for every task (≈ the slowest); WhenAny = the first one to finish.
🔥 Easy interview recall

WhenAll = "start them together, wait for all." WhenAny = "first one home wins."

Think: Sequential awaits add the times up; WhenAll takes the longest. With two failures, await shows one — the task keeps all.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

await on a WhenAll task throws only one of the failures. If two calls failed, the other exception is not lost — it is in the WhenAll task's Exception property (an AggregateException) — but you only see it if you look there.

🔄 Likely Follow-up

"How do you add a timeout?" Race the work against Task.Delay with WhenAny — and remember the loser is not cancelled, so pass a CancellationToken if you want the work to stop (see Cancellation).

🎯 Say this in the interview — the exact lines to land

"I start the calls first and then await Task.WhenAll, so the total time is roughly the slowest call, not the sum. If several fail, await rethrows just one; the task's Exception holds them all."

  • Sequential awaits → total time is the sum.
  • WhenAll → total time is about the slowest call, and it returns all results in order.
  • WhenAny → completes when the first task completes; good for timeouts and first-wins.
  • Two failures → await rethrows only one; the task's Exception property keeps every one.
  • Losers of a WhenAny → keep running unless you cancel them yourself.
📖 Explanation ▾

A Task starts running the moment the async method is called — await only waits for it. So await A(); await B(); runs A to the end and only then starts B. If they are independent, call both first, keep the two tasks, and then wait for them together with Task.WhenAll. It gives back the results as an array in the same order you passed the tasks.

Task.WhenAny completes as soon as any one of the tasks completes, and it hands you that task. The classic use is a timeout: race your work against Task.Delay and check which one finished. The other tasks are not stopped.

If more than one task in WhenAll fails, the combined task is faulted and holds all the exceptions in an AggregateException. await unwraps that and throws just one of them, to keep ordinary catch blocks simple. To see every failure, keep the WhenAll task in a variable and read its Exception.InnerExceptions.

💻 See the code ▾
C# 
var userTask   = GetUserAsync(id);      // starts now
var ordersTask = GetOrdersAsync(id);    // starts now, too

await Task.WhenAll(userTask, ordersTask);   // wait for both
var user   = await userTask;                // already done — returns instantly
var orders = await ordersTask;

Both calls run at the same time; the total wait is about the slower one.

C# 
var all = Task.WhenAll(t1, t2);
try { await all; }
catch
{
    foreach (var e in all.Exception!.InnerExceptions)   // every failure, not just one
        Log(e);
}

await throws one exception; all.Exception lists them all.

C# 
var work = DoWorkAsync();
var first = await Task.WhenAny(work, Task.Delay(TimeSpan.FromSeconds(2)));
if (first != work)
{
    // timed out — but work is still running unless you cancel it
}

The classic WhenAny timeout. The loser is not cancelled for you.

🌍 Real-world scenario ▾

A product page needs details, price and stock from three services. Awaiting them one by one took about 600 ms (200 ms each); starting all three and awaiting Task.WhenAll brought it to about 200 ms.
