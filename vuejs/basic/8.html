computed vs. methods — cached once, or recalculated every time?

"What's the difference between a computed property and a method, if they can both return a derived value?"

Why it matters ▾
⚡ computed
❗ ProblemAn expensive derived value shouldn't be recalculated on every re-render if none of the data it depends on actually changed.
✅ SolutionA computed property caches its result and only recalculates when one of its reactive dependencies actually changes.
Recallcomputed = calculate once, reuse the cached result.
🔁 methods
❗ ProblemSome logic genuinely needs to run fresh every single time it's called — it's an action, not a cacheable derivation.
✅ SolutionA method re-runs its full body every time it's called — including every template re-render — with no caching at all.
Recallmethod = runs fresh, every single call.
🔥 Easy interview recall

computed → cached, recalculates only on dependency change

method → re-runs every single call

Think: calling a method from the template is like re-asking the full question every render; computed remembers the answer until something it depends on changes.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Putting an expensive calculation in a method called directly from the template ({{ expensiveCalc() }}). It silently re-runs on every single re-render of that component, not just when its actual inputs change.

🔄 Likely Follow-up

"Can a computed property have side effects?" It shouldn't — computed properties are meant to be pure derivations of other reactive state. Side effects like an API call or a DOM manipulation belong in a watcher or an event handler, not inside a getter Vue may evaluate more or less often than you'd expect.

🎯 Say this in the interview — the exact lines to land

"A computed property caches its result and only recalculates when one of its reactive dependencies actually changes. A method re-runs its full body every single time it's called — including every template re-render for an unrelated reason — even if nothing relevant to that method's own logic changed."

  • computed → cached, recalculates only on a real dependency change.
  • method → no caching, runs fresh on every call.
  • A computed getter should stay pure — no side effects.
📖 Explanation ▾

A computed property is reactive and memoized: Vue tracks exactly which reactive values it reads while computing its result, and only re-runs the getter when one of those specific dependencies changes. Reading it again in between — even many times, even from several places in the template — returns the same cached value instantly.

A method called from the template has no such tracking. It's just a function call, so it executes its full body every time the template re-renders for any reason — even a re-render triggered by something that has nothing to do with that method's own inputs.

💻 See the code ▾
Vue 
<script setup>
  import { ref, computed } from 'vue';
  const items = ref([10, 20, 30]);
  const total = computed(() => items.value.reduce((a, b) => a + b, 0));  // ✅ cached
</script>

<template>
  <p>{{ total }}</p>  // recalculates only when items changes
</template>

total only re-sums when items itself changes — not on every render.

Vue 
function total() {
  return items.value.reduce((a, b) => a + b, 0);  // ❌ re-runs on every render
}
<!-- template: <p>{{ total() }}</p> -->

Same math, but this version re-sums every single time the component re-renders for any reason.

🧭 Use Cases — recognize these when they happen to you ▾
1 A derived value shown directly in the template, like a cart total

A value the template reads repeatedly, derived from other reactive state. This is the #1 scenario a computed property exists for.

RememberDerived display value → computed, not a method call.
2 A function that needs fresh arguments each time, like formatting a specific row

Computed properties can't take arguments. Anything that needs a per-call parameter, like formatting one row in a loop, has to be a method.

RememberNeeds a parameter → has to be a method, computed can't take one.
3 A heavy filter/sort called as a method from a long list template

A heavy sort called as a method from the template re-runs on every unrelated re-render of the component — a silent, easy-to-miss performance cost that a computed property would have avoided entirely.

RememberHeavy work in a template method call → check if it should be computed instead.
🌍 Real-world example ▾

A computed property is like a whiteboard with the answer already written on it until someone erases and changes the numbers. A method is like re-doing the whole math problem on scratch paper every single time someone asks for the answer, even if nothing about the problem changed since the last time.
