match is not a switch — it matches the shape of a value, then unpacks it

"What is match/case in Python — is it just a switch?"

Why it matters ▾
🧩 Pattern matching
❗ ProblemLong if/elif chains full of isinstance checks, length checks and manual indexing get messy when the data comes in different shapes, like events or API messages.
✅ Solutionmatch checks the shape of a value and pulls out its parts in one place — the first case that fits runs, with the parts already bound to names.
Recallmatch = check the shape, then unpack the parts.
🔥 Easy interview recall

match = "match the shape, then unpack the parts."

Think: case [x, y] → a two-item sequence, with x and y bound case {"type": t} → a mapping that has a "type" key case Point(x=0) → a Point whose x is 0

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

case RED: does not compare against a variable named RED. A bare name is a capture pattern — it binds whatever is there and always matches; to compare, use a literal or a dotted name like Colour.RED.

🔄 Likely Follow-up

"What happens if no case matches?" Nothing — there is no error, and the code just carries on after the match block. Add case _: as the catch-all default.

🎯 Say this in the interview — the exact lines to land

"match isn't a switch — it's structural pattern matching, added in Python 3.10. It checks the shape of a value, binds the parts to names, and runs the first case that fits."

  • Not a switch → shape plus unpacking, not just equality on a value.
  • Patterns: literals, [a, *rest], {"k": v}, Class(attr=v), and | for "either of these".
  • case [x, y] if x == y → a guard adds an extra condition.
  • A bare name captures, never compares — dotted names compare.
  • _ → the default case; with no match and no _, nothing happens.
  • First match wins — no fall-through between cases.
📖 Explanation ▾

match takes one value (the subject) and tries each case pattern from the top. The first pattern that fits runs and the rest are skipped, so there is no fall-through. A pattern checks the shape of the value and, in the same step, binds its parts to names: case [x, y] means "a two-item sequence, with x and y set to its items."

Pattern kinds: literals (404, "quit"), a capture name (binds anything), _ (matches anything, binds nothing), sequences ([a, *rest] — they match lists and tuples, but not strings), mappings ({"k": v} — extra keys are allowed), class patterns (Point(x=0, y=y)), | for OR, and an if guard. Positional class patterns like Point(0, y) need __match_args__, which dataclasses create for you.

If nothing matches and there is no case _, nothing happens. match and case are soft keywords — they only act as keywords in this statement, so an existing variable called match still works. It needs Python 3.10 or newer.

💻 See the code ▾
Python 
def handle(event):
    match event:
        case {"type": "click", "pos": (x, y)}:
            return f"click at {x},{y}"
        case {"type": "key", "key": "q"}:
            return "quit"
        case [first, *rest]:
            return f"list: {first} + {len(rest)} more"
        case str() | int():
            return "plain value"
        case _:
            return "unknown"

print(handle({"type": "click", "pos": (3, 4), "extra": 1}))
print(handle({"type": "key", "key": "q"}))
print(handle([10, 20, 30]))
print(handle("hello"))
print(handle(3.5))

Prints click at 3,4, quit, list: 10 + 2 more, plain value, unknown. The extra "extra" key is ignored, and the string "hello" does not match the sequence pattern.

Python 
RED = "red"
colour = "blue"

match colour:
    case RED:   # ❌ a bare name CAPTURES — it never compares
        print("matched, RED is now", RED)

Prints matched, RED is now blue — the case matched anything and overwrote RED. To compare, use a literal ("red") or a dotted name (Colour.RED).

🌍 Real-world example ▾

A service reads JSON messages from a webhook, and each message has a different shape. One match with a case per shape replaces a pile of if "type" in msg and isinstance(...) checks, and the fields it needs are already unpacked into names.
