🔥 Must Know

Promise vs. Observable — nothing happens until you subscribe

"When does an Observable actually start doing anything, and how is that different from a Promise?"

Why it matters ▾
  • RxJS underlies almost everything async in Angular — HTTP, forms, router events, reactive state — so misunderstanding when a stream actually runs causes silent bugs everywhere.
  • A very common early interview question, used to check whether you've actually built with Observables or only skimmed the syntax.
  • Explains a real bug pattern: an HTTP call that looks fine in code but never fires because nothing ever subscribed to it.
🔥 Easy interview recall

Promise → starts immediately

Observable → starts on subscribe

Think: a Promise is already cooking. An Observable waits for someone to order.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

this.http.get(url) on its own sends nothing. A cold Observable does nothing until something actually subscribes — no request, no error, just silence, until .subscribe() or the async pipe triggers it.

🔄 Likely Follow-up

"If two components both subscribe to the same cold HTTP Observable, do they share one request or get two?" Two, independently — a cold Observable re-executes its producer for each new subscription, so two separate .subscribe() calls trigger two separate HTTP requests; sharing one execution across subscribers takes deliberately making it hot (e.g. shareReplay, covered next).

🎯 Say this in the interview — the exact lines to land

"An Observable is lazy — it represents a stream of values but does nothing until something subscribes. A Promise starts running the instant it's created, whether or not anything is listening. Subscribing both starts a cold Observable's work and gives you a Subscription you can unsubscribe from to stop it."

  • Promise → already running the moment it's created — no way to cancel it.
  • Observable → lazy, does nothing until .subscribe() is called.
  • Cold vs. hot → cold re-runs per subscriber (its own HTTP call each time); hot broadcasts to whoever's listening right now.
  • async pipe → subscribes and unsubscribes for you — no manual cleanup needed in the template.
  • Manual .subscribe() with no matching .unsubscribe() → the classic memory leak.
📖 Explanation ▾

RxJS is the library Angular leans on for asynchronous and event-based code — HTTP calls, forms, router events, and reactive state all flow through it as Observables. A Promise represents exactly one eventual value and starts executing the instant it's created, whether or not anything is listening yet. An Observable represents a stream of zero, one, or many values over time, and — for the common "cold" kind — does nothing at all until something subscribes.

Calling .subscribe() is the act that actually starts a cold Observable's producer running, and it hands back a Subscription you can call .unsubscribe() on later — which can genuinely cancel underlying work, like an in-flight HTTP request. A Promise has no equivalent: once created, it's already committed, with no built-in way to cancel it. A cold Observable also re-runs its producer for every new subscriber, each getting its own independent execution; a hot Observable is already producing values regardless of subscribers, so a new subscriber just taps into whatever's currently happening, missing anything that already went by.

Operators like map and filter are pure functions chained through .pipe() to build a processing pipeline without touching the original source — the next page covers these in depth. In a template, the async pipe subscribes to an Observable directly, unwraps its latest value, and unsubscribes automatically when the component is destroyed — which is exactly why it's the recommended default over a manual ngOnInit subscribe that's easy to forget to clean up.

💻 See the code ▾
TypeScript 
const request$ = this.http.get(url);   // ❌ nothing sent yet — no subscriber

request$.subscribe();                     // ✅ NOW the HTTP request actually fires

Defining an Observable never runs it — only .subscribe() (or the async pipe) starts a cold Observable's work.

HTML 
<div *ngIf="user$ | async as user">{{ user.name }}</div>

The async pipe subscribes when the template renders and unsubscribes automatically when the component is destroyed — never needs a manual unsubscribe.

🌍 Real-world example ▾

A food order already cooking vs. a recipe card waiting to be used. A Promise is like placing a food order — the kitchen starts cooking the moment you order, whether or not anyone's there to pick it up. A cold Observable is like a recipe card: nothing gets cooked until someone actually asks for a plate — and if two people ask, the kitchen cooks it twice, independently, unless someone deliberately sets up one shared pot everyone eats from.
