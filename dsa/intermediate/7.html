Dijkstra, Bellman-Ford, Floyd-Warshall, Kruskal, Prim — which one actually fits your graph?

"Given a weighted graph, how would you choose between Dijkstra, Bellman-Ford, Floyd-Warshall, Kruskal, and Prim?"

Why it matters ▾
  • Interviewers ask this to check you understand why each algorithm works — reciting all five names back rarely earns credit on its own.
  • Comes up any time a problem says "weighted graph," "cheapest route," "network delay," or "connect everything for the least cost."
  • The negative-weight constraint is a favorite follow-up that separates a memorized answer from real understanding.
🔥 Easy interview recall

Dijkstra → single source, non-negative weights only

Bellman-Ford → single source, handles negative weights

Floyd-Warshall → every pair of nodes at once

Kruskal / Prim → MST — cheapest way to connect, not to reach

Think: Dijkstra is fast but breaks silently on a negative edge Bellman-Ford is slower but safe, and can catch a negative cycle Floyd-Warshall answers every pair at once, at O(V³) Kruskal/Prim solve a different problem entirely — connecting, not reaching

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Dijkstra doesn't reject negative edge weights — it just quietly gives the wrong answer. Its greedy rule assumes a node finalized as "closest" can never get closer later; one negative edge can break that assumption without ever throwing an error.

🔄 Likely Follow-up

"Your graph has negative edge weights — can you still use Dijkstra?" No — switch to Bellman-Ford, which relaxes every edge up to V-1 times and can even detect a negative cycle; for all-pairs with negative edges, Johnson's algorithm exists for exactly this case.

🎯 Say this in the interview — the exact lines to land

"I'd pick based on the graph's constraints: Dijkstra for single-source shortest paths when weights are non-negative — it's the fastest fit. If negative weights are possible, or I need to detect a negative cycle, I'd use Bellman-Ford instead. If I need shortest paths between every pair of nodes on a small or dense graph, Floyd-Warshall. And if the goal isn't reaching a node at all but connecting every node for the least total cost, that's Kruskal or Prim building a minimum spanning tree."

  • Dijkstra → non-negative weights, single source — the common, fastest case.
  • Bellman-Ford → negative weights or negative-cycle detection — Dijkstra can do neither.
  • Floyd-Warshall → all-pairs on a small/dense graph — O(V³) DP over every intermediate node.
  • Kruskal / Prim → MST, not shortest path — cheapest way to connect every node with exactly V-1 edges.
📖 Explanation ▾

Dijkstra keeps a priority queue of "best distance found so far" and always finalizes the currently-closest unvisited node next, then relaxes (updates) its neighbors' distances. That greedy order is only provably correct because weights are non-negative — a later negative edge could otherwise let a path the algorithm already gave up on become the real shortest one, and Dijkstra has no way to revisit a node it already finalized.

Bellman-Ford gives up Dijkstra's speed for generality: instead of picking a "closest" node, it relaxes every edge in the graph, up to V-1 times (V = number of vertices) — enough passes to guarantee the true shortest path has been found, since no shortest path (without a negative cycle) needs more than V-1 edges. Run one more pass after that: if any edge can still be relaxed, the graph has a negative cycle, and "shortest path" is undefined.

Floyd-Warshall answers a different question — every pair of nodes at once — by trying each node in turn as a possible waypoint between every other pair, an O(V³) dynamic program. That cost is fine on a small or dense graph; on a large sparse one, running Dijkstra from every single source is usually cheaper if all-pairs is truly needed. A minimum spanning tree (MST) is a separate problem again: given a connected, undirected, weighted graph, find the edge subset that connects every node using exactly V-1 edges, no cycles, for the least total weight. Kruskal sorts every edge by weight and greedily adds it if it doesn't create a cycle (checked with Union-Find — its own topic, next). Prim grows one tree from a starting node, always adding the cheapest edge that reaches a new node, using a min-heap much like Dijkstra's.

💻 See the code ▾
Pseudocode 
dist[source] = 0, everything else = ∞
pq = min-heap([(0, source)])

while pq not empty:
    d, u = pq.pop_min()            // closest unvisited node
    if d > dist[u]: continue       // stale entry, skip
    for (v, weight) in neighbors[u]:
        if dist[u] + weight < dist[v]:
            dist[v] = dist[u] + weight   // ✅ relax — found a cheaper path
            pq.push((dist[v], v))

Only safe because weight ≥ 0 — a negative edge could make an already-finalized node's distance wrong.

Pseudocode 
dist[source] = 0, everything else = ∞

repeat V - 1 times:                 // longest possible shortest path
    for (u, v, weight) in all_edges:
        if dist[u] + weight < dist[v]:
            dist[v] = dist[u] + weight

for (u, v, weight) in all_edges:      // one extra pass
    if dist[u] + weight < dist[v]:
        report "negative cycle"   // ❌ shortest path undefined

Handles negative weights and tells you when "shortest path" doesn't even make sense.

Pseudocode 
edges.sort_by(weight)             // Kruskal: cheapest edges first
mst = []
for (u, v, weight) in edges:
    if find(u) != find(v):     // Union-Find — next topic
        union(u, v)
        mst.add((u, v, weight))   // ✅ safe — no cycle created

🌍 Real-world example ▾

A maps app finding your fastest route uses Dijkstra — road travel times are never negative, so its speed is safe to rely on. A network that models a currency-arbitrage graph, where an edge's "cost" can be negative (a trade that gains money), needs Bellman-Ford instead — and its negative-cycle check is exactly how you'd detect that a profitable arbitrage loop exists.
