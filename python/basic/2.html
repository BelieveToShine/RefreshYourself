A variable is a name bound to an object — not a box holding a value

"What is a variable in Python — does it store a value or a reference to an object?"

Why it matters ▾
🏷️ Names and objects
❗ ProblemIf you picture a variable as a box holding a value, passing a list into a function and changing it there will surprise you when the caller's list changes too.
✅ SolutionA variable is a name bound to an object, and = only binds — it never copies — so two names can point at one object.
RecallAssignment binds a name; it never copies.
🔥 Easy interview recall

Assignment = "binding a name to an object, never copying it."

Think: b = a → same object, two names — mutate through either one, and both see it.

🧠 Visual Mental Model — understand it in 5 seconds
🔮 Predict the Output
Python 
a = [1, 2]
b = a
b.append(3)
print(a)

What does this print, and why?

Answer: [1, 2, 3] — b = a binds a second name to the exact same list object, it doesn't copy it. b.append(3) mutates that shared object in place, so the change is visible through a too.

⚠️ Common Trap

b = a does not copy the value. It binds a second name to the exact same object — true for every type, not just lists — so mutating through either name is visible through both.

🔄 Likely Follow-up

"How would you make b an independent copy?" Call b = a.copy() (or list(a)) for a shallow copy — real independent copying, including nested objects, is the Shallow vs. Deep Copy topic (Intermediate).

🎯 Say this in the interview — the exact lines to land

"Assignment never copies — it binds a name to an existing object. If two names end up bound to the same object, mutating it through one name is visible through every other name pointing at it. The only way to break that link is to create a genuinely new object, like with .copy()."

  • Assignment binds, it never copies — true for every type, always.
  • Same object, two names → b = a doesn't create a second object.
  • Mutating through one name is visible through every other name bound to it.
  • b = a.copy() → the way to actually break the link and get an independent object.
📖 Explanation ▾

Every value in Python is an object living somewhere in memory, and a variable is just a name pointing at one of those objects. Assignment (=) always binds a name to an existing object — it never manufactures a copy of it. Even a = 10 doesn't put 10 "into" a; it makes the name a point at the integer object 10.

Every object carries three separate things: its identity (id(obj) — effectively its memory address, unique for its lifetime), its type (fixed for that object, e.g. list, int), and its value (the actual data). Two names can share identity — meaning they're literally the same object — or hold equal values while being two distinct objects. is checks identity; == checks value.

This is also what "everything is an object" actually means — not just lists and dictionaries, but functions, classes, and modules too. Each one has its own identity, type, and value, and a name binds to any of them exactly the same way.

💻 See the code ▾
Python 
a = 10
b = a

"What's the relationship between a and b afterward?" Both names point to the same object at first — but rebinding one (a = 20) doesn't affect the other; a now points to a new object, while b still points to the old one. Assignment binds, it never copies.

Python 
a = [1, 2]
b = a
b.append(3)
print(a)

"What does print(a) output, and why?" [1, 2, 3] — b and a are the same list object, so mutating through b is visible through a. This is the core "reference, not a box" lesson.

🧭 Use Cases — recognize these when they happen to you ▾
1 You change b and your other list a changes too

b = a does not copy. Both names point at the same list, so a change made through one name shows through the other.

RememberAssignment binds. It never copies.
2 You do b = a, then give a a new value

Rebinding only moves the name a to a new object. b was never touched, so it still points at the old one.

RememberRebinding one name never moves the other.
3 You need to know if two names are the same object, or just equal

== compares values, so two separate lists with the same items are equal. is compares identity, and these are two different objects.

Remember== is value, is is identity.
🌍 Real-world example ▾

This is exactly why "I passed a list into a function, and it mutated my caller's list" surprises people — same underlying reference semantics as this page, just showing up through a function argument instead of a plain assignment (the Functions page, also Basic, covers that version of it).
