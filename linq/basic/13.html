Min / Max / Sum / Average / Count — five aggregates, three different empty-sequence behaviors

"What does each of these five basic aggregate operators need, and what does each actually return on an empty sequence?"

Why it matters ▾
🧮 The five basic aggregates
❗ ProblemFive methods that all look like the same "do one number math thing to the whole sequence" family silently disagree on what an empty sequence means — assume they all behave the same way and production code crashes on a day with zero orders instead of reporting a clean zero.
✅ SolutionMin, Max, and Average throw InvalidOperationException on empty — there's genuinely no minimum, maximum, or average of nothing. Sum and Count return 0 — adding nothing, or counting nothing, is still a well-defined number.
RecallEmpty sequence: Min/Max/Average throw, Sum/Count return 0.
🔥 Easy interview recall

Min / Max / Average → throws on empty

Sum / Count → 0 on empty

Think: there's no such thing as the minimum, maximum, or average of nothing — but adding nothing, or counting nothing, is still a perfectly good zero.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Assuming all five aggregates treat "empty" the same way. Sum and Count quietly return 0; Min, Max, and Average throw InvalidOperationException instead — mixing those two groups up is exactly the kind of thing a code review (or an interviewer) catches fast.

🔄 Likely Follow-up

"How would you guard against that Average call throwing?" Check Any() (or the count) before calling it, or use the sequence's own default/guard value instead of letting the exception happen — Average itself has no "on empty, return 0" overload to opt into.

🎯 Say this in the interview — the exact lines to land

"On an empty sequence, Min, Max, and Average throw InvalidOperationException because there's genuinely no such value — but Sum and Count return 0, because adding or counting nothing is still a valid number."

  • Min / Max / Average → throw on empty — no minimum, maximum, or average of nothing.
  • Sum / Count → return 0 on empty — a well-defined number either way.
  • Any of the five with a selector (e.g. Sum(x => x.Price)) needs the selector to return a numeric type the method can actually aggregate.
📖 Explanation ▾

All five are terminal operators — they force immediate execution and hand back one value instead of a sequence. The split in behavior comes down to one question: does "nothing" have a sensible answer for this operation?

For Min, Max, and Average, the answer is no — there's no smallest value, largest value, or mean of a set with zero elements, so .NET throws InvalidOperationException rather than inventing a number that would be misleading. For Sum and Count, the answer is yes — the sum of nothing is 0, and the count of nothing is 0, both perfectly ordinary results.

💻 See the code ▾
C# 
List<int> prices = new();   // empty

prices.Sum();     // ✅ 0
prices.Count();   // ✅ 0
prices.Max();      // ❌ throws InvalidOperationException

Same empty list, three calls — two return a clean 0, one throws.

C# 
decimal average = prices.Any()
    ? prices.Average()
    : 0m;   // ✅ guard the throwing ones before calling

The fix is always the same shape: check Any() (or a count) before Min/Max/Average.

🧭 Use Cases — recognize these when they happen to you ▾
1 A dashboard computes "today's average order value" on a day with zero orders

A page that calls orders.Average(o => o.Total) without checking Any() first works fine every day there's at least one order — and throws the first quiet day there isn't. This is the #1 scenario you'll actually run into.

RememberAverage on a possibly-empty sequence → guard it or it throws.
2 A report shows "total revenue" and "order count" for a category with no matches

Sum and Count never need a guard for this — an empty result set for "revenue in this category" or "orders this week" is genuinely a 0, and that's exactly what gets rendered, no special-casing required.

RememberSum/Count on empty → a real, safe 0, no guard needed.
3 You need the cheapest item in a possibly-empty shopping cart

An empty cart has no "cheapest item" — checking cart.Any() before calling Min is the correct fix, not trying to special-case a "default minimum" that doesn't really mean anything.

RememberMin/Max on possibly-empty data → check Any() first, every time.
🌍 Real-world example ▾

Ask someone "what's the average height of the people in this empty room?" — there genuinely isn't an answer, which is why Average throws rather than guessing. Now ask "how many people are in this empty room?" — zero is a perfectly good answer, which is exactly why Count doesn't throw.
