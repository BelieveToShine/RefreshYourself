🔥 Must Know

{{ }} and [property] — look almost identical, but do genuinely different things

"What's the actual difference between interpolation and property binding in an Angular template?"

Why it matters ▾
  • Mixing up interpolation and property binding is a real, early bug — binding a boolean into text instead of setting the real property.
  • [(x)] looking like its own special mechanism is one of the most common "what does this weird syntax actually mean" follow-ups.
  • Calling a method straight inside a binding is an easy way to quietly hurt performance without a single error being thrown.
🔥 Easy interview recall

{{ }} → text only, always a string

[prop] → real property, keeps its type

(event) → runs code when it fires

Think: [()] isn't a 4th thing — it's [prop] + (event), combined.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

[()] is not its own two-way binding mechanism. It's shorthand for one property binding in plus one event binding out — [(x)]="y" expands to [x]="y" (xChange)="y=$event" — so a component needs both @Input() x and @Output() xChange for it to work at all.

🔄 Likely Follow-up

"If interpolation just inserts text, why not always use [innerText] or [textContent] instead?" You could — the underlying mechanism is the same — but interpolation reads more naturally inside HTML content, and it's the idiomatic, expected style for inline text; this is a readability choice, not a capability difference.

🎯 Say this in the interview — the exact lines to land

"Interpolation always produces text — it's really property binding aimed at text content. Property binding sets the real DOM or component property directly, keeping its actual type. Event binding wires up a handler and passes $event, and two-way binding — [(x)] — is just that property binding plus an event binding named xChange, combined into one syntax."

  • {{ }} → text only, always a string.
  • [prop] → the real property, any type — no string conversion.
  • (event) → runs code on a DOM/component event; $event carries the payload.
  • [(x)] → shorthand, not magic — expands to [x] + (xChange).
  • Never call a method straight inside a binding — it reruns on every check; precompute the value instead.
📖 Explanation ▾

Interpolation ({{ }}) always turns its result into text — Angular evaluates the expression, converts it to a string, and drops it into the surrounding content. It's really a specific case of property binding aimed at text content, which is exactly why it can only ever produce text, never a real boolean or object. Property binding ([prop]="expr") skips the text step entirely — Angular sets the actual DOM or component property to whatever the expression evaluates to, keeping its real type. [disabled]="isLoading" sets a real boolean disabled property, not the string "true".

Event binding ((event)="handler($event)") wires a DOM or component event to a method call; $event carries the native event object, or a custom payload for an @Output. Once the handler runs, Angular triggers a change-detection pass in case anything changed. [(ngModel)] isn't a separate mechanism — it's shorthand that expands to exactly one property binding in and one event binding out, named xChange by convention, and it needs FormsModule imported for ngModel specifically.

Template expressions aren't full JavaScript — no assignments, new, or ;-chained statements — Angular parses a restricted expression language against the component instance. That's also why a method like getFilteredItems() called directly in a binding is risky: with the default change-detection, every template expression re-runs on every check, so the method (and any array it allocates) runs again and again even when nothing relevant changed. Precompute the value instead — a class property, a pipe, or computed().

💻 See the code ▾
HTML 
<p>{{ user.name }}</p>              // text only — always a string
<input [value]="user.name">      // real property — keeps its actual type

Both display user.name — but only [value] hands Angular the real value, not a stringified copy of it.

HTML 
<input [(ngModel)]="value">
// desugars to exactly this:
<input [ngModel]="value" (ngModelChange)="value=$event">

[(ngModel)] is shorthand, not a separate mechanism — it's [ngModel] plus (ngModelChange), written as one thing.

🌍 Real-world example ▾

Interpolation is like reading a value out loud — it becomes words. Property binding is like turning a dial to that value — it sets the real thing, whatever type it actually is. Two-way binding just does both at once: turning the dial, and announcing it out loud the moment someone else turns it.
