<component :is> — does the old component remember anything?

"How does <component :is> work, and does state persist when it switches?"

Why it matters ▾
🔀 Dynamic Components
❗ ProblemA tabbed interface where each tab is a different component needs some way to swap which component actually renders, without writing a separate v-if/v-else-if chain for every tab.
✅ Solution<component :is="currentComponent"> renders whichever component the bound value currently points to — swapping the component type dynamically based on a single reactive reference.
Recall:is = a reactive pointer to "which component renders here."
🔥 Easy interview recall

<component :is> = "swap the component type, not just its data."

Think: :is changes → old instance destroyed → new one mounts fresh, no state carried.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Expecting state inside the swapped-out component to persist when :is changes. By default Vue destroys the old component instance and creates a brand-new one — state persistence across the switch needs <KeepAlive> wrapped around it.

🔄 Likely Follow-up

"Can :is point to a plain HTML tag name too?" Yes — a string like "div" works, letting :is dynamically choose between a component and a native element.

🎯 Say this in the interview — the exact lines to land

"<component :is="currentComponent"> renders whichever component that reactive reference currently points to. By default, switching it destroys the old component instance entirely and mounts a fresh one — nothing carries over unless it's wrapped in <KeepAlive>."

  • :is → swaps the component type, not just its props.
  • Default behavior → destroy old, mount new, every time it changes.
  • Need state to persist? → wrap it in <KeepAlive>.
  • :is → also accepts a plain tag string like "div".
📖 Explanation ▾

<component :is="X"> is a special built-in element — it isn't a real component itself, it's a placeholder that tells Vue which actual component (or string tag name) to render in its place. X can be a component object, a registered component's name, or a plain string like "div".

Because :is is reactive, changing the value it's bound to re-evaluates what should render there — and Vue's normal rule for "the template no longer points at this instance" applies: the previous component instance is fully unmounted (its local state, timers, and watchers all torn down) before the new one is mounted fresh.

Default :is switchWrapped in <KeepAlive>
Old instance❌ destroyed✅ cached, not destroyed
Local state on switch-back❌ reset✅ preserved
Mount/unmount hooksrun every switchactivated/deactivated instead
💻 See the code ▾
Vue 
<script setup>
import TabA from './TabA.vue'
import TabB from './TabB.vue'
const current = ref(TabA)
</script>

<template>
  <component :is="current" />         <!-- ✅ renders TabA, then TabB -->
  <button @click="current = TabB">Switch</button>
</template>

Clicking the button destroys TabA's instance and mounts a fresh TabB.

Vue 
<component :is="isWarning ? 'strong' : 'span'">    <!-- ✅ plain tag strings work too -->
  Message
</component>

:is isn't limited to components — a plain HTML tag name is valid too.

🧭 Use Cases — recognize these when they happen to you ▾
1 A tabbed interface where each tab is its own component

One <component :is="activeTab"> slot replaces a long v-if/v-else-if chain — adding a new tab just means adding another component to the lookup, not another branch.

RememberSwapping between several named components in one spot → reach for :is.
2 A form tab loses its unsaved input when the user switches tabs and back

Without <KeepAlive>, switching away and back always creates a brand-new instance of that tab's component — whatever the user typed before switching away is gone, because that instance no longer exists.

RememberUnsaved input disappearing on tab switch → missing <KeepAlive>.
🌍 Real-world example ▾

A settings page with "Profile," "Billing," and "Security" tabs, each a separate component. <component :is="tabs[activeTab]"> renders the right one from a lookup object keyed by tab name — adding a fourth tab later is one new entry in that object, not a new template branch.
