var vs. dynamic vs. object — know who checks your code

Why it matters ▾
  • Clears up a common myth — var is not "untyped."
  • Explains why dynamic typos only show up when the code actually runs.
  • A quick way to show you know the difference between compile-time and runtime.
🔥 Easy interview recall

var → compiler decides

object → general container

dynamic → runtime decides

Think: var is strict. dynamic waits. object needs casting.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

var ≠ dynamic. var's type is inferred once, at compile time; dynamic defers checking to runtime.

🎯 Say this in the interview — the exact lines to land

"var uses compile-time type inference, so it's still strongly typed. object is a general base type and may require casting, while dynamic defers member binding to runtime."

  • object → box value types, cast to use them.
  • A typo on a dynamic call compiles fine, throws later.
  • var never means "no type" — it means "infer the type for me."
📖 Explanation ▾

var doesn't turn off type checking — it just asks the compiler to figure out the type from the right-hand side, once, at compile time. var name = "Sam"; is exactly as strict as string name = "Sam";; it just saves typing the type twice.

object is the common base type for C# types — useful when you genuinely don't know (or don't care about) the specific type, but value types get boxed when stored as object, and you have to cast back to the real type before using its specific members.

dynamic defers type checking to runtime — operations aren't resolved (or checked) until that line actually executes. Call a method that doesn't exist on a dynamic variable and the code compiles fine — it only blows up, at runtime, the moment that line executes.

💻 See the code ▾
C# 
var a = 10;
a = "Hello";        // ❌ Compile-time error

var is not dynamic — the compiler already knows a is an int.

C# 
dynamic user = "Sam";
Console.WriteLine(user.Length);   // ✅ works
Console.WriteLine(user.Lenght);   // ❌ compiles, throws at runtime

The typo compiles fine — dynamic skips the compile-time member check, so the mistake only surfaces when that exact line runs.

C# 
object value = 10;
value + 1;                // ❌ no + operator for object

int number = (int)value;
number + 1;               // ✅ 11

The compile-time type is object — even though the boxed value is really an int, you can't use int operations on it until you cast it back.

🌍 Real-world example ▾

A labelled box vs. an unlabelled box vs. a mystery box. var is a box with the label filled in for you automatically — still clearly labelled. object is a plain box — anything fits, but you have to open it and check before using what's inside. dynamic is a box you don't even check — you just reach in and hope.
