⭐ Azure · Intermediate · Should Know

Redundancy is where the copies live; tiers are how fast you can read

"LRS vs. ZRS vs. GRS vs. GZRS — and Hot vs. Cool vs. Archive?"

Why it matters ▾
📍 Redundancy
❗ ProblemStoring one copy of your data in one building means a single hardware or datacenter failure can take it away.
✅ SolutionRedundancy options keep several copies in different places: one datacenter (LRS), across zones (ZRS), or also in a second region (GRS, GZRS).
RecallLRS one place, ZRS zones, GRS / GZRS add a second region.
🗂️ Access tiers
❗ ProblemPaying hot-storage prices for data nobody has touched in months wastes money.
✅ SolutionTiers trade storage price against access cost and speed — Hot for frequent use, Cool for infrequent, Archive for rarely read, with lifecycle rules moving data automatically.
RecallColder = cheaper to keep, slower and pricier to read.
🔥 Easy interview recall

L = Locally → one datacenter

Z = Zone → spread across zones

G = Geo → copy in a second region

RA- prefix → second copy is readable

Think: redundancy answers "what failure survives?", tier answers "how often do I read it?"

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

"Archive is just Cool but cheaper." Archive data is offline: you must rehydrate a blob back to Hot or Cool before reading it, which takes hours, and early deletion or access charges can apply. Use it only for data you truly do not need on demand.

🔄 Likely Follow-up

"Does GRS let you read from the second region?" Not by default. The second copy sits there for disaster recovery; read access needs the RA variants (RA-GRS or RA-GZRS). Also, redundancy is chosen per storage account and tiers per blob or account default.

🎯 Say this in the interview — the exact lines to land

"LRS keeps copies in one datacenter, ZRS spreads them across zones, GRS adds an asynchronous copy in a second region and GZRS combines zones with that second region. Separately, Hot, Cool and Archive trade storage cost against access speed, and lifecycle rules move blobs between them."

  • LRS → cheapest, one datacenter, no zone or region protection.
  • ZRS → survives a zone loss within the region.
  • GRS / GZRS → also a second region for regional disasters.
  • RA- prefix → second copy is readable before any failover.
  • Hot, Cool, Archive → cost vs. access speed; Archive is offline.
  • Lifecycle rules → auto-move or delete by age.
📖 Explanation ▾

Redundancy is about how many copies exist and where. LRS keeps copies inside one datacenter. ZRS spreads them across availability zones in a region, so losing one zone does not lose the data. GRS adds an asynchronous copy in a paired second region; GZRS uses zone-redundant storage in the primary and also copies to the second region. The RA- versions let you read the second copy before any failover.

Access tiers are a separate choice about cost against speed. Hot has the highest storage price but the cheapest access, for data you use all the time. Cool costs less to keep but more to read, for infrequent access. Archive is the cheapest to keep, but offline: reading means rehydrating first, which takes hours. Newer tiers such as Cold exist too, so check the current docs.

A lifecycle management rule moves blobs to cooler tiers, or deletes them, as they get older, so nobody has to remember to do it. Which redundancy and tier options are available can depend on account type and region, so confirm in the current docs.

💻 See the code ▾
Azure CLI 
# zone + region protection, Hot by default
az storage account create --name stordersdemo01 --resource-group rg-data --location eastus --sku Standard_GZRS --access-tier Hot

The redundancy is chosen with the SKU (Standard_GZRS here), and the default tier with the access tier. The account name is made up and must be globally unique.

🌍 Real-world example ▾

A company keeps this month's customer invoices in Hot, last year's in Cool, and seven-year audit copies in Archive through a lifecycle rule, and stores them in a GZRS account so a zone or region problem does not lose them.
