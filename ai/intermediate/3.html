🔥 AI · Intermediate · Must Know

Keyword nails the exact match. Vector nails the reworded one. Hybrid nails both.

"Why is hybrid search often better than pure vector search?"

Why it matters ▾
  • Tests whether you actually know vector search's real blind spot — exact identifiers and rare technical terms an embedding model never learned to represent well.
  • Comes up any time someone challenges "why not just use embeddings for everything" in a RAG system design.
  • A very common follow-up right after a chunking or RAG-pipeline question, since retrieval quality is the layer everything downstream depends on.
🔥 Easy interview recall

Keyword → nails exact terms

Vector → nails reworded meaning

Hybrid → runs both, keeps the best of each

Think: Keyword reads letters. Vector reads meaning. Hybrid reads both.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

A better embedding model doesn't fix this. An exact identifier like a SKU or error code can still be poorly represented in the embedding's similarity space no matter how good the model is — that's a job for keyword matching, not a "train a bigger model" problem.

🔄 Likely Follow-up

"Isn't that basically what reranking does?" No — hybrid search decides which results get retrieved in the first place by combining two search methods; reranking is a separate later step that re-scores whatever was already retrieved to fix the order they come back in.

🎯 Say this in the interview — the exact lines to land

"Hybrid search runs keyword search and vector search on the same query and combines both result sets — keyword search catches exact terms like SKUs or error codes that embeddings under-represent, while vector search catches meaning-based matches phrased in completely different words, so combining them covers both failure modes at once."

  • Keyword (BM25) → use for exact identifiers — SKUs, error codes, rare technical terms.
  • Vector (semantic) → use for meaning-based queries — the user asked it in different words than the source text.
  • Hybrid → run both, then combine — that's why it usually beats either search alone in production.
📖 Explanation ▾

Keyword search (commonly a BM25-style ranking) matches on exact, lexical term overlap — it's excellent at finding exact matches a candidate document actually contains, like a product code, a specific name, or a rare technical term. Vector search matches on meaning: it can find content that's conceptually related to the query even when the exact words are completely different. Each one has a real, opposite blind spot — keyword search misses a paraphrase that shares no words with the query, and vector search can under-perform exactly when an exact identifier is what actually matters, because that identifier was never well represented in the embedding's learned similarity space.

Hybrid search runs both searches on the same query — in parallel, or in some fusion scheme — and combines their results, for example by combining or re-weighting each list's scores or ranks into one final list. It doesn't have to pick a winner between the two methods; it covers both failure modes at once, which is exactly why it frequently outperforms either method alone in practice.

💻 See the code ▾
Pseudocode 
# same query, two independent searches
keyword_hits = bm25_search(query, top_k=20)         # exact/lexical
vector_hits  = vector_search(embed(query), top_k=20) # meaning/semantic

# fuse the two ranked lists into one
results = combine(keyword_hits, vector_hits)  # ✅ covers both misses

Both searches run on the exact same query — the fusion step is what actually makes it "hybrid," not just running two searches side by side.

🌍 Real-world example ▾

Think of a library help desk with two librarians on duty. One only recognizes exact call numbers and titles — hand her the right code and she finds it instantly, but describe the book in your own words and she's lost. The other listens to what you're describing and points you to something that sounds right, even if you got the title wrong — but she can miss the shelf with the exact code you actually needed. Ask both at once, and you get the exact match and the "this sounds like what you mean" answer, instead of gambling on which one your question needed.
