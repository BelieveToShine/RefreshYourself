Why one slows a loop and the other doesn't

Why it matters ▾
  • Explains a real, measurable performance mistake — concatenating strings in a loop.
  • Tells you exactly when reaching for StringBuilder actually pays off.
  • A clean follow-up once immutability (from Value vs. Reference) has come up.
🔥 Easy interview recall

string → immutable, every change is new

StringBuilder → one buffer, grows in place

Think: a loop of += vs. a loop of .Append()

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

String interpolation isn't magic. $"Hello {name}" still compiles down to concatenation under the hood — same allocation cost as +=.

🎯 Say this in the interview — the exact lines to land

"string is immutable, so every change allocates a new string. StringBuilder keeps one resizable buffer and writes into it directly — that's the whole reason it's faster in a loop."

  • Few concatenations → plain stringLoop / many appends → StringBuilder
📖 Explanation ▾

string is immutable — once created, it never changes. So every += doesn't edit the string, it builds an entirely new one and throws the old one away. Do that once, no problem. Do it a thousand times in a loop, and you've created a thousand throwaway strings.

StringBuilder keeps one resizable buffer and writes into it directly — .Append() extends the same buffer instead of replacing it, so a loop of a thousand appends does far less allocation work overall.

For a handful of concatenations, plain string is simpler and perfectly fine — StringBuilder earns its keep specifically inside loops or long chains.

💻 See the code ▾
C# 
string s = "";
for (int i = 0; i < 1000; i++)
    s += i;   // 1000 new strings created, 999 thrown away

Each += is a brand-new allocation — the loop body pays that cost 1000 times.

C# 
var sb = new StringBuilder();
for (int i = 0; i < 1000; i++)
    sb.Append(i);   // ✅ one growing buffer, no throwaway strings
string result = sb.ToString();

Same 1000 iterations, one allocation instead of a thousand.

🌍 Real-world example ▾

Rewriting a letter vs. a whiteboard. string concatenation is like rewriting the entire letter by hand every time you want to add one more sentence. StringBuilder is a whiteboard — you just keep writing more on the same surface.
