🔥 AWS · Basic · Must Know

A subnet is public because of one route, not a feeling

"How does traffic actually flow from the internet to an EC2 instance in a VPC?"

Why it matters ▾
  • Almost every AWS networking question builds on this — EC2, RDS, and load balancer questions all assume you know how traffic actually gets in.
  • Explains a real design decision: why a database can sit with zero public IP anywhere near it and still be completely unreachable from the internet.
  • Sets up the exact misconception candidates state out loud: confusing "has a public IP" with "is a public subnet."
🔥 Easy interview recall

Public subnet → route table points to IGW

Private subnet → route table points to NAT Gateway (or nowhere)

Think: a subnet's public/private label lives in its route table, never on any instance's IP address.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

A subnet is public because an instance inside it has a public IP. It isn't — a subnet is public only if its route table sends 0.0.0.0/0 traffic to an Internet Gateway; what IP address an instance happens to carry has nothing to do with that classification.

🔄 Likely Follow-up

"How does a private EC2 instance reach the internet for updates?" Via a NAT Gateway sitting in a public subnet — the private instance routes outbound traffic through it, and nothing can initiate an inbound connection back through it.

🎯 Say this in the interview — the exact lines to land

"A subnet is public only because its route table points to an IGW — nothing else, not an assigned public IP, makes it public. A private subnet reaches the internet outbound-only through a NAT Gateway, and nothing can open a connection back in through it."

  • Route table → IGW is the only thing that makes a subnet public — never an IP assigned inside it.
  • NAT Gateway → gives a private subnet outbound-only internet access; nothing can initiate a connection back in.
  • Security Groups → stateful, attached to the instance — return traffic is automatically allowed.
  • NACLs → stateless, attached to the subnet — must explicitly allow both inbound and outbound directions.
📖 Explanation ▾

A VPC is your own isolated slice of the AWS network, defined by an IP range (a CIDR block, like 10.0.0.0/16). Subnets carve that range into smaller pieces, and each subnet lives in exactly one Availability Zone.

Whether a subnet is public or private comes down to one line in its route table. A subnet is public only if its route table sends 0.0.0.0/0 (anywhere on the internet) to an Internet Gateway (IGW). A private subnet has no such route — its default route instead points at a NAT Gateway, which lets its instances start outbound connections without ever being reachable from the internet themselves.

Inside the subnet, two more layers decide what traffic is actually allowed to move at all — independent of the routing question above.

💻 See the code ▾
AWS CLI 
aws ec2 create-route \
  --route-table-id rtb-0abc123 \
  --destination-cidr-block 0.0.0.0/0 \  -- "anywhere on the internet"
  --gateway-id igw-0def456                    -- this one line is what makes the subnet public

This single route, on this subnet's route table, is the entire definition of "public" — nothing about any instance's own IP is involved.

🌍 Real-world example ▾

A company's database sits in a subnet whose route table has no route to an Internet Gateway at all — not even indirectly through a NAT Gateway. It's reachable only from the app tier inside the same VPC. Even if someone leaked the database's private IP address, there's no path in from the internet for it to matter.
