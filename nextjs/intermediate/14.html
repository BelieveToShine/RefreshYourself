(.)folder — a modal that's still a real, shareable URL

"How does Instagram-style 'click a photo, see it as a modal, but the URL still works directly' routing work in Next.js?"

Why it matters ▾
🖼️ Intercepting Routes
❗ ProblemOpening a photo as a modal over a feed feels great in-app, but a modal has no meaningful full-page version — sharing or refreshing that URL would leave the visitor looking at a photo with no feed behind it, or no modal at all.
✅ SolutionA folder named (.)folderName intercepts a client-side navigation to that route and shows it in the current layout's context (a modal) — while a direct visit or hard refresh to that same URL still renders the route's normal full-page view.
Recall(.) = soft nav gets the modal, hard nav gets the real page.
🔥 Easy interview recall

(.)folder = "intercept a client-side navigation and show it differently — same URL either way."

Think: click a photo in-app → modal. Open that same URL fresh → full photo page.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

An intercepted route doesn't permanently replace the underlying route's normal rendering. It only intercepts client-side soft navigations from within the app — a direct URL load or hard refresh always falls through to the real, non-intercepted route.

🔄 Likely Follow-up

"Why does this matter for shareability?" The URL still changes to the real route's URL even while showing the intercepted modal view — so the link is fully shareable and bookmarkable, and whoever opens it fresh gets the real full-page version instead of a modal with nothing behind it.

🎯 Say this in the interview — the exact lines to land

"A folder named (.)folderName intercepts a client-side navigation to that route and shows it in the current layout's context — usually a modal — while a direct URL visit or hard refresh to that same route still renders its normal full page."

  • (.), (..), (...) → different levels up from the intercepting segment.
  • Soft navigation only — a hard refresh always falls through to the real route.
  • URL still updates to the real route — fully shareable, not a dead-end modal state.
  • Classic use case → feed photo click → modal, direct link → full page.
📖 Explanation ▾

A folder named (.)folderName "intercepts" a client-side navigation to that route — instead of replacing the whole screen with the target route's page, Next.js renders it inside the current layout's context, commonly as a modal overlaying whatever was already on screen. The dot-notation names how many levels up from the interceptor the target route lives: (.) for the same level, (..) one level up, (..)(..) two levels up, and (...) for the root app directory.

The key distinction from a route group or a plain modal component: interception only happens for a soft, client-side navigation — a `<Link>` click from inside the app. A hard refresh, or opening that same URL fresh in a new tab, bypasses the interceptor entirely and renders the target route's own real page.

Because the URL itself still updates to the real target route's URL even while the intercepted modal is showing, the link stays genuinely shareable — whoever opens it without the feed behind it gets the full dedicated page instead of a broken, context-less modal.

💻 See the code ▾
Next.js 
// folder structure
app/
  feed/
    page.js                  // the feed, with @modal slot
    @modal/
      (.)photo/[id]/page.js   // intercepted — renders as a modal
      default.js               // nothing to show when no photo is open
  photo/[id]/page.js          // the real, full-page route — hit on direct visit

The intercepting route lives inside a parallel @modal slot — interception and Parallel Routes are normally used together for exactly this pattern.

🧭 Use Cases — recognize these when they happen to you ▾
1 A photo/video feed where tapping an item opens it as a modal

The feed stays visible behind the modal, the URL updates to the photo's own route, and closing the modal returns to the feed exactly as it was.

RememberInstagram-style photo modal is the textbook interception use case.
2 A multi-step sign-up flow shown as a modal over the current page

The sign-up step opens as a modal over the current page for a smooth in-app feel, while still being a real, directly-loadable /signup page for anyone who opens it without the surrounding context.

RememberAny "open as overlay, but still a real page" flow fits this pattern.
3 Assuming the modal view is what loads on a hard refresh

Interception only applies to a client-side soft navigation. Hitting refresh (or opening the link fresh) always falls through to the plain photo/[id]/page.js route — that's by design, not a bug to work around.

RememberHard load/refresh always bypasses the interceptor, on purpose.
🌍 Real-world example ▾

An e-commerce product grid where clicking an item opens a quick-view modal. Clicking from the grid intercepts the navigation and shows the product as a modal over the grid; pasting that same product URL into a new tab opens the product's full dedicated page instead — the same route, a different render depending on how it was reached.
