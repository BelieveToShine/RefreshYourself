🔥 Must Know

Change detection — Default checks everything, OnPush only checks when told

What's the actual difference between Default and OnPush change detection, and what specifically makes an OnPush component update?

Why it matters ▾
  • Change detection is the mechanism that ties together everything else in this tier — Signals, RxJS, and rendering performance all sit on top of it.
  • Comes up any time a component "just isn't updating" — the real cause is almost always a missed OnPush trigger, not a broken binding.
  • A near-guaranteed interview follow-up once you mention OnPush — interviewers probe for the exact list of what triggers it, not just the definition.
🔥 Easy interview recall

Default → checks every component, every run

OnPush → checks only on specific signals

Think: OnPush isn't "off" — it's "only when a new @Input reference, an internal event, markForCheck(), an async pipe emission, or a Signal says so."

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

OnPush doesn't mean "never re-renders unless forced." It updates normally on a new @Input reference, an internal template event, markForCheck(), an async pipe, or a Signal change — the actual trap is mutating an array/object in place and expecting an OnPush component bound to it to notice, which it won't, because the reference never changed.

🔄 Likely Follow-up

"If a parent is Default and a child is OnPush, does the parent's re-check force the child to update too?" No — being checked because the parent is Default doesn't override the child's own OnPush gate; the child still only updates if one of its own specific trigger conditions is met, regardless of how often the parent gets checked.

🎯 Say this in the interview — the exact lines to land

"Change detection is Angular walking the component tree checking bindings against their last values. With the Default strategy every component gets checked on every run, triggered by Zone.js noticing an async event. OnPush skips a component unless a specific trigger fires — a new @Input reference, an event from its own template, markForCheck(), an async pipe emission, or a changed Signal."

  • Default → checks every component, every run, unconditionally.
  • OnPush → skipped unless a new @Input reference, an internal event, markForCheck(), an async pipe, or a Signal fires.
  • markForCheck() flags for the next run; detectChanges() runs it now, synchronously.
  • Zone.js patches async APIs so Angular even knows an event happened — remove it and nothing triggers automatically unless the app is built zoneless.
📖 Explanation ▾

Change detection is Angular walking the component tree, comparing each component's template bindings against their last-known values, and patching the DOM wherever something changed. Angular doesn't watch your data directly — with the Default strategy, it relies on Zone.js, which patches common async browser APIs (setTimeout, promises, DOM events, HTTP) so that whenever one of those fires, Angular gets notified and re-checks the whole tree, just in case something relevant changed.

OnPush doesn't disable checking for a component — it changes the condition for checking it, from "always" to "only when something specific says it's actually needed." That list is short and exact: a new reference on an @Input, an event bound inside the component's own template, an explicit markForCheck() call, an async pipe emitting (it calls markForCheck() for you), or a Signal read in the template changing.

markForCheck() and detectChanges() solve different problems. markForCheck() only flags the component (and its ancestors) as no-longer-skippable next time a run happens — useful right after something outside Zone.js's reach changes state (a third-party callback). detectChanges() actually runs the check immediately, synchronously, for that component and its children — no waiting for the next cycle. detach() is the rare escape hatch: it stops a component being checked at all, even under Default, until reattach() or a manual detectChanges() call.

💻 See the code ▾
TypeScript 
// @Input() items: Item[] — component is OnPush
this.items.push(newItem);        // ❌ same reference — OnPush never sees this
this.items = [...this.items, newItem];  // ✅ new reference — OnPush picks it up

The array's reference is what OnPush checks on @Input — mutating in place never changes it.

TypeScript 
thirdPartyWidget.on('select', (value) => {
  this.selected = value;
  this.cdRef.markForCheck();  // ✅ flags it — outside Zone.js's tracked APIs
});

A callback from outside Angular's Zone.js-patched APIs never triggers a run on its own — markForCheck() is what makes the change visible next cycle.

🌍 Real-world example ▾

A manager checking desks. Default change detection is a manager who walks around checking every employee's desk any time a phone rings anywhere in the building. OnPush is a manager who only checks one specific employee's desk when that employee's own inbox gets a genuinely new item dropped in, or they raise their hand — far less walking around, as long as everyone actually raises their hand when something real happens.
