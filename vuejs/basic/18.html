Vue 2 vs. Vue 3 — a rebuilt reactivity engine, not a paint job

"What are the biggest differences between Vue 2 and Vue 3?"

Why it matters ▾
🔁 Vue 2 → Vue 3
❗ ProblemVue 2's reactivity, built on Object.defineProperty, couldn't detect a brand-new property or array index assignment without a special Vue.set workaround — and Vue 2 itself reached end of life on December 31, 2023.
✅ SolutionVue 3 rebuilt reactivity on JavaScript Proxies, which natively track property addition/removal and array index changes, and added the Composition API, Fragments, and new built-ins like Teleport and Suspense.
RecallVue 3 = Proxy reactivity + Composition API + Fragments — a real engine rebuild, not a version bump.
🔥 Easy interview recall

Vue 2 → Object.defineProperty, one root required

Vue 3 → Proxy, Fragments + Composition API

Think: Vue 2 ended December 31, 2023 — this isn't old-vs-new taste, it's unsupported-vs-current.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Still reaching for Vue.set()/this.$set() out of habit. Vue 3's Proxy-based reactivity natively tracks property addition/deletion and array index assignment, so that workaround no longer exists or is needed.

🔄 Likely Follow-up

"Is Vue 2 code automatically compatible with Vue 3?" No — there's a documented migration build and a real breaking-changes list (global API reshaped, some lifecycle hook renames, filters removed); most Options API component code ports with modest changes.

🎯 Say this in the interview — the exact lines to land

"Vue 3's biggest change is Proxy-based reactivity, replacing Vue 2's Object.defineProperty, which couldn't track new or deleted object keys or array index assignment without Vue.set. On top of that, Vue 3 added the Composition API, multiple root elements through Fragments, and new built-ins like Teleport and Suspense. Vue 2 itself reached end of life on December 31, 2023."

  • Object.defineProperty → replaced by Proxy, the core reactivity rewrite.
  • Single root requirement → Fragments allow multiple roots in Vue 3.
  • Options API → Composition API added alongside it, not instead of it.
  • Vue 2 → end of life December 31, 2023 — no longer receiving updates.
📖 Explanation ▾

The headline change is reactivity itself. Vue 2 tracked changes using Object.defineProperty on each known property at creation time — which meant it genuinely couldn't see a property added later, or an array index set directly (arr[0] = x), without routing through Vue.set/ this.$set as a workaround. Vue 3 wraps the whole object in a Proxy instead, which intercepts property access generically — new keys, deletions, and array index writes are all tracked with no special-case API.

Everything else follows from having a new foundation to build on: the Composition API (its own topic, Basic #15) became possible because reactivity no longer needed to be wired through a component instance's fixed options; Fragments let a template return more than one root element, which Vue 2's compiler couldn't support; and new built-ins — Teleport (render content elsewhere in the DOM) and Suspense (coordinate loading state for async components) — are new primitives Vue 2 never had at all.

This isn't a stylistic preference between two still-current options: Vue 2 reached end of life on December 31, 2023 and no longer receives updates, including security fixes. A documented migration build exists for teams moving existing Vue 2 code forward, and most Options API component code ports with modest changes rather than a full rewrite.

💻 See the code ▾
Vue 
// Vue 2 — adding a brand-new key needs the special-case API
this.$set(this.user, 'age', 30);   // Object.defineProperty can't see a new key otherwise

Without $set, this.user.age = 30 in Vue 2 wouldn't trigger a re-render.

Vue 
// Vue 3 — the Proxy sees it directly
user.age = 30;   // ✅ tracked automatically, no $set needed

Same assignment, no workaround — this is the practical, everyday payoff of the Proxy rewrite.

🧭 Use Cases — recognize these when they happen to you ▾
1 You're starting any new Vue project today

There's no real decision to make here — Vue 2 is unsupported, so every current scaffolding tool and tutorial targets Vue 3 by default. This is the #1 scenario you'll actually run into.

RememberNew project → Vue 3, Vue 2 isn't a live option anymore.
2 You've inherited an older Vue 2 codebase still in production

A team on an unsupported Vue 2 app isn't usually looking at a full rewrite — the documented migration build and breaking-changes list exist to carry most Options API code forward with modest changes.

RememberExisting Vue 2 app → migration path exists, not a full rewrite.
3 You call Vue.set() in Vue 3 code out of habit

Vue.set is a Vue 2 API tied to Object.defineProperty's limitation — Vue 3's Proxy already tracks the assignment directly, so the function isn't there to call. Plain assignment is the actual fix, not a replacement API to look up.

RememberVue.set() in Vue 3 → not needed, not available. Just assign.
🌍 Real-world example ▾

Think of swapping a building's electrical wiring while keeping the rooms the same shape. The Proxy rewrite is new wiring underneath the whole house — most of what you see day to day (components, templates, props) looks familiar, but what each wire can now do (track any change, support new fixtures like Teleport and Suspense) is genuinely different, not cosmetic.
