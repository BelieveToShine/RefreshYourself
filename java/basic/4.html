Stack vs. heap memory — private per thread, or shared by everyone?

"What's the difference between the stack and the heap in Java's memory model?"

Why it matters ▾
🧵 Stack
❗ ProblemEvery method call needs somewhere to keep its own local variables and know where to return to — and two threads running at once can't share that bookkeeping.
✅ SolutionEach thread gets its own private stack of call frames; locals and primitives live there, and a frame is popped automatically the instant its method returns.
RecallStack = per-thread, auto-cleaned on return.
🗄️ Heap
❗ ProblemReal objects often need to outlive the single method call that created them, and be shared safely across many threads at once.
✅ SolutionThe heap is one shared memory area per JVM instance holding every object and array — managed and reclaimed by the garbage collector, not freed on method return.
RecallHeap = one shared area, GC-managed.
🔥 Easy interview recall

stack → per-thread frames + locals

heap → one shared area for objects

Think: stack pops itself automatically. heap waits for the garbage collector.

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

A StackOverflowError and an OutOfMemoryError are the same kind of failure. They aren't — a StackOverflowError is a thread's own stack running out (usually uncontrolled recursion), while an OutOfMemoryError is the shared heap running out; different root cause, different fix.

🔄 Likely Follow-up

"What's the usual cause of a StackOverflowError?" Recursion with no base case, or a base case that's never actually reached — each call pushes another frame until that thread's fixed-size stack runs out.

🎯 Say this in the interview — the exact lines to land

"Each thread gets its own stack for method call frames, locals, and primitives, popped automatically on return. The heap is one shared area per JVM instance holding every object and array, reclaimed by the garbage collector instead of on a fixed schedule."

  • stack → per-thread, cleaned up automatically on return.
  • heap → one shared area, managed by the garbage collector.
  • StackOverflowError vs. OutOfMemoryError → different memory area, different root cause.
📖 Explanation ▾

The stack exists once per thread. Every method call pushes a new frame holding its local variables and primitive values; when the method returns, that frame is simply popped — no garbage collector involved, no delay.

The heap exists once per running JVM, shared by every thread. Every object you create with new, and every array, lives there — kept alive for as long as something still reaches it, and reclaimed by the garbage collector once nothing does.

💻 See the code ▾
Java 
void crash(int n) {
    crash(n + 1);   // ❌ no base case — StackOverflowError
}

Dog d = new Dog(); // ✅ d (reference) is on the stack, the Dog itself is on the heap

Uncontrolled recursion exhausts the stack. The object it creates would live on the heap instead.

🧭 Use Cases — recognize these when they happen to you ▾
1 Each request on a server runs on its own thread

Each request gets its own private stack for that call's frames; a shared object like a cached config still lives once on the shared heap. This is the #1 scenario you'll actually run into.

RememberPer-request work → private stack. Shared state → the one heap.
2 A recursive function has no base case

Every call pushes another frame onto that thread's stack — with no base case, it runs out of stack space, not heap space.

RememberUncontrolled recursion → stack exhausted, not the heap.
3 Memory keeps climbing under load and you call it a "stack leak"

Retained objects nobody releases is a heap problem — the stack unwinds completely on every method return, automatically, every time.

RememberGrowing memory under load → check the heap, not the stack.
🌍 Real-world example ▾

The stack is like a personal to-do notepad each worker keeps at their own desk — it fills up and empties as they work through tasks, and nobody else ever touches it. The heap is the shared filing cabinet in the middle of the office — anyone can store something there or look something up, and it only gets cleared out once nobody needs that file anymore.
