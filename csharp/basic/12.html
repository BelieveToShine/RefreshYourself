enum — turn magic numbers into named choices

Why it matters ▾
🔢 enum
❗ ProblemA status stored as a bare number like 2 forces every place that reads it to remember what each number means, and nothing stops a comparison against the wrong number.
✅ SolutionAn enum gives that fixed set of options real names, so code reads and compares Status.Active instead of a memorized 1.
RecallEnum = a fixed list of meaningful choices, compared by name, never by the raw number.
🔥 Easy interview recall

Enum = "a fixed list of meaningful choices."

Think: Status → Pending | Active | Closed

🧠 Visual Mental Model — understand it in 5 seconds
⚠️ Common Trap

Casting an out-of-range number to an enum doesn't throw. (Status)99 compiles and runs fine, even though 99 isn't Pending, Active, or Closed.

🎯 Say this in the interview — the exact lines to land

"An enum is a named set of integer constants — readable instead of magic numbers. Compare and switch on the name, never the raw underlying number."

  • Numbering starts at 0 by default — you can override it when the value matters.
  • [Flags] enums are the exception — for combining multiple options at once.
📖 Explanation ▾

An enum gives a small, fixed set of options real names instead of raw numbers. Under the hood each name is backed by an integer — starting at 0 and counting up by default — but the whole point is that your code reads Status.Active, never a bare 1 that means nothing on its own.

You can assign the numbers yourself (Closed = 5) when the exact value matters — stored in a database, sent over a wire — but for a purely internal set of options, the default numbering is fine.

A separate, more advanced use — the [Flags] attribute — lets an enum's values be combined with bitwise OR, for "more than one option at once" cases (permissions, days selected). That's the exception, not the everyday case.

💻 See the code ▾
C# 
enum Status { Pending, Active, Closed }   // 0, 1, 2 by default

Status current = Status.Active;
if (current == Status.Active)   // ✅ compare by name, not number
    Console.WriteLine("Still open.");

The name is what your code reads and compares — the number underneath never shows up.

C# 
var weird = (Status)99;
Console.WriteLine(weird);   // prints "99" — no exception, even though invalid

C# doesn't validate the cast — an enum variable can hold a number that isn't one of its named values.

🧭 Use Cases — recognize these when they happen to you ▾
1 Your code compares or switches on a status-like value

You read and compare by the name, Status.Active, never a bare number — this is the everyday reason enum exists, the exact pattern in this page's own code example. This is the #1 scenario you'll actually run into.

RememberCompare and switch by name, never by the raw number.
2 The exact underlying number matters — it's saved or sent somewhere

You deliberately assign the numbers yourself when that exact value gets stored in a database or sent over a wire — outside code depends on the number staying stable, so the default 0/1/2 numbering isn't good enough here.

RememberAssign custom numbers only when the number itself must stay stable.
3 A number outside the enum's defined range gets cast straight to it

C# doesn't validate the cast, so a variable declared as Status can silently hold 99 — a number that isn't Pending, Active, or Closed — and no exception ever fires.

RememberAn invalid cast to an enum compiles and runs — it doesn't throw.
🌍 Real-world example ▾

A traffic light. The light is always exactly one of a fixed, known set — Red, Yellow, Green. You'd never say "the light is state 2" out loud; you say "the light is Green." An enum is that same idea, written into the code.
